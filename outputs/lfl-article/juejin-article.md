# 把"诚实"写进 Agent 运行时：回执契约、三层权威与事件溯源

> **TL;DR**：LLM Agent 最大的痛点往往不是不够聪明，而是**谎报完成**、**拿训练记忆当现状**、**跨会话失忆**。开源项目 llm-first-loop（LFL）把这三件事当架构问题来解：未获成功回执不得声称完成、先取证后判断、事件日志做单一真相源。Apache-2.0，v0.6.32，Python ≥ 3.13，CLI / Web / 飞书三端接入。

## 1. Agent 为什么会"谎报完成"

先看三个高频翻车现场：

- 让它改 bug，它说"已经修好了"，一跑测试，报错原封不动；
- 问它文件路径，它给出精确到目录级的答案，一打开 404；
- 出了错它自己悄悄重试，最后回复看起来一切正常。

这些不是玄学，是机制问题：

1. **没有回执契约**：模型说"已完成"只是文本生成，背后有没有对应工具的成功回执，没人校验。
2. **训练先验当现状**：关于"当前代码/文件/版本"的回答来自训练记忆，而现场早已变化。
3. **静默降级**：工具失败被中间层吞掉，错误没有透传到最终回复。

## 2. LFL 的解法：把规矩写进运行时

LFL（llm-first-loop）是一个 LLM-first 的 Agent 运行时：**程序最小化（做感官、手脚、边界），文档规则驱动，模型做判断**。几个核心设计：

**五步闭环 + 真诚回答**：每条消息走 `消息进 → 理解 → 行动 → 真诚回答 → 记住`。其中"真诚回答"对应一条架构规则契约（RULE-AI-01）：未获成功回执，不得声称完成；程序负责把每笔工具回执记入账本，供模型声明"完成"前对账。

![核心循环](assets/img2_core_loop.png)

**架构纪律**：工具执行的成功、失败、异常都必须如实构造回执，错误完整透传，不静默降级。

**三层权威边界**：

| 层 | 职责 | 禁止 |
|---|---|---|
| L3 用户层 | 真人指令是唯一授权真值 | —— |
| L2 模型层 | 任务策略、完成判断、证据引用 | 扩大授权、伪造精确 |
| L1 程序层 | 安全硬边界、超时预算、原子写、证据持久化 | —— |

铁律：**下层不得扩大上层授权**。

![三层权威](assets/img3_three_layers.png)

**诚实工程**：涉及当前代码/文件/运行态的事，先取证后判断；无法核对就明示"未核验"，不猜。

![诚实工程](assets/img4_honesty.png)

**记忆与事件溯源**：事件日志（`data/event_logs/<sid>.jsonl`）作为轨迹单一真相源，会话创建、消息追加、上下文压缩等事件全部落盘，支持回放重建、逐字段对账、会话 fork 与滚动归档；经验教训跨会话沉淀。

![记忆分层](assets/img6_memory.png)

## 4. 能力全景

浏览器感知与操作（CDP 接管真实 Chromium）、子代理与编排（并行/流水线/DAG + 租约预算）、服务生命周期控制、模型目录与应急降级、评测体系（固定场景集 + Wilson 区间 + nightly）、蒸馏数据导出（ReAct JSONL）、MCP 只读导出、插件化 Skill。（部分能力由配置开关控制，以运行配置为准。）

## 5. 五分钟上手

```bash
# 安装（Python ≥ 3.13，lockfile 可复现）
cd llm-first-loop
uv sync --frozen --extra dev

# 配置模型
export LLM_API_KEY=sk-xxx
export LLM_BASE_URL=https://api.deepseek.com/v1

# 跑最小闭环
.venv/bin/python -m llm_loop.cli "请读取 data/notes.txt 并总结内容"

# 或交互模式（--session 可跨天续聊）
.venv/bin/python -m llm_loop.cli --interactive
```

## 6. 适用边界（如实说）

- **适合**：需要长任务、跨会话记忆与可审计自动化的开发者/团队；想把 LLM 接进真实终端、浏览器与服务的工程场景。
- **请注意**：灾难性安全是"已知灾难模式硬阻断 + 全量审计"，**不是完备沙箱**；演进闭环有人工审阅环节；0.6.x 接口仍在快速演进。

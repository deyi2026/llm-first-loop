## Trigger
工具调用返回程序层守卫/预检路由回执（非网络错误、非安全拒绝），文本明确指出该 URL/请求类已被识别为专用抓取路径、通用执行本次被跳过，即环境声明存在专门能力，而目标内容尚未取得。

## Discriminator
守卫回执本身点名『专用路径』存在；一次定向 lookup（技能文档或工具 schema）即可拿到可执行契约，典型表述为『快路径内置于主工具受保护层、优先一次调用、禁止同参盲重试与手写 curl』。这两条当时已在手的事实把『怎么获取该 URL』从{重试被拦形态、换工具、枚举技能目录、搜索镜像、手写低层请求}缩成{按契约发一次标准调用}。若同一守卫回执第二次原样出现，即证明调用形态未按契约改变。

## Short path
- 收到守卫回执后，做且只做一次定向契约查询（该专用能力的 SKILL 或工具 schema）；未知量：标准调用形态是什么。
- 按契约原样发一次调用（通常=主工具+用户原始 URL，适配由工具内部完成）；未知量：目标内容是否可得。
- SUCCESS 回执即直接分析正文并停止，不做二次抓取验证；若失败，按该新回执的原因类别只分流一次（404/不存在→转载或归档搜索；BLOCKED→不绕过、说明边界；超时/反爬/JS 壳→镜像或浏览器通道）。
- 全程不原样重发被拦截的调用形态，不在『如何获取』这一未知量上枚举完整技能/工具目录，不用 execute_command 手写低层请求绕过守卫。

## Stop conditions
- 成功回执显示专用路径确实被触发（如 extract/快路径标识）且正文与 URL 实体身份（文章 ID）一致 → 立即分析并停止，不再重复抓取。
- 同一守卫回执第二次原样出现 → 判定调用形态未变，禁止第三次同形态尝试；下一步只能是契约查询或切换恢复通道。
- 守卫属于安全边界类拒绝（BLOCKED/SSRF）且未点名可用专用能力 → 停止绕过尝试，转说明边界或使用用户提供内容。

## Verification
- 最终成功回执中确认专用路径字段（如 extract=快路径名）与 URL 中的实体 ID 一致，说明内容来自目标源而非镜像/缓存。
- 复盘轨迹：被拦截形态未被原样重发；技能目录全量枚举未出现在『获取内容』未知量的路径上；成功后无 post-sufficiency 再抓取。

## Counterexamples
- 守卫回执是纯安全拒绝（SSRF/BLOCKED），未点名任何专用能力或替代通道 → 不适用『再发一次标准调用』，应停止绕过并走边界说明分支。
- 专用能力的契约要求尚未具备的前置条件（API Key、登录态、特定参数）→ 未知量是前置条件而非调用形态，重复调用或重复读文档都会得到同一失败，应先补前置。
- 回执未点名专用路径、且无任何已加载契约可查 → 此时目录/搜索层面的宽发现是合法的下一跳，本方法不适用。

## Trigger
收口阶段出现：验收要求分层（实质内容正确 vs 更强的身份/形式一致）；强层差距只剩环境故障（如某传输通道黑洞而另一 API 通道正常）；弱层等价已有权威独立证据；而模型仍在对同一故障通道反复换法重试以求恢复强层。

## Discriminator
当时已在手的事实：两侧内容的权威指纹完全一致（tree/内容哈希相同、关键对象逐一 MATCH），说明用户实质需要已满足且阻断与内容无关；且故障呈通道选择性（一条通道正常、仅另一通道黑洞），说明是环境问题而非成果问题。这两点足以把继续枚举修环境方案缩为按已证等价收口并拆项，无需使用事后信息。

## Short path
- 盘点验收分层：区分实质需要（内容正确性）与附加形式（如远端精确含本地身份），确认弱层已有独立权威证据。
- 若强层仅被环境故障阻断：停止环境排查，冻结显式映射并如实标注差异性质（内容等价、身份不等），不得表述为精确一致。
- 沿正常收口链推进：远端 CI 全绿后合并，再用避开故障通道的权威 API 验证最终主干内容指纹与本地合格内容一致。
- 完成台账/checkpoint/handoff，把环境故障连同已知线索与坑单独立项，随即结束当前长任务，不在其中开启新阶段。
- 若强层属治理硬规则：不降级冒充完成，改记部分收口并保留专项待补。

## Stop conditions
- 最终主干内容指纹与本地合格内容一致且经独立权威来源验证，映射与未决项均已写入收口与交接文档。
- 用户或治理明确要求强层：仅登记部分收口，不得声称完全完成。
- 弱层证据不完整（仅部分对象匹配或两侧指纹模型不可比）：本方法不适用，继续排查内容差异。

## Verification
- 用独立于故障通道的权威 API 复核合并后主干的 tree/关键对象指纹与本地合格内容一致。
- 映射记录明确写出内容一致、身份不等，收口文档不含精确一致的表述。
- 环境故障已作为独立专项登记，且未出现在本任务的完成条件中。

## Counterexamples
- 强层是审计/合规硬要求（必须精确身份锚点）：不可用等价收口替代，只能部分收口并另修。
- 下游依赖精确身份按 SHA 拉取或复现：身份等价具有操作意义，需修复传输后再锚定。
- 等价证据仅部分成立或两侧指纹不可比：弱层未满足，方法失效。
- 故障同样阻断验证通道本身（无任何权威来源可比对）：须先恢复任一验证通道再谈收口。

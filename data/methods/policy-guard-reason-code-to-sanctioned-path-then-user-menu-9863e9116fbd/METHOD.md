## Trigger
用户指定经某通道（浏览器/桌面/面板）完成的状态翻转或收口动作，接连被命名策略护栏拒绝（私网导航拦截、跨会话写拒绝、网页目标禁入等），且仍有多个候选执行通道未定性

## Discriminator
归属记录回执已显式打印写权限合同（如『任务图翻转无跨会话出口，须 owner 会话执行；仅 goal 记录可带 reason+evidence 跨会话』）；且拒绝码可在 tests/设计文档中查到唯一放行路径及其归属（host-owned 环境变量、需重启、或须 owner/人类主体）。这两点在探测试错之前就已可得，足以把『逐个通道试』缩成『按合同归类通道』

## Short path
- 读归属/Goal 记录提取写权限合同：哪些写被拒、哪些有带条件出口——一步排除整条工具通道，剩余未知量收敛为『谁能合法执行 owner 会话动作』
- 服务地址用部署回执里的 pid 直接 lsof 查监听端口，不从其它 runtime 回执猜端口号
- 被护栏拒绝时，用拒绝码原文在仓库内做一次检索：tests 锁定=设计行为，设计文档给出唯一放行路径及其归属主体
- 放行路径若需本会话不能自授的主体权限（host 环境变量+重启会中断会话、ax_trusted、owner 身份、禁止把指令伪装成 human turn）→ 判该通道死，不再对剩余通道做端到端探测试错
- 全通道判死后停止探测，输出给用户的最小二选一菜单：A 把目标 URL 开进我可控的浏览器实例（我代发带来源标注的收口指令并盯到终态）；B 用户在面板直接粘贴现成指令文本；两条路径都以权威记录（任务前沿/Goal 查询）核实终态收尾

## Stop conditions
- 任一通道的放行路径可由本会话合法调起（如 per-call 显式授权旗标 cross_session=true + reason + evidence_refs）→ 立即改走该通道执行，不做用户交接
- 所有 sanctioned 路径均要求 host/owner/人类主体权限 → 输出决策菜单并停止探测
- 已由权威记录核实终态（如任务 5/5 done + Goal complete）→ 停止

## Verification
- 代发/交接指令必须带来源标注（谁授权、以何身份代发），不伪装成用户本人输入
- 终态以权威记录查询复核（task_frontier/get_goal），不以 UI 快照单方面为准
- 引用的放行配置名须与护栏单一事实源（实现/tests/设计文档）一致，不凭记忆拼配置名

## Counterexamples
- 拒绝原因是 per-call 合同差分（缺字段）且可由本次调用携带修复（补 reason+evidence_refs 或显式跨会话旗标）→ 补参重发即可，不升级成用户交接
- 单机自管环境且用户已授权改环境变量/重启 → 设置放行配置并重启就是 sanctioned path 本身，不是绕行，应直接执行
- 拒绝是传输类瞬时失败（超时）→ 走快速重试/换通道 triage，不做护栏合同检索
- 目标内容存在静态文件副本或只读查询即可满足 → 直接读静态面，无需打通交互面板

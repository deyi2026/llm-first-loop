## Trigger
即将通过工具对真实页面或外部系统执行任何变更类操作（navigate/click/set_text/select/submit/send 等），且操作前 snapshot 可观察（URL、目标 kind、现有 value_text）；设计或评审此类操作安全流程时同样适用。

## Discriminator
执行前即可从可观察事实分类动作语义，无需等运行时错误暴露：机械回执只证明『已派发』而非业务结果；目标是否命中 下单/付款/删除/发送/提交 类不可逆模式（看 URL/按钮文本）；动作是否非幂等（click/发送重执行即重复副作用）；写入是否覆盖语义（set_text 直接抹掉原值）。本集四个盲点全部属于这类『无运行时错误也能事前枚举』的语义缺口。

## Short path
- 先感知：snapshot 取 URL、目标 ref、目标当前 value_text —— 解决未知量『页面当前真状态与风险级别』
- 分类动作三语义：可逆性 / 幂等性 / 写入语义 —— 解决未知量『该动作的失败会长成什么样』
- 不可逆 → 输出『我将点击 X，因为 Y』等待确认；高危页只感知不操作 —— 解决未知量『这一下该不该点』
- 覆盖写 → 先读原值，非空则告知并确认（超长文本截断并告知） —— 解决未知量『会不会抹掉用户已有内容』
- 单步执行，操作后重新观察以 diff 验证业务成功（回执只算派发） —— 解决未知量『是否真的生效』
- 非幂等动作复验成功立即停；失败/目标消失不重试原命令，重新感知后按新证据决定 —— 解决未知量『要不要做第二次』

## Stop conditions
- 非幂等 mutation 已被复验确认成功 → 对同一目标永久停手，绝不再执行（防重复下单/发送）
- 遇登录墙/验证码/多标签盲区 → 停手交用户，自己保持只感知
- 不可逆操作未获用户明确确认 → 不执行
- 所需业务事实已被操作后复验确认 → 立即停止，不做多余确认动作

## Verification
- 以操作后 snapshot 的实际变化 diff 判定业务成功，不采信工具回执的 success（回执仅=已派发+已截图）
- 覆盖写之后重读目标 value_text，核对最终内容与意图一致
- 不可逆操作执行前必须存在『我将点击 X，因为 Y』的显式确认记录

## Counterexamples
- 纯只读任务（snapshot/读取/内容抽取）：无状态变更，三轴分类全不成立，无需确认门控或 value 预检，直接观察即可
- 显式幂等操作（查询/GET/带幂等键的调用）：重执行无害，『复验成功即停』不必永久化，但仍以重新观察判定结果
- 输入框已确认原本为空且内容为新构造：无既有内容可覆盖，value_text 预检退化为一次性确认，不必逐步阻塞
- 目标系统自带确认弹窗或幂等键防护：确认门控可降级，但『回执≠业务结果、以复验为准』仍然适用

## Trigger
续跑一个曾中断的外部系统状态型操作，存在影响行动方向的未核实状态假设（目标条目是否仍在、平台是否真在拦截），且可见聚合计数或上一轮 STATUS/停点文档

## Discriminator
聚合计数跨关键事件（如一次失败的发布点击）保持不变，同时兼容『条目仍在』与『条目已丢失』两种世界，不具判别性；判别性证据只有身份级观察：以唯一键查列表成员、读平台权益/权限页的真实语义。且停点文档中显式标注的『未核实』项清单本身就是优先未知量列表，应先于代码考古被消解

## Short path
- 读停点 STATUS/目标检查点，抽出显式标注『未核实/待确认』的状态假设，按文档给出的顺序排列
- 对每条假设做一次身份级直接观察：打开草稿箱按标题/日期查成员归属；打开创作权益页读横幅真实含义；不以计数不变推断个体存在
- 按观察结果分派行动：条目丢失→从本地冻结产物重建并回读校验；横幅与发布无关→从阻塞假设集合删除；条目完整→直接进入修复/重试路径
- 全部状态假设落定后，才进入缺陷修复或重试派发；终态由公网权威回读验证后停止

## Stop conditions
- 每条影响行动方向的未核实假设都已被一次直接观察证实或证伪
- 用户所需终态（如发布成功且公网回读与冻结产物一致）已由权威来源验证并落盘

## Verification
- 公网回读（如 info 接口）核对标题/正文结构/配图/声明与本地冻结产物一致
- 重建场景核对本地产物哈希与重新上传内容一致
- 落盘时显式记录本轮推翻的上一轮假设，防止后续再沿旧假设规划
- 宣称『不存在/已丢失』前，用搜索/筛选而非首屏肉眼扫一遍确认（分页/懒加载漏检风险）

## Counterexamples
- 任务目标本身就是聚合计数（如查询剩余配额）——计数即所需事实，成员检查是浪费
- 系统只提供状态字段或 API 而无列表界面——直接读状态字段即可，方法退化为普通读
- 停点文档不存在或未列未核实项——此时无法从文档导出未知量清单，需先做一次窄的状态盘点而非直接套用
- 本地无冻结产物且无法重建时——先确认可恢复性再执行任何删除/覆盖类动作，身份检查结论只用于判断、不授权破坏

## Trigger
需要对一个关于知名厂商产品的事实性断言（是否付费、免费额度、单价、配额、前置资源要求）进行核实，且该厂商存在可由产品名推导的稳定规范文档/定价 URL 模式；或首次通用搜索的回执已显示结果全是厂商门户首页/营销页而没有任何目标详情页。

## Discriminator
首次搜索回执本身即可观察：8 条结果标题/URL 全是 azure portal 首页类页面，没有一条 pricing/details 详情页；同时产品官方名称已知，规范详情页 URL 本可由名称+固定模式直接构造——下一步动作立刻构造成功并抓到目标行，证明两次搜索没有贡献任何不可推导的信息。

## Short path
- 把待核实断言拆成逐项未知量（某产品的免费额度/单价/前置条件），不在通用搜索引擎上展开。
- 对第一项由已知产品名构造厂商规范定价页 URL（如 /pricing/details/<service-slug>/）直接抓取；未知量：该产品是否存在免费层及额度。
- 提取成功的部分（免费额度行）即固化为可引用事实；观察到金额列为 JS 占位符（`$-`）时，把该项收窄为『免费额度已核实、单价未核实』，不对同一 URL 原样重抓。
- 第二项的规范页超时：最多一次改变条件的重试，随后降级抓相邻权威文档（service-limits/quickstart）以佐证可佐证的前置条件，其余显式标注未核实。
- 汇总输出：每项要么附提取行来源、要么标 unverified，并据此收窄此前『需要付费资源』式的无依据断言，然后停止。

## Stop conditions
- 每项待核实断言都有规范页提取行背书，或已显式标注为未核实
- 同一 URL 第二次出现同样超时/同样占位符提取后，停止原样重试
- 关键结论（如免费额度）已由第二条权威文档（配额页/FAQ）交叉印证

## Verification
- 确认抓到页面的域名与标题确为该产品的官方定价/文档页，而非门户首页
- 免费额度等关键行用第二条权威文档交叉印证（本集 service-limits 与定价页 FAQ 互相一致）
- 最终答案逐项可溯源：引用行与来源 URL 对应，无编造数值，且先前的过度断言已被收窄而非静默保留

## Counterexamples
- 不知名服务、内部系统或无公开 URL 规律的产品：直接构造 URL 会 404，搜索/文档索引才是正确的发现首步
- 目标数值是服务端渲染、提取完整：无需收窄断言或渲染降级，直接引用即可
- 用户要的是自己账户/区域的实际成交价：官方页自标 'Prices are estimates only'，页面数值也不可信，需登录控制台或价目 API，本方法不适用
- 搜索后端本就返回详情页首条结果时，一次探测即够，『跳过搜索』的前提（搜索返回营销首页）不成立，方法无收益

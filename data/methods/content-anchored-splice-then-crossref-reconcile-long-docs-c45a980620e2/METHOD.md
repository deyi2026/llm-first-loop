## Trigger
需要用脚本/精确替换对一份本 run 已分段读过的长文档做多处章节级插入或改写；查看回执的显示行号与真实文件存在可观测偏移（如回执宣称总行数与锚点实测差 1 行级），正文含代码围栏，且文档结构含 §编号引用、决策编号标签、汇总表或附录。

## Discriminator
两个当时已可见的事实：①查看回执头部的总行数与一次内容锚点扫描的实测行数不一致，证明回执位置信息不可直接用于拼接计算；②回执正文已出现密集交叉引用（『理由见 D5』『见 §8.3』式）与编号决策标签、阶段表、附录——证明任何多点插入必然使部分引用/标签/汇总表失同步，且含围栏的载荷容易让转换层 ABORT。

## Short path
- 先由改动动机列出待插入/推翻的结论清单，不做全文件重扫
- 对每个插入点用唯一标题串或长句做内容锚点定位（必要时一次锚点扫描顺带校准真实行数），不用显示行号做拼接数学
- 逐锚点替换；载荷含代码围栏时先做围栏安全处理或改用唯一整串替换，避免 heredoc/转换层 ABORT 重试
- 最后一次写入后立即跑一次机械清单：全部 §/D 引用可解析、章节号单调、决策标签唯一且不与新结论矛盾、汇总表与附录更新或显式标注失效
- 同一循环内修完清单暴露的失同步项，清单全绿才收尾作答

## Stop conditions
- 机械清单全绿：每个 §/D 引用有现存目标；无重复或互相矛盾的决策标签；汇总表与正文最新结论一致；被推翻的旧建议已显式标注失效而非静默保留或删除
- 最终标题清单与最后一次写入回执一致，无未解释的悬空节、错序节或重复节

## Verification
- 写入后 grep 标题行与 §/D 引用做一次解析性核对，而不是只看写入回执的 OK 状态
- 抽查每个拼接锚点上下几行，确认边界没有吞段或残段
- 对被推翻结论，确认旧主张处留有失效标注（可追溯），而非无声消失

## Counterexamples
- 向无内部交叉引用的文档（changelog、独立笔记）追加自包含新节：直接追加即可，无需对账扫描
- TOC/引用由标题自动生成的文档：只修源头结构，人工逐项对账无意义
- 单点小改（错字、单个数值替换）：锚点定位与清单核对都是过度工程

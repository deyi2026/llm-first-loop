## Trigger
需要取某条已知记录的稳定引用或完整内容，且已握有其精确名称/短 ID；或检索工具刚对该记录返回一次确定性『未找到』回执（非超时、非瞬态错误）。

## Discriminator
查询串中已包含该记录的精确 token，检索仍权威返回『未找到』——说明该检索的匹配语义不是子串/包含式，问题在查询形态而非记录缺失；同时目标存储是本项目可直访的本地工件目录（每记录一目录 + 主文件 + 资格/证据文件），存在比语义检索更窄的原生寻址路径。

## Short path
- 明确未知量（目标记录的稳定 ID/完整内容），盘点已持有的精确标识（本集为方法短名 poc-a-b，来自本会话自己的存量清单）。
- 优先用精确短名直接过滤存储目录（如 ls <store> | grep <name>）取得完整 ID；不要先发长串语义化查询。
- 若已发生一次含精确 token 的『未找到』：据此推断匹配语义不含子串，立即换寻址方式（直读存储或查该检索工具的 kind 匹配规则源码取精确形式），不再换词重试、更不放宽成泛化查询。
- 读主文件 frontmatter 取 ID/status 后，继续读完完整资格/证据文件（不截断），核对关键字段（如 promotion、episode 溯源是否与当前同源）。
- 用完整字段预判门槛：字段不满足（如 promotion=not_evaluated 且与源 episode 同源）则不发起流转调用，直接报告正确的激活路径（需下一次独立应用 run 记录 promotion=pass）。

## Stop conditions
- 已从存储直读取得稳定 ID 与完整记录，且关键资格字段（promotion/溯源）已逐项核对。
- 检索工具的精确寻址形式（如 method:<完整ID>）已用一次命中验证可用。
- 不再对同一记录发起新的语义改写查询；门槛动作的依据已来自完整而非截断的证据文件。

## Verification
- 直读所得 ID 与检索工具精确形式命中的是同一条记录（双向一致）。
- 若门槛最终仍拒绝流转，确认错误信息要求的缺失字段与完整证据文件中的实际字段一致（说明预判有效）。
- 结论中区分『记录不存在』与『查询形态不匹配』两种空结果，只有前者才扩大发现范围。

## Counterexamples
- 并不掌握精确标识、目标本身就是模糊发现相关方法/记录时，语义检索（可换词扩检）才是正确工具，切到直列目录无益甚至更差。
- 存储为远程或仅 API 可访问、无直读权限时，只能先学习其查询语法/文档，不能直列目录。
- 首次未命中是超时、索引未就绪等瞬态错误回执时，应重试原查询而非立即换通道（判别事实是回执类型，不是空结果本身）。
- 文件系统存储只是滞后镜像、检索索引才是权威状态源时，直读可能取到过期 status，须以权威源核对后才能行动。

## Trigger
为 rollout 验收、覆盖率、审计等目的，对日志/事件/数据库新写一条聚合或验证查询并返回空/零；同时 (a) 来源已知为活跃（服务刚确认重启成功、写入方在线），(b) 查询的路径与字段/事件结构来自假设、未经独立来源核对。

## Discriminator
空结果自带的机械元数据区分两类失败：'files touched: 0' 说明文件定位假设失败，下一步只做发现（按 mtime 定位正在写入的文件/分片），不碰字段；有文件扫过但 0 条，才对照真实样本检查顶层结构与字段名。另一条当时已可见的判别：文档明写'用与既有审计 § 同型查询'——这是显式 provenance，路径+schema 本可直接继承，零命中一轮都不必发生。

## Short path
- 写查询前：若当前 artifact 已引用同型既有查询、读取方或事件写入方，先读它一次拿到路径+schema（未知量：数据位置与结构），再写查询。
- 若查询已写出且返回空：先读回执元数据。files/dirs touched=0 → 只修发现，按修改时间找活跃文件，不查字段。
- 找到活源后取一条原始记录样本核对结构与字段名（未知量：schema 是否与假设一致），修查询重跑。
- 取得非零计数后逐条归因验收断言；对个别异常项（某字段整体缺失）用主键取原始事件对精查，然后停止扩搜。

## Stop conditions
- 修正后查询返回与已知活性证据（启动时刻/pid/重启回执）时间窗一致的非零结果，且每条断言已归因，含如实记录的真零。
- 扫描元数据确认已扫到正确活源、schema 经样本核对仍为 0 → 这是真发现，记录（含扫描范围与条件）即停，不换措辞继续探测。
- 单一权威参考已同时确认位置与结构且结果为空 → 直接采信为空。

## Verification
- 最终查询所用 schema 必须与目标文件中一条原始事件样本逐字段一致（顶层类型/时间戳、payload 字段名）。
- 非零计数须与独立活性证据（进程启动时刻、写入方在线）在时间窗上吻合。
- 真零结论必须显式给出扫描范围与过滤条件，使读者能区分'查询失败'与'事实为零'。

## Counterexamples
- files touched>0 且 schema 已核对仍为 0：这是真实零流量发现（如'重启后无某类调用，如实记 0、待流量'），继续怀疑查询会变成无信息循环。
- 断言本身预期为空（缺勤/不变性断言，如'旧数据中新字段必须=0'）：空即通过，无需 localize。
- 对单一权威只读源的一次性点查且其 schema 已在上下文中展示：空结果可直接采信，不再三重核对。

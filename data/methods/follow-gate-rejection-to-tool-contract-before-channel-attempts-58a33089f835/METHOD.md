## Trigger
即将调用带静态门控/沙箱/白名单的执行类工具（如沙箱浏览器 exec、受审代码执行），或刚收到确定性拒绝（门控、白名单、帧超限），需要决定重试、调参还是换通道时

## Discriminator
拒绝消息已具名替代路径与门控原因（如'必须用预置 helper；防绕过 URL 白名单'）——这证明契约源码/文档中存在可读的 helper 全集与白名单范围，一次定向读取即可把'哪个通道可用、怎么用'从多候选缩成一条确定结论；且该范围可能直接排除目标域，使任何执行尝试都不必要。

## Short path
- 收到确定性拒绝（门控/白名单）→ 不重试同形态代码、不先做目录级宽枚举；把拒绝消息当作指向契约的指针
- 定向读契约：一次搜索+读取该工具源码/文档，拿到 helper 全集与白名单 host 集合
- 用白名单先验裁决通道：目标域不在名单→该通道对本次目标判死，零执行尝试；在名单→按 helper 语法写最小用例
- 通道被否决后按数据形态换通道类：结构化数据→服务 API（最小 JSON 载荷），正文→纯 HTTP fetch，确需渲染/登录→先导航到小页再感知，绝不驻留大页
- 通道矩阵足以回答用户问题即停止；系统性缺陷（如大页困死）另提演进建议

## Stop conditions
- 契约已读，白名单/能力范围已明确覆盖或排除目标域
- 已用与数据形态匹配的最小载荷通道取得所需事实（如几十行 JSON 对比 >1MB 帧失败）
- 不再对已被门控或传输超限判死的通道做参数级重试或目录级宽枚举

## Verification
- 白名单/helper 结论引用契约源码或文档的具体位置，而非从失败结果反推
- 对比成功通道与失败通道的载荷量级，确认量级差异支持通道级而非参数级结论
- 检查轨迹中不存在对同一静态门控的重复撞墙调用；宽枚举仅在契约不可读时出现

## Counterexamples
- 无门控的普通工具（curl/web_fetch/标准库）：没有内部契约可读，直接最小尝试更便宜
- 错误是 transient（超时、网络抖动、5xx）而非确定性策略拒绝：应重试或调参，不应判通道死刑
- 目标确需登录态/JS 渲染且目标域在白名单内：该执行通道正是正解，'API 优先'不适用
- 工具明确支持上游分帧/分页/帧上限参数且可解决载荷问题：调参有效，属参数级而非通道级失效
- 契约完全不可读的闭源黑盒工具：单次最廉价的受控试探是获取契约的唯一途径，此时试错合法

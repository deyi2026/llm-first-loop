## Trigger
在既有安全/策略闸上新增放行或转换路径，实现会同时触及扫描、准入审查、审计等多个消费点；或闸模块源码带有既往红队/清单漂移登记注释。

## Discriminator
动手前读到的闸模块注释已登记『枚举清单各自维护、互相漂移、被红队击穿』的教训（如解释器名单被迫单源化的记录），且代码结构显示同一命令形态存在多个独立消费点——新路径只要再开一张平行枚举清单、或只改入口不查下游视图，就是在复刻已登记的失败模式。

## Short path
- 实现前摘出闸模块内全部红队/漂移登记注释，转成设计约束（禁止新增平行枚举清单）
- 新路径的拒绝面按构造类闭合：变量拼接派生、list 形式 argv、间接派生到受保护动作的构造整类 fail-closed 并附说明
- 对每个下游消费点逐一问『转换后的工件在这里长什么样』，原始语义被隐藏（如下游只见临时文件形态、看不到载荷在跑 git push）即整类拒绝
- 拒绝回执与审计证据自检：不得把被拒敏感文件的内容（如 .env 首行）写进日志
- 提交对抗审查前先跑自建负例集（间接派生、list argv、载荷内受保护动作、held-out 时序），PASS 后登记收口

## Stop conditions
- 全部派生构造类已闭合拒绝且 fail-closed 均带说明
- 每个下游消费点对转换后工件的视图已逐一核验，无原始语义隐藏
- 负例自测集与原硬阻断回归全绿，对抗审查取得 PASS

## Verification
- 负例集覆盖：变量拼接派生受保护动词、list 形式 argv、载荷内受保护动作经转换形态触达下游、held-out 封条时序
- 原硬阻断集合回归不降级；审计链含转换标注且不含敏感文件明文

## Counterexamples
- 受保护集合本身封闭且极小（如块设备写目标正则），枚举即等价于类拒绝，无需重构
- 任务只是诊断/解释一次拦截行为，不是实现闸变更：不造类机制
- 类拒绝会重现大规模误伤时（本集 heredoc 形态本体）：对良性大种群用『机械变换+同级内容扫描』放行，整类拒绝只施加于变换路径内部的受保护动作网，不对整个形态类硬拦

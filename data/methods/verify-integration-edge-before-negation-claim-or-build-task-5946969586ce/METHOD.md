## Trigger
准备把『A 不写 B / A 与 B 不相通 / 某机制缺失』写成治理或设计文档的背景事实，或据此创建『补建 A→B 打通/桥接』任务时；且 A 的代码或 B 的数据至少一方可本地检视（例如当前 repo 已被核实为运行时源）。

## Discriminator
写否定断言之前手头已有的两个廉价事实：①B 的账本刚被实测为非空且写入者路径未确认（88 条记录、最新一条就在当天——非空账本+未知写入者本身就是待解未知量）；②本 repo 已被核为运行时源码，调用点检查一次 scoped grep 即可完成。二者任一都能把『通道不存在』这个宽断言缩成『A→B 这条边在代码/数据里是否已存在』这一可一跳验证的未知量。

## Short path
- 遇到待写断言『A 与 B 不相通』→ 先把未知量改写为『A→B 这条边在代码或数据里是否已存在』，不要先问『为什么没生效』
- 数据探针：读 B 实际 store 的 2~3 行，检查是否带只有 A 通道才会写的签名现场字段（如 run_id/attribution）
- 代码探针：scope-grep A 的写入/结算路径对 B 的 record/write API 的调用点
- 命中任一探针 → 断言翻转：边已存在，缺口在别处（本集：真实缺口是 rejected=0 与如实结算纪律）；任务从『实现桥接』改scope为『账本级测试+补缺口』
- 两探针皆空 → 才允许写否定事实，且断言旁附可复跑探针命令（grep 命令/数据行样例）作为 claims
- 用一次真实最小操作触发 A 路径并确认 B 落一行带签名的新记录后停止

## Stop conditions
- 断言方向已被调用点或数据签名任一证据钉死，且写入文档的机制事实均附可复跑探针
- 据断言创建的任务 scope 已按『边存在/不存在』两种结果重写，不再默认『需要新建』

## Verification
- grep 调用点与数据行签名现场指向同一结论（代码边 + 数据现场双证据，防死代码误判）
- 一次最小触发（如结算一条）后 B 账本新增带签名记录，证明该边在当前运行版本真实生效

## Counterexamples
- 断言对象是外部第三方系统（无本地调用点可查）——只能写『未观察到』并标注证据边界，代码探针不适用
- B 是不透明存储且写入口名称未知，两类探针均不可行——断言应标『未核验』而非机制性否定
- 文档明确是时点性观察记录（『截至 D 日未见证据』）而非机制断言，无需先做探针
- 调用点存在但长期无数据现场——可能是死代码，不能仅凭 grep 命中就写『相通』，需运行证据补证

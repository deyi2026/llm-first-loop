## Trigger
拿到一份此前生成的审查结论/修订单/迁移计划，要求按它对多个文件或知识卡做原地修订，且清单中的关键论据是可变事实（数值上限、权限归属、超时常量、受影响条数、规则条款引用），而非纯操作指令。

## Discriminator
修订单自身已标注核查边界或来源缺口（如『本地连接器失败、未读本地最新规则』『清单基于远端镜像，须以本地真值为准』），且每条事实断言都能被一次就地 grep/读当前规则节/查当前工具 schema 证实或证伪——清单过期风险已知且可测，不核验就批量写入会把过期事实（如已废止的上限、已迁移的权限、已消失的常量）复制进多个文件，并让后续 Agent 继续按错误前提操作。

## Short path
- 读修订单，列出每条待执行修订背后的事实断言及其权威来源（规则节、源码常量、工具面 enum、库内实际计数）
- 对每条断言做一次针对性就地核验：读当前本地规则对应节、grep 常量定义位置、查当前工具 schema；未知量：清单是否仍与当前真值一致
- 用目录枚举取得被修订对象的准确全名与路径；不把检索结果里被截断的标题/引用当字面文件名传给命令
- 按核验后的事实做最小原地修订；断言被证伪处按真值改写修订内容（如常量仍在代码中生效→改写语义表述而非删除约束），并把分歧单列：哪条断言、实测是什么、依据在哪
- 写后回读一致，再做一次检索层探针确认卡面不再呈现过期事实；权威源不可达、无法核验的条目降级为待办并报告，不写入

## Stop conditions
- 所有会影响操作方向的断言均已被当前本地权威来源证实或按真值改写，且分歧清单已随交付报告显式给出
- 修订对象写后回读一致，检索探针不再返回以现行口径会误导的旧表述

## Verification
- 每条断言的核验依据可回溯：规则文件行号、源码常量位置与行号、工具 schema 字段名
- 分歧清单条目与实测证据一一对应；交付报告如实声明未执行的下游验收场景与未做的超范围动作（未 push、未改 status 等）

## Counterexamples
- 清单是纯操作指令（改标题、挪目录、统一格式）且不含可变事实断言时，直接执行即可，逐条核验是浪费
- 清单结论是本会话刚基于同一真值生成的（时效性已保证），无需重复核验
- 断言对应的权威源当前全部不可达且无本地镜像可查时，正确动作是搁置批量修订并报告阻塞，而不是按清单盲改

## Trigger
用户要求枚举并风险评估一个代码库中所有程序注入/prompt 生产面（或同型'找齐全部生产者并逐个拷问'的审计任务），且首个内容命中已指向定义相关常量/API 的模块。

## Discriminator
首个命中行本身就是规范文案的定义处（如统一仲裁声明常量所在模块），说明该模块是分类学与渲染 API 的锚点，先读它即可获得枚举符号；同时命中显示的是包内相对路径而非可直读的绝对路径，直接拼仓库根路径会 not-exist。这两个当时可见事实分别把'宽关键词扫全库找线索'缩成'先读定义模块'，把'拼根路径盲读'缩成'先归一化布局再读'。

## Short path
- 把首个精确命中的路径按仓库布局归一化（用已知正确前缀或一次根目录列举确认），读取定义模块；未知量：注入面的分类学与枚举锚点（render 函数名）。
- 读治理/设计文档；未知量：应然面清单、哪些面已有冻结结论可复用。
- 以 render 函数名为精确锚点搜调用点；未知量：实际活跃生产者全集（以代码为准，与文档清单对照）。
- 只读文档未覆盖或触发条件不明的调用点；未知量：各面何时/何频/是否任务相关地注入。
- 若使用委托拷问/评审工具且返回空模板（分节标题下无实质条目），不重试，直接自查；仅对结论直接依赖的具体未知量做定向补读。
- 每个面形成 机制→结构防线→残余风险 的代码级证据后停止并成文。

## Stop conditions
- 调用点集合闭合：活跃 render 调用点均已分类，无未读活跃生产者。
- 每个结论面的触发条件（频次/时机/任务相关性）有代码行级证据，风险结论不再依赖任何未验证的声明文案。

## Verification
- 报告中每个'面'可回指到具体调用点或文档条目，且其防线描述来自触发条件代码而非标签/声明文本。
- 反查 render 调用点清单：不存在报告未分类的活跃生产者。

## Counterexamples
- 注入为分散 ad-hoc 拼接、无中心 render 函数：调用点枚举不完整，应退回对 prompt 组装入口做模式搜索。
- 用户只问某一个具体面：全量枚举是浪费，直接定位该面的定义与触发条件即可。
- 设计文档已过期于代码：文档只能当线索，'活跃全集'必须以代码调用点为准。
- 平铺布局仓库或搜索工具返回绝对路径：路径归一化步骤不必要。
- 委托工具返回实质性非空问题：应作答并继续分层，而非立即改为自查。

## Trigger
跨会话/无活动目标时，用户用模糊症状词询问项目进展、主要问题或是否需要部分重构，且工作区存在索引文档与阶段性结论/冻结文档

## Discriminator
事件流回执已显式给出最近一次写盘的结论产物路径与性质；而按用户措辞去记录库做症状关键词检索（『重构/失败/问题』类）通常空命中——锚点已在手，不需要先做记录库或全目录宽枚举

## Short path
- 读 event_stream：取最近一次产物写入的路径与性质（结论/结果文档），跳过症状关键词的记录库检索
- 直读该最新结论文档：未知量=当前 verdict 与触发失败的条件；收其引用的冻结 spec 与判分器版本
- 读仓库索引文档（README）：未知量=阶段图与在研修复所在目录
- 读在研修复的 spec 与 pilot/notes：未知量=修复机制是什么、推进到哪一步
- 用一次机械命令核实待办产物状态（行数/空列计数/mtime）：未知量=人工环节是否已开始
- 分层作答：执行层以回执完整性（ok/err/dup/哈希一致性）裁决，判分层以冻结诊断条件裁决；重构只圈 FAIL 层，冻结资产不动

## Stop conditions
- 最新结论 verdict + 在研修复机制 + 待办产物机械状态三者齐备，足以回答『哪层不顺/重构什么/下一步』
- 事件流无产物路径可锚时，改用索引文档+目录 mtime 定锚一次，不再回退到症状关键词检索

## Verification
- 每个阶段结论都落到具体文件引用（结果/冻结/spec），无无出处的状态断言
- 『未开始/未跑/未回填』类否定断言须有本 run 的机械统计回执支撑，不据叙述文档推断
- 重构建议不触碰已冻结资产，且不重排冻结文档显式规定的步骤顺序

## Counterexamples
- 事件流被截断只剩 harness 内部事件、无产物路径：锚点不存在，应退回索引文档与目录枚举
- 用户问题指向具体已知子系统（如『CI 为什么红』）：直接定位该子系统，不绕道最新结论文档
- 工作区只有代码、无索引/结论文档：本方法无从锚定，应走源码/测试/日志路径
- 最新结论产物 mtime 已被其他分支或目录反超：以文件系统时间为准换锚，不盲信事件流 recency

## Trigger
宿主/用户发来受管 P0/协调通知：要求结束当前 Run 以释放其持有的锁（下游统一发布被 waiting_for_idle 类空闲门阻塞、有超时 HOLD 风险），可能叠加未闭环质量门（如 R3 P1→禁止发布）与明确非目标（禁继续润色、禁新开 Reviewer/工具循环）。

## Discriminator
通知文本当时已自含三判别事实：(1) 锁可归因于本 Run 且 run 不结束锁不释放——仅此一条即足以把行动集从『继续任务管道』切换为收尾协议；(2) 硬门禁（未闭环 P0/P1→禁发布）决定 checkpoint 中『未发布/被阻断』的标记；(3) 非目标清单圈定禁止分支。三者任一出现即停止任务管道；不得把『收到通知』降级为信息同步而继续润色直至收到更强措辞的第二次通知。

## Short path
- 读通知即分类：『结束请求+锁依赖』=范围终止信号，宣布停止一切编辑与新循环，不等升级版通知
- 登记：未闭环门禁项（如 P1 及其复核材料缺口）、发布依赖的准入闸、验收步骤，连同续接顺序写入 STATUS 待办
- 一次性落盘：稿件/台账/receipts/发布脚本 + task_state checkpoint + 收尾结算一次批量提交
- 用一次合并只读核验确认落盘完整（登记文件逐个存在、机器门禁 PASS 读数、tracked_modified=0），通过即停
- 声明交付物，给出如实终态报告（未发布原因=硬门禁未闭环，注明非能力/故障），正常结束 Run 释放锁

## Stop conditions
- 通知点名的全部保存项已落盘且合并核验逐项通过
- 收尾结算待办=0 或已一次性批量提交
- 无未决外部副作用（子代理全部结算、无平台提交、无后台任务/未决提醒）
- 满足以上即立即结束 Run，不追加润色、复审或任何新工具循环

## Verification
- 合并只读核验输出与通知保存清单逐项对照：文件存在、门禁读数 PASS、tracked_modified=0
- task_state 保存回执含 state_ref/run_generation，checkpoint 文本含未闭环项与续接指引
- 终态报告中的『未完成项』与 STATUS 待办一一对应，未闭环项未被宣称已闭环

## Counterexamples
- 通知仅是状态同步或继续指令、未要求结束 Run → 正常任务管道，不套收尾协议
- 无未闭环硬门禁且通知允许发布 → 走正常发布流程，不得以『还能再润』为由停在未发布
- 下游阻塞锁不可归因于本 Run（另有持有者）→ 关键判别事实不成立，先核实归因再决定是否收尾
- 通知要求取消工具/删除锁/丢弃工作 → 与本协议『不丢弃工作』前提冲突，需另行裁决，不照搬
- 合并核验发现保存项缺失或门禁读数异常 → 不得带病结束，先补齐落盘再退出

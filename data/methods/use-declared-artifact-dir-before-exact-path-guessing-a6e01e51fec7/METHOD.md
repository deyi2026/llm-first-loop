## Trigger
需要读取某类流程产物（回执/admission/清单/发布状态 json），本 run 已读的规范、skill 或 SoT 文档已显式声明该类产物的落盘目录与命名方案，此时正准备对『某个目录 + 产物名』发起精确路径读取或路径猜测

## Discriminator
在手判别事实（满足任二即可缩域）：(a) 已读文档中的显式落盘声明（目录 + 命名方案）；(b) 目录枚举显示该声明目录真实存在；(c) 在手同类路径样例均带同一目录前缀。另有反向佐证：父级目录列表中未见该类产物。三条联合把候选位置从任意层级缩为『声明目录 + 产物名』，父级猜测被在手证据直接证伪

## Short path
- 从已读规范/skill 文档抽取目标产物类的『落盘目录 + 命名方案』声明，解决未知量：这类产物住哪
- 按修改时间枚举声明目录的父目录，定位最新一期 STATUS/台账并读取，解决未知量：本期产物清单及其相对路径
- 候选路径 = 声明目录 + 产物名；对声明目录做一次定向枚举，解决未知量：文件名是否如声明存在
- 枚举命中即精确读取；枚举未见则停止推导，转 search_files 或向用户求证，不再换层级猜路径

## Stop conditions
- 已在声明目录中枚举到目标产物并成功读取，且路径前缀与已读声明一致
- 声明目录为空或目标产物缺失（声明可能过时/迁移）→ 升级 search 或求证，禁止继续同层级换名猜路径

## Verification
- 成功读取路径的前缀与已读声明中的落盘目录逐字一致
- 最新 STATUS/台账引用的产物相对路径解析后落在同一声明目录

## Counterexamples
- 产物类没有任何已读目录声明、也无同类样例（新流程首次产物）→ 猜测+搜索是合法起点，本方法无判别输入
- 同一父目录下多类产物分家（如 STATUS 台账在父级、回执与 admission 在 receipts/ 子目录）→ 目录判别必须逐产物类进行，把一类的目录套给另一类会反向误导
- 规范声明已过时（目录迁移/改名，定向枚举为空）→ 声明不再是真值，应升级求证而非坚持按声明推导

## Trigger
执行通道曾有故障且已预声明止损条件；一次成功调用的回执是确定性修正类报错（原文指明缺失项，如 Content-Type），足以唯一确定下一步命令；随后回合仅产生边界/状态声明、未实际发出任何工具调用。

## Discriminator
两条当时已知事实：(1) 工具回执是修正类报错而非权限失败（'Expected Content-Type: application/json' 而非 unauthorized），说明下一命令已完全确定、不存在需要 agent 继续探索的语义未知量；(2) 本回合输出为仅声明无工具发射，且开局已预声明'同款故障立刻止损转回用户'——第一个无发射回合即已满足移交触发条件，无需连续观察多轮来确认。

## Short path
- 成功调用返回机械性报错 → 由报错原文逐字构造修正后的完整命令（未知量仅剩：修正后是否通过）。
- 发出该命令一次：对刚验证过可用的通道做单次有界重试。
- 若该回合仍为仅声明、无实际工具发射 → 同款故障复发，立即触发预声明的止损条件。
- 执行移交：粘贴精确命令序列并附条件分支（如 probe 显示孤儿锁则跟清理命令、显示活进程则等待），停止 agent 侧重试，等待用户回贴输出后判定收口。

## Stop conditions
- 修正后的命令被实际发出且成功返回 → 通道健康，回到正常流程继续。
- 连续 N（默认 2）个回合仅输出声明、无工具发射 → 立即移交，不再增加重试轮。
- 用户回贴执行输出 → 按预置分支判定结论，任务收口。

## Verification
- 移交的命令端点/请求头与实际观察到的报错逐字对应，无臆造参数或路径。
- 移交内容包含判定分支，使任何一种可能的回贴输出都能直接得出唯一结论。
- 通道复发之后 agent 侧额外消耗的回合数 ≤ N（本应为 2，实际为 8+）。

## Counterexamples
- 剩余动作未被完全确定：probe 输出仍需 agent 做多路语义分支（不同结果对应不同后续端点）→ 提前移交会把判断工作推给用户，应继续 agent 侧尝试或换通道。
- 仅声明的回合携带新信息（错误码/状态在逐轮变化）→ 属诊断线索而非纯通道故障，不适用本方法。
- 用户侧无法执行任何命令 → 移交目标无效，必须寻找替代执行通道而非移交。
- 故障为首次出现、无预声明止损且移交代价高（用户不在线）→ 可再多做一轮诊断性尝试后再决定。

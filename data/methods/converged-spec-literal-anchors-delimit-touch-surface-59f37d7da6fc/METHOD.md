## Trigger
接到实施/续做一个已有成文规格的任务（设计文档中里程碑已立项、需求条目含具体字段/schema/开关/阈值、文档声明裁决点已收敛），需要定位代码修改面时。

## Discriminator
发现阶段当时已可见：规格 grep 回执中含逐字实现锚点（字段名、schema 版本、可选字段/默认行为约束、cap 等数值）和显式 file:line 代码指针，且决策记录节声明全部开放点已收敛——这些事实把'要改哪里'从全库枚举缩成少数 token 命中与被引用区间，任何超出锚点集的继续发现（重读同区间、宽模式 grep）都是无未知量的扩散。

## Short path
- 从 search-miss 回执点名的权威文档中提取：需求全文、里程碑账本（已完成 vs 待办）、决策收敛声明；确认无开放裁决点。
- 汇总规格中的逐字标识符与被引用的 file:line，作为唯一锚点集。
- 仅按锚点 grep 代码并读取命中处定义与调用点，得到闭合的修改面清单。
- 按规格的兼容约束实现（schema frozen、附加可选字段、默认关闭=行为逐字节不变、旧数据读取不报错）。
- 跑单测+集成验证；默认关闭路径与现状一致即停，不再重读已在上下文中的契约。

## Stop conditions
- 规格全文、里程碑账本与收敛声明已在上下文中（发现阶段结束，禁止重读同一 path+range）。
- 锚点 token 的全部代码命中与规格引用区间均已读取，修改面清单闭合，无未解释命中。
- 测试通过且默认关闭行为与现状逐字节一致（或任务等价验收条件满足），立即停止。

## Verification
- 每个规格字面 token 在代码中的命中都能映射到修改面清单中的具体文件/函数，反之修改面每一处都有规格依据。
- 实现与规格约束逐条对照：schema 兼容、默认行为、截断/空值与不可比语义、值不外泄。
- 轨迹中不存在对相同 (path,range) 的重复读取，也没有以宽模式 grep 替代锚点 grep 的步骤。

## Counterexamples
- 规格仍为散文、无逐字标识符，或文档自己标注'待定/待实测校准'等未收敛项——锚点不存在，需常规发现流程且开放点须先裁决再实现。
- 代码已与规格漂移（schema 版本不一致、被引用区间与真实签名不符）——以运行时真实定义为准，规格只当意图说明，须先验证定义面与调用点。
- 全新代码库或无成文规格的探索任务——本方法不适用，属一般 API 发现场景。

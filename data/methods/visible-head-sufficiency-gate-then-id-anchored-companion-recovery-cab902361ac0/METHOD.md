## Trigger
按唯一 ID 检索登记簿（evolution/审批/工单/经验类记录）命中 1 条但正文中途截断，且下一步动作（执行/实施/登记收口）依赖弄清『到底要求做什么』。

## Discriminator
截断点的位置与头部完整性：结论性字段是否已在可见头部完整出现（本集建议句与『不建议改动物理执行面』的排除项齐全，截断落在『背景（…）』括号内列举历史 action_id 处）；且回执携带记录唯一 ID，可作高精度工作区检索锚点。

## Short path
- 按唯一 ID 查登记簿 → 命中但截断；先读可见头部，判断被截掉的是要点还是背景叙事
- 若仅背景被截：以 ID 短串做工作区内容检索并排除发布镜像/制品目录（如 .releases），命中应收敛到个位数
- 直读命中的伴生落盘（经验卡/摘要），取其列出的完整要点清单与背景
- 头部结论句 × 伴生要点清单双源一致 → 判定逐字全文非必需，停止追原文
- 按要点中的符号名对 src/ 等真实源码目录做 scoped 检索定位实施面，进入 TDD
- 仅当要点本身被截断或 ID 检索零伴生：才 grep 检索工具实现找 store 路径常量，按 ID 读原始记录兜底

## Stop conditions
- 实施所需全部要点已由『可见头部 + 伴生落盘』双源一致覆盖
- 伴生落盘与可见头部矛盾或明显过期 → 停用双源结论，转原始记录逐字核验

## Verification
- 伴生落盘中引用的记录 ID 与回执命中的 ID 一致
- 实施与验证面覆盖伴生落盘列出的每一条要点，而非仅头部可见的那部分
- 最终登记/收口时如实注明：正文为双源拼合、未取得逐字全文（若有披露要求）

## Counterexamples
- 截断砍掉的是验收标准、危险操作参数或需逐字引用的条款：『大意完整』不授权跳过全文，必须回原始记录
- ID 短串只命中发布镜像里的陈旧副本、排除镜像后零伴生：双源缺一，须走工具实现→store 兜底路径
- 回执是未命中/404 而非命中截断：那是『记录在哪』的定位问题，应先走精确标识符内容检索分流
- 伴生落盘可能滞后于现状（建议已被部分实施）：仍须做单据×部署 delta 比对，双源一致不能替代已实施检查

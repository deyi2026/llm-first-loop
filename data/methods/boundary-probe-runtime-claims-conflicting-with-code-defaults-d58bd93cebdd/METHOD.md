## Trigger
委派子代理或二手来源给出关于运行态是否开启/生效的断言（认证开关、防护启用、通道放行），且手中已读过相关模块源码的默认/激活逻辑，断言即将写入审查结论或报告

## Discriminator
断言依据（仅静态配置读法：键被注释或缺失）与已读代码事实（模块默认逻辑为暴露即强制开启/fail-closed）是否矛盾——矛盾即判定静态读法不可单独作数，触发一次边界探针；无矛盾且低危才归入普通抽验批次

## Short path
- 对每条委派结论先二分：代码结构断言（重读代码即可裁决）vs 运行态断言（需触达真实决策边界）
- 运行态断言对照已读源码默认/激活逻辑：一致或低危 → 记入待核清单，不立即展开新动作
- 矛盾 → 构造一次打在默认翻转条件上的最小探针（如伪造公网式 Host 头请求），按回执一次裁决（拒绝=开启，放行=关闭）
- 防护可绕过/拦截类断言：在进程内直接调用判定函数，输入恶意构造并带正对照（已知被拦输入仍 BLOCK），不执行真实载荷
- 按实测改写结论，报告中保留静态读法与实测差异作为证据；探针不可安全执行时停在代码路径可达性并标注未实机验证

## Stop conditions
- 探针属破坏性或对外非幂等动作（真删除、真外发、真实审批）→ 禁止实做，降级为判定函数级验证或代码可达性分析
- 断言纯为代码内部结构、无运行态成分 → 重读代码即止，不发探针
- 无可达服务且配置由部署环境注入 → 标注 unverified，不写成确定性结论

## Verification
- 探针回执与代码默认逻辑自洽：公网式请求被拒、可信本机路径行为不同，形成天然对照
- 判定函数实测带正对照，证明测到的是活防护而非空壳调用
- 被改写结论在最终交付物中注明实测证据形态（探针/函数调用），未实测项单列假设区

## Counterexamples
- 『函数 X 缺少校验』属代码结构断言：正确动作是重读该函数，发 HTTP 探针无信息量
- 代码无默认开启逻辑、配置完全由部署环境注入时，静态配置读法可能就是真值：先确认加载链再探
- 目标为远程或不可达环境 → 只能代码级推断并如实标注，不得以本地行为代替远端事实
- 探针会触发真实告警/审计等对外副作用 → 不做，改读判定与审计代码

## Trigger
用户要求把定时/周期唤醒任务（schedule/recurring wake）的执行参数（如所用 LLM 模型、成本档）改为 X，而该参数未出现在任务名或注册信息中；需要先决定改动落在哪一层

## Discriminator
排程工具 schema 是否含该参数字段，以及模型目录回执是否标注唤醒会话为『默认装配』。schema 无该字段且唤醒另开新会话 ⇒ 不存在可编辑的任务级参数配置，唯一持久改动面=已存消息文本；消息不可原地修改 ⇒ 只能 cancel+recreate（换代重注），且指令必须自包含（含运行时验证门，因唤醒会话看不到本次对话上下文）

## Short path
- 先读排程工具 schema（+模型目录回执），一步裁决参数所在层：注册字段/消息载荷/会话默认装配；不做全库『配置在哪』的宽搜索
- 由最新台账或排程状态枚举该类任务的现役代，确认用户所说『全部』的边界与各条目剩余次数
- 取当前代注册消息原文（注册回执或数据备份）
- 构造新消息=自包含指令头（到点第一步切换参数、以运行时回执确认后才干活、失败即停上报）+原文逐字保留；先取消再新建避免瞬间双跑，剩余次数折算进新条目，选两次触发之间的窗口执行
- 回执验证（新 sid 齐、尾部逐字比对、次数守恒）后在该类任务必读的台账留注，停止

## Stop conditions
- 新条目回执齐备、消息尾部与原文逐字一致（sha 比对）、剩余次数折算守恒、且在下一次触发前的窗口内完成
- 若 schema 已含该参数字段或存在保 sid 的升级工具（如 schedule_upgrade）：改走字段级路径，停止重注
- 若运行时无参数切换工具或目标模型不在目录：停下如实上报，不注册每次唤醒都会失败的条目

## Verification
- schedule 回执显示旧 sid 全部取消、新 sid 全部创建成功
- 新消息尾部与原消息逐字比对（sha 指纹）一致，仅前置指令头
- 各条目剩余次数之和与旧账折算一致，未越授权预算
- 目标模型在模型目录中确切存在且与用户点名一致（区分同名 -Preview 等变体）并在汇报中说明选择

## Counterexamples
- 排程 schema 本身含 model 字段或提供保 sid 的升级工具 → 直接改字段/升级，不做消息头重注
- wake=true 的同会话一次性续跑 → 会话上下文仍在，会话内直接切换参数即可，无需指令头
- 用户要的是全局默认模型（所有任务都换）→ 改默认装配配置，而非逐任务重注
- 运行时没有 switch_model 类工具或目标模型未登记 → 指令头不可执行，应停下上报而非注册必然失败的任务

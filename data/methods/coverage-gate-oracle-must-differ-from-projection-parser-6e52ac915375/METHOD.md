## Trigger
为派生索引/投影（规则索引、安装简报、生成清单）设计或评审『必须覆盖 SoT 全集』类覆盖率/完整性断言时，投影选择逻辑本身依赖某种格式解析（正则、ID 后缀、字段名、切片、白名单）。

## Discriminator
分母的计算机制是否与投影选择器同源。本集当时已可见的判别事实：SoT 条目同时具有两个结构不同的可数不变量（`^## 规则` 标题行计数 vs `（RULE-AI-xx` ID 后缀正则）——若『覆盖率 36/36』的分母也复用 `_RULE_RE` 同源解析器，格式漂移时两边漏同一条，断言恒绿，门禁形同虚设；独立 oracle 就在眼前却未被 v1 方案使用。

## Short path
- 读投影实现，确定索引条目如何从 SoT 选出：选择器依赖什么格式（正则/ID 后缀/ordered 切片/核心 ID 列表）
- 写覆盖率断言前先回答『分母由谁计算』；若与选择器同源（同 import、同正则、同格式约定），判为设计缺陷而非实现细节
- 用结构上不同的第二解析器（如数标题行、不依赖 ID 后缀格式）求期望集合，与投影实际 ID 集合做集合差，差非空即红
- 对同一源码里其他静默丢失通道重复该审计：静默切片截断→显式『另有 N 条未列入』标记且截断即红；排除白名单→硬上限+举证责任反转（为何模型不需知道其存在，而非为何不适用）
- 变异实测每条通道：删一条标题行/改 ID 后缀格式/造超限条目，门禁必须红；全通道可红即停

## Stop conditions
- 分母 oracle 与投影选择器已确认结构独立，且两集合差为空（实测，非推断）
- 解析漏配、静默截断、排除清单三类丢失通道均有可观测红灯路径并经变异实测确认

## Verification
- 删掉 SoT 中任意一条规则的标题行或改动 ID 后缀格式 → 覆盖门禁必须红
- 造第 N+1 条超限条目 → 显式截断标记出现且覆盖率断言红
- 若投影是无选择逻辑的逐字节复制，确认字节相等断言本身已构成独立 oracle，无需第二解析器

## Counterexamples
- 投影是 SoT 逐字节复制、无任何选择逻辑：不存在共享解析器，字节相等即可满足
- SoT 没有第二个可靠结构不变量（标题手写、格式不规则）：应建权威 ID 登记表作 oracle，而不是再造一个脆弱正则去数另一个格式
- 门禁验证的是行为效果（规则是否被遵守）而非覆盖完整性：需要运行时探针，第二解析器无意义

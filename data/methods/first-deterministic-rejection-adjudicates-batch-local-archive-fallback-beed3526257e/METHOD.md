## Trigger
向共享远端推送 ref（tag/branch，典型为归档既有历史提交）被准入/安全硬闸拒签，且拒收回执点名具体内容属性（某路径/敏感规则命中）而非瞬时错误；或同批多个候选正待逐一推送、首个已被拒

## Discriminator
拒收回执是否给出内容命名的确定性原因（具体路径/规则，可复现），且被拒 payload 是否不可变（tag 指向既有提交、内容无法在不重写历史下改变）、或同批剩余候选是否与首拒共享同一确定性属性——三者成立时首个拒签即裁决整批，之后每次同类推送都是零信息重复

## Short path
- 首个拒签回执到手：分类'确定性内容原因（点名路径/规则）' vs '瞬时错误（5xx/限流/超时）'——解决未知量：重试是否有意义
- 判 payload 可变性：被拒对象指向不可变历史（既有提交）→ 内容无法靠重试改变；同批其余候选共享首拒属性 → 首签即裁决整批，停止逐个推送
- 若为可变新内容（自己新写、可修）→ 修/改名/脱敏后单次重推；若不可变 → 不发起第 3 次同类推送
- 完成本地零丢失归档：本地 tag ＋ git bundle 并 verify 通过，清单落盘
- 上报并停止：闸名、点名原因、本地保留物、用户侧替代路径（UI 建 tag / 走审批/白名单），不尝试绕行硬闸

## Stop conditions
- 拒签原因为确定性内容属性且 payload 不可变：最多 1 次复核后停止全部同类推送尝试
- 本地归档产物 verify 通过且清单齐备：停止动作，进入上报
- 拒签给出正规替代通道（审批流/允许的 ref 命名空间/保护规则要求 PR）：改走该通道，而非继续重试或规避

## Verification
- 重读首个拒签回执：原因是否点名具体路径/规则（确定性），排除 5xx/二级限流/超时（瞬时）后再决定停或重试
- git bundle verify <bundle> 退出码 0；本地 git tag -l 覆盖全部预期归档 tag
- 远端状态核对：无半推残留（目标 tag 未创建、既有分支未被改动）
- 台账核对同类拒签次数 ≤2：超过即视为方法失效信号

## Counterexamples
- 瞬时失败（HTTP 5xx、二级限流、网络超时）：重试/退避才是正确动作，本方法不适用
- 拒签指向可变新内容（如自己新推文件真含敏感信息）：正确分支是修内容后重推，而非放弃远程并只做本地归档
- 保护规则本身给出替代机制（分支保护要求走 PR、闸门提供审批/白名单流程）：换机制是合法路径选择，不属无效重试
- 单候选一次性被拒、无同批共享属性：没有可被'首签裁决'的整批，逐案判断即可

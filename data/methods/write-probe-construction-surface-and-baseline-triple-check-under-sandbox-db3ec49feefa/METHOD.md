## Trigger
沙箱/受限执行环境中承接需要修改代码的任务，且首个命令回执已带权限作用域横幅（如『仅允许写工作区与缓存目录』），或任务文档已声明 execute 处于沙箱内，而任务点名的代码根可能落在可写集之外

## Discriminator
任意一条命令回执上的沙箱横幅已明示可写集合，且更早的文件读取回执已给出可写工作区根路径——两者在深入枚举仓库结构、规划子代理委派之前就已可见；touch 探针在点名根被拒、在工作区通过，即可一跳定死施工面

## Short path
- 从设计书/任务记录提取点名的代码根，并确认文档是否声明执行受沙箱限制
- 读任一命令回执的权限横幅，推出可写集合及其已知根路径（来自更早回执的工作区路径）
- 先于结构枚举与子代理委派，跑一次写探针：在点名根 touch（预期拒）+ 在可写根 touch（预期成）
- 若点名根只读：在可写根下建隔离克隆作施工面，基线取主干 HEAD
- 三方一致性核验：施工面基线 == 主干 HEAD == 运行时部署版本指针（如 restart/code_root），不一致先上报
- 之后才做门禁/venv/测试入口等结构发现，并让子代理带足量工具白名单指向已核施工面

## Stop conditions
- 探针显示点名根本身可写 → 原地建分支/worktree 施工，撤销克隆步骤
- 任务为只读分析/评审 → 不设施工面，跳过探针
- 基线三方不一致（主干≠部署版）→ 施工面选择升级为用户决策点，先问再动工

## Verification
- 任何 edit 类动作发生前，两条 touch 探针回执（根拒绝/可写根通过）已入档
- git -C 施工面 rev-parse HEAD == 主干 HEAD == 运行时部署 SHA
- 开发子代理首次写入施工面成功，无权限类失败回执

## Counterexamples
- 点名代码根可写（探针通过）时克隆反而引入漂移风险，应原地施工
- 纯阅读/评审任务，探针与施工面设置是纯开销
- 沙箱只隔离网络不限文件路径时，横幅对可写路径无信息量，只能依赖探针本身
- 用户明确指定在特定分支施工且不关心部署版本时，三方核验退化为对齐该分支

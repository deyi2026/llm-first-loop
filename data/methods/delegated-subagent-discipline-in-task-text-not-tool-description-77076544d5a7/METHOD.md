## Trigger
委派/spawn 的子代理任务流中，某个要求自主发起的行为（如方法论检索、预写验证）在多个 run 中持续不触发（如 0/17），而含该纪律句的工具描述对子代理可见——即『描述可见但行为缺失』的实测事实。

## Discriminator
行为触发率与指令位置强相关：同一纪律措辞放在工具描述→0/17 触发；同一句话作为任务文本最后一行→3/3 首调触发。判别事实是『子代理首动作跟随任务末行而非工具描述』，因此行为类必须执行的纪律应放在任务文本末行，工具描述只适合调用该工具时才被查阅的参数性契约。

## Short path
- 先量化不合规：统计 N 个委派任务中目标行为零触发的比例与成本（tokens/调用数），确认是位置问题而非任务本身不需要
- 把纪律压成一行、追加为委派任务文本的最后一行；模板级实现，父任务已含等价标记（如 kind=method）则不重复追加
- 单变量重跑对照：唯一自变量=该行的位置，核对首动作合规率（如首调 kind=method）与成本增量
- 合规恢复且成本可接受→固化进委派模板并补模板用例；若目标行为本就天然高频→该行降级为可选而非全局强制

## Stop conditions
- 子代理首动作已按纪律执行，且行为与成本两维判定已完成（机制触发、任务收益分开裁决）
- 发现该纪律可由程序机制强制（schema 校验/guard/hook）时，停止在提示词层解决，改用机械防线
- 父任务文本已携带等价纪律标记，追加只会造成重复

## Verification
- 单变量对照：除指令位置外其余条件冻结，比较触发率（对照本集量级 0/17→3/3）与每场景 tokens/调用数
- 成本对账双侧记录：有适用卡时应行为+成本双改善；无适用卡时记录可接受的固定开销（约 +1 调用/+10-16k tokens）
- 模板去重逻辑有测试覆盖：父任务已含标记时不二次追加

## Counterexamples
- 子代理对目标行为已天然执行（如本集场景 B 首次检索即命中）：强制加行只有 +1 调用/+10-16k 的纯开销，不应全局注入
- 纪律属于工具参数正确性/机械约束：应放工具 schema 或程序校验；工具描述在这类调用时会被真正查阅，是正确位置
- 没有任何不合规测量就预防性加纪律行：每行都摊进所有委派任务的 token 成本，无测量不加注
- 纪律需要逐案语义判断而非固定措辞：一行静态提示覆盖不了，需 runtime 注入或按需水合，不适用本方法

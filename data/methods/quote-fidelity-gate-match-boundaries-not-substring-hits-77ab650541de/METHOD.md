## Trigger
稿件含逐字引用第一手原文的句子或数字（以 blockquote 或行内 code 标记），需要机械核验引文保真后再定稿或派发独立审读

## Discriminator
核验回执里 grep 带回的上下文行已包含引文在原文中的真实边界（句末标点、"(Figure N)"、起始词如 "So the…"）；稿件引文若结束在真边界之前，子串仍命中——回执本身已含判别信息，只是没被比对。第二判别事实：逐字引用的载体不止 blockquote，行内 code 同样是引文结构，只扫一类标记必然漏段（本集 18 段→53 段）。

## Short path
- 先落盘完整原文副本并确认抓取完整（总字符已知，非分段读取）
- 按结构而非按标记类抽取全部逐字引用候选：blockquote＋行内 code 中 ≥6 个连续英文单词
- 每条候选带上下文 grep 原文完整句，比对两端边界：起始词、句末标点、图表编号、引号形式逐字一致才算通过
- 数值断言做集合闭合：枚举原文全部同类数值（如所有百分比=9 个数据点），验证稿件数值集合是其子集
- "原文说/原文自述"类归属断言：对完整副本 grep 特征 token，零命中即红旗（该节可能整段来自二手稿）
- 机械层全部闭合后，才把 grep 做不到的语义维度（归属、转述 vs 直引、虚构）派给独立审读

## Stop conditions
- 结构抽取的引文候选边界逐条一致、数值集合闭合、负存在性检查无红旗
- 剩余问题只属于语义/归属维度，机械闸已无法进一步区分

## Verification
- 对比抽取器加宽前后的覆盖段数（如 18→53），确认候选面 ≥ 稿件全部逐字引用
- 对每条命中回执的上下文行与稿件引文做两端字符级比对，而非只看 HIT 标志
- 以独立审读轮不再报引文保真类 P1/P2 作为闸门有效性的外部校验

## Counterexamples
- 稿件全部为转述、无逐字引文：子串闸不适用，直接语义审读
- 引文由程序从原文切片生成且未经人工编辑：边界风险低，抽查即可，不必建抽取器
- 原文极短（数千字符）：直接全文 diff 比建抽取器便宜
- 带省略号的合法节选会呈现"边界不一致"假象：先识别省略标记再比对，不要一律判失真

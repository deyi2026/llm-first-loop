## Trigger
评测量表的结构性矛盾已被诊断确认、用户已选定修复方向且要求两侧能力都可测；判据侧（或矛盾任一侧）代码属他会话未提交 WIP 或其它无编辑权的在途改动，状态回执明示未获指令不动

## Discriminator
矛盾两侧是可独立寻址、由跑批器逐题组装的 artifact（题面 JSON 与判据注册表分离）；git status 显示判据文件混在多关注点未提交 WIP 中（无权改）；定点读现成通用判据实现确认参数（must_contain/any_of 等）足以承载纯文本门；读 run_one_sample 确认行为轨是真实引擎+样本级临时隔离。四者齐备即可零编辑重组两轨

## Short path
- 恢复状态回执：钉住权威 worktree、WIP 所有权约束、镜像未合事实；后续发现只在该 worktree 内做，不做全库宽搜索
- 一次 git status+diffstat：确认外来 WIP 仍在、关注点混合、无权改
- 单脚本枚举 题面×判据×禁令标记：量化矛盾结构（多少题禁令 vs 多少行为门）
- 动手前两次定点读源码验证可组合性：(a) 现成参数化判据可零新代码承载知识轨文本门；(b) 跑批器真实执行引擎且样本级隔离——行为轨可测真实工具调用
- 新增版本目录实现双轨：行为轨=去禁令的行动型新题面，引用 WIP 判据原样；知识轨=原题面原样+参数化文本门；WIP 文件 diff 保持为零
- 每轨先模拟 trace 夹具（含负例：乱序/盲重试/缺门），再每轨 1 题最小真实烟测；文本锚点措辞与真实作答不符→放宽变体并正反双向复验（错误作答仍被拒）
- 全量跑批放行、需真实副作用的题（服务 mutation/restart）、WIP 提交归属——升格为显式用户决策点，不自行放行

## Stop conditions
- 两轨烟测均通过（同模型同判据，题面自洽后通过率翻转）且外来 WIP 文件零改动
- 发现某题判据要求真实危险副作用即停该题，交用户裁决或加 stub
- 复用前提断裂（WIP 被所有者撤走/冲突、无可参数化判据可用）→ 停下改设计或升格，不硬凑

## Verification
- 模拟 trace 正负例双向过门（负例必须被拒）
- 每轨至少 1 题真实小样本烟测，对照首跑同题失败签名
- 放宽后的知识门仍拒错误作答样本（负例复验不变）
- git status 复查：外来 WIP 文件内容未变

## Counterexamples
- 矛盾在单一 artifact 内部（判据逻辑自身 bug）→ 重组题面救不了，必须改代码
- 不存在可参数化的现成文本门 → 知识轨需新写判据，勿为复用硬凑
- 题面需与历史基线逐字可比 → 改题面本身破坏可比性，须用户显式接受该权衡
- 只需单轨结论 → 不为对称性造第二轨、双倍样本预算

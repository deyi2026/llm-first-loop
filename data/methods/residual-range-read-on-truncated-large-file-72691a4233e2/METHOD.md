## Trigger
read_file/检索回执声明文件总行数（如 共658行），但实际可见内容在更早处结束（如 592 行），且任务仍需要缺失部分——典型场景是待编辑文档的尾部/附录尚未确认。

## Discriminator
回执的声明总量与已见内容末端之差给出精确残差（本集：658−592 → 593–658，约1900字符）；且当时已知全部9处patch落点（§6.1–§13）都位于已见区间内，因此任何中段重读（如 start=140, limit=560 的519行请求）不会产生新事实，只是重复已知内容并再次触发截断。这两个数在首次读取回执后即可计算，无需等第三次读取。

## Short path
- 按 edit 契约先做全文快照读取；读后立即记录两个数：回执声明总行数、实际最后可信可见行。
- 两者不等则计算残差区间，只对残差发起一次读取（起点≈可见末端−5行锚点，limit=残差长度），不做中段重叠重读。
- 用回执 range(start/count/complete) 与返回内容首末行验证：已见区间∪残差 == 声明总量，无缺口。
- 覆盖闭合后停止一切发现类读取，直接进入计划中的编辑/动作阶段（后续动作沿用快照链校验）。

## Stop conditions
- 已见区间∪残差读取结果==声明总量、覆盖无缺口 → 发现阶段结束。
- 回执缺少可信的声明总量或无对账依据 → 先审计内容实际末端再判断，不能盲算残差。

## Verification
- 残差读取回执满足：start 不晚于缺口起点、start+count ≥ 声明总量、complete=true，且内容首末行与缺口边界吻合（本集：start=588, count=71, complete=true）。
- 若后续是编辑类动作：每次写入后复读/回执一致（本集11处原子编辑均写后复读校验）。

## Counterexamples
- 未知量位置不局部化：目标事实可能位于全文件任意处（事实查找/审计类任务）→ 残差法不适用，应走搜索或分块发现。
- 早期内容已被上下文驱逐，或任务需要重新定位中段章节 → 重读已知区间属于上下文刷新，不是冗余枚举。
- 回执声明与内容矛盾且无截断标记（头部声称已显示全文但内容被静默剪断）→ 需先做一次输入显著改变的诊断性读取确认可见末端，才能计算残差，不能直接信任头部声明。

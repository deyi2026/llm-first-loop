## Trigger
审查回执、事后审计或二手讨论文档对某门禁/执法代码的发现给出较轻严重度定性（如『仅打印告警』『不阻断』），且明确点名执法脚本文件；或正在决定是否修复此类『仅告警级』发现、如何排序

## Discriminator
回执本身已给两个当时即可用的事实：①执法脚本确切文件名（一跳直读可达，无需先做文档面宽搜索）；②行为摘录写明『打 ⚠️ 后不阻断』——『不阻断』≠『不污染凭据』，后者只能在控制流终点（最终结论行/exit code）处核实，这正是轻量定性可能失真的位置

## Short path
- 读回执，列出各发现及其定性标签；未知量：哪些定性依赖对代码行为的断言？
- 对定性较轻且点名了代码文件的发现，跳过文档面宽搜索，直读该脚本相关分支直到最终结论输出；未知量：降级路径是否改变外部凭据？
- 若降级放行与干净通过共享同一无条件成功凭据（同 exit 0＋同 ✅ 结论行）→ 判定凭据混叠、严重度上调；未知量：影响面有哪些？
- 回溯所有引用该凭据的既有结论（含自己上一轮的话，如『连续 N 次 success』），逐一标注未核验前提；未知量：修正建议的形态与成本？
- 给出修正方向：保开放行、让凭据可区分（区分性结论行＋首轮红清单落盘供下游拒引），并附验收方案（桩注入构造降级场景，不真实复现抖动）

## Stop conditions
- 已确认降级路径最终结论输出与干净通过可区分（定性成立），或不可区分（已上调严重度、回溯标注引用、给出可区分性修正与验收方案）
- 执法代码不可直读（需 CI 运行日志而本地无凭据）时，改为按流水线记录面量化混叠通道被走过的次数后停止，不臆断

## Verification
- 逐行核对降级分支到脚本末尾：⚠️ 之后确无区分性 exit/结论行，才认定混叠
- 检查下游消费面（发布资格、release 流程等）是否把该结论行/exit code 当凭据引用
- 修正后验收：用注入桩构造『serial 绿＋并行首轮红＋复跑绿』场景，确认输出不再与干净绿相同

## Counterexamples
- 降级路径本就有区分性终态（不同 exit code 或独立结论行/产物）——回执『仅告警』定性成立，无需上调
- 告警纯属日志格式/提示，不进入任何下游凭据链——无混叠面，不必开修复线
- 抖动检出率极低而缺陷代价高、且有廉价复跑手段时，硬阻断可能优于仅区分——『只区分不阻断』不是普适结论
- 主源只有运行时行为（需真实 CI 日志）时，静态读代码判不了通道是否被实际走过，须另行量化而非推断

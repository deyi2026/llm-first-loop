## Trigger
browser 语义快照回执被截断（complete:false/输出截断），可见前缀由编辑器工具栏等 UI chrome 同质对象占据，而本轮真正要操作的控件（标题输入、正文区、上传/提交按钮）不在可见前缀内；页面属于复杂 SPA 编辑器或后台类界面。

## Discriminator
第一次快照回执就已同时给出两个可观察事实：(a) 截断标记且前缀全是与目标无关的 toolbar 按钮类对象；(b) 随后一次仅换过滤参数的快照返回了相同前缀（同样对象、同样顺序）——证明调整枚举参数不改变返回内容排序，继续全量枚举不会暴露目标控件。另外用户上下文本身已提示『历史已验证平台上传可用某工具』，说明存在可优先复用的已验证机制线索。

## Short path
- 读第一次快照回执即判断『截断 + chrome 前缀 + 目标不在前缀』→ 放弃第二次全量快照重试
- 把任务拆成具体未知量（标题框在哪、正文编辑区在哪、发布/上传按钮在哪），对每个未知量用 name/role 谓词定向查询单个对象，而非枚举整页对象
- 若谓词未命中或工具不支持，检索经验库中该平台/该编辑器类型的已验证选择器与锚点（如精确选择器、行尾锚点）并按其操作；无历史经验则跳过此步
- 对锁定的单对象执行语义操作，读 delta/diff 回执确认对象指向正确且 world_version 前进
- 仅当谓词查询与历史选择器都失败时，才做有界 range 分页读取（利用 next_start 逐段），读到目标即停，不做整页全读

## Stop conditions
- 目标控件已唯一锁定并收到成功的操作 delta 回执，停止该页任何进一步枚举
- 谓词查询与已验证选择器均证明当前页面不存在目标控件（转入换页/换流程分支），不再对该页重复快照

## Verification
- 操作回执的 delta 指向预期对象、scope 未漂移、world_version 前进
- 对结果只做 scoped 状态复查（查该对象属性），不用全量快照复查
- 最终用户可见结果（如正文/图片入站）通过定向回读目标元素验证，而非整页对象枚举

## Counterexamples
- 简单页面一次快照即完整覆盖且含目标控件 → 直接使用该快照，不引入谓词查询或历史检索
- 目标就在分页第 2-3 段且 range 读取便宜 → 有界分页一次读取即可，本方法的『先查历史选择器』反而绕远
- 全新平台无任何历史经验且控件无稳定 name/role → 谓词与经验库都不可用，应做一次有界 DOM 探查，本方法不适用

## Trigger
工具回执自报成功产物落在某文件系统路径（常为相对路径、位于本会话任何工作区枚举输出中从未出现的目录），回执同时声明另一套检索契约（如按 key 查询归档恢复），而下一步计划是沿该路径追加/写入，或把该路径当作后续会话的可读入口。

## Discriminator
三点在写穿前即可见：(1) 回执自报路径是相对路径，而本会话所有已确认的工作区操作均使用绝对路径；(2) 该目录从未出现在任何先前的枚举/回执输出中，工具后端是否落到共享工作区未经验证；(3) 回执自己声明的恢复方式是按检索 key 查询其归档——即声明的契约才是访问通道。若已写穿且 shell 对精确路径返回 ENOENT，这是权威不存在信号，不是换工具再搜一遍的线索。

## Short path
- 收到回执后，未知量=『产物是否真的落在我可控的工作区文件系统』；对回执精确路径做一次存在性/身份检查（ls -l 或 test -f），不先写穿。
- 存在且身份匹配→可沿路径追加；不存在或首次写穿即 ENOENT→判定该归档为外部/虚拟存储，立即停止对该路径的进一步搜索（不再叠加第二类存在性探测）。
- 把继任者必读的权威补充内容写到工作区固定、可检索的位置（如 docs/ 下带时间戳的交接文件），写后用 ls 确认尺寸与 mtime。
- 在权威状态记录（task-state/交接真值源）中同时写入两个入口：回执的检索 key 与实际落盘路径，使后继会话任一路径可达。

## Stop conditions
- 最终落盘产物的绝对路径与身份（size/mtime）已确认，且被权威状态记录引用。
- 对回执自报路径的探测以一次为限；得到 ENOENT 后不再发起第二类存在性搜索。

## Verification
- 写后 ls/stat 最终文件，确认非空且时间戳属于本次写入。
- 复核权威交接记录同时含检索 key 与实际路径两个入口，任一后继路径可独立恢复关键事实。

## Counterexamples
- 回执路径为绝对路径且位于先前已枚举确认的工作区目录（普通写文件工具、后端就是共享文件系统）→ 直接操作即可，先探反而多余。
- 回执已给出稳定检索句柄且后继恢复流程本就走该句柄（路径缺失不影响继任者取回内容）→ 无需落盘副本，把 key 写进交接即可。
- 路径缺失源于已知异步落盘延迟且有明确收敛时限 → 有界重查一次是正当动作，不能立即判为外部存储而放弃该路径。

## Trigger
需要核验由本任务自己脚本生成的图表/版式产物（PNG/PDF/HTML）中文字是否重叠、溢出、截断，且已确认某处失败源于坐标/尺寸等数值计算（如 x 坐标算错），或多轮目视对同一确定性产物给出互相矛盾的裁决。

## Discriminator
当时已知事实：图形由自己的 Python 脚本逐坐标生成（生成命令在 trace 中可见），且首例失败已被承认为『x 坐标算错』的算术错误——几何真值可在本地用字体度量精确算出；同时目视裁决已出现矛盾（对 fig8 的检查报告所称元素根本不存在；fig6 先判底部截断、修复加高后又被判标签严重重叠）。这些事实足以把『继续目视』判定为噪声通道：确定性代码产物的精确版式问题应由生成侧度量裁决，而非反复感知。

## Short path
- 脚本出图后先做一次目视粗检，只回答一个未知量：是否存在明显版式问题。
- 一旦确认问题根源是坐标/尺寸算术错误，或目视裁决开始互相矛盾，立即停止『改→再目视』循环；未知量改为：哪些文本元素超界、超多少。
- 在生成代码旁写字体度量校验，对每个文本元素输出 width vs limit 的 OK/OVER 清单。
- 只修复度量证实超界的条目（缩短文案/换行/加宽卡片/加高画布），重新生成并重跑同一校验脚本。
- 全部 OK 后做一次最终目视粗检，确认无度量盲区（遮挡/乱码/字体回退），停止。

## Stop conditions
- 度量校验对全部受检文本返回界内（width ≤ limit），且图像保存回执正常。
- 修复后重跑同一度量脚本全 OK；目视仅做一次终检，不再因『贴边/略重叠』类描述做额外重生成。
- 目视新指认的问题经度量证实界内时，判定为假阳性并忽略，不据此修改。

## Verification
- 度量校验输出逐条含元素名、width、limit 与 OK/OVER，覆盖此前所有出问题的及相邻元素（正文各行、标签、底部说明行）。
- 修复后用同一脚本复测全 OK 才声明通过；最终目视只确认度量覆盖不到的异常（乱码、字形回退、遮挡）。
- 目视结论与度量冲突时，以度量为裁决并记录该冲突，作为感知通道不可靠的后续证据。

## Counterexamples
- 产物不是自己代码生成的（用户截图、扫描件、第三方图片）——没有字体度量可达的真值，多轮目视/OCR 是唯一通道，不应套用。
- 待验证属性本质是感知/语义的（配色是否协调、图是否传达信息、美观度）——字体度量无法裁决。
- 生成管线不可插桩（闭源二进制工具、拿不到布局内部量），无法做程序化度量。
- 单次目视已给出与代码事实一致、明确可执行的结论（如整段明显溢出）——直接修即可，无需先建度量脚本。

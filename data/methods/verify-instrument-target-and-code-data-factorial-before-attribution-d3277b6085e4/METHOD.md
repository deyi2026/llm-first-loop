## Trigger
准备声称或采纳'指标提升来自某代码机制'的结论（评测/基准/检索质量对比），而量具经外部解释器、venv 或独立进程运行，仓库又存在部署快照镜像或多份同名源码副本，import 解析未经验证

## Discriminator
量具调用行（哪个解释器、何种环境变量）与仓库布局（工作树 src/ 与快照镜像并存）在归因之前均已可见：一条 import 解析检查（python -c 'import pkg; print(pkg.__file__)'，或在解析出的源码 grep 新字段名）即可判定量具是否真的在测含改动的代码；缺失这一步的 before/after 对不支撑机制归因

## Short path
- 未知量：量具到底加载哪份代码？在量具同一调用方式（同 venv/命令行/环境）下解析 import 目标；若落在快照/部署镜像，用 PYTHONPATH 或绝对路径钉住工作树后重跑
- 未知量：增量是否在含改动的代码下复现？钉住后重跑基线组与改动组
- 未知量：增量属于代码轴还是数据轴？跑 {旧代码,新代码}×{旧数据,新数据} 因子交叉
- 代码轴逐位不变 ⇒ 撤回机制归因，改报'数据/文本经普通通道索引，机制未验证'；停止一切以该机制声明为前提的后续建设
- 把钉住动作固化为量具自检（eval 启动断言模块 __file__ 位于目标树下），防止下轮再测错对象

## Stop conditions
- import 目标已钉住、因子交叉已定位增量所在轴、对外结论与轴证据一致
- 量具无法钉住目标树（解析被部署机制接管）时，停止测机制差异，先修量具本身
- 撤回声明后，被推翻的机制结论不得再被下游计划当作前提引用

## Verification
- 解析回执中 __file__ 指向含改动的树，或在该源码中能 grep 到新字段/新分支
- 2×2 表中代码轴两行（同数据不同代码）逐位一致 ⇔ 机制贡献为零；任何机制声明必须伴随代码轴上的可观测差异
- 重跑一次钉住后的量具，确认旧数字出自快照口径并已在结论中显式更正

## Counterexamples
- 进程内 pytest/评测已强制 src 布局、import 无歧义：跳过解析检查，固定数据上单次前后对比即可支撑归因
- 纯数据改动（只新增卡片/文档文本，无代码路径变化）：没有代码轴可交叉，从一开始就不得做机制归因
- 只为决定是否保留一批数据改动、不需要因果解释时：因子交叉属过度投资——但相应地不得发布任何机制性说法

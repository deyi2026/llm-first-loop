## Trigger
任务需要核实/获取锚定在具体命名平台或来源类上的事实，且对这类来源的一次通用检索已返回零相关结果，或同一来源已出现重复同类抓取失败回执。

## Discriminator
回执本身就是当时已知的判别事实：对目标平台内容的通用查询 10/10、8/8 全部离题（返回与本任务无关的泛化/本地化页面），或同一来源连续同类失败——这证明该通道根本看不到目标内容，与措辞无关；同时目标平台存在规范结构化检索接口可作替代通道。

## Short path
- 识别事实锚定的来源类及其规范接口：论坛讨论→站内搜索 API；仓库/org 数据→平台 API；不可抓取的原文→存档或降级为二级证据。
- 用精确标识符（帖 ID、org 名、精确标题）对规范接口做一次查询。
- 规范接口也失败或不存在时，把该主张标注为最高可达证据层级（主源不可得，二级转述一致则注明），停止对该事实的检索。
- 引用帖子/接口内容前，与实际取回的 item 文本逐条核对，再写入结论。

## Stop conditions
- 规范接口已给出该平台侧事实（帖存在且含 ID/内容、仓库数据取回）——停止通道切换。
- 规范接口不可得或同样失败——记为该层级不可核验，转向其余待核主张，不再重试同源。

## Verification
- 取回条目必须引用目标精确实体（仓库名/org/帖 ID），而非仅词面相似。
- 报告中归于该来源的每条引语须与实际取回的 item/正文文本一致。
- 最终结论按通道分级标注每条事实（一手 API vs 二级转述 vs 不可核验）。

## Counterexamples
- 首次通用检索已返回目标平台相关内容（如本集开头两条搜索直接命中 GitHub 仓库与官网）——无需切换。
- 事实不锚定于特定平台（一般新闻、产品常识）——通用搜索正是合适的宽发现工具。
- 目标平台不存在可用规范接口或需要不可得的凭据——应走存档快照或降级判级，而不是猜测 API 端点。
- 开放式发现任务（『关于 X 有什么』）——宽检索的不精确可接受，过早切换反而缩窄视野。

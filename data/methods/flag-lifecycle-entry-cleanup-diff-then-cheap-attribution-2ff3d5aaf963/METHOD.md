## Trigger
偶发测试失败被打包归因为「时序敏感」，但失败断言读取的状态字段值翻转无法由单样本内时序机制解释，且测试夹具复用同一会话/实体 id 跑多个样本；或已有第三方报告对该失败给出宽泛归因需复核。

## Discriminator
一次受限符号检索即可拿到该字段的全部 file:line（定义于跨 run 保留的 per-entity 状态桶、写入点、轮内复位点、断言读取点），且作用域入口存在一份显式字段清理清单——三者齐备时，清理清单差集中恰有失败断言读取的字段，即可把候选空间从「整个时序机制空间」缩到一个具体泄漏通道字段。

## Short path
- 从失败断言实际读取的字段名出发做一次作用域受限检索，列出该字段定义/写入/读取/复位的全部 file:line，不先做全仓或全目录枚举
- 读定义处确认字段容器生命周期（是否 per-entity 跨 run 保留），读写入点与复位点确认单样本内生命周期是否闭环
- 读作用域入口（run 入口/请求入口/夹具 setup）的字段清理清单，diff 出「被断言读取但入口未清理」的字段作为泄漏通道候选，同时核对测试是否复用同一实体 id
- 做最小归因实验：样本间显式打印该字段值，或每样本改用新实体 id 重跑少量样本
- 按实验分支定性：翻转消失→测试隔离缺陷（修夹具/测试构造）；仍翻转→产品缺陷（沿该字段的置位/判定阈值继续定位）；归因结论与源码生命周期证据互证后即停止，不追加重复轮次

## Stop conditions
- 入口清理清单完整覆盖该状态桶全部字段（差集为空）→ 泄漏假设证伪，转回时序/竞速机制分析
- 字段语义上本应跨 run 保留（如累计统计），入口不清理是设计意图而非泄漏
- 最小实验显示翻转与实体 id 复用无关 → 已归因到产品侧，转入判定点/阈值定位
- 已取得「测试缺陷 or 产品缺陷」二选一定性且与源码证据链一致 → 停止，不再跑重复轮次或提前隔离

## Verification
- 打印实验中样本间字段值确有残留/清空，与源码生命周期顺序（写点→读点→复位点）一致
- 修复方向（修测试夹具 or 补产品入口清理）与实验分支结果一一对应
- 若判定为产品缺陷，复位缺失点可在源码复核：入口清理了兄弟字段却独漏该字段

## Counterexamples
- 失败签名确实可由时序抖动机制产生（字段生命周期在单样本内闭环、入口清理完整，失败源于竞速归属）→ 应先做抖动可解释性判定，本方法不适用
- 字段是刻意跨 run 保留的语义状态（会话累计计数、用户偏好），「未被入口清理」是设计而非缺陷
- 失败在单样本内稳定复现、与实体 id 复用无关 → 直接沿复现路径 debug，无需归因实验

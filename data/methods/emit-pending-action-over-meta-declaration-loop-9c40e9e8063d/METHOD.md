## Trigger
环境中同时存在动作类工具（execute_command/curl/browser 等）与元管理类工具（convergence/boundary/reflection 类），当前叙述已明确唯一待执行的下一动作（如『只剩一跳：curl bundle 提取 API 路径』），且用户核心问题已基本可由已落地证据回答（如授权通道已实测可用、相关配置项已查证）

## Discriminator
元工具回执连续≥2 次仅返回 continue/无新事实，且该窗口的工具轨迹中没有任何新的动作类调用；self-history/自述条目只是重复同一意图（『下一消息将执行 X』）。这表明缺失的不是信息而是动作调用的发出本身——继续元调用不可能缩小任何未知量

## Short path
- 识别出唯一待执行动作时，把计划与该动作的工具调用放进同一条消息发出，声明不延后到下一消息
- 若确需调用元/边界工具，收到 continue 回执后的下一条消息必须包含动作调用本身或显式 conclude，不得再发一轮纯声明
- 连续 2 次元调用之间无动作调用即判空转环：若用户问题已可答（授权通道已实测可用、配置已查证无对应项），立即收敛作答，并把剩余一跳写成单条可复制命令交给用户
- 辅助：404/SPA 兜底页已显式命名 JS bundle 时，从 bundle 提取真实 API 路径，而非继续猜测端点

## Stop conditions
- 动作调用已发出且回执落地（无论成败），环解除
- 用户问题已由当前证据完全回答，剩余子目标已以单条命令/明确请求交接
- 元工具回执显示真正的硬门控（boundary 未释放、需人工审批），此时等待而非强行动作

## Verification
- 回看轨迹：任意相邻两次元/边界调用之间是否夹有动作类工具调用，无则该段判定为空转
- 最终回复应包含用户问题的直接答案 + 剩余未知量的唯一交接动作（一条可复制命令或明确说明无法本地执行）
- 自检最近两条 emission：若叙述含『将执行/下一条消息』而工具轨迹无对应调用，视为环仍存活

## Counterexamples
- 元工具是硬门控协议的一部分（回执 boundary_released=false 或要求先规划审批后执行）：必须走完流程，不能跳过元步骤直接动作
- 该步骤没有可用动作工具（无 shell/browser）：正确做法是收敛并向用户交接，而非强行发空动作调用
- 用户问题确实依赖子目标结果且下一跳未确定（无 provenance 边、多候选并存）：继续探查/规划是正当的，判环前提（唯一动作已识别+问题已可答）不成立
- 待执行动作具破坏性或不可逆，元轮次用于审慎评估：延长斟酌可能正当

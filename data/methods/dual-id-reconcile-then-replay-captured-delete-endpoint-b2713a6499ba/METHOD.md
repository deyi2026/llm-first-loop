## Trigger
对平台/外部系统的具名记录执行删除等不可逆操作，且用户提供的记录 id 与平台列表/接口暴露的 id 不一致，或删除端点对列表中可见存在的记录返回 404

## Discriminator
同标题+同时间的列表卡片，其 href/id 字段与用户 id 数字尾不同，且用户 id 对应的编辑页 tab 仍在浏览器存活；记录原始 JSON 在删除前即可读出同时存在的 id 与 url 两个字段指向不同数字尾——这条事实足以把『全局搜索用户 id / 判定用户记错 / 判定记录不存在』缩成『同一实体双 id，逐个试端点』

## Short path
- 读列表/记录原始 JSON，只解一个未知量『哪条是用户指的记录』：比对标题与时间；发现 id 字段与 url 字段数字尾不同 → 判定同一实体双 id，不全局搜索用户 id
- 删除前内容指纹：打开目标取字数/标题数/表格数/声明出现次数，与幸存权威副本对照，确认是重复污染版且无独有内容
- 不走合成 click 的 UI 路径：CDP 真实鼠标事件点删除+确认，同时抓 Network，拿到平台真实请求的端点与参数
- 端点 404 时不判『记录不存在』：换用记录暴露的另一个 id（url 字段）重放同一端点 → 2xx
- 双向回读：列表条数递减且列表接口不含该条；权威已发布副本指纹与删前一致 → 停止

## Stop conditions
- 刷新后记录已从列表消失且列表接口不含任一版本 id（可能已被并发删除）→ 无需再删
- 内容指纹显示目标含独有内容或与预期不符 → 冻结删除，交人工裁决
- 两个候选 id 均返回非 404 失败（403/CSRF）→ 停止重放，改为整包复制抓包请求的头与 token

## Verification
- 删后列表计数恰好递减 1，且列表接口首屏不含任一版本 id
- 幸存权威副本（如已发布文章）的内容指纹与删前完全一致
- 成功回执的端点与 UI 抓包所得端点一致，仅 id 参数不同

## Counterexamples
- 两个 id 确实对应两条不同记录（旧自动保存稿与新稿）：内容指纹不符即停，否则删错记录
- 404 因记录已被他人删除而列表是缓存：先刷新列表确认记录仍存在，再归因于 id 不匹配
- 平台把 CSRF/token 与会话绑死：仅换 URL 里的 id 重放会失败，须原样复制抓到的完整请求
- 非破坏性读取任务：id 不一致影响小，不必启动抓包与重放流程

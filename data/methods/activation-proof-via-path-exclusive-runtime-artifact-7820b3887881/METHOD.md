## Trigger
重启/发布后需验证一个此前从未运行过的运行时特性是否真正生效；回执显示配置 flag=true 及来源，但该特性与回退/降级路径的用户可见输出不可区分

## Discriminator
当时已见两个事实：①回执的 flag=true+配置来源+进程启动时间只证明『已加载』，不证明『已路由』；②新旧进程写同一日志文件且历史保留——仅由启用路径打印的日志行可用『新窗口出现+历史窗口零命中』的 novelty 对比成为二元判据。而『两种路径输出不可区分』这一事实本身就说明继续换词重试探针是死路

## Short path
- 读重启回执，关闭『配置是否加载』未知量：flag、来源、进程启动时间
- 确认输出与回退路径不可区分后，立即停止换词重试探针；在服务日志的新进程启动窗口 grep 特性名特征行并与历史窗口对比——出现启用路径独有的启动工件即证明该路径已在启动时构建
- 一次有界 grep 定位查询路由门（enabled&&available 才走新路径的条件行）确认查询期路由；不枚举整棵源码树
- 需要行为级证据时做一次差分探针：与命中卡零字面重叠的查询应命中，无关查询应 0 命中（阴性对照，排除硬凑）
- 启动工件与路由门/差分探针均成立即停止，不重读链路中段源码

## Stop conditions
- 启用路径独有工件存在于新进程日志且历史窗口零命中
- 路由门源码确认新路径会被调用，或差分探针阳/阴对照均符合预期
- 『是否真正生效』已被二元证据回答，不再做补充性重复检查或源码全量枚举

## Verification
- 工件行时间戳不早于回执中的进程启动时间
- 对历史日志窗口 grep 同一特征行应为 0 命中（novelty 成立）
- 无关查询返回 0 命中，排除『总是返回结果』的假阳性通道

## Counterexamples
- 输出回执本身带可区分字段（如检索模式标注、时延差异）时直接对比输出即可，无需日志考古
- 特性不打印任何独有日志或该日志级别未采集时 novelty 判据失效，应改用差分探针或临时插桩
- 验证一次性动作而非常驻通道时，以该动作自身回执为准，启动日志无关
- 若『加载→开关门→行为产物』因果链已在先前上下文确立，应按端点检查法（启动时间 vs 配置 mtime + 唯一行为产物）执行、不重读源码推导中段——那是既有方法 verify-config-activation-at-chain-endpoints 的适用域，本卡仅覆盖链路未确立且输出不可区分的首次启用场景

## Trigger
周期性定时/班次任务以委派方式唤醒，任务书自带幂等条款（按执行编号核对对应动作是否已完成，已完成不得重复执行），且该任务产物受命名约定管辖（如按日期一档的 append-only 产物文件）。

## Discriminator
首次定向检索（班次名/调度标识/任务名）的命中已同时给出：历史产物目录的日期命名约定（可推出本执行编号的期望产物文件名）、执行依据文档路径、以及 .releases/ 冻结副本属噪音。此时幂等核对只剩一个未知量：以触发日推导的产物文件在活树中是否存在 + 产物目录最近提交时间。无需任务全文、无需枚举历史、无需重跑宽搜索。

## Short path
- 用班次名/调度标识做一次定向检索；未知量：产物落点约定与治理文档路径（不是任务答案本身）
- 从任务书的触发时间推导期望产物路径（按触发日归档，不用唤醒时刻）
- 一次存在性检查：活树列举产物目录 + 该目录最近 git 提交；未知量：本执行编号动作是否已完成
- 已完成 → 只核对与记录即停；未完成 → 才读治理文档执行规程与任务全文并执行
- 被取消前任会话的抽样/半成品只作背景，不重放其未结算工具

## Stop conditions
- 门控未知量（本执行编号对应动作是否已完成）已由活树产物存在性 + 产物目录提交记录双侧闭合，核对性发现即停
- 产物存在但治理规定有实质格式要求（如逐行须带证据摘录）时，须通过内容核验才算已完成

## Verification
- 推导出的产物路径与治理文档/历史产物命名约定一致，引用有出处
- 已完成/未完成结论同时有文件系统与版本库两侧证据
- 检索命中的 .releases 等冻结副本未被当作活树真值

## Counterexamples
- 动作无本地确定性产物（发邮件、外部发布等外部副作用）→ 存在性检查无法闭合门控，须查外部回执台账或写者收口记录
- 一次性任务且无幂等条款 → 无重复执行风险，不需要此门控，直接执行
- 前任写者可能仍在途撰写产物 → 存在性检查有竞态，先闭写者存活门控再判定
- 产物文件已存在但是空壳/半成品 → 存在≠完成，须按产物硬格式验实质内容

## Trigger
正在把设计草案经评审收成需求/设计/实现文档（或做定稿裁决），草稿中存在关于某资产集合的量化参数（抽检数量/覆盖周期/容量/增速），且该集合可在本地用一条廉价命令枚举。

## Discriminator
写文档前草稿已含依赖资产规模的量化参数，且该资产集合路径已在会话既有证据中被点名（schedule 消息明确提及 experiences/ 与 data/methods/）——即“参数是否可行”取决于一个当时就能一次枚举得到的数量，而非后续才可得的答案。

## Short path
- 重述目标：把草案经拷问收成 MD 文档；未知量＝草案哪些假设不成立。
- 运行 grill/评审工具，把返回的问题单（哪怕通用）当检查清单逐条对草案作答；未知量＝作答中暴露的真盲点。
- 识别草稿中依赖资产规模的量化参数（如每周抽检张数）；资产路径取自既有证据中已被点名的目录。
- 用最廉价命令枚举计数（两目录 ls 得 407+868）；未知量＝实际 N。
- N 与假设偏差达数量级 → 按实测 N 重算覆盖周期并重构机制（事件驱动主阀门＋风险导向抽样）；同数量级 → 仅修正措辞。
- 所有量化参数落到当次实测值后才开始写文档；写完即停，不追加确认性枚举。

## Stop conditions
- 草稿所有依赖规模的量化参数已用当次实测值钉死，或不可枚举处已显式标注为假设并给出估算方法
- 草稿不含依赖资产规模的量化参数（无需计数，直接进入写作/评审）
- 实测值与假设同数量级、参数可行性成立（只做措辞级修正）

## Verification
- 文档中每个量化参数可指回本次会话取得的实测值或显式标注的假设；抽样覆盖周期按实测 N 复算可重现（如 1275 张、每周 3-5 张 → 覆盖一轮按年计）
- 计数命令的对象与草稿所指资产集合路径一致，避免数错集合

## Counterexamples
- 资产集合本地不可枚举（远端 API 无列表端点、无界流）：不阻塞在计数上，显式写假设＋估算方法
- 草稿的量化参数与资产规模无关（纯命名规范、流程图修订）：计数是不必要动作
- 需要的是单条记录/引用的当前值而非集合规模（如某提醒 sid 是否仍存在）：适用 fresh-read-authoritative-record 一类方法，本卡不覆盖
- 规模差异仅在同数量级内、只影响文案措辞：改措辞即可，不重构机制

## Trigger
任何工具调用失败（HTTP 404/抓取失败、扫描超时、命令 BLOCKED）后决定下一步时；或问题为『某凭据/资源在哪』且环境中已有错误轨迹/文档可能点名其位置

## Discriminator
失败回执的类别与点名内容在失败那一刻即已可见：404+跨传输仍 404=定局『地址不存在』（未知量变为找正确来源）；timeout=范围问题而非意愿问题；stderr/文档回执点名的具体文件名/变量名=可直接缩到的检查范围。这些事实足以把『再试几种可能』缩成一条确定下一 hop。

## Short path
- 失败回执到手先分类：定局（404 经一次跨传输确认仍 404）vs 瞬态/范围（timeout、可重试错误），并读出回执点名的对象
- 定局 404：停止对该 URL 的传输层重试；把真实未知量写成一次搜索查询（含官方域名限定）或从原始 HTML 提取真实链接，一次解析正确地址
- 超时/范围失败：不原样重跑也不放宽；按回执与证据已点名的目标（env 类文件名、缺失变量名、home 配置路径）跑 scoped 检查，只查存在性/名字
- 『凭据在哪』类问题先查项目证据库：stderr 与设计文档常已记录『该文件无此凭据』，一次检索可替代全库扫描，再做一次定点核验
- 两侧未知量各有权威答案（官方 console 入口 / 本地零匹配回执）即停，输出时如实标注未查项（如钥匙串需授权）

## Stop conditions
- 官方域来源已给出 key 创建入口，且第三方仿站已被域名规则排除
- 本地检查覆盖回执点名位置并得到明确零匹配回执
- 定局失败后已完成一次发现层切换并命中，不再回传输层重试同一路径

## Verification
- 最终引用的入口与官方域一致（console 位于官方域下），非第三方站点
- 本地『不存在』结论有具体回执支撑（文件名清单、零匹配、存在性检查），且未读取凭据值
- 失败调用之后无对同一 URL/同一宽扫描的同参数类重复调用

## Counterexamples
- 回执为 403/429/反爬拦截页：状态码不证明资源不存在，应先做一次跨传输诊断区分『被挡』与『真没有』，确认为定局后才适用本方法
- SPA/客户端路由站点所有路径返回 200 壳：不会出现 404 判别事实，方法不触发，需改走 hydration/provenance 路线
- 全新环境无任何先前错误轨迹或约定（无 .env 惯例、无点名目标）：宽发现本身是必要手段，不能直接缩到点名范围
- 首次抓取的页面已直接包含目标答案：无需任何失败后分支，直接停止并输出

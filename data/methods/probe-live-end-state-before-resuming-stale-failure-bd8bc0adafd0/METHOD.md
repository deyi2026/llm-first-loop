## Trigger
恢复 ready/blocked 任务，其『失败/阻塞』前提来自上一会话带时间戳的记录；且操作对象是外部可变系统，其线上终态可只读探测（已登录浏览器会话、live URL、列表接口）。

## Discriminator
阻塞记录本身携带的两个可观察事实：(a) 记录时间戳与当前时刻存在明显时间差（本集约 4.7 小时），期间可能存在其他写者/重试脚本；(b) 记录的依据是现场态（『编辑器计数器卡死』）而非经验证的线上终态结论（未附 live URL 存证）。两者同时成立说明前提是未复核的旧快照，而终态另有可直接观测的权威来源。任一不成立则不适用。

## Short path
- 读 goal/task 记录，记下阻塞前提的时间戳与证据类别（编辑器现场态 vs 已验证 live URL）。
- 存在时间差且有只读线上通道时，先探测线上终态（browser page_list → rebind → snapshot，或抓取 live URL），解决未知量『是否其实已发布/已完成』。
- 线上显示已完成 → 任务降级为核验：与本地定稿做行级 diff，核对 datePublished/图片/私密标记，不执行任何写动作，再标 done。
- 线上显示确实未完成 → 才按原阻塞前提进入材料定位与绕障/重发准备。
- 线上终态与定稿比对完成、差异均可解释后停止。

## Stop conditions
- 线上终态与本地定稿行级核验一致（diff 中无未解释缺失项）→ 任务完成，本轮零写动作。
- 线上状态确认目标确实未完成 → 切换到重执行分支，此时才开始原阻塞前提的处理流程。
- 无只读线上通道（无会话、无 URL，或探测本身具破坏性/消耗配额）→ 退回使用本地最新记录，并把结论标注为未验证。

## Verification
- 线上页 title、datePublished、行级内容与定稿逐项对应（本集 96 vs 95 行、章节标题 12/12），所有 diff 差异能归因为『线上更新』而非缺失。
- 全部图片实际可加载（含懒加载占位），无草稿/私密标记。
- 输出结论带核验时间戳，表述为快照而非终局，并如实声明本轮未执行任何写动作。

## Counterexamples
- 阻塞记录是同一会话数秒前生成、且无其他并发写者 → 按记录直接处理，无需再探测线上状态。
- 目标为纯本地状态（文件编辑、内部计算），不存在可观测的外部终态 → 本地检查即权威核验，本方法不适用。
- 探测线上状态会触发写动作/破坏性操作或消耗一次性发布配额 → 不能先探测，须先评估代价。
- 旧前提是『已发布成功』而任务是防重复发布 → 核验方向反转（查重而非查完成），机制相关但不等同适用。

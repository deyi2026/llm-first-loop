## Trigger
任务要求按登记/SoT 处置存量项（分支、特性、部署状态归类），且登记中的状态断言与当前运行时可观察事实存在直接矛盾（如声称未部署，但运行时已具备对应工具/行为）。

## Discriminator
两条当时已存在的事实：(1) 运行时是否已直接展示登记所否认的能力——矛盾成立时，候选空间从『审计全部 N 个存量项』缩为『该能力经哪笔提交进入权威线』这一个未知量；(2) 已读文档/搜索命中是否已给出精确锚点（符号名、commit SHA、worktree/分支名）——有则窄查询可立即执行，无需宽枚举。

## Short path
- 读登记原文，提取明确状态断言（未合并/未部署）及其点名的符号、提交、分支。
- 与运行时直接观察对照：若运行时已具备该能力，『未部署』即被证伪，未知量收窄为『它经哪条提交进入 main』。
- 用文档已给出的精确符号/SHA 在主工作树做窄查询：ls-tree main 查文件是否存在、git log main -- 路径查引入提交。
- 引入提交在 main 即判定登记陈旧，按事实修正登记并同步锚点测试，停止对该项的继续扩散。
- 存量盘点改为过滤式枚举：单命令只输出与 main 不一致的项（NOT-IN-MAIN + ahead 计数），避免全量 -vv 倾倒与跨 .worktrees 的全仓 grep（后者在本集超时 >60s）。

## Stop conditions
- 已用权威仓库事实（文件在 main、引入提交 SHA、祖先关系）判明登记哪侧失真并修正，即停止发现动作；
- 运行时与登记无矛盾时，不套用本方法，回到常规审计路径；
- 运行时能力可能来自插件/外部服务/其他仓库时，先定位提供者，不下『本仓 main 已合并』结论。

## Verification
- 登记修正后引用的每个事实（符号在 main、引入提交、部署状态被推翻）均有对应命令回执支撑，不靠推断；
- 修正处的同步锚点测试通过；
- 过滤式枚举的覆盖数与 for-each-ref 总数对账，确认无遗漏。

## Counterexamples
- 运行时并不展示该能力（工具不存在、端点无响应）：无矛盾，登记可能准确，照常审计。
- 能力由插件、外部服务或另一仓库提供：运行时存在推不出『本仓 main 已合并』，须先定位来源。
- 登记是权威决策记录（豁免/锁定/禁用决定）而运行时出现属违规：矛盾方向反转，应查运行时泄漏而非改登记。
- 登记对象无运行时可观察形态（文档未发布、费用未结算）：方法不适用。
- 单工作树小仓库：窄范围搜索的收益缩小，但『精确锚点先行』仍适用。

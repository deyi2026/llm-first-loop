## Trigger
目标事实位于仅用户本地环境可达的资源（loopback/私网服务、本地进程、需本地凭证或本地 env 的端点），且工具回执明确判定为策略性阻断而非瞬时故障。

## Discriminator
阻断回执是否明确写出策略原因（如『私网地址默认拒绝』）、是否不可由重试/换参数解除、建议项是否全部超出 agent 权限；配合侧信道（session evidence）一次性检索 miss，即可当时判定：判别数据只能来自用户侧或历史归档，远程侧枚举不再可能缩小假设空间。

## Short path
- 读阻断回执并分类：策略性且补救在用户侧（进入本方法）vs 瞬时/可换通道（重试即可，不适用本方法）。
- 至多执行一次与被阻断资源直接相关的历史/已知问题检索，确认现象是否为已声明的已知差距。
- 若历史记录已足以定性则直接作答；否则收口：声明我侧不可复核，列出可分辨假设集（如已知残留缺陷 vs 正常任务）。
- 向用户提出单一最小委托：给出可直接复制的命令（如 curl 本地 API 端点）请其贴回输出，或索要 run id/截图等一条判别信息。
- 停止对同一目标的一切进一步远程尝试与重复检索；不在收敛轮重述未知量或把承诺动作推迟到下一轮。

## Stop conditions
- 用户侧判别事实（命令输出/run id/截图）已取得并完成定性；
- agent 侧历史/归档记录已足以独立判定现象（如已知差距声明直接解释观察）；
- 用户明确表示无法提供时，改为输出两分支各自的条件处置建议后结束。

## Verification
- 收口前确认：没有对同一被策略阻断目标的重复或换参数重试；
- 历史/侧信道检索仅执行一次且与被阻断资源直接相关；
- 对用户的请求只含一条最小判别信息并附可直接复制的命令；
- 后续若拿到用户回传数据，验证其能否唯一区分预先列出的假设分支。

## Counterexamples
- 阻断为瞬时错误（超时/5xx）——应重试或换通道，不应立即委托用户；
- 存在 agent 可用的同机执行/日志/文件通道可观测目标——先走该通道，不要求用户代查；
- 权威历史/归档记录本身已含答案——直接引用作答，无需用户往返；
- 用户不可用且任务必须推进——输出两分支条件行动方案，而非阻塞等待用户输入。

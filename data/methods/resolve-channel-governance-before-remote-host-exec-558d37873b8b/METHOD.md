## Trigger
任务包含跨机执行子任务（如在生产主机安装新版本、重启服务、跑运维命令），且当前会话对该主机无既定可用通道（ssh config 检索 miss、无已部署的 peer/agent 任务通道）

## Discriminator
两个当时即可观察的事实把'枚举连接手段'缩成'读一份文档'：① 通道配置检索 miss 的工具回执证明无 standing 通道；② experiences/docs 列表里存在以该主机命名、标题即'远程接管/互操作'的治理设计文档——治理文档定义通道许可（经验文件只记录既有操作），其中'仅允许端口转发、禁止远程命令执行'类硬约束加'合规替代通道未部署'直接判定该子任务对本会话不可执行

## Short path
- 子任务落到远程主机时，把第一未知量定为'哪条通道是被允许的执行通道'，而非'怎么建立连接'
- 一次只读检查既定通道（ssh config/已登记 host），miss 即确认无 standing 通道
- 按主机名在 experiences/design docs 定位治理文档，读通道与硬约束章节，并确认文档点名的合规替代通道是否已部署
- 存在执行禁令且替代通道未部署 → 停止构造连接/凭据/隧道方案，产出双选项裁决：A=目标机器本机可独立执行的命令+逐项验收清单；B=明示豁免触发语的一次性授权
- 等待裁决期间继续本机并行子任务；用户选定后按选定路径执行并留痕

## Stop conditions
- 治理文档确认合规执行通道已部署 → 直接走该通道完成任务，不再升级
- 任务属于文档白名单内的只读探活（如经隧道 curl）→ 按白名单直接执行
- 用户已给出 A/B 裁决 → 停止升级，按裁决执行

## Verification
- 实际采用（或放弃）的执行路径能在治理文档中找到逐字依据条款
- 升级消息中的命令与验收项在目标机器本机可独立复制执行，无隐含前置
- 全程未发生绕过约束的连接尝试：无地址/凭据猜测、无隧道内夹带远程命令

## Counterexamples
- 治理禁令已被后续部署取代（如受控 peer 任务通道已上线）：应改查替代通道现状并直接使用，而非固定走人工升级
- 目标主机存在常设授权通道（CI/deploy 管线、登记凭据）：无需此检查，直接走既有通道
- 文档约束针对同名但不同的环境/主机：须先确认文档与目标机器一一对应，否则约束不适用
- 纯本机任务没有远程执行面：不引入通道检查，避免空转

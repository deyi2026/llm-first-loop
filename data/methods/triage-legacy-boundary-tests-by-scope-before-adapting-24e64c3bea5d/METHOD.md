## Trigger
自己刚给系统上线一个默认开启的新行为边界/检查点/打断机制，随后的全量回归中多个既有测试失败，需要逐个决定：修产品代码、适配测试、还是不动

## Discriminator
读失败测试本身即可获得的三类事实：(a) 测试关键事件的注入时点落在哪个执行阶段、是否处于新边界的激活范围内（如注入发生在工具执行期的 sleep 中而非 LLM 调用窗口内 → 新机制对该失败不可达）；(b) 同一失败在不含本次改动的基线上是否复现；(c) 测试断言的旧边界机制在新语义下是否仍被需要（服务晚到事件、关闸回退路径）

## Short path
- 对每个失败测试先读其事件注入时序与断言目标，判定注入点是否落在新边界激活范围内——解决未知量：本次改动是否可能触及该失败
- 范围外且单跑通过 → 归为时序余量抖动（负载收窄毫秒级 margin），不追修不改测试；基线（改动前/HEAD）同败 → 预存，单列不动
- 范围内且断言旧边界语义 → 判断旧机制是否仍服务活语义：是 → 在测试内显式关闭新闸并注释机制原意与理由；机制已被完全取代 → 把断言归属更新到新边界口径
- 只有归因为新调用点违反既有契约或引入真缺陷（如被契约回归测试捕获）时才修产品代码，并以对应测试锁定防复发
- 跑目标子集确认后，再跑一次全量回归，对剩余失败重复归类，直到归零或全部标为已证预存

## Stop conditions
- 每个失败已唯一归入 {新缺陷已修并锁定 / 显式关闸或归属适配 / 已证预存或抖动} 之一
- 目标子集与全量回归通过（或仅剩已证预存项）
- 不为抖动或预存失败修改测试语义

## Verification
- 抖动归因须有单跑通过佐证；预存归因须有基线同败佐证，不凭印象
- 关闸适配的测试注明其机制测试原意及与新边界的关系；关闸回退路径本身仍被专门测试覆盖
- 产品代码修复有对应回归测试（如 fail-open/保守降级契约测试）锁定

## Counterexamples
- 失败与注入时序无关（纯断言错误、构造数据错误）→ 范围定位法不适用，直接读断言 diff 定位
- 失败测试本身是契约/规格测试且与新机制冲突 → 不可关闸绕过，应上升为契约决策：评估契约保护属性与替代方案后果（如保守降级被违反会把诊断管道故障升级为 run 级失败，比改动前更差）后再决定遵守或修订契约
- 新边界默认关闭发布 → 既有测试不会失败，此归类法无用武之地
- 时序敏感测试单跑也失败 → 不是负载抖动而是真实时序缺陷，必须修余量而非归为环境

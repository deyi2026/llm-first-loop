## Trigger
任务需要判断一个被文档/CHANGELOG/记忆声称的机制当前是否生效（如实现其前身、核对记载特性是否在树内），且已存在一个权威符号名可供一次覆盖性搜索；第一次搜索返回了极小候选集。

## Discriminator
一次覆盖性 grep 已返回极小且完整的候选文件集，并且两个事实当时已在场：(1) 定义/唯一实现处的 docstring 明确写出当前职责边界（如'仅作 durable handoff 记录，不自动进入模型 prompt'）；(2) 其余命中已确认属于无关语义（如 UI 会话置顶 pinned、压缩 history_anchor）。这两个事实合起来已证明该机制不在当前生效路径，剩余未知量只剩'是否曾被有意移除及理由'。

## Short path
- 用机制符号名做一次覆盖性 grep，得到完整候选文件集（未知量：该机制在当前树的全部落点）
- 逐个读候选中的定义/唯一实现处（如 focus.py），确认当前职责边界（未知量：机制是否在生效路径上）
- 若定义处证明机制不在生效路径 → git log -S <符号名> 定位增删提交（未知量：是否曾存在、何时被移除）
- 读移除提交的 message/diff 摘要，取得移除意图与风险理由（未知量：直接恢复是否安全）
- 以移除理由决定跳过/独立设计轮次/恢复，结论显式记录'有意移除+提交号'，停止

## Stop conditions
- 定义处职责已证明机制不在当前生效路径，且版本历史已给出移除提交与理由
- 两个以上独立关键词族的覆盖性 grep 均无该机制的活跃调用点，且历史无对应增删记录

## Verification
- git log -S 找到的移除提交 message 与最终决策依据（跳过/重设计/恢复）一致
- 当前树 grep 结果与'机制不在树内生效'结论自洽（无活跃调用点）
- 决策输出显式引用移除提交号，可被第三方复查

## Counterexamples
- 符号可能已被重命名（首个关键词未覆盖新名）→ 允许第二次受控变体搜索，但不超过两个关键词族，之后必须转向版本历史
- 工作副本是无 VCS 历史的快照/离线抓取包 → 历史考古不可用，应退回目录枚举与文档核验，而非本方法
- 任务目标本身是枚举 X 的所有出现位置（存在性统计）而非判断 X 是否生效 → 宽搜索就是任务，不适用本方法
- 定义处 docstring 与实际行为不一致（注释过时/实现漂移）→ 必须再看调用点或运行时行为，不能只信 docstring

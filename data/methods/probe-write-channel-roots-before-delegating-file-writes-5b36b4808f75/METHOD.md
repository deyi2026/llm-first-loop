## Trigger
任务成功前提是向某路径写入或修改文件（checkout 知识文件、修订卡片、落盘文档等），且回执中已出现写权限边界声明（执行类回执的沙箱可写根、lease/状态回执的 workspace 值），而目标路径在边界之外或未验证是否在边界内；尤其当写入将被委派给子代理、或用户重新放行一个既定施工方案时。

## Discriminator
当时已可见的一条事实：执行回执的沙箱声明『仅允许写工作区与缓存目录』，且 lease/状态回执的 workspace 值与目标仓库路径不一致——这一条即可把候选空间从『哪个写工具能用』缩成『哪个通道有权写』，一次探针定案；且权限性拒绝（Operation not permitted 类）与瞬时错误必须区分对待。

## Short path
- 对齐已到手回执的写权限声明与目标路径：本会话与拟委派子会话的可写根是否覆盖目标？仅用已有回执即可回答大半
- 边界外或未验证 → 发一次最廉价写探针（如 touch 目标目录）；若为权限性拒绝即停，不再让子代理逐类枚举写通道（execute_command/edit_file/任务通道/workflow 各试一遍属浪费）
- 确证无写权 → 立即改判重定计划：payload 先 staging 到可写根（如 /tmp），最终写入交有权限通道并请用户裁定；若存在正在写同一目标的并行执行者则不重写
- 已派出的委派改为只读核验：目标清单逐文件内容比对（哈希 vs git show <ref>:<path>），不以 git status/diff 账面推断『未改』——本地 exclude 与 NFC/NFD 文件名会遮蔽或失真改集
- 运行时层事实经权威核验（逐字节保真+检索命中切换）即停止发现，残余缺口（git 耐久性、未落地文档）按通道上报用户裁定

## Stop conditions
- 已确定唯一有权限的写通道并取得授权方确认，或用户明确选择通道
- 目标变更已被并行执行者完成且逐字节核验通过（运行时层已生效）
- 探针回执属瞬时/网络类错误而非权限拒绝 → 按瞬时错误处理，不套用本卡改道逻辑

## Verification
- 探针拒绝回执与已声明可写根边界一致，且可复现一次（排除瞬时误判）
- 委派前显式回答：子代理 lease 的 workspace 是否等于目标仓库路径；不相等则视为无写权直至探针证明
- 验收一律用逐字节/哈希比对 pinned 参考版本，而非 status/diff 账面清单

## Counterexamples
- 目标路径本就在可写根内（工作区、/tmp staging）→ 直接写，无需探针仪式
- 子代理 lease 显式以目标仓库为工作区（绑定==目标路径）→ 探针通过，照常委派写入
- 纯只读分析任务 → 不存在写权限未知量，不适用
- 权限由显式工具白名单而非路径沙箱决定时，回执 banner 不预测结果：探针仍是第一步，但结论以白名单为准

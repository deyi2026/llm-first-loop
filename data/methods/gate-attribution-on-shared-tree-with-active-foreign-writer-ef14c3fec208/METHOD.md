## Trigger
即将执行对整棵工作树生效的门禁（全量测试/review_admission 冻结全量 diff），而 git status --porcelain 显示大量非本交付范围的未提交改动，或存在迹象表明另一会话仍在同一工作树活跃写盘（准入冻结 sha 在 PASS 后数秒漂移、外域文件 mtime 持续更新）

## Discriminator
两条当时已在手的事实：(1) 恢复状态的首个回执已明示『工作树含其它工作流未提交改动，提交必须按精确路径』，随后 git status 改动清单远超交付路径集合（安全加固/docs/reports 等外域文件）；(2) 准入失败回执的类别本身——被内容闸拦截的原因是外域密钥样例字面量、sha 漂移发生在 PASS 后数秒——这两类回执指向并发写者，而非本交付缺陷

## Short path
- 恢复状态读到『工作树含其它工作流未提交改动』时，把『门禁结果能否归属本交付』列为独立未知量，与代码正确性分开处理
- git status --porcelain 与交付路径清单比对，确认外域改动范围与共享文件；以外域文件最近写盘时间判断并发写者是否仍活跃
- 交付域测试/审查全绿后，准入最多尝试一次以确认失败类别；按回执分类：外域敏感字面量被拦/短时 sha 漂移 ⇒ 归类为树级阻塞，停止重试
- 归属可分：构建仅含交付范围的隔离快照再过闸；共享文件混 hunk、模块归属无法单方判定时停止，向用户升级选项（等外批提交/授权 hunk 拆分/仅提交交付路径）并如实报告未验证边界
- 全程不改外批次的基线文件，不把外域 P1 记入本交付账目，临时改动用完即还原

## Stop conditions
- 失败类别已确认源于外域改动/并发写者，且树或范围决策超出单方权限
- 或已用仅含交付范围的快照完成准入与门禁，每个红项/结论归属清晰
- 用户已就等待/拆分/提交路径作出裁决并给出新指令

## Verification
- 隔离快照的 diff 路径集合 == 交付路径清单，不含任何外域文件
- 准入回执冻结 sha 在等待期不再漂移（并发写者已停或已被隔离在外）
- 全量结果中每条红项/审查发现都能映射到明确归属方（本交付 or 外批次），无模糊账

## Counterexamples
- git status 只有本交付范围的改动（或外域改动已提交、无活跃写者）→ 直接在活树上跑门禁，无需隔离或升级
- 门禁红项落在本交付路径内 → 是可归属的交付缺陷，回去修代码，不要归咎共享树
- 门禁/准入工具本身支持按路径限定范围 → 用路径限定直接解决，不必整树隔离或找用户裁决

## Trigger
用户要求为既有 store 中的记录增加『知道是哪个会话/连接提交的、事后一键打开该来源』的回链能力，需产出设计书或实现方案，且链接键与链接目标都应存在于既有持久化数据中。

## Discriminator
三个可独立验证的事实各有权威面：producer/store 写入路径证明键已落盘；outlet 响应与前端类型证明是否暴露；真实数据文件统计目标解析率与位置分布（本集 161/174 异址）。其中数据级解析率是纯代码阅读给不出的判别事实，缺它就会交付一个对多数记录空转的链接。

## Short path
- 沿用户点名的 UI 面（复制按钮所在面板）定位组件：ls 前端 src → 同目录测试文件名给出组件路径 → 直读组件；头注释与 interface 即列出它消费的 endpoint 与记录字段，键是否暴露立即可见。
- 用组件注释中的 endpoint 精确串 grep 后端路由，直读 list/detail/review 各出口处理器，确认返回字段集合。
- 读 store 与提交工具源码，确认链接键（如 session_id）是否在写入端已落盘——若已落盘，改动收敛为『补出口』而非『补存储』。
- 扫真实数据：从 store 落盘记录取出键值，逐条检查目标文件是否存在、位于哪个工作区，统计存在/缺失/异址比例。
- 三个未知量均有直接证据后才写设计：最小 delta（出口补字段+渲染期构造链接，不存易失信息如端口）+ 不可解析目标的显式处置分支（定位器/切换提示/降级文案）。

## Stop conditions
- producer 写入路径、outlet 返回形状、真实数据解析率三者均有文件级直接证据；
- 用户口语概念（『本地连接』）已映射到可持久化真值，并说明原概念为何不可跨进程保留；
- 不可解析/异址目标的比例已量化并转化为设计中的显式处置分支，而非隐含假设目标总在本工作区。

## Verification
- 核对 outlet 响应字段与前端类型定义一致地包含/缺失该键；
- 键的落盘以 producer 写入代码行+落盘文件抽样双重确认；
- 解析率统计可复算（记录总数、可解析数、异址数、仅身份残留数、缺失数）。

## Counterexamples
- 链接键从未在写入端落盘：第一未知量变成写路径改造，扫描旧数据无法指导出口设计；
- 链接目标按构造即全局可寻址（URL slug、服务端可解析 id）：无逐记录解析问题，跳过数据扫描；
- store 刚建或样本极少：解析率不具代表性，只能按 schema 设计并显式标注假设；
- 需求为纯后端行为或无前端工件：『用户点名 UI 面为入口』不成立，退回定义面检索。

# 不可回滚外部动作的无损全量对照校验

## Trigger
当任务包含不可回滚的外部动作（发布文章、发送消息、删除、下单、提交表单），**且**目标经过富文本渲染层（ProseMirror / Slate / 微信编辑器 / 各家自研 block editor）时使用。
若动作可撤销或目标是纯文本 API（直接 POST JSON），本方法不适用——回执 diff 更省，套用行级对照是浪费。

## Discriminator
不要用「抽查几个锚点关键词」当验证。锚点法依赖一个在富文本上不成立的假设：*源文的特征词在渲染后能以纯文本被搜到*。
- H1/H2 常被渲染成自定义 block，标题文字**不进 innerText**；
- 列表项、代码块可能被拆进不同容器，跨块连续文本被打断；
- 图片描述、样式可能落在属性而非文本节点。

结果是 `indexOf('结语') === -1`，**度量失效被误读成页面异常**；反向失效同样致命——锚点恰好在、正文后半段全丢，锚点法照样放行。

判别一步：**目标是否会把标题文字渲染进 innerText？** 会 → 用普通 diff；不会 → 必须用本方法。

## Short path
1. **选不会被屏蔽的度量**：正文容器的 innerText / textContent。
2. **从源侧抽实义行**：解析源 Markdown，取 ≥12 字符的正文行，剔除空行、分隔线、纯标题行、代码围栏。匹配键只用**行首 ≥12 字**——行尾最容易被加样式标记或改写。
3. **逐条查前缀命中**，统计缺失条数与缺失内容。
4. **判据只有一条：缺失计数 == 0**。不设比例阈值，不做「关键行都在就算过」。
5. **附带校验结构类产物**：图片数、顺序、唯一性（用尺寸/自然高度序列去重比对，防重复上传）。
6. 缺失非 0 → **不在目标平台修补**（通常也无入口），改度量或注入时序，从源重发。

## Stop conditions
- 缺失计数为 0 且图片唯一性通过 → 停止，产物可信，收工。
- 缺失计数 > 0 → 停手，先判断根因归属，**不要继续往上叠校验**。
  - **度量层失效**（校验显示正常但产物有缺陷）→ 优先级最高，必须先换度量，否则重发多少次都拦不住。
  - **执行层失效**（校验如实报缺失）→ 按缺失位置定位注入时序/分页/截断，修执行路径。
  - 两者常同时存在。
- 连续两次发布都出现缺失 → 停止手工重试，转去检查编辑器是否有虚拟滚动/分页加载（只渲染视口附近内容）。
- 目标平台无自助编辑入口 → **校验是唯一防线**，不存在「先发再改」这条路，必须在发布前把上述全部跑完。

## Verification
发布后运行缺失计数脚本：抽取源实义行 → 逐条查前缀命中 → 输出 `missing=N`。**N=0 才算通过**。
本卡实证：知乎首版用锚点法放行，正文实丢 48 行（结语/参考来源/上手命令/结尾问句全失）且 3 图重复；改本方法后 71 行 0 缺失、5 图唯一且高度序列 [660,640,700,600,760] 与源引用一一对应，一次通过。

## Counterexamples
- 拿本方法去校验可回滚的本地文件写入——直接 diff。
- 放宽成「缺失比例 < 5% 就算过」——等价于退回锚点法。
- 只抽首尾两段做对照——**正文中间截断是最常见失败形态**，首尾看起来都正常。本卡来源案例中，正文即从中间「这张图想说明的是一条更普遍的原则：」处硬截断，首尾两段都无异常。
- 源侧行数少于约 20 行时不必套全套流程，锚点法够用（样本太小，对照无统计意义）。

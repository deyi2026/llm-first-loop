## Trigger
任何验证/收口函数把'最高信任态/已验收'的晋级判据建立在调用方可控的输入字段上（自报通道名、自附验收回执引用），且这些字段无签名、无独立身份校验——构造合法形状即可晋级

## Discriminator
当时已可见事实：报告方用真实运行证明仅凭调用方伪造字典（伪造通道 id + 伪验收引用）即返回最高信任结论——晋级判定完全由不可信输入计算得出；读码亦可见晋级字段 ⊆ 输入 dict 且函数内无签名/独立 UID 验证。'形状完好但来源自报'是权威级 fail-open，与'字段缺省/坏类型被救成合法值'的值级 fail-open 是两类不同问题

## Short path
- 先裁决结构而非字段：确认晋级字段全部来自输入且函数内无独立校验 → 定性为结构性 fail-open，不是校验遗漏
- 不信任路径的返回结论封顶为待定态，任何自报字段不再参与晋级
- 篡改检测（epoch/快照摘要）放在封顶之前、保持失败结论优先，防止把可检出的篡改降级成普通待定
- 最高信任态只从专用可信入口（签名+独立 UID 校验）产生，且不与不信任字典判定共用代码路径
- 逐字重放报告中的同一伪造输入作回归断言，另加篡改仍失败的负测；跑齐全量检查后冻结证据
- 汇报字段分列'本地检查通过'与'独立验证待定'，外部权威通道未清前不提交、不宣称已验收

## Stop conditions
- 同一伪造输入重放后返回封顶态、篡改样本仍返回失败结论 → 结构封堵完成，停止迭代修复
- 全量检查绿 + 负测固化 + 证据回执冻结 → 收口；外部权威未清前保持待定，不做越权提交/宣称

## Verification
- 用报告给出的同一伪造字典逐字重放，断言现返回待定而非最高信任态（本集已实测：伪造字典现返回 PENDING）
- 篡改样本（epoch/快照 sha）负测仍优先返回失败结论，确认封顶没有吞掉篡改检测
- 断言最高信任态只能由专用可信 verifier 产生（如 in-process oracle 不可自晋级的负测）
- 检查对外回执/报告无矛盾表述：本地几何/本地检查通过与独立验证待定分列，不合并成单一'通过'

## Counterexamples
- 输入虽来自调用方，但函数内用可信密钥验签/验独立身份后才晋级 → 属已验证输入，可正常晋级，本方法不适用
- 判定依据是特权侧真值（如引擎 oracle 直读场景状态判放置成功），结论不来自调用方自述字段 → 无需封顶
- 纯本地契约、不存在外部权威或待定语义，只缺严格校验 → 直接加严格校验即可，强拆'封顶+专用晋级入口'属过度设计
- 数据来自已验签的可信通道（Host 签发回执），字段非自报 → 按既有信任模型处理，不套用封顶规则

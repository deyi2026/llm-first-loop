## Trigger
需要将若干具体技术论断与某产品官方文档逐条核对，且权威文档域名已知、或首轮对该域名的直连抓取已成功返回同主题内容

## Discriminator
两条当时已知的事实：(1) 对权威域名的直连 web_fetch 已成功并返回与论断同主题的参考内容——证明直连通道可用且权威，此时通用搜索枚举是降级；(2) 抓取回执带抽取器标记（如 trafilatura）且内容被截断——指示应改走原始格式/机器可读索引通道

## Short path
- 对已知官方文档页直连抓取，确认通道可用并覆盖已可见的论断点
- 若回执带抽取器截断标记，抓取该站 llms.txt/索引，取得全部页面及 .md 原始 URL 列表
- 逐论断点抓对应 .md 原文取证；子主题路径未知时沿已读页面内的显式链接跳转，而非猜 URL 或搜索引擎
- 猜测 URL 返回 404 时，回索引查准确路径一次纠正，不再换 UA/换猜法重试
- 每条论断都有官方原文引用、或带有覆盖边界声明的'未见'后，停止取证并输出逐条裁决

## Stop conditions
- 每个核验点都有权威来源的直接引用或明确的缺失证据
- 站点无机器可读索引/原始格式时，退化为分页读 HTML 并显式声明覆盖边界
- 论断属于运行时行为或本机版本时停止查文档，改为实测

## Verification
- 每条结论标注来源 URL 与原文引句，区分'文档确实未提及'与'我只读了部分页面'
- 区分文档口径与用户实际安装版本，未实测处如实标注
- 确认最终来源确属权威域名，而非搜索快照或第三方转述

## Counterexamples
- 需核实本机实际版本或实际行为（如 CLI 版本、validate 实测输出）——文档原文无法验证，必须实测
- 目标内容不在单一已知权威域（社区多源说法比对、寻找教程）——通用搜索才是正确主通道
- 站点不提供 llms.txt 或 .md 原始格式——只能分页抓 HTML，'原始格式'步骤不适用
- 用户锁定旧版本而文档 volatile——最新文档口径不能直接判定用户环境真伪，需版本对齐

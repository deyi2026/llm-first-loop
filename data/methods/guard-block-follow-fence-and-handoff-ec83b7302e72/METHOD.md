## Trigger
工具动作被策略守卫以描述性规则文案拒绝（如标明 operator-only、给出替代入口），且任务链还有后续步骤，需要判断哪些步骤模型仍可执行、哪些必须移交操作员。

## Discriminator
拦截回执是确定性的策略拒绝：含具体规则文案、所在模块与替代指引，而非 timeout/5xx/网络抖动。这一事实把候选空间从“重试/换工具/想办法绕过”缩小为“读围栏定义并逐项分类剩余步骤”。

## Short path
- 按计划执行链；一旦被策略围栏拦截，取回执中的规则字符串与模块名作为定位线索，不重试原命令
- 用该文案精确 grep 守卫源码，找到判定函数，读出确切的被围栏子命令/动作集合（以源码为准，不以记忆为准）
- 把剩余计划步骤逐一对照集合，分类为模型可执行 / 操作员专属
- 验证被拦截动作将变更的外部状态（如 desired generation、目标 git head），确认其仍待执行并取得精确前置参数（如当前代数值）
- 从源码读被拦截动作的 CLI 契约（subparser/argparse 定义），组装与定义逐项一致的一次性操作员命令
- 移交：报告已完成项、被拦截项、可复制命令与完成后的验证承诺；操作员完成后立即执行自己被允许的步骤并全程验证

## Stop conditions
- 被围栏集合已从守卫源码读出，且每个剩余步骤已归类 permitted/gated
- 被 gate 动作的目标状态与前置参数已从权威状态文件读出，确认其仍待执行
- 操作员命令每个 flag 与源码 CLI 定义逐项一致，无猜测参数
- 全程未尝试围栏规避（换壳调用、改路径、改守卫代码）

## Verification
- 确认剩余步骤（如 restart 类子命令）确实不在被围栏集合内——依据源码清单而非记忆
- 确认所读守卫定义与实际拦截你的那份代码同版本/同 HEAD（避免跨 worktree 或旧分支读到过期围栏清单）
- 操作员命令与 subparser 定义逐 flag 比对；expected-generation 类参数与刚读出的当前状态一致
- 交接前重读目标状态文件，确认被 gate 的变更仍未发生（防操作员已执行或状态已推进）

## Counterexamples
- 拦截是瞬时错误（timeout、5xx、网络失败）：不应读策略源码，应重试或排查基础设施
- 守卫来自第三方服务且有官方错误码/文档：按文档与支持渠道处理，不 grep 自己不拥有的内部源码
- 围栏定义中明确存在模型可用的合法替代通道（如官方子命令带 requester/delegation 参数）：走定义内的替代，但仍不做 shell 层规避
- 单角色环境、无守卫系统的一次性操作：整个分类与移交流程不适用
- 被拦截动作对最终目标其实非必需（可跳过或状态已由他方推进）：先重读状态再决定是否需要人工移交，避免不必要介入

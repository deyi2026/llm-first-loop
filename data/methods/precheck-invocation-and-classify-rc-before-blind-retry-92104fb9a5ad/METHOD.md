## Trigger
编写、审阅或接手带 sleep+continue 的无人值守重试链；或观察到某步骤返回非零 rc，且循环对 rc 类别不加区分地原样重试。

## Discriminator
当时已可见的两条事实：(1) 链日志显示 restart 步 rc=126（执行/权限类确定性错误）；(2) 循环体是 `if rc != 0; then sleep 120; continue`，重试不改变任何调用参数。二者结合在当时即足以断定剩余全部 attempt 都会同因失败，继续等待只会烧掉空闲窗口；且脚本在 git 中为 100644（无执行位）却被写成 `./script` 直接执行。

## Short path
- 读链脚本体，列出它将执行的每个外部命令；未知量：这些调用方式能否成功执行？
- 启动前对每个脚本做前置检查（test -x / 解释器存在 / flag 跨平台），发现不可执行就改用 `bash <script>` 调用——本例中一条命令即可提前拿到 100644 这一事实，免去整段 kill/重写/重启环节
- 若链已在跑且日志出现确定性类 rc（如 126）：不做额外等待，直接终止该链——循环无法自愈
- 只修调用方式重建同一条链，安全门（等空闲、HEAD 校验、脏区中止）原样保留
- 挂 canary 唤醒验证新进程与端口可达后即停止

## Stop conditions
- 修正版链已用验证过的调用方式启动且安全门完整 → 停止干预，只等 canary
- 出现确定性类 rc（126/127/权限拒绝/缺文件/配置错误）→ 不等待后续 attempt，立即修复或中止
- 探测命令自身失败 → 结论只能是“未知”；换可移植探测确认前不得断言进程/服务已消失

## Verification
- 启动前干跑每个外部调用的调用方式；链内日志保留 rc 与 stderr 以便事后分类
- 循环内非零 rc 先分类再行动：确定性类→中止/修复，瞬态类→带退避重试
- 进程存活探测用可移植写法并单独取 rc（如 kill -0 <pid>，避免 BSD ps 不认的 GNU flag），兜底分支输出 'probe failed' 而非 'gone'
- canary 确认目标服务新进程在跑、端口可访问、原错误不再复现

## Counterexamples
- 瞬态失败（网络超时、锁未释放、服务仍在启动中）：等同重试+退避正是正确做法，按本方法立即中止反而错
- 非幂等操作的重试（扣减额度、发出用户可见消息）：需要幂等性分析，单靠 rc 分类不足以决定是否重试
- 非零 rc 实际来自探测命令自身：本例中 macOS BSD ps 不认 --no-headers，'||' 兜底误报 'PID 66137 gone'，实际三服务全程健在——此时 rc 描述的是探测器坏了而非目标死了，应先修探测再下结论，而不是对“目标死亡”采取行动

## Trigger
委派给子代理的任务返回运行级失败回执，且回执参与度指标为零（tools=0、tokens_in=0、tokens_out=0、rounds≤1）、错误类别为 LLM 流式总时长超限/滴流不收敛，任务本身可由父级上下文直接完成

## Discriminator
回执里的参与度字段（rounds/tools/tokens）：零参与说明失败先于任何任务内容发生，是通道级问题、与任务粒度无关；有参与后死亡才存在『失败点』，才谈得上缩小范围重派。一次读回执即可把『重试原派/换子代理/切小重派/等待/父级接管』五条分支缩成一条

## Short path
- 读失败回执的参与度字段与错误类别，先做分类：零参与+流式总时长超时=通道级病理
- 据此决定不向同一子代理通道重派任何粒度的任务（同通道大概率复现同款滴流超时）
- 检查剩余任务是否需要隔离：无隔离需求且任务有界⇒父级直接执行
- 父级确定格式与证据：grep 工具定义拿到存放目录名，ls -t store 拣最近一份已接受实例作权威样例；再定点 grep 源码逐条锚定拟提交断言
- 一次提交成功后落 checkpoint，报告 pending 状态与需人工决策的分叉，停止

## Stop conditions
- 提交回执返回 id 且状态进入审阅队列（pending_review）
- 任务确需子代理隔离（盲评、不可信内容、独立复审）⇒记录等待/换通道条件后停止，不在本会话强推接管

## Verification
- 提交 id 与 store 中新落盘记录一致
- 若同会话后续其它子代理调用出现同款零参与流式超时（本会话 reviewer 即复现），佐证通道病理假设成立
- 确认父级接管未破坏任务的隔离要求（如盲评盲态、审查者与执行者分离）

## Counterexamples
- 子代理已跑多轮、调用过多个工具后才死于上下文爆窗或轮次上限——存在任务内失败点，应按『重切范围再委派』处置，不适用本卡
- 任务本身要求隔离（机械盲评、不可信内容独立审查）——父级接管会破坏隔离不变量，只能等通道恢复或换通道
- 失败由父端输入引起（prompt 超长、参数坏导致的首包失败）——修输入后原粒度重派即可，无需接管

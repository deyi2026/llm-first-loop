## Trigger
用户指令按上一轮建议执行（『按建议执行』/『修 1/2/3』），建议清单中包含对权限、沙箱或读写门禁的放宽项，且该项正当性理由是一条『无害』性质断言（如『只读无副作用』『该限制过于保守』）。

## Discriminator
看两点即可裁决且都当时可得：(1) 无害断言覆盖了哪些威胁面——完整性论证（读不改动东西）对保密性不成立，越域读+域内写组合即外泄通道；(2) 闸门 choke point（如 file_service.observe 的 raise/判定点）docstring 是否已写明 uniform fail-closed 的理由。若已写明，前提被现成权威文本证伪，一次定义面直读即可，无需实现或实验。

## Short path
- 把计划逐项拆成前提问句：该项成立需要什么事实为真？放宽项的前提通常是『现行限制没有正当理由』。
- 对放宽项直读 enforcement choke point 定义处的 docstring 与设计注记，找文档化的 fail-closed 理由与威胁模型，而不是先动手改默认值。
- 比对威胁面覆盖：断言只覆盖完整性而文档理由点名保密性/组合通道 ⇒ 前提证伪，该项停止并引用原文行号作证据。
- 不折半实现：若放宽仍必要，重整形为宿主侧显式授权（环境变量 allow-roots 同构模式），授权不来自模型可控参数，立独立 SPEC 待批。
- 前提成立的其他项照常执行并用行为级验收：以门禁唯一接受的命令形态真跑；安全闸改动要求原绕过向量集结果不变、仅原因码变化。
- 收尾汇报：逐项列出与原计划的偏差、上轮编号/口径纠正（留纠正记录不改历史），把未执行项列为待授权步骤。

## Stop conditions
- 放宽项前提被 choke point 文档化理由证伪：该项不执行、不实现替代形态的一半，转为提案+等待授权
- 用户在看到证伪证据后仍显式授权原方案：按授权执行并在报告保留风险记录
- 其余项前提成立且行为级验收通过：汇报完成与偏差后停止

## Verification
- 证伪证据以原文位置（文件+行/docstring 段落）引用，不转述
- 已执行项验证到行为层：真跑门禁唯一接受的命令形态，而不是只看 mode 位或退出码
- 安全闸改动验收口径：原绕过向量集结果不变、只允许原因码变化
- 汇报中含与原计划逐项偏差表，包括编号纠正记录

## Counterexamples
- 行为与文档不变量相矛盾的缺陷（如 `..` 逃逸把零权 pattern 编译成 equivalent 且 root 落在工作区外）：方向是收紧/恢复不变量而非放宽，不触发『停做转提案』分支
- 纯可用性限制、无任何文档化理由且自证无组合通道：走正常变更流程即可，不必强制宿主配置化
- 机械事实型条目（谁 trim、几处退化、import 是否未用）：直接按 verify-finding-predicate-at-source 口径处理，本方法不增加信息
- 用户已在看到同一取舍后预先授权的放宽：无需重复停做，只需再标注与文档理由的冲突

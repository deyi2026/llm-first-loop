## Trigger
知识卡/经验卡/治理文档中的锚点或 freshness 引用指向当前工作树不存在的仓库内路径，需要决定恢复、重指还是失效；或上一轮/压缩上下文已按『文档被删』预设了处置分支

## Discriminator
该路径在所有分支的 git 历史（git log --all -- <path>，含删除记录）是否为空：空且无删除提交 ⇒ 文件从未存在，引用创建时就是错的；非空且有删除提交 ⇒ 内容可从历史恢复。辅判别：卡正文是否自包含（引用只是指针，还是承载卡的操作内容）

## Short path
- 发现引用路径不在工作树 → 把未知量定为『该路径的存在类别』，先跑 git log --all -- <path> 与删除记录，不预设『被删』
- 历史非空且有删除提交 → 从对应提交恢复文档内容，核对恢复版与卡引用语义一致后走修锚-恢复
- 历史为空 → 读卡正文判自包含性；自包含 → 在同族现存文档中按正文机制覆盖度（逐行对照，不看标题/文件名）选等价锚
- 重指：把锚点/freshness 引用换成真实文档并注明覆盖范围，同时清掉 description/正文里的悬空『详见』句，避免检索面继续挂不存在的路径
- 卡不自包含、操作内容确依赖该文档 → 走事实轴失效回执，不硬重指
- 收尾把治理规则里按错误前提写的措辞（如统称『被删文档』）修正为按存在类别分支

## Stop conditions
- 新锚路径经 git log --all 非空且工作树存在，正文机制覆盖已逐行核对并记录覆盖范围
- 卡正文与 description 中旧路径引用 grep 无残留
- 判定『从未存在且卡依赖它』并已签发失效回执

## Verification
- git log --all --oneline -- <新锚路径> 非空，且该文件当前存在
- grep 旧路径在卡目录与相关治理文档中无悬空残留
- 同族文档正文与卡核心机制逐条对照（如分层结构逐层映射），确认覆盖并列出未覆盖部分

## Counterexamples
- 引用是外部 URL 或跨仓库资源：git 历史不适用，改用 HTTP 状态/上游来源核实存在性
- 路径曾改名或移动：log 未跟随时可能误判『从未存在』，先按文件名词根与内容搜同族现存文件再定类别
- 文档存在但内容版本漂移：问题不是存在性而是新鲜度，走内容比对与引用版本更新，不做三分支
- 卡正文完全自包含且引用只是可选延伸：删悬空引用即可，无需强行找等价锚

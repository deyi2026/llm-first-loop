## Trigger
用户明确要求并行子代理执行由一份长文档（千行级，read 回执已给出总行数）派生的多个实现任务；父会话已读全文；子代理运行时的工具面（尤其有无上下文外置/压缩检索类工具）未确认。

## Discriminator
两个可先验事实：①首个 read 回执已给出源文档总行数，乘以子代理必读面即得输入下界，接近其窗口则预检必拒；②首败回执若写明『模型输入接近实际窗口且无可用上下文检索工具』，即为包体过大而非任务难度问题——应缩小必读面或父直写，不得重试同型大包。

## Short path
- 读源文档时记下总行数与既有分段结构（工作项表/不变量/契约清单），作为可蒸馏素材
- 并行 fan-out 前先派一个最小单任务子代理探路，确认该运行时的准入包体上限与工具面，未确认前不要多路同时派发
- 每个子任务包以父蒸馏的简报（≤3 个小文件+精确不变量+验收+轮次上限）替代『读整篇源文档』，简报本身可作为交接产物提交入库
- 首败回执指向输入超窗时判定为包体问题：压缩必读面或父直写该层；无法满足包体约束的任务标 blocked 并写明原因，不伪装进行中
- 无法压进包体的层由父直写收口，并把委派限制（文件数/禁读原文/轮数）写进交接文档供后续轮遵守

## Stop conditions
- 子代理以简报为唯一必读面、在轮次上限内产出文件且父侧本地测试绿
- 回执证实该运行时既无压缩工具也不接受任何更小切分 → 剩余层全部转父直写

## Verification
- 子代理 tokens_in 显著低于预检拒绝阈值（如半窗以下）且无零产出运行
- 产出文件与简报声明的不变量逐条对得上，父侧 pytest/ruff 通过

## Counterexamples
- 子任务天然是单文件小改、不依赖长文档 → 直接委派，无需探针与简报，先探路反而拖慢
- 子代理运行时明确具备上下文检索/压缩工具 → 输入下界不成立，允许其读源文档
- 任务本质要求对全文做一致性审查（输入就是全文）→ 简报无意义，应换工具面更强的子代理或父直接执行

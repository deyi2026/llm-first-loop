## Trigger
确定性机器门禁（准入/解析/校验器）记录了否定判定，且同一份工件/回执逐字携带该判定函数的完整输入（如 answer 尾部 VERDICT/计数行/绑定 SHA），二者表面矛盾；任务为只读诊断且未授权绕过门禁。

## Discriminator
reason 字符串在源码中是否唯一命中一个发射点、且该判定函数是否为可用回执逐字输入离线重放的纯函数——这两点在动手前即可把『哪一侧有缺陷』从猜测缩成一个可复现实验。

## Short path
- 读门禁工具完整 schema，枚举正式能力（解析诊断/格式控制/重判）；不存在则确认无正式修复路径，诊断全程只读。
- 在同一份工件中提取逐字输入与机器判定（不凭记忆重构），核对指纹绑定与截断标记。
- 用 reason 串做内容搜索；唯一命中才直读该判定函数，列出全部放行条件。
- 写只读脚本，把工件逐字载荷+指纹喂给当前仓库同名函数，记录各条件通过情况。
- 复现与记录矛盾 → 对账代码身份：判定时间 vs 进程启动时间 vs 相关提交合入时间三点交叉；解析进程自报 git_head 对应发布快照，diff 该函数快照 vs HEAD。
- 逐字节一致仍矛盾 → 停在进程边界：报告缺失的进程内观测通道（内存代码指纹/判定实参转储）与宿主侧解法（授权重启后用同指纹经既有 start 接口重跑 / 新增诊断接口），不重试 start/status、不改工件、不跑被门禁动作。

## Stop conditions
- 复现重现否定判定 → 根因即失败条件行，给门禁侧修复建议后停止。
- 复现矛盾且快照函数与 HEAD 不同 → 旧代码根因成立，重启加载新代码即可，停止。
- 复现矛盾且函数逐字节一致 → 已到静态分析边界，报最小阻断并 checkpoint 后停止，禁止向同一进程态重试门禁。

## Verification
- 复现输入必须取自承载该否定判定的同一文档的逐字段，并核对 body_truncated 等完整性标记。
- 确认 reason 串发射点唯一后，才把该函数当作真实判定路径。
- 代码对账必须 diff 进程自报快照中的该函数（如 .releases/<git_head>），不能只比 HEAD。

## Counterexamples
- 判定函数非纯（依赖网络/DB/时钟/进程内可变状态）→ 离线重放不复现属预期，不得断言进程异常。
- reason 串多处发射、或否定判定出自更上层前置检查 → 锚定单一函数会误导。
- 回执不含逐字完整输入（截断为真）→ 复现前提不成立，阻断本身即『输入不可得』。
- 自己有重启授权时 → 边界停报退化为『重启+同指纹重跑』，无需升级路径。

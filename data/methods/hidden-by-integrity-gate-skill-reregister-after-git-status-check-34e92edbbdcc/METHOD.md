## Trigger
技能/工具可用性清单回执中，被任务文本或派单单点名的条目缺席，且同一回执带『已隐藏 N 个未过基线/完整性校验的本地条目』类显式警告；或子代理行为像没有某护栏技能约束、怀疑该技能在子代理视角不可见

## Discriminator
清单回执的隐藏计数警告 + 引用名缺席 = 条目存在但被门禁隐藏（可排除『记忆拼接/真不存在』）；随后对条目路径的 git status 零输出且改动已有提交号 = 基线清单滞后而非脏改动，可安全重登记

## Short path
- 读可用性清单原始回执，把『已隐藏 N 个』警告当存在性证据：下一个未知量是『为何被隐藏』，不是『是否存在』
- 对隐藏条目路径跑只读 git status：干净且改动已提交 → 登记滞后；有未提交修改 → 停止自助修复，先审 diff
- 读登记脚本的诚实语义段（谁能跑、baseline 与 --approved-by 的区别），选择不冒充人工审阅的默认方式
- 重跑基线登记脚本重写清单
- 用同一清单面复验：条目出现、『已隐藏』警告行消失，才宣称修复生效

## Stop conditions
- 重新拉清单后目标条目可见且隐藏警告消失
- git status 显示脏改动，或门禁清单在只读挂载/外部系统、或隐藏原因本身是待人工安全复核 → 转人工决策，不代跑登记

## Verification
- 重新执行技能/工具清单查询，确认条目出现且『已隐藏』警告行消失
- 核对登记回执的批准者标识如实为 baseline/自报身份，未伪造人工审阅痕迹

## Counterexamples
- 清单无任何隐藏警告而条目缺席 → 是真缺失或记忆拼接，走引用核实路径，重跑登记脚本无意义
- 工作树对该技能有未提交修改 → 直接重登记等于把未审内容基线化，必须先审 diff 并走独立推送审查
- 门禁清单在只读挂载或由外部系统管辖 → 本方无重写权，只能上报
- 技能被隐藏本是因为等待人工安全复核 → AI 重跑登记会洗掉待审状态，属禁止动作

## Trigger
对某站点机器端点（API/清单）的发现性调用在 UA 轮换后仍持续 403，而同站点其他内容端点在本会话早些时候成功；目标未知量（如“已读文档之外仓库里还有没有别的东西”）尚未解决。

## Discriminator
工具回执明确是 HTTP 403 且已轮换 3 个 UA、curl 回退亦失败——这是授权层针对该端点类的封锁，不是 404/超时；同时同域兄弟内容端点（raw.githubusercontent.com）本会话已两次成功，说明封锁按访问面区分，并非整站不可达。

## Short path
- 先把未知量钉死：“已读材料之外，目标仓库/站点还有什么内容？”——这是枚举类未知量，不是阅读类。
- 走直取枚举面（API tree 列表）；未知量：机器可读清单是否存在且可达。
- 收到持续 403 回执后先分类失败：授权层封锁、身份轮换已穷尽；未知量：整站被封还是仅此访问面被封。
- 用会话内已有事实回答：同域兄弟内容端点几分钟前刚成功 → 只换轨一次，改取同一资源的人类可读面（仓库 HTML 页）；未知量：它是否列出顶层文件与描述。
- 读取 HTML 页面，从文件列表/描述解出未知量（本例：发布页仅 README+BibTeX，无其他文档）。
- 停止，并在结论中注明覆盖边界：HTML 面只反映顶层结构，不等于完整递归树。

## Stop conditions
- 备选面返回了所需清单/描述，未知量已解决（找到其他文档或确认没有）。
- 备选面同样 403 或承载不了所需数据（如需要完整递归树）→ 停止在同一路由类内继续换面，改选真正不同的路由（缓存/镜像/鉴权）或明确声明覆盖缺口。

## Verification
- 从工具回执确认失败类别是 403+轮换穷尽，而非 404/429/超时——各类别走不同预案。
- 确认备选面的主题与目标资源一致（同一仓库/同一路径）后，才把它的清单当作答案。
- 在最终回答中声明备选面的覆盖上限（HTML 页≈顶层+描述，非递归全树）。

## Counterexamples
- 404 或超时：资源缺失/不可达而非被封锁，换 HTML 面不会凭空造出内容；应去发现正确 URL 或退避重试。
- 429 限流：限流器通常覆盖整站，换面只会继续消耗配额，应先退避。
- 被封端点是所需数据的唯一载体（完整递归树、私有字段）且 HTML 面是纯 JS 壳——本方法的停止条件失效，需走缓存/镜像/鉴权路线并披露部分覆盖。
- 所需内容早已抓全在手——根本不需要枚举调用，本方法不应触发。

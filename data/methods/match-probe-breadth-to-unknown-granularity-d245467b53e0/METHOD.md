## Trigger
需要确认某来源（仓库/站点/文档包）在已读主文档之外是否还有其他相关内容，且目标是"有/无"判断而非完整清单或文件元数据。

## Discriminator
决策时已可见的缩小事实：(1) 未知量本身是存在性问题，递归全量枚举提供的粒度远超所需；(2) 同一会话中普通页面/原文通道（raw 文件、HTML 页）持续成功，而未认证递归 API 端点是本环境尚未验证、封锁风险最高的通道；(3) 主文档当时已读到尾部（引用/社区段），全文未见指向其他仓库文档的引用，"还有其他文档"只是"之类"式的低先验猜测。

## Short path
- 把未知量压成一句话："除主文档外，来源是否还有其他相关内容？"——确认它只需要有/无答案
- 查已读主文档是否有指向其他文档的显式引用：有则直接抓那个具体文件，跳过探针
- 无显式引用时，用一次低成本、同粒度的探针：抓来源的渲染页（文件列表与正文一次暴露），回答有/无
- 探针失败且失败语义为 403/封锁：只切换一次表示（API↔HTML↔raw/镜像），不重复同一通道
- 存在性结论落地后停止发现；写总结前把将被引用的原文段落水合进当前上下文，避免跨轮上下文丢失导致凭记忆写数字

## Stop conditions
- 存在性问题已有可追溯来源的回答（例如渲染页确认来源仅由主文档+引用信息构成）
- 总结所需的全部原文段落已在当前上下文，且与覆盖清单逐项对应
- 探针与备用通道都失败：该未知项明确标注"未能核实"，不得默认为"不存在"

## Verification
- "没有其他内容"的结论必须能指向一次成功抓取的具体来源，而不是由 API 封锁反向推断
- 摘要中每个关键数字/主张可对应到本次抓取的证据回执（source label + range/完整性字段）
- 失败语义已分类并驱动分支：403/404=通道或资源问题→切换表示；超时/5xx=瞬态→同通道重试

## Counterexamples
- 需要完整文件清单、路径或大小（如大仓库审计、依赖盘点）时，递归 API 正是正确粒度的工具，HTML 列表会被截断分页
- 主文档明确引用了具体附加文件（如 docs/prompting.md）：跳过存在性探针，直接抓被引用文件
- 来源页是 JS 渲染的 SPA、提取器拿不到列表内容：HTML 探针失效，此时才应使用 API 或 clone
- 失败回执是超时/5xx 而非 403：应重试同一通道，切换表示反而浪费调用并引入噪音

## Trigger
任务回执显示终态 success/exit=0 但本进程输出为空或退化，且回执文本明确指定了交叉验证通道（落盘文件/重定向/重跑）或警告勿仅凭本回执判定产出；而该结果正要被用作后续高成本或半不可逆动作（发布、重启、终局性结论）的依据。

## Discriminator
回执中显式存在的验证指令原文（本例："产出判定请以落盘文件或重定向交叉验证，勿仅凭本回执"）在首次读取时即已可见。它直接把未知量从"测试是否真通过"收窄为"找到该 job 的落盘日志或重跑后重定向读尾行"。对照地，通读 ci_gate.sh 用 set -euo pipefail 语义反推 exit=0 等价于走完全链路，得到的是推断而非一手证据；ls 无关 reports/ 目录也不会命中该 job 的产出。判据即：回执是否内嵌验证指令 + 待支撑动作是否带门禁性质。

## Short path
- 读到终态成功但 0 行输出的回执 → 未决量：产出是否真实且可证。以回执内嵌验证指令为下一跳，不先通读脚本源码做语义反推
- 沿指定通道取证：优先定位该 job 自身的落盘日志/产物文件并读尾行（成功标记）；一次未命中（如 ls 出的目录与该运行无关）立即切换到第二通道：重跑一次并重定向落盘后读标记行
- 一手证据到手后才执行门禁动作（publish/deploy）；调用参数按刚读过的 schema 逐字段构造（如 restart 必带 target），避免 missing 参数的失败重试
- 对两阶段异步动作只声明"已受理"并记录终态查询入口（action_id + status/event_stream），不宣布完成
- 用户问询的每个事实都有与其断言强度匹配的证据来源即停

## Stop conditions
- 指定通道已产出可读的一手证据（日志尾行/成功标记），且与回执终态一致
- 指定通道被证不可用（无落盘产物且重跑代价不可接受）→ 将结论显式降级为推断级并标注，门禁动作暂缓或带强度披露推进，不再继续在无关目录枚举找文件
- 本轮全部待证事实均已归类为：一手证据 / 推断级（已标注）/ 未核验（已声明）

## Verification
- 门禁动作之前的测试/审查结论引用的是被实际读过的产物（文件路径 + 尾行内容），而非仅回执的 exit code
- 最终答复中各结论的证据等级标注与实际证据类别一致（一手 / 推断 / 未核验），无把推断写成事实的条目
- 受门禁保护的下游动作（发布代际、重启受理）在时间上晚于其证据成立，且异步动作未被宣布为已完成

## Counterexamples
- 纯由退出码定义语义的检查命令（回执无"勿仅凭本回执"类警告、无产出核验要求）——exit=0 即充分证据，重跑只为看标记行属浪费
- 门禁动作廉价且完全可逆、推断已很强（如 set -e 全链脚本 + durable exit=0）——可直接推进并简注依据等级，无需阻塞等待更强取证
- 回执指定通道与目标产出无因果关系（指向的目录属于其他运行）——沿通道一次未命中即应改走重跑重定向，而不是在无关目录继续宽枚举

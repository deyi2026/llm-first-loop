## Trigger
续跑/恢复会话（如极简『继续』）在共享仓库发现一批连贯的未提交 tracked 改动+新文件，且本会话证据账本没有任何对这些文件的写入回执

## Discriminator
恢复时读到的任务状态/收口回执明确断言『tracked 文件干净』或其交付清单不含这些文件，而当前 git status 显示多处 M/新文件——矛盾证明归档后有写者；本会话又无写入回执，故写者是另一个会话/进程

## Short path
- 恢复时先读任务状态回执，记下其对工作树的断言与 seq/时间戳
- 取当前 git status / diff --stat 与回执断言对比；未知量＝这段 delta 的写者是谁
- 查本会话账本是否有这些文件的写入回执；没有则查写者归属：其他活跃会话登记、近期写入事件的 session id、文件 mtime vs 本会话启动时间
- 确认并发写者 ⇒ 停手：不提交、不跑会被其写入作废的闸门，把『谁收口/谁停』列为有界选项交用户裁决（单写者才可能过闸）
- 仅当归属到本会话谱系（回执/账本支持）才收编提交，范围由 status 全清单驱动并如实署名

## Stop conditions
- 写者归属已裁决：并发写者确认 ⇒ 交用户定单写者后不再动仓库；归属本谱系 ⇒ 按全清单收编并署名
- 回执断言与当前观测一致且账本含这些文件的写入回执 ⇒ 属于本会话在途工作，正常续做，无需并发排查

## Verification
- 提交前：这批改动的每个文件都能在本会话或本谱系回执中找到写入证据，或用户明示归属
- 过闸时审查切片确实只含自己名下的改动，无『切片之外漂移』回执复现

## Counterexamples
- 状态回执本身就列出这些文件是上轮在途交付（本谱系残留），直接按 salvage 全清单收编即可，不必先怀疑并发
- 单会话环境或已明确无其他会话可运行，残留假设安全（仍需回执交叉核对）
- 改动是可再生的构建产物/临时文件，作者归属不影响闸门与提交语义

## Trigger
沙箱或受限执行环境（会话内每条命令回执都带写隔离/sandbox-exec 标记）中，带『门禁未过禁止合并/发布』契约的全量门禁在最终候选的动态测试段成批变红；候选的静态棘轮与门禁前几段已全绿，且存在已知曾在无限制环境通过该门禁的同血统基线。

## Discriminator
三个当时已知事实同时成立：(1) 本会话所有命令回执均标注 sandbox-exec 写隔离；(2) 候选上静态棘轮双 PASS、门禁前段与定向测试全绿，红集中在依赖系统 temp/系统工具的段；(3) 同血统基线曾在无沙箱环境对该门禁 EXIT 0。三者把『N 个独立代码缺陷』缩成『单一共享环境因素』，并直接给出一个零风险可证伪实验：零修改基线同环境复跑。

## Short path
- 门禁动态段成批变红时，先固定未知量：红属于候选还是环境；禁止逐条 debug 或为红项修改候选
- 取零修改的原始基线 commit，在同一沙箱、同一 worktree 布局下复跑同一门禁段做对照实验
- 基线复现同一红集 ⇒ 判环境红：候选保持冻结，红项不修、不绕、也不计入候选质量信号
- 门禁契约仍未满足 ⇒ 停在合并/publish/restart 之前，不以『红是环境造成』自我豁免发布红线
- 转有界执行请求：环境全备（repo/venv/依赖/构建产物在场）+ 一条精确命令 + 预期耗时与 exit code，交无沙箱通道执行，不寻找歪路提权
- 收到无沙箱通道 EXIT 0 权威回执后，立即恢复受控合并→publish→Web-only 重启→行为验收序列

## Stop conditions
- 对照基线全绿或红集与候选不同 ⇒ 红为候选所有，转正常修复循环，本方法停止并禁止升级
- 存在不改门禁判定语义的会话内环境修正（如 TMPDIR 指向沙箱允许目录）且复跑变绿 ⇒ 原地解决，无需人工通道
- 无沙箱通道回执 EXIT 0 ⇒ 直接恢复后续受控动作，不重复运行门禁

## Verification
- 对照实验两侧除 commit 外完全一致：同一沙箱、同一命令、同一 worktree 布局，否则对照不构成归因证据
- 升级请求中给出可复制的一条精确命令与预期 exit 0，并核实环境确已备好（venv/依赖/构建产物在场）
- 以执行通道的完整日志与退出码为凭，不以口头转述当作门禁通过

## Counterexamples
- 对照基线全绿或红集与候选不同 ⇒ 是候选引入的回归，套本方法会把代码缺陷误豁免
- 门禁契约明文允许环境性豁免或沙箱豁免条款 ⇒ 直接记录豁免推进，无需人工执行通道
- 红集分散、无共享签名、分属不相关子系统 ⇒ 更像真实回归，先做异常类别分诊（errno 级方法）再决定是否跑基线对照
- 不存在任何曾通过该门禁的可用基线 ⇒ 对照只能证明环境共享红，不能排除候选特有红，需叠加逐红排查

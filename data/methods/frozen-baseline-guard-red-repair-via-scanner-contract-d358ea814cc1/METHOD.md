## Trigger
冻结候选在父侧原版 CI 门禁出现 tier0 架构守卫红（棘轮/红线/依赖边基线三类），而修复约束把基线、守卫、ci_gate、豁免全部锁死，只允许同树最小语义提取或搬移；守卫失败信息自带『重登记』提示但该路径被任务明令禁止

## Discriminator
一次定向重放后即可拿到的合同事实：失败输出逐函数给出 登记值→实测值 与未登记阈值；守卫源码显式列出被扫描的包根集合与边生成规则（哪些根的 import 被计数、哪些包不在扫描范围、某根仅允许指向哪些目标）；基线 JSON 给出登记边集与 legacy 值。这组事实把『搬去哪/怎么拆』从多个直觉选项缩成唯一合法解——例如共享层只能是消费方自己的包，新建顶层 shared 包仍会产生新边而必败

## Short path
- 定向重放原失败测试，逐字收集每函数 登记值→实测值、未登记项与新增边及其 import 位置；忽略守卫自带的『重登记』提示（该面已锁死）
- 读守卫源码提取测量合同：扫描哪些包根、边怎么生成与计数、阈值与登记从哪个文件读；读基线 JSON 拿登记边集与允许边
- 用合同推导合法变换：共享纯函数原文搬进消费方所在的被扫描包内新模块（包内 import 不产生跨面边），原属主改 re-export；≥阈值的未登记/超登记函数按 diff 语义切出 gate/builder/分派等 helper，压到登记值以下或阈值以下
- 加单实现防漂移测试：断言两个消费方引用同一函数对象（a.f is shared.f），且新消费方源码不再含被禁方向的 import
- 先只重放三项原红到 PASS，再跑守卫全套与相关专项，冻结新 commit/tree；若代码变化使旧审查失效，只报告不自行重审/重跑门禁

## Stop conditions
- 三项原红定向重放 PASS、守卫全套绿、新 commit/tree 已冻结，且基线/守卫/ci_gate/豁免文件 diff 为零
- 读完合同后确认不存在不改基线的自然语义边界（函数增量无法提取、或共享代码非纯函数不能搬）时，停止并上报，不擅自放宽

## Verification
- kernel 边集合与基线逐项一致，无任何新增边
- 曾红函数 实测≤登记值 或低于未登记阈值（如 <120）
- identity 断言两个消费方引用同一函数对象，且禁方向 import 已从消费方源码消失
- 基线/守卫/豁免路径 git diff 为空；新候选 SHA 已对账并写入 receipt

## Counterexamples
- 守卫红属于继承侧基线债且所有权方授权迁移基线：应走基线重登记流程，而不是搬代码绕行
- 被共享的函数不是纯函数（含状态、IO 或路径归属语义）：机械搬进消费方包会改变语义，需先拆出纯内核再搬
- 失败根因是环境或产物可见性（如新文件只暂存未提交、产物 tier 看不到）：与测量合同无关，读扫描器源码不解决
- 目标函数本已低于阈值、红来自守卫自身变更：先核对守卫 diff 再动代码

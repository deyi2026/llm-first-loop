## Trigger
交付/推送闸口前，checkpoint、设计/交付文档或子代理自述里存在成功数字（测试计数、零改动声明、门禁结论），而最终树在这些记录生成之后又落了提交（自己的修复提交或并发写者会话的提交）

## Discriminator
继承的 PASS 数字指向的是旧树：判别问题只有一个——权威验证命令是否在本轮将要推送的确切 commit 上由本轮亲自跑过？若否，数字不可引用。首个证伪信号是复跑出现前序从未报告的失败（如实际 1 failed / 12254 passed 对文档声称的 12223 passed）。

## Short path
- 闸口处列出从前序记录继承的全部验证性断言（测试计数、零改动声明、门禁结论），标注每条断言对应哪棵树
- 对将要推送的确切 commit 亲自重跑一次权威验证命令（全量套件/门禁探针），不引用记录里的数字
- 复跑出现新失败时先分类：看失败断言的写法与致变提交的性质——是守卫测试断言了字面量（源码文本/注册表快照）被合法并发演进打破，还是交付代码真回归
- 字面量守卫被合法演进打破：把断言升级为行为级（注册表直查 + ast.parse 判调用），不改 src 迁就旧字面量、也不抬 baseline
- 在文档中就地标注更正（保留历史原文、注明复跑数字），聚焦复验绿后重新过闸，直到门禁在确切推送树上 PASS

## Stop conditions
- 权威命令已在本轮将要推送的确切 commit（同 SHA）上跑过且结果与断言一致
- 新失败已定位到断言层或代码层之一并按对应层修复，聚焦复验 + 门禁 PASS
- 更正已就地写入文档且未删除原始历史记录

## Verification
- 复跑所在的 commit SHA 与实际推送的 commit 一致（隔离环境时确认 delta 基准 = 推送 base）
- 升级后的守卫测试仍能抓住其原本要防的行为（做一次负例检查），不是单纯放宽
- 文档最终数字与复跑回执一致，被证伪的旧断言保留并带更正标注

## Counterexamples
- 单会话且树自上次全量记录后未移动：直接引用已记录结果即可，重复跑数十分钟级全量是浪费
- 复跑失败定位为交付代码的真回归：修代码而不是修测试，不得以『行为级升级』为名弱化守卫
- 任务中途快速迭代（非闸口）：用聚焦测试迭代，全量复跑留到闸口一次

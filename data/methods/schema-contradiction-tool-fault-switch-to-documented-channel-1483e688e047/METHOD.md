## Trigger
浏览器/外部工具在任务中途反复失败，且错误内容与工具自身 schema 矛盾（schema 显示已提交参数形态合法，错误仍断言缺少对象/格式不符），同时此前检索已命中记录同一任务替代通道机械细节的已验证经验卡。

## Discriminator
两条当时已知事实同时成立：①schema 回读证明参数合法，且同一错误在第二次合法输入上复现，可排除单次输入错误与瞬态环境中断（后者错误签名不同，如绑定目标消失）；②第一轮检索命中的已验证经验卡已给出替代通道的具体可用细节。二者把候选从『继续调试该工具/怀疑页面』缩为『换通道执行』。

## Short path
- 首次失败先回读工具 schema 比对已提交参数：确有类型/语义错误则修正后重试一次，留在原通道
- 若 schema 确认参数合法而同一错误在再次合法输入上复现，判定为工具层故障，禁止第三轮同型调用
- 从已命中经验卡提取替代通道的已验证机械细节，剩余写入/操作全部改走替代通道
- 用与通道无关的页面级证据核验：按平台规范的持久化节点计数（不把上传浮层/loading 容器计入）、发布类动作收尾回读线上终态 URL
- 收尾报告显式记录故障工具、错误签名、判定依据与替代通道，供工具层排查

## Stop conditions
- 替代通道完成同一写入并经通道无关证据核验通过
- schema 比对发现参数确实非法（矛盾不成立），修正后原通道恢复正常
- 错误签名属环境中断（绑定目标消失/连接断开）而非 schema 矛盾，改走重新观察/重绑路径

## Verification
- 以平台规范持久化节点选择器统计已插入媒体数量并与预期一一对应；瞬态容器不计数
- 发布/提交类操作收尾回读线上终态 URL，结论不依赖故障工具的回执
- 判定过程可复查：schema 引用、两次合法输入的错误复现记录、替代通道所依据的经验卡

## Counterexamples
- 错误源于参数语义误用（如应传数组传了字符串），schema 一读即可修正：此时换通道会掩盖自身输入 bug
- 故障是瞬态环境中断（绑定浏览器目标消失）：应重新观察/重绑，而非弃用健康通道
- 经验库无已验证替代通道，或替代通道缺少唯一必要能力（如登录态语义 grounding）：应上报并调试工具而非硬换
- 仅一次失败、未做 schema 比对与修正重试：证据不足以判工具层故障，不能触发换通道

## Trigger
评审/验证任务：对象已具名（版本化文档或具名 artifact），验证点均在其内部章节；可用的检索线索只是裸短标识符（编号类 ID），或首个 search 回执已显式列出目标文档名

## Discriminator
knowledge-at-time：任务上下文或首个 search miss 回执已具名目标文档并注明当前版本，且评审重点声明『其余部分已核验勿重复』；若尝试裸 ID 宽搜，结果里同一 ID 撞多个无关命名空间——这一可见事实本身即证明该关键词无判别力，应改为对目标文档的定点读取

## Short path
- 由具名评审对象直接 read 目标文档全文（未知量：焦点章节的当前文本），跳过裸 ID 的全库宽搜
- 对已固定的追问点直接基于读入文本作评审；若问题集已在任务参数中写死，不再驱动交互式多层追问壳（其首层可能返回空模板）
- 仅当某焦点章节的判断依赖文档外部且未标『已核验』的事实时，解析那一条引用做定点查证；对声明已核验的章节（如跨文档对齐）不做重复验证
- 结论落编辑时逐处串行修改并核对写后复读的 diff 回执；焦点判断所需事实均来自目标文档自身即停

## Stop conditions
- 目标文档全文已读入，所有焦点章节判断所需事实均在手
- 每处修订均有写后复读一致的 diff 回执，无未落地的评审结论
- 焦点判断不依赖任何未验证的外部声明（或已定点查证完毕）

## Verification
- 确认任何进入修订依据的事实，其出处都是读入的当前版本文本的章节/行，而非宽搜命中的同名异 namespace 条目
- 确认宽搜若执行过，其拉回的其他 namespace 同 ID 条目未被用作评审证据
- 确认未对任务明确声明『已核验勿重复』的部分做再次查证（复查 diff 是否越界改动焦点外内容）

## Counterexamples
- 任务本身就是标识符普查（『找出 R4 在全库的定义与使用点』）——全库宽搜正是正确动作，本方法不适用
- 焦点章节的裁决依赖一条未标『已核验』的外部跨文档事实——必须先定点查证该引用才能下结论，不能只读单一文档
- 具名文档的时效性本身存疑（可能存在更新的决策记录）——需先确认哪份是当前权威版本，这属于续跑/权威记录类方法的领域
- 评审对象尚未具名、需先发现候选文档——此时的目录/搜索层发现是必要前置，不能跳过

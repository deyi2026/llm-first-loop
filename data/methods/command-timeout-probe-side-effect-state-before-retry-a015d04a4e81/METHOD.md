## Trigger
副作用命令执行后回执为超时（无退出码、无成功/失败凭证），效果是否落账成为未知量；或计划内的只读侦察批次即将夹带无关变更动作时

## Discriminator
超时回执可观察地区别于结果回执（无 rc、无失败字面量）；当环境中已知存在慢 hook 与一次性/不可逆资源（如一次性审查资格、不可逆队列条目）时，盲重试有二次成本，而权威后状态可用一次只读调用廉价取得

## Short path
- 把第一个未知量固定为『副作用是否落账』，用一次只读权威状态查询回答（git log --oneline -1 + git status --short；登记类操作则按 ID 查登记簿）
- 已落账：从确认后的状态继续原计划，不重发命令
- 未落账：先查现场（暂存区/队列内容），针对超时成因（慢 hook、范围过大）拆小或改小后再试一次
- 仅当重试被证明幂等且不消耗一次性资源时，才允许免探测直接重试
- 只读侦察阶段不夹带无关变更动作：副作用命令独立成批执行，超时才不会污染主线未知量

## Stop conditions
- 权威状态回执确认副作用恰好存在一份（无重复提交、重复登记或二次资格消耗），即回到原计划
- 命令可证明为只读（无副作用）：超时只需收窄范围重跑，无需状态探测

## Verification
- 在权威状态中核对副作用唯一性：目标提交/登记恰好一条，一次性资格消耗次数符合预期
- 后续动作依据探测后的真实状态，而非超时前假设或超时回执本身

## Counterexamples
- 只读命令（grep/ls/单测）超时：无副作用未知量，直接收窄范围重跑，状态探测是纯开销
- 协议级幂等登记（唯一键去重、重试不消耗一次性资源）：直接重试比先探测更省
- 超时回执自带明确『未执行/已回滚』凭证的操作：凭证即状态，无需另查

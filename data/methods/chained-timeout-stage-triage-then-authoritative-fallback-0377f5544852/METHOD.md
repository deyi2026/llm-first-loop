## Trigger
多阶段链式命令（本地 git/文件操作 + 网络推送/开 PR 等副作用操作）收到裸超时且无部分输出，需要判断哪个前缀已完成才能安全重试；或需先确认远端副作用是否已发生以避免重复

## Discriminator
本会话此前所有本地 git/文件操作回执均在秒级完成，而超时落在链尾网络阶段——据此可推断本地前缀（commit）大概率已完成、卡点在网络尾部；且可达性探针必须用显式短超时（如 curl -m 6）按端点分别测，不能用真实工具（git push/gh/ls-remote）当探针——后者会挂到整体超时而非快速失败，这正是第二次 60s 超时的原因

## Short path
- 超时后只跑纯本地状态命令（git log/status）确认链头本地阶段的产物与位置，分诊命令绝不夹带任何网络子命令
- 对涉及的每个不同远程端点用显式短超时探针分类可达/阻断，得到分裂态图谱（如主站阻断而 API 端点可达）
- 用已验证可达且已认证的通道查询权威远端状态（分支/PR 是否已存在），据此排除或确认重复副作用，再决定重试范围
- 若原生传输（https git、ssh-over-443 及各 key）逐一有界探测均失败、而 API 通道可达：改用 API 原语重建最终状态（blob→tree→commit→ref，基于远端已有基线）
- 以内容寻址校验收尾：远端 tree sha 与本地逐字节一致 + 远端 ref 指向预期 head 即视为 push 等效完成，再经可达通道补齐剩余动作（建 PR）并停止

## Stop conditions
- 每个阶段的真实状态均已由本地证据或权威远端查询确认（本地产物在/不在、远端效果有/没有），不再存在未知阶段
- 远端内容寻址哈希与本地一致，且副作用（PR/ref）经权威通道确认唯一无重复
- 操作幂等且可去重、远端状态已确认时，可停止分诊直接补做缺失的最终一步

## Verification
- 任何重试或重建前，先经权威通道列出远端分支/PR，确认目标副作用不存在（避免重复 PR）
- 远端 ref head 与本地 commit sha 对齐，且远端 tree sha 与本地 tree sha 完全相等（内容寻址证明逐字节一致）
- 所有分诊/探测命令均带显式短超时上限，复查分诊阶段不再出现 60s 级整体超时

## Counterexamples
- 超时的慢阶段是本地计算（构建/测试/索引）：端点探测与网络分诊无意义，应转查进程、日志或锁
- API 查询发现远端效果已存在（分支/PR 已建）：跳过重建与重试，只补缺失步骤，否则制造重复
- 所有端点均阻断、或无已认证 API 通道：API 重建回退不可用，正确动作是等待或上报而非继续枚举绕行
- 副作用非幂等且无权威查询通道：任何形式的重试都不安全，分诊结论只能是停手上报

## Trigger
需要确认某类记录的全量规模（如待处置 candidate 池）但存储只提供关键词检索且无 list/count 端点；或存在一个待验证的规模先验（如'只剩 4 张'）而该先验可被一条类目查询廉价证伪

## Discriminator
第二次查询结束时已可观察的两条事实：(a) 零命中回执明示'未找到匹配（不伪造结果）'，证明匹配是字面词级、召回受查询词限制；(b) 换词后两次结果集互不嵌套（各自含对方没有的稳定唯一 ID），证明没有任何单查询覆盖全池。这两点当时即可把'逐个换词直到感觉搜全'判定为无停止条件的搜索空间扩散，并把未知量收敛为'边际新颖度何时坍缩'

## Short path
- 起点先做最便宜的先验证伪：用一条最宽的类目查询（如 kind=method）对照此前的规模断言；未知量=池子真实大小
- 第二条查询换正交维度（status/日期窗/生产者）；对比两次结果的稳定唯一 ID 集合，互不嵌套即当场确认召回不完整，承诺分面扫描设计而非继续零散换词
- 按正交分面批量查询并维护唯一 ID 并集，计算每分面边际新颖度；连续 2 个最异质分面新增 0 个 ID 即停止，把 N 记为有界下界
- 并行执行与枚举独立的子交付物：一收到'无活动目标'信号即 create_goal，self_eval、schedule 不阻塞在枚举之后
- 对并集内每张卡按家族分批落 qualification 处置；汇报时明示'N 为下界非全量'+残余风险+增量复核日期

## Stop conditions
- 连续 2 个正交分面（选维度差异最大的）新增唯一 ID 为 0，新颖度坍缩
- 到达用户或资源边界——显式以'下界+复核计划'收尾，而不是继续无界换词
- 并集内全部记录完成处置、各独立子交付物均已获得落盘回执

## Verification
- 最终计数等于唯一 ID 并集大小，而非各次命中数之和（重叠未重复计数）
- 每条 qualification 回执中的 method ID 均存在于并集中；零命中回执确属'无记录'而非静默查询失败
- 汇报显式标注下界性质并绑定增量复核安排（如后续检查点复核）

## Counterexamples
- 存储本身提供 list/pagination/count 端点——一次拉全量即可，分面扫描纯属浪费
- 查询结果可嵌套（宽查询按全局稳定排序取 top-N 即覆盖全部）——单次最大 limit 查询可能已足够，无需多分面
- 任务只需定位具名子集（如上周某 3 张卡）——定向查询即可，不应触发全量枚举
- 记录无稳定唯一 ID——并集与新颖度核算失效，须先解决去重键，否则本方法不适用

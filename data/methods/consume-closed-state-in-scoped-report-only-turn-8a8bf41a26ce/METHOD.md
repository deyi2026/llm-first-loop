## Trigger
用户消息把本轮限定为『只审查/只报告+等待下一条消息』并逐字列出禁做动作；同时任务状态快照已标记终态闭合且写明已交叉核验、无新反证不重复核验

## Discriminator
当时已见的两条事实即可闭合本轮动作空间：(1) 用户消息本身含禁做清单与『等待』指令，即本轮合同只是转述；(2) 状态快照已闭合并写明『已交叉核验，无新反证不重复核验』——本轮不再存在需要新工具调用回答的开放未知量，唯一剩余工作是把终态事实如实组织成报告。

## Short path
- 解析约束消息，提取禁做清单与等待指令，确立本轮合同=报告+待命
- 读取已闭合状态快照，确认终态事实：资格判定、材料指纹三方一致、问题计数、回执缺失字段
- 检查有无新反证（指纹漂移/并发写手）；无则不重验、不重poll，直接消费快照
- 撰写报告：终态事实+来源、缺失字段如实披露（只披露不回填）、逐字重申禁做清单显式冻结下游动作
- 把会影响后续闸口的未决风险（如 baseline 与 delta 的拓扑疑点）作为待决事项移交用户，本轮不处置
- 停止，等待下一条消息，不执行任何超出报告范围的动作

## Stop conditions
- 报告已包含终态事实、缺失字段披露、禁做清单重申、待决事项移交，且无任何越权动作
- 用户所需事实已由闭合快照权威覆盖且无新反证出现

## Verification
- 报告中每条事实可回溯到快照/回执显式字段，无凭空补齐
- 禁做清单与用户消息逐字对应，无擅自增删
- run 尾部对已终态闸无重复 status 调用、对已核验事实无重验记录

## Counterexamples
- 状态快照未闭合或出现新反证（材料指纹漂移、并发写手改写）→ 直接消费快照是错的，必须先重新核验
- 用户未冻结下游动作且资格已 PASS → 应消费资格进入下一步，而非待命
- 待决风险动摇本轮结论本身（PASS 存疑）→ 不能只移交，须本轮解决或显式降级结论

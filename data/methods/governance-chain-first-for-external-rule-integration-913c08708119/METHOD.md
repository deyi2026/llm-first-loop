## Trigger
需要把外部来源的规则/约定整合进已有治理体系的项目，落点、命名及与现有规则的冲突关系未知，且项目根目录列表中已可见 agent 契约类入口文件（或后续读到自declare的真相源声明）。

## Discriminator
第一次根目录列表已显示 AGENTS.md 这类 agent 契约入口，而任务对象恰是'规则/规范'——该因果边在任何广度搜索之前就可用；随后读到的规则文件标题自declare '唯一规则真相源'，连同守护测试与 admission asymmetry 条款，把'放哪、跟谁对照、什么不能写'从全库候选缩成一条权威链。

## Short path
- 列根目录后直接读可见的 agent 契约入口；未知量：该项目对新增规则/文档有什么治理约束。得到准入政策、安全契约指针和规则命名体系。
- 沿规则命名体系定位并读规则 SoT 的标题与目录；未知量：规则真相源是什么、新规则能否写入。得到 SoT 范围声明与现有规则清单。
- 对来源文件 grep/读取外来规则的准确原文；未知量：6 条规则的真实内容（不用记忆转写）。
- 定向读 SoT 中语义相邻的具体条款；未知量：每条外来规则与哪些现有规则重叠/冲突。逐条输出采纳/限制/否决三分结论并引用条款。
- 按 SoT 范围声明与命名惯例选落点（范围外的表达层内容独立成文，不污染 SoT），写入并运行守护测试，通过即停。

## Stop conditions
- 治理链（入口契约 → SoT）读取完毕，且每条外来规则都有带条款依据的采纳/限制/否决结论
- 外来规则原文经当轮读取核对，落点文档通过 SoT 同步/清理守护测试且有 success 回执

## Verification
- 逐条 triage 引用具体具名规则/条款；每个否决必须指出照搬会复现的受保护规则或已知事故形状
- 落点选择同时满足 SoT 范围声明与现有命名惯例，并以守护测试成功回执证明
- 引用的外来规则原文来自当轮对来源文件的读取，不得凭记忆或旧记录转写

## Counterexamples
- 绿地或个人项目：无 agent 契约、无 SoT 声明、无守护测试时，目录惯例与广度发现是合理起点，本方法无权威链可沿
- 用户已明确指定落点文件：直接写入即可，仅当内容与已知契约冲突时才启动治理 triage
- 外来材料是纯内容（文章/数据/说明），不含规则语义且不改变仓库行为：无需 admission/triage，直接写作

## Trigger
续跑/接手会话中，收口或状态回执同时显式给出工作区绝对根（workspace 字段或项目根路径）与待办文档/工件的相对路径；或一次读取已因『目录不存在/文件不存在』失败且回执提示该路径族已登记不存在

## Discriminator
同一回执内『绝对根 + 相对路径』两字段并存——机械拼接即得唯一目标路径，候选根集合已被解析为 1；目录级『不存在』回执进一步把整个猜测根族证伪，换同族根重试零信息增益

## Short path
- 从状态/收口回执提取 workspace 绝对根与待办文档相对路径，拼成绝对路径——未知量从『文档在哪』变为『文档内容是什么』
- 直接 read_file 该拼接路径，取待办项定义、位置、决策点
- 按文档内给出的符号/位置定点 search_files 定位源码定义，不做目录级枚举
- 仅当拼接路径一次 404（文档确不在该 workspace）才降级为文件名搜索，一次即止，不再尝试第二个猜根

## Stop conditions
- 已读到登记/待办文档全文，拿到各项定义与位置，即停止一切路径发现
- 拼接路径失败一次后只允许文件名搜索这一个降级动作，禁止再枚举候选根
- 根确认后，本会话所有文件操作以该根为前缀，不再回头猜测

## Verification
- 回读文档的日期/来源字段与状态回执所述一致（登记日期、来源 commit、审查轮次）
- 实际读取成功的路径，其目录前缀等于状态回执的 workspace 字段
- 降级搜索命中后核对所在根与状态回执根是否一致；不一致说明文档在另一 checkout，需注明归属再继续

## Counterexamples
- 状态回执只给文档名不给 workspace 根，或根属于另一台机器/另一个 checkout：拼接不可用，文件名搜索是合法第一步
- 相对路径在会话间已被移动或改名（状态过期）：一次拼接失败即转搜索，勿再猜根
- 目标文档是本会话待新建的产物而非既有工件：读取失败是预期结果，不是路径错误
- 状态回执的 workspace 本身指向陈旧快照镜像（如 .releases 副本）：先以 git 回执的真实工作树为准再拼接

## Trigger
长驻网络守护进程（cloudflared/frp 等隧道、代理类）进程存活且持续重试，但活跃连接数为 0、公网入口返回隧道类错误；其日志反复出现对同一固定 IP 段的 dial timeout，且启动参数中带源地址/网卡绑定（--edge-bind-address / --interface 类）。

## Discriminator
日志中的拨号目标 IP 落在合成/保留 DNS 段（fake-IP 常用 198.18.0.0/15 等），而 ps/服务定义又显示该进程绑定了绕开该代理数据路径的物理接口或源地址——『目标只在代理路径内可解析可达，拨号却被绑定绕开』的组合。此组合在读取日志当时即可证实重试永不收敛，把『0 连接+持续重试』下的多候选根因（origin 宕、网卡消失、瞬态网络、解析污染）一步缩成一个，并直接否定『等待自愈』分支。

## Short path
- 从 ps/服务定义与日志尾部一次读齐三个未知量：进程是否在重试、拨号目标 IP 段、是否存在绑定参数
- 交叉核对判据：目标段是否合成/保留（198.18.0.0/15 等）且绑定绕开该段的生产路径；以同机未绑定实例的健康状态作对照
- 判据成立 → 跳过 origin/全局连通性重复检查与观察等待，直接经进程管理器（launchctl kickstart / systemctl restart）做一次强制重新解析的干净重启
- 以同一判据验证修复：守护进程连接数恢复（如 readyConnections>0）且公网带错误码探测的原错误码消失
- 判据不成立 → 回落既有分层排查（origin→进程→控制面），允许短暂瞬态观察窗口

## Stop conditions
- 重启后守护进程活跃连接数>0，且公网探测返回正常业务响应、原隧道错误码不再出现
- 日志判据不成立（拨号目标为真实公网 IP、无绑定参数、或该段属环境合法用途），停止套用并改走常规分层排查

## Verification
- 重读守护进程 metrics/控制面：活跃连接数>0（如 readyConnections=4）
- 公网侧重复一次带错误码探测：原 530/1033 类错误消失、返回预期业务状态码（如 303 跳转登录页）
- 对照确认同机未绑定实例仍健康，修复效果只归属于被判据命中的那个实例

## Counterexamples
- 拨号目标是真实公网 IP 的 i/o timeout（本机链路瞬断或对端故障）：存在等待自愈的可能，不应仅凭超时就重启
- 198.18.x.x 仅作为连接源地址/统计字段出现而非拨号目标，或进程没有任何绑定参数：『fake-IP×绑定』组合判据不成立
- 实验室性能基准环境合法使用 RFC2544 段（198.18.0.0/15）作为真实可达地址：段命中不能推断为解析污染

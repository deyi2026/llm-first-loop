## Trigger
要把一个『上轮用过且有效』的委派任务书/提示词模板重新发给一批子代理（评审员/评分者），但其权威文本未持久化：文件名与内容搜索无命中、产出提交的文件足迹只含回执/账本/状态翻转等结果工件；或首波代理已出现同字段同方式的批量格式违约

## Discriminator
当时已可见的三条事实：(1) 模板检索无命中；(2) 上轮产出提交的 --stat 文件清单里只有结果工件、没有任何输入/模板文件——『验证过的文本』不可恢复，重述必然未验证；(3) 若首波已回，多代理在同一受约束字段上以同一方式违约（如词表外自造短语）证明缺陷在共享任务书而非个别代理。任一成立即不应再按『已验证模板』对待。

## Short path
- 恢复硬事实后，把『上轮模板是否持久化』当显式未知量：文件名/内容搜索 + 看产出提交的文件足迹
- 足迹只含回执与状态翻转 → 判定模板不可恢复：停止继续找模板，按既有纪律重建，并给重建稿降级为未验证
- 按门禁自身词表加固重建稿：一份合格回执的字面 JSON 示例 + 每个受约束字段的枚举值域 + 一致性红线（如存在 unverified claim 时 promotion 不得为 pass）
- 放 2 个试点代理，机械校验其回执（枚举字段合法、红线不违反）通过后，一次性撒剩余批次
- 把加固版模板提交入库，使下一轮模板可恢复、不再重建

## Stop conditions
- 试点回执通过与首波完全相同的机械门禁（枚举值域合法、一致性红线无违反）→ 剩余批次一次性放行
- 模板在仓库中确有持久化命中 → 直接复用原文，跳过重建与试点
- 违约为个别代理且纠正预算充足 → 走逐个纠正分支，不改共享任务书

## Verification
- 对比首波与试点在同一门禁下的违约率：应从批量级（如 6/8）降为 0/试点数
- 确认加固模板已出现在提交文件足迹中，下轮模板检索可命中、无需重建

## Counterexamples
- 模板本就持久化在文档或提交里 → 直接复用，试点只增加延迟
- 批量只有 1–2 个代理 → 试点-扩展的开销超过单次按回执重试
- 违约是实质裁断错误（格式合法但结论缺证据）→ 字面示例救不了，需换评审者或补证据，不是合同问题
- 输出无枚举约束时，完整字面示例可能诱发照抄示例值 → 只给字段级 schema 而非整份示例

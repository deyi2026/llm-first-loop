## Trigger
用户问'是不是最近合并/分支/改动导致某行为倒退了'，且无报错、无红测试等客观回归信号，唯一依据是用户对过去行为的印象；所称旧行为落在当前版本库内、可映射到具体符号/端点/字段。

## Discriminator
前提中可提取的存在性断言本身：用户命名的领域词（如审批/登记/exec）就是现成检索键，且旧'合并行为'是否对应过真实端点/调用，可由当前定义面 rg + git log --all -S/-G 一步裁决——因此跳过 search_files/全目录枚举等宽发现，也无需运行时实验。

## Short path
- 把问题拆成两个可验证断言：A=过去存在该合并行为（存在性）；B=近期合并改变了它（变更性）。
- rg 用户命名的领域词定位定义链与路由表，确认当前职责分工（哪个环节产生哪个状态）。
- 对关键符号做 git log --all -S/-G：裁决该行为是否曾存在、何时引入、近期合并实际触碰哪一层（源码 vs 展示层/构建产物）。
- 用台账/近期同类记录交叉验证当前链路与历史一致。
- 作答：或给出回归 commit，或宣布前提不成立——并区分'用户的操作性印象'（常正确）与'机制模型'（常错误），分开回应两者。

## Stop conditions
- 存在性断言已由当前定义面+全历史检索一致裁决，且近期变更的实际影响面（哪些 commit、哪一层）已定位。
- 发现前提为真（旧行为确实存在且被改动）→ 停止前提溶解，转入定位回归 commit 与最小修复。
- 每条历史断言均映射到可复核工件（源码行/commit/台账）后才回复。

## Verification
- 答案中'从未存在''零改动''未变'类断言逐条回指 git log -S/-G 输出或当前源码行。
- 确认 --all 检索覆盖了可能承载旧行为的分支，而非仅当前分支。
- 剔除 dist/生成产物命中，存在性结论只基于源码路径；历史过浅或经重写时，把'从未'降级表述为'可见历史内'。

## Counterexamples
- 症状是运行时/数据层现象（缓存、配置漂移、环境差异），代码无对应符号变更——静态历史证明无效，应转 baseline+单变量实验（method-root-cause 场景）。
- 用户描述的是外部系统或另一仓库的历史行为，本地 git 历史与命题无关。
- 已有客观失败信号（报错/红测试）指向真实回归——直接 diff/bisect 定位，不必先做前提溶解。
- 版本历史经 squash/重写或过浅，'从未存在'证据力不足，只能表述为'可见历史内未出现'。

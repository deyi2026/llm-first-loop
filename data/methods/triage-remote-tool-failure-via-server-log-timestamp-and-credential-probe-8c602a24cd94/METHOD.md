## Trigger
远端/外部客户端调用本方 MCP/HTTP 工具失败，错误为统一包装（generic internal failure），真实原因被客户端折叠；用户或自己已给出拓扑类归因（隧道断/服务挂/最近关过某组件）并倾向先回滚；服务端日志与凭证存储本地可读，失败调用时间点已知或可估。

## Discriminator
服务端日志在失败调用时间窗内是否有对应事件（本例首条 ps 命令即暴露了 sidecar 日志路径）：命中鉴权失败→凭证问题，链路与服务当场排除；无事件→链路问题；5xx→服务问题。辅助判别：无凭证探测得到 401/403 本身即链路活的证据（响应穿透公网→代理→服务端），超时/530/1016 才是链路断。

## Short path
- 记录失败调用确切时间戳；未知量：请求是否到达服务端。在本地服务端日志 grep 该时间窗（±1min），按命中事件类型分流：鉴权失败→凭证层；无事件→链路层；5xx→服务层
- 分流到凭证层时：从服务端权威存储（DB/配置）读当前 token，带它经与客户端相同的完整公网路径调一次 tools/list；未知量：服务端侧三层是否全好
- 返回 200 且工具清单包含失败的那些工具 → 服务/链路/服务端凭证全部证活，唯一剩余差异是客户端持有旧 token（对照 token updated_at 与客户端配置时间）
- 最小修复：仅在客户端更新凭证，服务端零变更；在分流完成前不执行任何回滚/重启

## Stop conditions
- 带权威凭证的端到端公网调用返回 200 且包含目标工具 → 停止服务端侧排查，结论锁定客户端凭证
- 日志时间点对齐完成、三层分流出唯一目标层之前，不执行回滚/重启等拓扑变更

## Verification
- 结论须与日志时间戳一一对应：客户端每次失败 ↔ 服务端每条事件
- 修复仅作用于判定的那一层；服务端零变更后问题即应消失（客户端更新凭证后接口恢复）

## Counterexamples
- 客户端错误已明确分类（如明确 DNS 解析失败/连接超时），可直接进链路层，无需日志对齐
- 服务端日志不可得（纯第三方 SaaS）或与客户端时钟漂移大，时间戳对齐失去判别力，退回黑盒探测
- 失败为间歇性且时间点不可知，需先主动复现抓时间窗再套用对齐分流
- 本地直连 200 不等于公网路径 200（多入口/边缘差异）；判凭证前必须经与客户端相同的完整路径验证一次

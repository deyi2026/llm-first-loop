## Trigger
用户用『1/2/3』等序数引用先前工作产出中的编号待办/缺口清单（常带动作动词：要补/要重签/要跑），而该清单本身不在当前会话上下文中

## Discriminator
用户消息自带两条可判别线索：主题词（如 rsi 需求）与逐条动作动词（补→缺口项、重签→预注册/授权文档）；且首轮 evidence/记忆已点名带日期前缀的主题文档（当日产物），说明清单真值在仓库当日 dated 文档集，而非 evidence 短语索引或记忆中的旧路径

## Short path
- 从用户动词+主题确定第一未知量：编号清单出自哪份当日文档；用 ls/grep 按主题与日期枚举 docs（如 ls docs | grep -iE 'rsi|PREREG'），不用用户原话查 evidence
- 读命中的候选文档，抽取各自编号『待办/缺口』清单（本集为 REPORT §6 R1-R3 与 ANALYSIS §9 三项两套候选）
- 把用户动词逐条对到清单条目语义（重签→预注册重签、补→缺口补齐）选定对齐；两套候选都说得通时，在答案开头显式声明所取口径与弃用另一套的理由
- 附属问题（如『可否用子 agent 补』）按任务形态（生成型可委派、机械型自写更快）直接裁决，无需新发现
- 建议引用具体文档、条目与预注册文件名作依据，随后停止

## Stop conditions
- 已读到包含编号清单的当日文档，用户每个序号均能对上具体条目，且对齐口径已在答案中显式声明
- 按主题+日期枚举后仍有多份清单同样匹配且动词无法区分 → 停止自查，用一句话向用户确认对齐

## Verification
- 候选文档回执中确有编号待办清单，条目与用户序号、动词逐条对应
- 最终答案显式声明对齐解释（如『你说的1/2/3我按X§N理解』）并说明为何不取另一候选清单
- 所引文件均来自当前活树枚举且回执成功，未依赖记忆或旧快照路径

## Counterexamples
- 编号清单已在当前会话或用户引用文本中给出 → 直接回答，不做文档发现
- 序号指向外部系统对象（工单号、配置字段、平台条目）→ 仓库文档枚举无效，应查该系统
- 用户动词无判别力（『做1做2』）且同日存在多份同构清单 → 枚举+动词匹配不能消歧，应直接询问用户
- 记忆路径经当前性核验仍有效（ls 确认存在）→ 直接读该路径即可，无需目录枚举

## Trigger
会话重启或接手后 task state/上下文丢失，用户指令引用上一轮结论（如「方案A，保留搜狗」），必须先恢复「当时怎么连、怎么执行」的通道才能动手。

## Discriminator
检索回执明文带作用域限定词（「未找到…的当前会话 Evidence」）——该 miss 只排除当前会话，不排除旧会话记录；且恢复目标是字面命令行材料，这类内容由跨会话 tool 调用历史（带 session_id 与命令摘要）持久化，而非当前会话内容型 evidence 库。

## Short path
- 一次 task state 探测确认上下文丢失，把未知量定为「上一轮执行通道：目标主机、连接参数、env 提取命令」
- 对当前库做一次主题检索；若 miss 且回执带「当前会话」类作用域限定，立即停止换词重查该库，也不再按时间新近度水合证据碰运气
- 查运行时 tool_history 中 execute_command 类记录，从命令摘要直接读出通道要素（BatchMode ssh 目标、ConnectTimeout、env 来源）
- 摘要被截断时水合对应历史条目，补全确切命令行
- 用恢复的通道对权威现场做一次有界侦察（读目标配置原文+可用管理接口+进程管理链），一步重取全部决定性领域事实；此后停止一切历史挖掘，进入执行

## Stop conditions
- 通道（主机/连接方式/必要 env）已从调用历史确认，并能跑通一条只读侦察命令
- 现场侦察已重取决定性领域事实（本例：profile 原文、dbus 接口可用性、systemd 管理链），且与用户引用的上一轮结论吻合
- 两个不同源都 miss 后不再第三种措辞，转为现场重取或向用户索要锚点

## Verification
- 用恢复的通道实际执行一条只读命令成功，即证明通道恢复正确
- 重取的现场事实与用户指令引用的上一轮结论一致（如组内确有要保留的目标条目名）
- 后续操作回执的主机/会话标识与调用历史记录一致

## Counterexamples
- 上一轮关键事实是瞬态现象（一次性报错栈、当时网络状态）且现场已变化——不可用现场重取代历史检索
- 检索库无作用域限定词且为全局库时，miss 更可能是关键词不当，一次系统性换词合法
- 任务目标本身就是审计「上一轮做了什么」——历史记录是目标而非手段，现场重取不能替代
- 运行时的 tool 调用历史不跨重启持久化——此时应转归档/交接回执，而非套用调用历史路径

## Trigger
重放已验证经验卡中的浏览器自动化步骤操作第三方 SPA 编辑器（发布/插图等），某机械子步骤出现破坏性失败——摧毁已录入状态（如正文被清空）——而非可重试的普通报错

## Discriminator
经验卡自身已记录的通道可靠性分层：合成 HTML 一次粘贴整段正文是跨多次验证从未失败的稳定通道；上传控件/面板是已有失败记录的脆弱通道（首传失败需重试、图注丢失）。破坏性失败落在脆弱通道且换牺牲态复现仍在该通道，则『平台前端变更』假说优先于『操作有误』假说，恢复方向应是绕开脆弱通道而非修补它

## Short path
- 按经验卡重放；首个子步骤出现破坏性失败（已录入状态被毁）即停止整段重放，记录被毁状态与失败子步所属通道
- 用最小牺牲态（短 dummy 正文）复现一次，确认失效范围属于控件通道，避免用完整内容反复试错
- 保留稳定通道子步（整段粘贴、勾选、验收），把失败子任务迁移进该通道：全部资产以 data-URI 内嵌进一次粘贴的 HTML，交由编辑器自身导入逻辑转存图床
- 核验编辑器内图数=内嵌数、正文与源稿零损伤，再继续原发布流程并做公网/登录态 DOM 实见验收
- 落盘新经验卡（verified）并显式标注旧子步已失效及复现证据，防止下次按旧卡再踩

## Stop conditions
- 资产经稳定通道迁移成功：编辑器内已转存图数等于内嵌数、正文零损伤，且发布后实见每张图渲染
- 稳定通道被证伪（粘贴内容被 sanitizer/CSP 剥离 data: 源）→ 停止载荷迁移，转向平台直连 API 或请用户人工介入
- 平台存在直连发布 API 可绕过编辑器 → 直接改走 API，不再修编辑器链路

## Verification
- 粘贴后立即在编辑器内计数已转存图片并与内嵌数对账，diff 正文与源稿确认零损伤
- 发布后用登录态 DOM 逐图实见核验（curl 壳页面不作为验收依据）
- 新经验卡 verification_state=verified，附旧子步失效的复现次数与变体探测记录，旧卡相应子步标注失效

## Counterexamples
- 失败非破坏性且经验卡已记『重试即成功』（如头条首轮上传失败重试即过）→ 直接按卡重试，不重构链路
- 编辑器 sanitizer 或 CSP 剥离 data: URI → 载荷迁移不可行，回退上传端点或 API 直调
- 媒体体积超出粘贴载荷上限（视频/超大图）→ 分块或走专用上传端点
- 故障位于自控代码/协议而非第三方前端 → 应用 method-root-cause 的单变量根因分析，而非本卡的通道迁移策略
- 经验卡未沉淀任何通道可靠性分层（无从判断哪条通道稳定）→ 先做一次小规模实跑建立分层，再谈迁移

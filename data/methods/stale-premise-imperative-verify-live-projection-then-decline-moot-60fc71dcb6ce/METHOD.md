## Trigger
动作型指令隐含一个数天/数周前形成、或来自其他会话/旧记录的前置状态断言（某门仍 pending、某实现仍未提交、某变更仍未合并）；或执行前在当前权威投影中已找不到该动作目标。

## Discriminator
一份新鲜权威当前态回执即可裁决：pending 投影里目标 id 缺席（负存在事实）；目标分支 git 历史按内容锚点能定位且 merge-base 为祖先。旧记录中『未提交/worktree 已落地』带旧时间戳，在活跃仓库默认已过期——闭环源是当前投影与 VCS 历史，不是对证据库换措辞检索旧容器。

## Short path
- 收到指令先并行取两类事实：动作域的权威当前态投影（状态注册表 / git log+status），以及记录库中目标的身份锚点（全名、批准/形成时间、内容关键词）。
- 对照前提：目标仍在投影中或内容确实缺失 → 前提成立，转入正常执行路径，本方法不再介入。
- 目标从当前投影缺席 → 唯一未知量转为终态归因：查事件流/账本在其最后活动时点之后的记录，区分『已被放行/完成』与『归属方死亡后被运行时清除/收编』。
- 提交/合并类：用身份锚点对目标分支 git log --grep 定位提交并逐条 merge-base 验证祖先；旧 worktree/容器可能已删、内容可能已被收编，不以『找不到容器』作为未完成证据。
- 前提失效即停手：不制造空提交、不对不在列表的门执行放行；以当前回执+归因汇报『无需动作及原因』，相邻但不同的待办只报备不代做；若用户可能另有所指（如合并当前分支）显式另询。

## Stop conditions
- 每条被指令的动作要么带回执执行完毕，要么被当前权威回执证明 moot 且完成终态归因，即停。
- 一旦前提被当前投影证伪，停止对旧容器/旧快照继续换措辞检索。
- 不得用 freshness/currentness 未验证的历史快照代替当前投影来下『无需动作』结论。

## Verification
- 『已清除/已解决』结论需双证据：当前投影内容 + 事件流/账本归因，且两者时间戳晚于前提断言的形成时间。
- 『已在目标分支』结论需逐条 merge-base（或等价 VCS 祖先）验证，不以『存在相关提交』代替『在目标分支上』。
- 最终汇报中每个『无需动作』都能指向一份当次获取的权威回执，而非过程记忆或旧快照。

## Counterexamples
- 当前投影确认前提仍成立（门仍在 pending 列表、git status 确有未提交实现）→ 直接执行动作，本方法不适用，勿过度核验致瘫痪。
- 指令不依赖任何过期状态断言（如『把当前分支合进 main』是对现状的全新决定）→ 走正常执行与审查门流程。
- 权威投影自身可能过期或缓存（freshness 存疑、来源版本不明）→ 先验证投影本身，缺席不能当作证据。
- 对外非幂等动作且完成证据含糊（可能已发出的发布/push）→ 按『权威完成证据优先』类方法处理，缺席推断不足以支撑重做或放弃。

## Trigger
对活跃写入中的数据目录执行复制/迁移类校验门（rehearsal、verify、备份比对），失败项恰是比较「源统计 vs 复制产物统计」，且其余校验全绿；或在此类校验门的设计/审查阶段，发现有人把活源统计当作复制产物的判定基准。

## Discriminator
失败回执本身即可判别，无需额外取证：文件数精确相等（5320==5320）而字节仅微差（3058/1.08GB，约 3e-4），identity 改写/注册表/桶复制/幂等等其余检查全部 PASS，且已知该数据目录正被活跃写入（本会话审计与 usage 落盘、并行评测会话可见）。计数不变 + 字节微增 = 统计时刻与复制时刻之间发生了追加写（TOCTOU），可直接排除「迁移逻辑丢/重文件」（会改变计数）与「数据损坏」（漂移应更大或随机）。

## Short path
- 读 FAIL 回执的 checks 明细确认签名（计数相等 + 字节微差 + 其余全绿），把未知量收敛为「基准统计与复制之间是否存在写窗口」这一个
- grep 校验项名定位代码并读该 span，确认源统计与复制两个动作的先后顺序（stat-then-copy），证实竞态窗口真实存在
- 确认源→复制保真已有独立机制（如逐文件 SHA256SUMS 清单）——这是允许把源比较降级为「仅参考」的前提，缺此步不得降级
- 最小修正：判定基准改为快照内自一致（复制后/迁移前统计 == 迁移后统计）；源统计保留在报告中作 reference 并注明「活数据竞态，不参与判定」
- 单测通过并提交（提交信息记录实测差值与根因）后重跑校验门，PASS 即停止；报告中不隐藏源差异，只改判定基准

## Stop conditions
- 重跑后快照内前后统计精确相等且全部校验项 PASS
- 文件数不相等，或字节漂移量大/为负：本方法不适用，转入复制集合或迁移逻辑缺陷排查
- 数据实际处于停机无写者状态（maintenance.lock 持有、服务全停、无并行会话）：不得以竞态为由放宽，源与复制必须精确相等

## Verification
- 重跑报告中 mirror_before == mirror 精确相等，且 source_reference 字段仍如实展示实测差异（放宽判定但不隐藏事实）
- 确认存在独立的逐文件哈希/清单机制覆盖源→复制保真，且该机制在本轮实际执行过
- 修正提交说明中写明实测差值与 TOCTOU 根因，防止后续审核误判为「放宽门禁」而被回退

## Counterexamples
- 真正停机窗口内的 verify（写者已全部停止）：源与复制本应精确相等，套用「活数据竞态」重定基准会掩盖真实的丢文件
- 文件数不相等的失败：不是追加写竞态，是复制集选错或迁移逻辑缺陷，应排查复制范围而非基准
- 没有独立逐文件哈希机制时把源比较降级为参考：会拆掉唯一的复制保真检查，必须先补独立校验再重定基准
- 字节漂移为负或量级巨大：可能是桶选错、多复制文件或损坏，应排查复制范围而非改基准

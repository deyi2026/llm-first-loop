## Trigger
对抗式拷问/审稿工具提供逐层递进追问（宣称 N 层），当前层已答完、正决定是否开下一层；或草稿评审循环已≥2 轮，而 motivating 事故（如十轮审稿空转）恰是同型循环失控

## Discriminator
三件当时即可核验的事实任一成立即收窄决策：①本轮问题形状与上一轮已答问题同构（只换数字）；②被追问的锚点 token 在被审文档正文中 0 命中（如把『310 次』『31,698』切成『310 s』『698 字符』的提取噪声，且上轮已声明『正文无此参数』后仍复现）；③本轮新盲点按严重级别清点新增 P0/P1 为 0

## Short path
- 成稿前给全文数值标注证据等级（[实测]/[参数]/[假设]），使『实测还是估算』类锚点问题可机械作答、其重复可被识别为非新颖
- 每轮拷问结束后先把新盲点按 P0/P1/P2 分级登记；未完成分类不开下一轮
- 开下一轮前核对锚点存在性：在被审文本中搜索被追问 token，0 命中记为提取噪声，不为『修复』不存在的参数而改稿
- 若本轮产出仅为同构重复+噪声锚点且新增 P0/P1=0→声明冻结理由（引用轮级签名）并停止追问，直接落盘交付
- 若被审设计自身含迭代上限/分级停止规则，将同一规则显式套用于本次评审循环（自应用），并在交付说明中记录两轮即冻结的依据

## Stop conditions
- 连续一轮无新增 P0/P1 盲点且产出以同构问题与噪声锚点为主→冻结
- 被审产物已落盘且内容身份（SHA）固定→不再因追问重开全量评审
- 任务书/评审方合同性要求的层数或流程未满足时不冻结（外部合同优先于自设停止规则）

## Verification
- 逐条核对每个被追问数值锚点在被审文档中确实存在，或已用文本搜索证明确为误提取
- 确认第 1 轮登记的全部盲点（含分级误判回路、降级链等）均已吸收进冻结稿，防止以噪声为由漏改真问题
- 确认冻结时刻不存在未关闭的 P0/P1 条目；冻结理由中引用了本轮签名（新增高级别数=0）

## Counterexamples
- 本轮仍产出新的 P0/P1 级盲点（如缺失败降级链、缺误判检测回路）→循环仍在挣得其成本，必须修订并继续，不得冻结
- 追问重复是因为评审方不接受上一轮答案（实质性分歧未解决）→重复是未决信号而非模板噪声，需正面回应而不是停止
- 拷问方是真人利益相关方且明确要求跑满 N 层→单方面冻结违约，应显式声明并协商缩减
- 一次性单轮评审、无循环结构→无停止规则可套用，正常答完即止
- 对自己产物中的参数没把握、无法确证锚点是否误提取→必须先在文本中核实再定性，不得凭直觉判噪声

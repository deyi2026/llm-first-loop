## Trigger
刚生成文档格式转换产物（markup/HTML→PDF 等）并需要验证内容完整无缺失/截断；源是以文本为主的文档且其结构已在生成前探明，转换器在环境中可用，产物来自带文本层的打印/渲染管线

## Discriminator
生成前已探明源文档为纯文本类结构（行数/标题数已知，无表格无代码块无图片），且转换器本身能把同一源再输出为 plain 文本——这把『内容是否完整』从未知分辨率的图像/元数据通道缩成一次可逐行判定的文本等值比对；markup 与渲染符号必然不出现在产物文本层，属可预先声明的良性差异

## Short path
- 产物有效性：用一个 PDF 解析库打开产物取页数与页结构（必要时临时 venv 安装），一次回答『文件是否完好、共几页』
- 内容完整性：用同一转换器把同一源输出为 plain 文本基准，与 PDF 文本层做规范化逐行 diff；比对前先列出预期良性差异类（标题/强调/列表 markup、列表圆点、自动目录、变体选择符）
- 裁切/截断：对全页文本块做 bbox 越界检查（0 越界即无内容被裁切）；截断类主张必须由几何证据裁决，不采信单纯目视证词
- 字形抽查：只抽样 1-2 页目视查豆腐块/乱码；目视结论与文本层或几何证据冲突时采信确定性通道，并复核目视前提（如该标题本在哪页）
- 抽取层异常：文本层若出现成批异常码位（如部首区字符），做一次换字体对照实验；计数无实质变化即定性为转换器 ToUnicode 固有限制，作为已知限制披露并停止迭代

## Stop conditions
- 同源 plain 基准的全部内容行均在 PDF 文本层匹配，残余差异逐条归入预先声明的良性类
- bbox 零越界且抽样目视字形正常
- 抽取异常已定性（转换器固有 vs 字体缺陷）并如实披露

## Verification
- diff 出现批量『缺失行』时，先怀疑基准选错（原始 markup 源 vs 渲染后文本），换同源 plain 基准复比再下结论
- 任何『标题缺失/末行截断』的视觉报告，用锚点文本所在页码与 bbox 复核后才接受或否决
- 异常码位结论须有换字体对照数据支撑才可断言为固有行为

## Counterexamples
- 源文档含表格/代码块/图片等版式承载内容时，文本等值不能覆盖版式保真，需几何或图像通道补足
- 产物无文本层（扫描件/纯图 PDF）时文本比对不可用，须 OCR 或整页目视
- 单页短文档或用户只要快速粗检时，一次目视即够，搭建解析与比对管线属过度工程

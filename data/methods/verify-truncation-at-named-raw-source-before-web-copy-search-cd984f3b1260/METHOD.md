## Trigger
对单条内容链接的直接抓取已成功，提取回执显式点名了产生该内容的上游原始 endpoint/API，而内容呈现疑似截断症状，于是产生'去网上找完整版/副本'的冲动

## Discriminator
回执中已写明的提取器名与原始 endpoint URL 本身就是完备性的裁决点：拉取原始 payload，看目标字段是否恰在可疑结尾处自然闭合（字段长度+结尾字符+富文本span为空）即可判定截断发生在源头还是抓取层；同时 payload 已枚举出其余可能承载缺失内容的载体（附件清单）。公开搜索引擎对平台内部数字 ID 几乎不可检索，只返回同形异义词的无关结果

## Short path
- 抓取分享链接，从回执记下提取器名与被点名的原始 endpoint
- 出现截断症状时，直接请求该原始 endpoint，检查目标字段的原始边界与长度、富文本 span、附件清单：判定截断在源头还是在抓取层
- 若源头即止，只核对同一 payload 列出的其余内容载体（附件大图/图集）：下载并解析（OCR），排除缺失内容藏在载体里
- 全部载体核对后仍缺，则结论定为'源头缺失/作者侧未写全'，显式标注未验证部分并停止；不发起公开网搜找副本

## Stop conditions
- 原始字段边界已证明内容在源头闭合或源头即缺，且同一 payload 列出的全部内容载体均已解析
- 已能向用户交付'接口原文 + 缺失定位 + 未验证声明'，不再存在未裁决的未知量

## Verification
- 对照原始 JSON 字段长度与结尾字符，与展示文本一致，排除抓取层截断
- 附件图解析结果与正文交叉核对，确认图内不含缺失条目
- 最终答复显式区分'接口原文如此'与'作者转述未核实'两档

## Counterexamples
- 原始 endpoint 返回少于渲染页（内容客户端拼装、需登录态、付费墙）：raw 源不足以裁决，转向渲染页/登录态接口/副本搜索才是对的
- 内容结尾自然、无任何截断症状：无需完备性核查，直接交付
- 用户目标本身就是跨平台找副本或核原始出处（查转载、辟谣）：搜索副本是任务本体而非绕路
- 平台对不同端点/用户分流返回不同内容且无单一权威真值：不能凭一次匿名 raw payload 下'源头缺失'结论

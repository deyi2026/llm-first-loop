## Trigger
进入实施设计/选型阶段，上游存在自己或他人早前产出的调研结论或备忘，且设计将基于其中『官方无X / X未核 / 某库负责某层』类主张做架构决定或工作量估算

## Discriminator
每条承重主张的探针出处是否可审计：(a) 负面存在主张——探测用的标识符是权威面打印的还是自己拼猜的？对自己猜的名字得到的 404 不是不存在的证据；权威文档页本身常印有准确制品名/下载表，说明线索当时已在手；(b) 依赖职责归因主张——存在可读的当前源码/import 图时，旧叙述不是真值

## Short path
- 从上游调研结论中筛出承重主张（会改变选型或工作量数量级的，非全部细节）
- 对每条承重主张查探针出处：标识符来源（权威面打印 vs 自猜）与证据类型（叙述 vs 可读源码）
- 自猜标识符探出的负结论 → 用权威面打印的准确名重探一次（registry / 官方文档下载表）
- 叙述型归因 → 用 import 图/代码结构工具核一次真实分层
- 承重主张全部有权威背书后再写设计文档，选型处旁注来源；随核随修正选型而非先写完整设计再返工

## Stop conditions
- 承重主张均由权威来源（官方文档/registry/当前源码）核实或证伪，选型已按修正事实更新
- 权威面不可达（下线/内网）时停止重探，显式标注未核并设计不依赖该主张的降级路径

## Verification
- 设计文档中每个选型决定旁注权威来源：文档 URL、registry 包名+版本、或源码位置
- 每条负面主张旁注探测时用的确切标识符，明确区分『猜名未中』与『权威名确实缺席』

## Counterexamples
- 负结论的探针已用权威面打印的准确名、权威 registry 仍明确 404——负结论成立，应走『官方无此制品且警惕同名 lookalike』路径而非反复重探
- 上游主张不影响选型与工作量数量级（非承重）——逐条重验会浪费预算，抽查即可
- 权威源已下线或仅存于不可达环境——无法重探，只能标注未核并把设计建立在可验证的替代事实上

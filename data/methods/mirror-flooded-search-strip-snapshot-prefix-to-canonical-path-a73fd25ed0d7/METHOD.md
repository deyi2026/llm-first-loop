## Trigger
按文件名/符号定位源码或数据文件时，仓库含发布快照/归档镜像目录（如 .releases/<hash>/、backups、archives），搜索结果被镜像副本刷屏、截断甚至超时；或拟 grep 的源码根目录来自命名习惯猜测而非已确认的目录列表

## Discriminator
命中列表的可见条目全部共享同一快照前缀、且公共后缀路径完全相同（镜像冻结自规范布局），同时 pwd 已给出仓库根——这两点当时即可把『全仓库找文件』缩成『直接验证一个具体路径』

## Short path
- 定位源码前先对仓库根做一次 ls（pwd 已知），确认真实源码目录名；不从命名习惯猜根目录，猜错会静默零命中
- 文件名搜索命中被快照前缀刷屏或截断时，停止加词重搜与全树 find（会遍历镜像和大数据目录而超时），改取全部命中的公共后缀路径作为候选规范路径
- 用一次 ls/stat 验证 <仓库根>/<后缀> 存在，并定点 grep 文档引用的行锚常量/符号（如某行号处的 limit 值）核对身份
- 确认后只在活树路径上继续读码/改动，后续搜索把快照目录排除出范围

## Stop conditions
- 活树路径存在且行锚常量命中 → 定位结束，进入读码
- 后缀在活树不存在 → 文件可能仅在快照中，转入按版本/时间裁决目标 release，不默认活树
- 仓库无快照/归档结构 → 命中即真身，直接读，无需剥前缀

## Verification
- ls/read 活树路径成功，且文档引用的行号附近能 grep 到所指符号/常量
- 抽一个镜像副本对照：同后缀路径同文件应存在（镜像冻结自活树某版本），差异须可用版本解释

## Counterexamples
- 目标文件在活树已被删除或重命名、仅存于快照：剥前缀后落空，若仍默认活树会得出错误结论，必须先裁决具体快照
- 各快照间路径不一致（跨版本重构/移动）：无公共后缀可用，需按版本定位
- 仓库没有镜像/归档结构时，此法多此一举，直接读命中即可

## Trigger
用户指令以文档章节号/任务编号锚定实施工作（如『按 §3.4 任务 1 删回退根 + 负向单测』），任务文本含至少一个唯一符号名，而目标代码位置尚未解析

## Discriminator
任务文本同时含『文档章节引用』与『唯一符号名』：对 docs/、reports/ 等小目录一次符号 grep 即命中权威文档，且其正文含精确 path:line-range 引用与验收标准（如负向单测的具体 monkeypatch 形态与不回归要求）——该组合在动手搜索代码之前就已在手

## Short path
- 用任务中的唯一符号对 docs/、reports/ 等有界目录 grep -rln，定位被引权威文档（未知量：规格原文在哪、是否内含路径引用）
- 读所引章节及相关行，提取目标 path:line、设计意图（可能强于字面动作，如『模式确定后不跨根试探』）与验收标准（负向测试形态＋既有用例不回归）
- 直接 read_file 引用给出的路径（带 snapshot 供编辑），并读同目录既有测试学习夹具与风格
- 编辑前三查：git 分支/HEAD、模式判定物存在性（如 _bundled/）、符号消费方 grep 圈定爆炸半径
- TDD：先按验收标准写负向测试→旧代码跑红（红输出应暴露旧行为）→按设计意图实现→绿＋相关回归

## Stop conditions
- 规格验收全部可证明满足：旧代码红、新代码绿、既有用例零回归、运行时直跑确认行为收敛
- 文档引用无法解析（章节/文档不在库内）→ 回退为对 src/ 的符号有界搜索，走常规发现流程

## Verification
- 红阶段失败信息确实暴露旧回退行为，而非夹具/导入错误
- 绿阶段相关测试全过；现场直跑确认单一路径候选
- 报告所引行号与当前源码实际内容核对一致（报告只是索引，当前定义才是真值）

## Counterexamples
- 任务只给符号名、无任何文档章节引用 → 本方法不适用，直接对 src/ 做符号定位即可
- 被引文档不在仓库（外部链接或仅存在于聊天历史）→ 无法一步定位，走普通发现流程
- 报告快照已过期、行号/结构漂移 → 引用仅当线索，须以当前源码与 git 状态为准
- 规格章节只讲意图不给路径 → 文档仅提供验收标准，代码定位仍需一次独立符号搜索

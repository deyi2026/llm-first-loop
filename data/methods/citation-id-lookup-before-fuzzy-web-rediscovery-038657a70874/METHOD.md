## Trigger
需要对已被手头文档引用/列出的外部实体（论文、系统、相关工作）做核验、对齐或取证；这些实体在任务中只以名字出现，而手头文档的参考文献/引用段已含其精确条目。

## Discriminator
手头文档（已在 evidence 中）的参考文献已给出目标实体的精确标题与持久标识符（如 arXiv ID），这把"很多候选来源"缩成"每目标一次确定性查询"；且目标名为常见词/品牌碰撞（Guava=Java库/水果，Aspire=.NET/金融平台），可预判通用关键词搜索会返回离域商业噪声。两点在首次搜索前即可观察，不需事后答案。

## Short path
- 从已在 evidence 中的手头文档参考文献提取每个目标的精确标题与 arXiv ID（未知量：各目标的确切身份与版本）
- 对 ID 寻址的权威 API 逐个用精确引号标题（ti:"..."）或 id_list 查询，一次一个目标（未知量：各目标的权威元数据/摘要主张）
- 在已取得的粒度（摘要级）上比对主张，显式标注未读正文与版本漂移（引用条目标题 vs 当前版标题不一致时记录为版本差异，而非再搜一轮）
- 所有目标的权威回执与引用条目对上即停；不做本地目录枚举，不对污染后端换词重试

## Stop conditions
- 每个被引目标都从权威源取得与引用条目标题/ID 一致的回执
- 引用版与最新版的标题/内容差异已作为版本漂移记录，不再为消差异追加搜索
- 剩余不确定项按"摘要未声称≠不存在"显式声明，交用户决定是否深挖正文

## Verification
- 最终回执的标题/ID 与引用文档的参考文献条目逐条一致
- 结论只声称到已取证粒度（摘要级），未读正文处标注为未验证假设
- 精确标题查询 0 命中时，改用引用条目中的独特短语或 ID 复查一次，仍失败才判定 provenance 断裂并转宽发现

## Counterexamples
- 目标实体不被任何手头文档引用、无 provenance 边时，宽发现（搜索/枚举）就是正确起点，此法不适用
- 引用元数据本身过期或错误，ID 查回的与引用意图不符（标题变过），需用引用上下文交叉核验，不能只信 ID
- 需要的是正文级主张（实验设置、晋升判据、消融）时，摘要级 API 回执不足以支撑结论，必须抓全文
- 名字足够独特且通用后端首查即返回相关结果时，无需切换通道

## Trigger
在已有工具回执流（git status/log/show/diff、部署回执等）的继续型任务中，下一个动作需要某个文件路径、测试名或引用标识符，而它可能已完整出现在之前回执里，或只以截断/省略形式出现。

## Discriminator
检查最近回执中该标识符的呈现状态，三选一决定动作：(a) 全名已完整可见（如 git status 的 M 文件列表）→直接复用，禁止再枚举；(b) 回执含明确截断/省略标记（'...'、行数截断）→对权威 ref 发精确名单查询取全名；(c) 完全未见→才允许宽搜索。截断标记与已列全名都是当时可观察的判别事实。

## Short path
- 发起新发现类调用前，先扫描最近回执：若目标路径/测试名已完整列出（如 git status 已给出两个改动文件），直接对该精确路径执行下一步（diff/read），跳过重复枚举。
- 若回执对所需标识符有截断/省略（如 --stat 长路径前缀被 '...' 替换），对该 ref 执行精确名单查询（git show <ref> --name-only --format= 或 git ls-tree -r <ref> --name-only）取回完整标识符。
- 用取回的精确标识符读取目标 artifact，校验结果非空且类型符合预期（如审计文档应含标题结构）。
- 仅当权威名单证明该标识符不存在（区别于猜错路径读到空）时，才回退到目录/内容层面的宽搜索。

## Stop conditions
- 精确标识符已取回，且读取结果非空、与预期 artifact 类型一致，即停止发现动作。
- 权威名单查询证明目标不存在，此时宽搜索才被允许并成为新的判据来源。

## Verification
- 新查询使用的标识符来自精确名单输出，而非对截断字符串的猜测重构。
- 读取结果非空且结构符合预期；空结果被当作'路径未证实'，回退名单查询而不是换前缀重试。
- 没有对前一回执已完整列出的标识符再发重复发现调用。

## Counterexamples
- 标识符在前一回执中已完整可见：任何再查询都是浪费，应直接行动。
- 回执截断的标识符与当前未知量无关：不必为它发名单查询。
- 目标可能在未知命名下存在且无权威 ref 可枚举：精确名单无能为力，宽搜索才是正确工具。
- 文件可能合法为空：空内容不等于路径错误，需用名单查询区分，而不是继续猜前缀。

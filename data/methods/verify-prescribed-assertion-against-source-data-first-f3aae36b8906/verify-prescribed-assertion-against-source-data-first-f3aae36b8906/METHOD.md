## Trigger
修复工单/QA 建议把某处断言或声明改写成对数据工件的具体谓词，且自带条件从句（『只有真实数据支持才这样断言』）时——既不要无视条件照单直改，也不要漏读条件直接照抄建议谓词。

## Discriminator
谓词所指的数据已冻结落盘，一次只读即可求值真值（本集：逐条 stage 全为 grasp，10/10，计数吻合），无需任何昂贵重跑或额外调查即可判定『数据是否支持该谓词』。

## Short path
- 把工单拆成独立编辑项，识别哪项带条件从句；该项的唯一未知量是『数据是否支持建议谓词』
- 只读谓词指向的那一个冻结数据工件，打印谓词字段的实际取值分布
- 分布支持谓词→在同次补丁应用建议断言；不支持→不写死，改用与实际分布一致的断言并在交付中说明偏离
- 跑 targeted pytest/Ruff/Pyright，记录真实 exit 码；全绿后 checkpoint 原 Goal
- 按工单边界列精确变更文件集交 Host 受管 commit，不越权 Git、不做工单外调参

## Stop conditions
- 谓词真值已由数据工件一次性判定（支持/不支持二选一），不重复读或换措辞再查
- 各验证套件 exit0 回执齐备且已写入 checkpoint
- 变更文件清单已完整交付受管通道，工单范围外零改动

## Verification
- 补丁中写下的谓词与数据工件打印出的分布逐字段一致（逐条取值与计数吻合）
- 各测试/lint/类型检查的 exit0 来自真实回执而非自报成功

## Counterexamples
- 工单指控的是代码缺陷（该不该这样写）而非数据谓词真值——应走对 base 提交做锚点对比裁决 finding 的方法，不做数据加载
- 数据分布混合（部分记录不满足谓词）——all() 式简化将为假，应断言真实分布或收窄条件，不得硬套工单字面
- 谓词所需数据不存在或必须昂贵重跑才能取得——不得凭上次运行的印象写死断言，先把『数据在哪』当未知量解决或明确延后该项

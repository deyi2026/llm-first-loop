## Trigger
需要在工作区直接读取/列出具体文件，且搜索工具命中路径展示中多种前缀格式并存（部分含包根如 src/、部分仅含包名、部分来自快照/release 目录）；或手工构造的绝对路径首次读取即返回文件/目录不存在。

## Discriminator
本 run 已存在一次指向同一包树的成功直接读取（其绝对路径携带唯一被验证过的真实前缀）；搜索展示前缀不一致这一事实本身即证明展示路径是相对不同根的、不可直接拼接；not-found 失败回执通常附带『路径已登记不存在（TTL）』提示。三者合一，足以把『换拼写试探路径』收缩为『恢复锚点前缀后重试一次』。

## Short path
- 盘点已持有成功回执中的绝对路径，取同一包树的前缀（如 <workspace>/src/<package>/）作为规范锚点
- 后续同树文件直读一律 = 锚点前缀 + 相对路径，各发一次，不采用搜索展示的原始拼接形式
- 首个 not-found：立即停止兄弟文件重试，将失败路径与锚点逐段比对，定位缺失/多余段（如缺 src/），修复前缀后仅重试一次
- 修复后仍失败则改为逐层列出锚点目录或用精确 search 命中定位，禁止继续盲拼写
- 多根并存（源码树 vs .releases/快照）时先选定任务所需根并统一锚点，核证场景优先 live 源码树

## Stop conditions
- 目标文件经锚点前缀成功读取
- 一次前缀修复后仍 not-found → 停止该拼写分支，改用目录列举/精确命中定位
- 失败回执已对某前缀登记不存在（TTL 提示）→ 不再对该前缀下任何路径发起读取

## Verification
- 每次发送前将目标路径前缀与锚点路径逐段比对确认一致
- run 结束时确认不存在因同一错误前缀导致的重复 not-found 失败
- 核证场景确认读取对象来自任务指定根（live 源码树而非快照副本），避免对过期副本核证

## Counterexamples
- 冷启动且无任何成功直读可作锚点：正确的下一步恰恰是一次诊断性列举/搜索，不能预钉锚点
- 项目布局唯一、无 src 嵌套、无快照或镜像目录：展示路径直接拼接即有效，套用此方法无收益
- 目标文件真实不存在（非拼写问题）：继续换前缀重试本身是反模式，应信任 TTL 登记提示并转向求证
- 同名多根场景下误把锚点钉到过期快照根，会核证错误版本——锚点选择必须与任务核证目标匹配，此判断不可程序化

## Trigger
用户要求对当前仓库/部署做安全或防攻击检查；根目录列举已显示敏感工件（.env 及其备份、密钥文件、内部数据/审计目录），且项目含正在运行的 web 或文件读写接口（本地监听或经隧道公网可达）。

## Discriminator
两份在手清单的交集是否非空：根 ls 明示秘密工件的路径与权限位（含权限异常项）；web 模块清单明示触碰文件系统的路由（预览/目录树/上传/删除）。交集非空即把『审什么』从全部端点缩成一个可裁决问题：这些路由的读/写边界是否覆盖仓库根、dotfile 过滤是否只作用于目录列举而不作用于读取。

## Short path
- 根目录 ls → 敏感工件清单（路径+权限位，标记异常项如 644 的备份）
- 列 web 模块文件与监听端口 → 网络可达面清单；注意经隧道暴露时 loopback 监听也算公网面
- 只读文件类路由的路径定根与过滤逻辑：读根指向哪、过滤作用于列举还是读取/删除两侧
- 用真实敏感路径做一次只读 live 探测：loopback 一次、伪造公网 Host 头一次，同时裁决越界与回环免鉴权两个问题
- 边界结论落定后再展开鉴权强度、执行闸、端点全量；输出按严重度+可利用链+修复性价比排序

## Stop conditions
- 文件接口读边界被证实不含敏感工件（探测 401/403/404，或读根定在沙箱目录且白名单）→ 关闭该类发现，转下一攻击面
- Critical/High 各有代码行+实测双证据，足以给出按性价比排序的修复建议

## Verification
- live 探测必须拿到 200+实际秘密内容作为证据，不能只凭代码推断可读
- 读写两侧对称核验：删除/重命名/上传是否复用同一过滤与审批通道（常见缺陷是只堵读侧）

## Counterexamples
- 仓库根目录没有任何秘密工件（无 .env/密钥/内部数据）→ 交集为空，直接按常规面审计，不要硬套
- 服务未运行且无法起测试实例 → 不能 live 探测，退回纯代码审计路径定根
- 审查目标是依赖 CVE 或某算法强度而非数据暴露面 → 本优先级不适用
- 文件接口已显式白名单且读根独立于秘密工件所在目录 → 快速排除后即转其余面

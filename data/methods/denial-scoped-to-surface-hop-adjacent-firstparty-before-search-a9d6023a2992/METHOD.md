## Trigger
任务需要对身份已完全已知的在线目标（org/repo 坐标已出现在被拒 URL 或上下文中）核实事实（版本、许可证、stars、README 断言），而其元数据/API 面的抓取回执是确定性拒绝（403/404，参数与客户端轮换均无效）

## Discriminator
失败回执同时含两件事：确定性状态码+被拒的具体 host（说明拒绝范围=该面，非目标、非瞬态）；目标完整身份坐标仍保留在回执/URL 中（说明邻接一手面可用机械替换直接构造）。二者缺一（如只剩模糊超时，或身份坐标不全）则本方法不适用

## Short path
- 拿到抓取失败回执先读拒绝范围：确定性状态码 + 被拒 host + 目标身份坐标是否仍完整保留在 URL/参数中
- 身份完整时，机械替换构造同目标邻接一手面（HTML 页 / raw 文件 / releases feed / 注册表页），逐个单次抓取，成功回执即刻裁决对应断言（存在性、许可证、版本时间戳）
- 仅被拒面独有的数值（如 stars）用一条第三方镜像补齐，结论标注降级证据等级
- 本地侧对比所需的自家实现，用运行时已给定的 code_root 做定点路径列举，不做全仓 dump
- 邻接面全部以同一原因被拒时才升级到搜索/镜像/归档等发现层，且搜索词须避开大品牌泛化词

## Stop conditions
- 同一目标至少一个一手面回执已覆盖任务全部可裁决断言，即停止发现，进入比对/写作
- 邻接面全部同因被拒：判定域级阻断，停止邻接尝试，改走镜像/归档/用户补充并标注证据限制

## Verification
- 每个成功回执的 host 不同于被拒 host，且回执内目标身份与已知坐标一致（防同名噪声顶替）
- 数值断言标明来源面；官方权威面未直连成功时结论显式写『非官方 API 值』

## Counterexamples
- 整个域被网络层阻断（站点 HTML 也连不上）：邻接面同域连环失败，镜像/归档才是真正不同通道
- 目标身份未完全已知（只有产品昵称、org 不确定）：第一未知量是身份解析（注册表/包管理器），无从构造 URL
- 被拒面独有的高精度数值且无可用镜像：邻接面取不到同精度，只能降级标注或带凭证重试原面
- 403 实为带认证即可通过的限流且凭证在手：加 auth 重试比换面更短

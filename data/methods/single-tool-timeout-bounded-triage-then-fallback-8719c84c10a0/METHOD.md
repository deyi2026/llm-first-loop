## Trigger
巡检/健康检查类任务中，某工具调用返回明确超时回执（挂起而非校验错误），且同会话其他工具同窗口内快速成功返回

## Discriminator
两条在首次超时后即可观察的事实：① 超时回执是确定性挂起（'超过 60s 未完成'），不是'参数不可用'类校验错；② 同会话 service_control/search_records 等毫秒级成功。这对事实把原因空间从{我的参数/会话运行时/网络/工具后端}缩到{工具后端 或 我的参数}，一次最小参数面重试即可定级

## Short path
- 先调用覆盖面最大的健康工具（如 service_control），一次性锁定服务层结论
- 目标工具首次超时后，仅做一次最小合法参数面重试，区分'参数面过大'与'后端挂起'这两个未知量
- 第二次仍超时 -> 查 exception_log 与 experience 记录：确认无已知故障登记，并获取'合法参数下应快速返回'的基线
- 参数无关 + 无已知问题 + 基线正常 -> 判定为新出现的单工具后端阻塞，停止一切重试
- 用其余健康工具的证据完成原任务，把该工具故障作为发现写入报告；实现级排查/重启列为需授权的下一步

## Stop conditions
- 同一工具 ≤2 次调用（含一次最小参数面重试）均超时且记录库无已知问题 -> 停止重试，转入替代证据收尾
- 任一次重试成功 -> 退出分诊，按正常流程继续
- 记录库命中已验证处置方法 -> 按其执行，不再变参试探

## Verification
- 确认失败与参数无关：不同维度数/scope 均同样超时，而非返回校验类错误
- 确认局部性：同会话其他工具同窗口内快速成功
- 确认无登记：exception_log/事件流无对应异常条目
- 报告引用基线证据（经验库或历史记录）说明该工具正常时应快速返回

## Counterexamples
- 所有工具都变慢或网络抖动导致的偶发超时：非单工具局部故障，应整体等待或换路径，不应套用'局部阻塞'结论
- 回执是参数校验错误（如'维度 X 暂不可用'）而非超时：应按白名单修参数，而非分诊后端
- 该工具是所需事实的唯一来源且无替代工具：无法'替代证据收尾'，必须升级为实现级排查或授权重启
- 工具正常耗时本就接近或超过超时阈值（长任务类）：超时是预期行为，不是故障

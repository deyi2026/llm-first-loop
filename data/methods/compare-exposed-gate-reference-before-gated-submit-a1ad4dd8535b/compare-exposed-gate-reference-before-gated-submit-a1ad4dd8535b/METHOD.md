## Trigger
即将对带机械预检（fail-closed 机检）的队列或状态机做写类提交（enqueue/转态/close），且门禁的参照值（如其记录的基准 main head）或所需凭证的落账情况在本会话先前回执中已经可读到。

## Discriminator
提交动作发生前，同一会话内已同时暴露两个事实：门禁状态回执显示的参照值（队列 main_head=本地 main）与待提交条目的声明基准（候选基于远端 main）不一致——即本地与远端基准分叉当时已可见，提交必然触发基准过时类拦截；凭证维度同理，可用一次 grep 查权威回执账本预判必需凭证是否缺失。

## Short path
- 读门禁/队列状态回执，取其当前参照值（基准 head、槽位、检查维度）。
- 与待提交条目的声明值逐维机械比对：基准 SHA 是否一致、必需凭证是否已在权威账本落账（各一次只读操作）。
- 任一维度已判必败 → 不提交；登记 checkpoint，把阻塞项上报为需授权方处理的收尾事实。
- 全部可预检维度通过 → 提交，让门禁裁决剩余本地不可判定的检查。
- 某维度无本地可读参照、只能由门禁本身判定 → 提交是合法求知手段，正常走门禁流程。

## Stop conditions
- 条目声明值与门禁参照值逐维一致、且必需凭证可在账本中定位 → 允许提交。
- 任一可预检维度已判必败 → 停止提交，转为登记与上报；不为过门禁代签或伪造凭证。
- 门禁判定包含本地不可知因素（并发槽位、时间窗、远端实时校验）→ 放弃本地预测，按合同直接提交。

## Verification
- 比对必须引用门禁状态回执原文中的参照值，不能用登记文本或口头声明的转述值。
- 失败预测必须在提交动作之前成立：终态报告要能指出是哪条先前回执的哪个字段预定了该失败。
- 不提交路径的最终报告仍须覆盖用户要求核验的全部事实（逐条对照回执），不因省掉提交而漏核验项。

## Counterexamples
- 门禁的检查维度与参照值从未在本会话暴露（无状态回执可读）：提交是唯一合法的求知方式，本方法不适用。
- 写操作幂等且无持久失败残留的纯探测型接口：预测失败的收益太小，直接提交探测可接受。
- 门禁逻辑远比本地可见的参照比对复杂（含远端实时校验、动态资格判定）：本地预测不可靠时不得用它拦截自己。
- 参照值一致、仅凭证未落账且账本本身不可读：此时提交吃一次 fail-closed 反而是获取权威拦截原因的最短路径。

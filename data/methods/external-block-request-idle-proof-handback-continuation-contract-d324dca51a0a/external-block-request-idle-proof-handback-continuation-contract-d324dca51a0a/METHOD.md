## Trigger
Run 所有本地可推进门禁已闭环，剩余唯一门禁完全依赖外部受管方执行（help 请求已投递并计入阻塞），本侧无可用完成唤醒/回调通道，只能靠有界等待+轮询外部通道状态推进。

## Discriminator
两个当时已可见的零信息信号同时成立：(1) 连续两次收件箱轮询返回完全相同状态（相同 pending/blocking 计数与相同条目，本请求仍 pending）；(2) 先前回执/历史日志已确立该外部动作的确定性进度产物模式与典型耗时（旧候选的 /tmp r9 产物 .pid/.log/.exit 命名，约7-8分钟完成），而实际耗时远超基线后新 SHA 产物仍缺席。当时即可判定外部未开始处理，而非需要更多轮询去确认。

## Short path
- 投递外部请求后，优先一次性注册完成唤醒/回调；仅当被 schema 约束拒绝（如 D8 谓词拒绝）时才退回有界轮询，并预设硬上限：2 轮状态核对 + 1 次只读产物探测
- 每轮核对只做一件事：与上一轮状态逐字段对比是否零增量
- 第一次零增量后做一次只读产物探测：既确认进度信号缺席，又建立产物命名模式与典型耗时基线
- 第二次连续零增量且耗时已超典型基线倍数 → 判定 idle，立即停止轮询
- 组装续跑契约交回控制权：精确 workdir、HEAD SHA、原样命令、回执必含字段（exit code、测试计数、log 路径+SHA256），并附本侧已闭环项/等待项清单与恢复后的收口顺序

## Stop conditions
- 外部回执到达（进度产物 .exit/.log 出现、help resolved、或通道状态变化）→ 不再重发请求，直接核验收据并恢复收口
- 产物出现但未终结 → 外部已开始处理，按产物增长有界等待即可
- 唤醒/回调注册成功 → 立即交权，不做任何轮询
- idle 证明成立且续跑契约已投递 → 本 run 正常结束，不追加等待

## Verification
- idle 判定必须同时满足 ≥2 次连续同状态轮询 + 进度产物缺席 + 耗时远超已知基线；单次无变化不构成证据（可能是瞬时未调度）
- 续跑契约自检：一个全新会话或协调员凭契约文本能否零上下文执行（workdir/SHA/命令/回执字段/恢复顺序齐全）
- 交棒前核对本地已闭环项与外部等待项分账清晰，不把未决项伪装成完成项

## Counterexamples
- 本 run 前半段的异步 Reviewer 轮询不适用此方法：该通道有文档化等待协议，回执带 remaining_seconds 递减的活信号（2758→2585→2421），计数在动即有进展，应继续按协议轮询而非交棒
- 收件箱中本请求状态发生变化（accepted/处理中）或其他条目变动导致计数改变 → 非零增量，不得判 idle，继续有界等待
- 外部通道提供可用的完成唤醒机制且注册成功 → 用唤醒等待，完全不需要 handback 路径
- 外部动作无任何确定性进度产物可探测（无历史命名模式、无典型耗时基线）→ idle 证明不完整，只能依赖通道自身状态变化判断，不可仅凭两次相同轮询就交棒

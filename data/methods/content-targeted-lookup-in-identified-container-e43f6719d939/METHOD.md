## Trigger
需要在已定位的配置/凭证容器（如 .env）中确认某具体条目（某服务 key、BASE_URL 覆盖）是否存在及其值，而先前读取因截断/脱敏未显示该条目；或已从权威来源取得可用内容后仍在考虑补充发现性查询

## Discriminator
目标容器已被识别且已部分读取（cat .env 已见其他 key，仅目标条目因截断/脱敏不可见）——这一当时已知事实把『哪个文件可能有』缩成『在该文件内 grep 服务名』，可直接一次解析存在性、值前缀/长度、有无 BASE_URL 覆盖三个未知量

## Short path
- 对已识别容器做内容定向查询：grep -i <服务名> .env*（含备份文件），一次解析 key 存在性、前缀/长度、所在行号
- sed/grep 该行上下文查有无 BASE_URL 覆盖，据此确定直连官方还是走代理；这两个结果都出自同一容器，无需文件名搜索
- 从官方文档取准确端点与最小合法参数（若工具提示该 URL 刚抓取过则直接复用），不猜参数
- 用文档给出的最便宜合法参数组合发一次最小实测请求，读取 HTTP 状态码 + 错误码体
- 用同一文档页的错误分类表（401/1004=key 无效、402/1008=余额不足、400/2013=参数或计费类型不支持）解释响应，一次性区分多层竞争假设后停止发现，落档并汇报

## Stop conditions
- 容器内条目已解析（存在性+值+覆盖关系均确认），不得再升级到文件名/全库搜索
- 权威来源（官方文档或一次实测响应）已给出当前未知量的可用内容后，停止一切补充发现性查询（如事后 Evidence 库检索）
- 一次实测的错误码已在文档分类表中命中并区分了竞争假设，不得再发变参重试请求

## Verification
- 确认 grep 命中行所在文件就是先前已读取的同一容器，且上下文显示无 BASE_URL 覆盖（或覆盖已被显式确认）
- 确认实测响应的 HTTP 状态码+错误码与文档错误分类表一致，且结论各层（key 有效性/计费类型/产品限制）各自有直接响应证据而非推断

## Counterexamples
- 容器本身未知（不知道 key 存在哪个文件甚至哪个服务）时，文件名搜索/全库发现是正确起点，本方法不适用
- 目标条目已在先前读取中完整可见（无截断/脱敏）时，直接使用即可，再 grep 属于冗余
- 实测错误码不在文档分类表中，或响应为超时/5xx 等疑似瞬态故障时，需要重试或换参数排查，不能凭一次响应定论
- 容器内确无该条目且无任何线索指向其他容器时，才应扩大到发现性搜索

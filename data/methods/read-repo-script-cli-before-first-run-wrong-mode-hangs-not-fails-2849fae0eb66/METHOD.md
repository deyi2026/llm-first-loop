## Trigger
需要首次调用仓库内自定义 CLI 脚本（用法/参数契约未知，非 git/jq 这类约定稳定的标准工具），且该步骤处于有时限的门禁、推送等阻塞序列中；或该脚本已出现超时、长时间无输出

## Discriminator
调用前已可见的事实：①脚本是 repo-local 自定义工具，本仓库脚本的惯例是把三种模式写在使用说明/头部 docstring（同一会话已对 knowledge_flush.py 先读头再跑成功，证明该惯例可用）；②找到脚本的那次内容检索已同时暴露一个 in-repo 调用方（SCAN=… 行），规范调用方式距一次有界读取只有一个未知量

## Short path
- 未知量=该脚本的合法调用形式：读脚本头 10~15 行用法注释（或 --help、已检索到的调用方那一行），拿到模式名与参数元数
- 按确认的契约调用一次；预计超过前台时限就直接后台启动，而不是先前台猜错再转后台
- 若已发生超时/静默：先读头部用法或入口参数解析段，确认上一条命令实际进入了什么模式，再杀任务并按契约重跑
- 输出与退出码符合所声明模式的签名后，进入下一道闸，不再对同一脚本重复调用

## Stop conditions
- 模式名与参数元数已从脚本头/调用方/--help 确认，并已按该契约完成一次成功调用
- 脚本无任何用法线索且无 --help/dry-run：读入口的参数解析分支确认接受形式后才运行

## Verification
- 实际输出/退出码符合所声明模式的签名（如 range 扫描报告『基线..头范围 29 个文件』），而非默认模式输出或静默
- 复盘确认没有出现『猜语法→超时→原样重发→再等待』的重复调用链

## Counterexamples
- 标准 CLI（git/jq/sha256sum）参数约定稳定：按通用语法直接调用，预读文档反而更贵
- 本会话已读过该脚本用法（如先读 docstring 后成功运行的兄弟脚本）：直接运行，不必重读
- 错参数会立即打印 usage 并快速退出的工具：一次廉价试错成本低于预读，无需此方法

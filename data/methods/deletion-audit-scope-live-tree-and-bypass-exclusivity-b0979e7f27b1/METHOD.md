## Trigger
用户要求对某配置项/门禁/参数给出删或留的有依据建议；符号触点分散在数据类字段、enforcement 函数、旁路参数、测试与文档；且代码库含发布快照/归档副本目录，首轮宽搜命中被其重复内容占据或截断

## Discriminator
首轮结果页本身已可观察两条事实：(1) 同一文件内容在快照/发布副本目录下重复出现，且 live 树路径同时在场——它们才是行为审计的权威子集，快照副本对『当前行为与触点』审计零信息量；(2) 旁路/逃生参数的命中列表是否全部只指向该门禁，决定删除连带范围与『免费出口』论据是否成立

## Short path
- 看到快照副本污染后，立即以 live 源码树为 scope 重查符号内容命中，不再对同一污染空间换搜索模式或改查文件名
- 读 enforcement 函数与字段定义，确认真实语义：默认值、启用条件、fail-open 行为、逃生口入口
- 单独搜索旁路/逃生参数，验证排他性：全部命中是否只服务该 feature（若被复用，删除范围与论据都要重估）
- 搜索测试与文档引用，闭合连带删除清单：字段、schema、调用点、专属测试文件、docs 描述
- 输出建议：论据分层（默认关死代码 / 免费出口不构成执法 / 与现行规则冲突）+ 连带范围 + provenance 路由（推翻已审批演进走审批通道）+ 可选执行路径供用户选择

## Stop conditions
- live 树触点闭合：字段、enforcement、旁路参数、测试、文档全部定位，新增限定搜索不再产生新引用
- 语义与默认值已从当前源码确认，不再依赖记忆或上轮印象
- 旁路参数排他性已有搜索证据（每条命中均指向该门禁）

## Verification
- 对每个已定位触点文件复核引用无遗漏，命中清单与建议的连带范围一一对应
- 确认旁路参数的每条命中都只指向该门禁，无其他 feature 复用
- 确认默认关/fail-open 语义与源码实际行号一致
- 确认删除建议包含 provenance 处理路径，而非默认可直接改

## Counterexamples
- 任务是历史考古（该 flag 何时引入、各版本行为差异）：发布快照目录恰是权威语料，不能排除，scoping 策略反转
- 仓库无快照/归档目录且首轮命中全部在 live 树：无需预限定 scope，宽搜即正确一步
- 旁路参数被其他 feature 复用：排他性不成立，『免费出口』单独不构成删除理由，需连带评估那些 feature
- 门禁默认开启或已被生产 goal 实际启用：『死代码』论据不成立，必须先评估真实执法影响
- 用户明确只要快速意见且已给出行号引用：全触点审计属于过度工程，直接作答

## Trigger
多轮只读复审/门禁审计中，清单项已有 file:line 证据、负测复现与冻结 SHA 均成立，但轮次仍持续增长或收到用户收口指令；剩余未决项属于审查环境结构上不可达的外部生产事实。

## Discriminator
对每个剩余未决项问：本环境（隔离 worktree / 只读通道）是否存在通往该事实的通路？无通路 → 它不是可被更多轮次缩小的未知量，而是裁决边界：代码内 fail-closed 兜底路径与匹配逻辑属可验范围，仅安装/部署状态本身属外部。

## Short path
- 把当前全部未决项二分标注：环境内可复现 / 结构性外部（判据是是否存在只读通路，而非是否还没试过）
- 环境内项用既有证据定论：只读负测 CLI、锁行为复现、file:line 核验、冻结 SHA 比对；按收口指令钉定的解释器与命令白名单执行，不做任何代码/文档/配置修改
- 外部项枚举成操作者确认清单（①②③…），并核验代码侧 fail-closed 兜底存在后即停止探测
- 输出双态终态：范围化代码过审结论（P0/P1/P2 计数 + 精确 SHA + 逐项证据）并列出外部门禁待确认项与责任方；声明未 push/未 merge
- 停止：不为外部项追加确认轮，也不把两态压成单一 PASS/REVISE

## Stop conditions
- 清单内全部环境内项均有可复现命令或 file:line 锚点支撑
- 外部项逐一枚举完毕且对应 fail-closed 代码路径已核验
- 双态终态已输出 → 立即结束，不再追加任何验证动作

## Verification
- 抽查每条过审依据：能给出本环境可复现的命令或锚点，而非仅引用开发者声明
- 抽查每条外部待确认项：能说明为何本环境不可达、需谁确认，且未把代码层结论外溢到安装/部署状态（或反之）
- 终态输出后 git 状态与冻结 SHA 不变（零修改承诺可被复查）

## Counterexamples
- 审查环境实际有通往真实远端的只读通道（API/HTTPS 可达）时，『外部』定性错误，应直接核验而非推迟给操作者
- 任务合同只允许单一 PASS/REVISE 终态、无第三档位时，外部未确认项必须映射到合同的 fail-closed 档，不得自创双态
- 剩余项其实是代码层断言（fail-closed 分支逻辑、redirect 剥离行为）时属环境内可验，不能借『外部』推给操作者
- 环境内证据尚有缺口（负测未复现、SHA 未冻结）时不得提前套用此法收口

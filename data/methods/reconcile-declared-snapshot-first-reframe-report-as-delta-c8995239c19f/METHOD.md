## Trigger
消费/完善/拷问一份分析或修复建议报告（自带问题清单与任务清单），其头部声明了快照基线（branch/HEAD/日期），且读取后可能存在并行推进（隔天接手、分支已切换、他人续修同一主题）

## Discriminator
报告头部的快照声明（如『读取时为 <branch>@<HEAD>，非归档基线，不应盲目应用补丁』）在首次读取时即已出现，是一条可用单次 git 调用核验的身份主张；若当前分支/HEAD 与声明不一致且分支名语义正对报告主题，即证明报告的问题清单部分已过时，照单执行会重做已完成工作

## Short path
- 读报告，提取三样东西：声明的 branch/HEAD/日期、问题/证据清单、待执行任务清单
- 一次 git status --short --branch（或 rev-parse HEAD）核对身份，解未知量『报告描述的状态是否仍是现状』
- 若漂移且分支名对上报告主题：把报告按增量消费——逐条将原主张分类为『当前 HEAD 已完成/仍剩余』，而非从零逐条核验
- 只对剩余项做定向读取核验（记 file:line），拷问回答全部引用当前 HEAD 代码事实而非报告自证
- 把报告重写为『已完成 vs 剩余 delta』结构，任务清单仅保留剩余项；不可核验的外部主张保留原有限定
- 对剩余处方重查前置条件：其依赖的门/消费者（升级、回滚、旧版本互操作）是否因基线移动而改变

## Stop conditions
- 报告已按当前 HEAD 重框为增量结构：剩余项均带 file:line 证据，任务清单不含已完成项，且不可核验限定未被删除
- 快照核对无漂移（同分支同 HEAD）→ 跳过增量机制，直接进入内容级评审

## Verification
- 修订后报告每条证据引用当前 HEAD 的 file:line，写入时复核 git 身份仍一致
- 任务清单逐项对照当前代码确认确未完成才保留
- 对剩余处方核对既有门控消费者的兼容性（新增强制项是否会把与旧版本的升级/回滚路径砖化）

## Counterexamples
- 报告为本会话刚产出，或声明的快照与当前 HEAD 一致 → 无漂移，直接评审内容
- 纯设计/规范文档，不含代码状态主张 → 无快照可对
- 报告主体是远端现场或外部系统、本地仓库非其真值源（如本集 Linux 现场与补丁 SHA）→ 本地 git 核对不产生对这些主张的结论，只能保留『不可核验』限定
- 无仓库/身份源可访问的任务 → 无法核对，只能显式标注按文档自述执行的风险

## Trigger
多会话共享 git 仓库中接到非平凡『修复并并回主线』任务，且已可见并发活跃信号：worktree 数量异常多、共享分支上存在他人工作线的未推送提交、或已知有并行会话在仓库内工作

## Discriminator
链接 worktree 共享同一对象库：其他会话在自己分支上的在途（尚未合并任何主线）提交，用 git log --all -- <目标文件>（或 --grep 主题词、--since 限近时段）一次只读探测即可观测。判别信号在本集开工前已可见：worktree 数量达数百、本地共享分支领先远端若干他人工作线未推送提交——并发密度如此高时，同主题等价修复可能在授权后一两分钟内就进入对象库

## Short path
- 开工前除『缺陷是否仍在』外增列一个未知量：『是否有并行会话在同主题在途』；用 git log --all --oneline -- <目标文件>（或 --grep 主题词、--since 近时段）一次只读探测
- 命中且内容等价（同一修复机制）→ 不进修复流：worktree 检出该提交独立验证此前失败的测试，绿则零改动收口（报告已修、无需并）
- 未命中 → 按原计划在干净 worktree 修复（此段无浪费）
- 提交前与并 main 前等廉价闸口：fetch 后重复该探测——高并发仓库前提按分钟级衰减，开工时的答案到合并时可能已翻转
- 合并闸发现主线已含等价修复（按内容判等而非提交 id）→ 零合并收口：独立验证主线上的版本、删除自己旁支分支

## Stop conditions
- 任一次探测命中已在对象库/任一 ref 上出现且独立验证绿的同主题等价修复 → 停止修复流与合并流，零改动/零合并收口
- 开工前与合并闸两次探测均无在途同主题工作 → 走正常修复-验证-合并流，不再追加探测

## Verification
- 对命中提交做内容级核对：目标文件 diff 是否实施同一修复机制，而非只信提交信息措辞
- 在 worktree 检出并发修复提交，重复运行此前不稳定的测试确认确定性绿
- 合并闸判等用内容等价：对最新远端 cherry-pick 本地修复得空提交、或树级 diff 为空；不以提交 id 或分支名匹配

## Counterexamples
- 单会话仓库、无并发信号（worktree≈1、无他人未推送提交）：all-refs 探测只添噪音，直接修复
- 同文件命中但改动不等价（仅重构 import/格式化，未触及目标缺陷机制）：不算已修，照常开工
- 无并回主线意图的本地探索性改动：不存在会衰减的共享状态前提，不需要该闸

## Trigger
调研或升级既有度量/遥测功能（如把测试期指标升级为运行时面板），且任务描述、goal 文本或验收测试 docstring 已显式枚举应覆盖的封闭集合（桶名/通道名/终态类别）

## Discriminator
命名全集减去分类器显式分支集合非空，且 grep 证实生产者确实在运行时写入该未覆盖值；同时既有验收测试是否路由经过分类器（还是直接读时间戳/底层字段）——两者合起来把『疑似口径缺陷』从『全部实现细节』缩到一个可证伪点

## Short path
- 从任务/goal/验收 docstring 抄下封闭全集（此时已知的桶名清单，零额外查询）
- 定位唯一的分类/聚合函数，列出其 if/elif 或 switch 的显式分支集合
- diff 两集合：命名但无分支的值 → 假设『样本静默落入默认/else 桶，两桶同时失真』
- grep 生产者写入点，确认该值真实被写入，区分『潜在缺陷』与『计划中未实现』
- 确认暴露面（端点/前端是否消费分类结果）与既有测试是否绕过分类层
- 写 red 测试：构造带该值的样本真实路由经过分类器，断言应归独立桶并复现误归；补分支后转 green，并适配他处的桶集合断言

## Stop conditions
- 全集每个值都有显式分支，或缺失值经 grep 证实生产者从不写入
- 默认桶合并是文档化设计且下游依赖该口径，非缺陷
- 缺陷已由 red 测试复现并修复，影响面 grep 闭合

## Verification
- red 测试必须路由经过分类/聚合函数本身（而非直接读原始时间戳），能复现误归默认桶
- green 后重跑桶集合断言与静态检查
- 在结论中登记既有验收为何没暴露（是否绕过分类层），防止下次再把绕过当覆盖

## Counterexamples
- 命名集合是愿景/计划，生产者尚未写入该值——缺分支属未实现范围而非潜在缺陷，直接 diff 会误报
- 分类基于连续阈值或正则而非封闭枚举——分支 diff 不适用
- 默认桶即文档化 catch-all 且下游依赖合并口径——补独立分支反而破坏既有契约
- 既有测试已路由经过分类器并断言桶集合——该缺口早被锁住，无需此法，宽泛调查才是浪费

## Trigger
需要验证或枚举一个正在运行的本地服务的注册表事实（工具/资源清单、schema、生效配置），且此前证据已暴露该服务的鉴权 header 形态与凭证管理端点（服务是自有资产、本机可达）；或旧文档断言与新实测出现局部矛盾（如某路径无 token 返回 200，而记录称一律 unauthorized）。

## Discriminator
未知量的权威答案只存在于服务自身的枚举端点（活体注册表性质），且当时已知：(a) API 面存在且鉴权 header 形态已从 bundle/文档确认；(b) 本机存在 token 管理端点，凭证大概率可取；(c) 静态面（前端 bundle、app 资源、二进制 strings）只能给出 UI 引用子集或混入配置键的污染候选。若『无 token ⇒ 清单只能静态取』这一前提从未被验证，它就是搜索空间开始扩散的位置——静态考古数轮之后，权威答案仍来自活体枚举。

## Short path
- 给未知量分类：活体注册表事实（清单/schema/生效值）还是编译期静态默认/预设——前者的权威来源是服务自身枚举端点，后者只能从静态工件定点取证。
- 文档与实测矛盾先做范围界定：对 UI 壳与 API 面各做一次无凭证探测，把旧断言改写为按路径类别的版本（如『Web 壳公开、/api/* 需 token』），不推翻整份文档，也不因局部矛盾转入全量逆向。
- 活体未知量：用已发现的凭证端点取 token（本机自有服务），带凭证调标准枚举端点一次取全量清单与 schema，落盘前脱敏扫描。
- 静态默认未知量：对 shipped bundle 只做精确 key 定点 grep（如默认值与预设档数组），一次即止，不做全量端点/符号逆向。
- 与文档记录数对拍（如 86 工具）；一致即关闭该项并停止一切静态挖掘，不再『换一个更干净的静态来源』。
- 顺手用一次进程识别（lsof+命令行）核实旧文档的拓扑性断言（如另一端口的 Python 服务归属），勘误一次即止。

## Stop conditions
- 活体枚举端点返回的清单与文档记录数严格一致且 schema 已脱敏归档 → 关闭该项，停止静态枚举
- 定点 grep 已取得默认值与预设档 → 停止 bundle 分析
- 矛盾已收敛为按路径类别表述且每类各有一次实测 → 不再对同一路径类重复探测

## Verification
- 活体返回的计数与文档记录严格相等（如 86），全量 schema 归档且泄密/绝对路径扫描通过
- 每类路径的实测状态码（如 200 壳 / 401 API / 403 能力缺失）与修订后断言一致
- 最终结论不再引用曾被静态途径污染的候选列表（如混入配置键的 62 项），且未对同一静态来源做第二次换参数枚举

## Counterexamples
- 服务未运行、不可达或非本机自有（无权铸造/读取凭证）→ 静态工件或历史抓包是唯一来源，本方法不适用
- 未知量本身是编译期默认值或 UI 预设（API 从不暴露）→ 活体端点答不了，定点静态 grep 才是正解
- 任务约束禁止任何带凭证调用或可能变更状态的请求（只读约束覆盖鉴权调用）→ 退回静态分析或向所有者索取已授权导出
- 静态 bundle/二进制本身就是审计对象（安全审查 shipped 代码）→ 静态分析是目标而非可剪枝的捷径

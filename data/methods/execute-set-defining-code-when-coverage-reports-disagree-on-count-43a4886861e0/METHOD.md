## Trigger
准备把覆盖/计数类断言（『X 被测过/有 N 个实例/被仪器 I 覆盖』）写进文档或计划，而手头多份报告对同一总体的基数不一致（如判定表记 5 对象×33 例、实际运行行数明显更少、对象总清单又更长），且成员资格由代码内映射/过滤表而非显式冻结清单决定

## Discriminator
基数不一致 + 成员资格由代码定义 + 未映射项走静默丢弃分支。此时『对象不在结果里』有两种不可区分解释——『测了无效应』与『从未进入可测集』——重读任何摘要都无法裁决，只有执行或静态读那段定义成员资格的枚举代码并输出集合差才能定案

## Short path
- 读目标文档，列出将写入的每条覆盖/计数断言及其依赖的仪器
- 对每条计数找到产出它的工件常量/表格并逐条核对，不做全目录宽探查
- 发现两份工件基数不一致→执行（或读）定义成员资格的枚举代码：映射表+默认分支，打印两侧集合差
- 若存在静默排除：把断言改写为『从未测量』口径，后续计划改为先补仪器（物化样本池、机械 check、进入门槛）再谈效应
- 每条断言都绑定到已执行的枚举输出或冻结工件常量后停止核验，落笔写入

## Stop conditions
- 新文本中每条覆盖/计数断言都能指向一个已执行的枚举结果或冻结工件的显式常量
- 每处基数不一致都已被集合差解释，或相应断言已改写为不依赖该覆盖

## Verification
- 重跑成员枚举并输出 in-A-not-in-B 的集合差，确认被排除对象与断言一致
- 引用的每个数字对应产出工件的具体常量/行号
- 『从未测量』类结论附排除它的具体代码位置（未映射分支/过滤条件）

## Counterexamples
- 成员资格已是显式冻结清单（FREEZE 文件）且断言直接引用它：读工件即可，无需执行代码
- 枚举代码昂贵或有副作用（触发外部调用/写状态）：只静态读映射表与分支，不实际运行
- 待写内容是纯建议/观点，不含覆盖或计数断言：无需此核验
- 两个仪器覆盖不同集合是有意设计（判定面宽、运行面窄）：不一致本身不是错误，错误仅在于把更大的集合写成已被测量

## Trigger
编排/实验长会话中，用户或上游在执行中途施加新的强制门（例：跑全量前必须由独立审查子代理 PASS），而一个昂贵的全量/批处理 run 已在飞行中持续产出结果

## Discriminator
ps 回执的进程启动时间/elapsed 可直接证明 run 早于规则到达；门的约束对象是结果可用性而非算力消耗或外部副作用本身；重跑成本可量化。三者同时成立才启用祖父隔离，缺一即改为立即停

## Short path
- 发现新门后先查在飞进程：用 ps 核对 run 启动时间是否早于规则到达，判定祖父条款是否成立，不凭记忆断言'早于'
- 估算剩余时长与全量重跑成本，作为'隔离 vs 直接停'的取舍输入
- 不杀进程；把本轮结果可用性显式挂到门上：审查 P0/FAIL → 本轮作废并排期门内重跑，PASS → 解除隔离
- 把祖父决定、作废条件与重跑成本在终值产出前写死落盘（交接文档），并向用户显式给出'不同意我立即停'的覆盖选项
- 门未落定前冻结一切下游阶段（新实验、变异器、发布类动作），裁决权留给门主人

## Stop conditions
- 用户表示不同意 → 立即停止在飞 run，不再讨价还价
- 审查门回执为 P0/FAIL → 本轮结果标记作废，只能按门重跑，不得部分采信
- 审查门 PASS → 解除隔离，结果可用，才继续后续编排

## Verification
- 复核 ps 启动时间戳确实早于规则到达时间戳，且该核验回执可追溯
- 作废/可用的处置规则在终值产出前已冻结落盘，事后不得再改口径
- 门结论落盘后按结论机械执行处置，处置结果回写交接文档

## Counterexamples
- run 剩余/重跑成本只有几分钟 → 隔离记账比直接停掉重跑更贵，直接停
- 门的目的就是阻止资源消耗或不可逆外部副作用（线上发布、共享 store 写入、API 花费）→ 事后隔离撤不回伤害，必须立即停
- run 启动晚于规则（明知有门仍启动）→ 不属祖父条款，按违规处理立即停并上报
- 门审查对象并非该 run 的产物（审的是另一组件）→ 挂接隔离无意义，按门的真实对象处理

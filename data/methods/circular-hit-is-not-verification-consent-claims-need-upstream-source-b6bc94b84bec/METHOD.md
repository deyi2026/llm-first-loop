## Trigger
待提交/待发布工件携带『用户在〈日期〉确认/同意』式事实性授权断言，本会话未亲历该确认，且断言将随 push/发布进入共享远端或公开面，推送前需核验；典型信号：对 evidence 库反复搜索均非空命中，但命中内容始终是该工件本轮被编辑的 diff 本身。

## Discriminator
首次 evidence 查询后逐条分类命中来源：若全部命中是本 run 自己编辑该工件的 execute_command 回执（内容即断言所在的 diff），即为自指循环命中——用户话语只存在于说出它的那个会话的记录面，不在工具观察库里。该分类一次即定案：继续换措辞查询只会返回同样回执，验证面必须切到断言点名的产出面。

## Short path
- 识别断言类型：归因于用户的授权/同意，本会话未亲历；未知量：是否存在独立记录
- 对 evidence 库查询一次并分类命中：存在非本 run 编辑产物的命中（用户原话、他 session 回执）→独立来源已在手；全部命中为工件自身 diff→停止再搜
- 切到断言点名的产出面：查产生该授权的并发会话的 goal checkpoint/消息记录，或向其 help_request，读取用户原话（如『同意这两条』）
- 读到原话语义吻合→工件可携带该授权注记并引用来源会话后推送；未找到→把措辞降级为『草稿记录用户确认、本会话未复核』，或有界询问用户后再推送
- 断言要么已验证、要么已显式降级，即停；不再为其追加任何措辞的证据查询

## Stop conditions
- 用户原话已在产出面读到，且语义与工件中的授权断言吻合
- 降级措辞已落文或有界询问已决，工件中不存在未验证的授权断言
- 证据命中清单已逐条分类为自指/独立，无未分类命中

## Verification
- 抽查最终发布的工件：每条授权断言都有独立来源可引，且没有一条引用指向本 run 自己编辑该工件的回执
- 回放证据查询命中清单，确认把『命中全为自指』当作了切换验证面的依据，而非当作『已验证通过』

## Counterexamples
- 断言的事实是工具观察（命令输出/测试结果）而非用户话语：execute_command 回执就是独立记录，换更精确词条继续查库是正当路径
- 命中里已含他 session 回执/goal checkpoint 对用户原话的独立转述：该命中即算独立证据，无需再切面
- 纯本地可核断言（本文件已脱敏）：直接读回比对即可，不必找上游来源
- 不携带授权/治理断言的常规内容：不强制全套流程，避免把每次改动都升级为溯源调查

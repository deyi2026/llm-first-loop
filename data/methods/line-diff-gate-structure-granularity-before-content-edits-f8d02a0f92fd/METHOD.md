## Trigger
跨平台提交/粘贴已审内容后，准入或验收闸以行级（逐行比对/相似度阈值）比对源稿与平台产物并首次被拒，而该内容刚通过语义级内容审稿

## Discriminator
拒绝回执给出行级比对分数（如 0.78 < 0.9 阈值）而非命名缺失字段，且语义审稿已 PASS——差异只能落在序列化粒度；此时源稿中存在 markdown 表格/多行复合结构，即构成『平台重排导致结构性失配』的判别事实，不需要先怀疑全稿措辞

## Short path
- 被拒后先对源稿与平台侧文本做一次行级 diff，列出全部失配行；未知量：差异在措辞还是结构
- 失配行聚在表格/复合结构块 → 判为平台重排造成的粒度失配，不改任何已验证措辞
- 把失配结构块改写为平台行稳定单元（每行一个完整句子），其余正文逐字保留
- 同一路径重交一次，核对分数过阈；grep 平台侧产物确认表格语法残留为 0、审稿修正串逐字在位
- 把『该平台会重排 X 结构』写入本任务系列台账，后续各期首次提交前预改写

## Stop conditions
- 同一准入路径一次重交即过阈值，且失配区域复检为 0
- 行级 diff 显示失配散布于正文措辞而非结构块 → 放弃结构假设，转内容修正
- 回执为自描述错误码点名缺失字段 → 属合同差分场景，机械补字段而非重排结构

## Verification
- 重跑同一闸（不换闸规避）确认分数 ≥ 阈值
- 平台侧产物中表格/多行结构语法残留计数为 0
- 此前语义审稿判定的错误串在新产物中为 0、修正串逐字在位

## Counterexamples
- 平台原生保留表格、行结构稳定渲染 → 低分即真实内容丢失，应修内容而非拆表格
- 闸做语义/归一化文本比对而非行级比对 → 结构改写不影响判决，拒绝另有原因
- 回执是命名缺失字段的自描述错误码 → 走『拒绝原因即合同差分』补字段路径，不需要重写结构

## Trigger
需要用户在其交互式 shell 里粘贴执行一段多行命令块（模型侧执行通道不可用，或动作必须真实发生）；或用户回贴的执行结果是 shell 语法级报错（如 parse error near ')'）且看不到任何命令输出

## Discriminator
三信号同时成立即判整块零执行：①错误文本是 parse/语法级且位于首条命令任何输出之前；②块内无任何中间命令输出；③提示符/工作目录未变。这把『哪几条命令跑了、要不要回滚』缩成『都没跑，直接重发』。写作期的对应判别：粘贴目标的 shell 选项状态不可探知，故装饰性 # 与裸 () 是词法地雷，功能必须与装饰分离。

## Short path
- 写作期：粘贴块内只保留可执行行——无 # 注释、无裸括号、无 heredoc；每条以 cd 锚定目录，有顺序依赖的步骤用 && 链接使失败短路
- 期望输出、停机条件、竞态核对说明写在块外的散文/表格中，绝不进入命令 buffer
- 已失败时：先逐项核对三信号（语法级错误在首条输出前、无中间输出、提示符未变），判定整块原子解析失败、零执行
- 零执行 ⇒ 不做任何回滚或状态修复，把同一批命令以无装饰版本原样重发
- 如需确证 shell 选项根因，另给一条无注释自查命令（如打印注释选项状态），但重发不依赖其结果

## Stop conditions
- 用户回贴无装饰块的输出，且各步与预先声明的期望输出吻合（含最终收口核对行）
- 错误从语法级变为某条具体命令的运行期失败 ⇒ 已发生部分执行，退出本方法，转入按实际执行边界排查

## Verification
- 重发块的第一条命令包含 cd 锚点加只读核对（pwd / git rev-parse HEAD / ls-remote），其输出证明执行发生在正确仓库与正确提交上
- 判零执行时逐项核对三信号，任一不成立（如已有中间输出）立即改判部分执行并排查状态

## Counterexamples
- 目标 shell 是 bash，或块被保存为 .sh 文件由 bash 执行：注释恒合法且提升可读性，强行去装饰反而损失信息
- 报错前已出现部分命令输出（如 push 已被受理后某步失败）：部分执行已发生，必须按实际执行边界排查与修复，不得套用零副作用结论
- 单条命令单行粘贴：不存在多行 buffer 整体解析问题
- 括号属于功能性语法（命令替换、引号内文本）而非装饰序号：保留不动，只剥离装饰

## Trigger
检索类工具回执为 timeout（执行失败而非未命中），或 miss 发生在多词复合查询上；未知量是'某先前产物是否存在可检索记录'（典型：用户问'我们设计的/上次说的 X 可以实现吗'）；或收敛镜像已写明'本轮必须执行某检索'但该轮无对应工具调用。

## Discriminator
回执文本可机械区分三态：'[状态: timeout]'表示结果未知；docs 的 no-hit 回执本身证明索引可用、且已列出当前全部相关文档（均非目标）——这两条当时已把'继续枚举一切'缩成'一次单词重试即可判定存在性'。另外镜像中已命名但未执行的具体检索命令，是'该轮必须执行'的直接可见事实。

## Short path
- 读到 timeout 回执：标记为'结果未知'，当轮用同一或更窄的单词参数重试一次（如 '中间件'/'middleware'），解决未知量：记录是否存在。
- 读到复合词 miss（如 'X 设计'）：降为单个关键词再试一次，区分'措辞/分词问题'与'真不存在'。
- 若两次均为确定性 no-hit 或重试再超时：停止枚举（不做最近N条宽列表、不换更多同义措辞），把超时侧标记为'不可判定'而非'未找到'。
- 向用户索要两个具体槽位：出处（哪个文档/哪次会话/仅口头/外部工具）+ 一句话核心目标；同时给基于已确立事实的条件化判断框架。
- 用户补齐后按条件分支评估可实现性，停止。

## Stop conditions
- 单词重试命中 → 读取命中的设计记录，进入可实现性评估，不再检索。
- 重试再次 timeout → 判定该存储本轮不可用，直接转向向用户要出处，不做第三次同参重试。
- docs 与 evidence 均有明确 no-hit 回执 → 输出缺性结论并附回执引用，同时提出出处问题，停止搜索。

## Verification
- 缺性结论里每处'未找到'都必须能指向明确 no-hit 回执；引用 timeout 的部分必须表述为'不可判定/本轮无法核验'。
- 收敛镜像中出现'必须执行/需再检索 X'的轮次，该轮工具调用里应存在对应 X；否则视为执行缺陷。
- 向用户的提问应包含'出处'与'一句话目标'两个具体槽位，而非开放式'再给我些信息'。

## Counterexamples
- miss 回执已显式列出权威最新文档且覆盖所问主题时，换措辞重搜是冗余（适用 resume-continuation-via-named-provenance 的边界），应直接沿回执引用走。
- 用户指涉物已在当前上下文或已打开文档中可见时，无需任何检索，直接评估。
- 工具预算将耗尽或该存储已知长期不稳定时，第二次 timeout 后不应再重试，立即转问用户。
- 回执是确定性 no-hit（非超时）且查询本就是单词时，同义改写重试信息量低，应转 broad discovery 或直接问用户。

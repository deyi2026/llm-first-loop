## Trigger
用户询问一个先前会话/先前构建的功能的启用状态或完成度（是否启用、做到哪一步、为什么页面上看不到），且存在可检索的决策记录或残留 artifacts（目录、脚本、日志、运行中服务）。

## Discriminator
『启用』的每个组成环节是否存在便宜的直接探针：决策=record/memory 检索；产物=artifact 目录与日志；运行=进程表+health；接入=拿具体服务名/端口在主代码树（src/scripts/webui/tests）定向 grep，权威位置零命中即可断定未接入；有效性=验证脚本+活服务秒级重跑。当某环节的直接探针存在且便宜时，同 corpus 的语义搜索变体、keyword 相似文档、evidence 档案恢复都是更弱证据类，不应先走——尤其当该 corpus 的定向搜索已经 miss，这个 miss 本身就说明该处不是此功能的权威位置。

## Short path
- 检索决策/记忆记录，恢复『当时约定做什么』，并锚定具体标识符（模型名/服务名/端口/endpoint）
- ls 产物目录 + cat 运行日志 + ps，回答『建了什么、服务还活着吗』
- 用锚定标识符在主代码树定向 grep：零命中 ⇒ 未接入主流程 ⇒ 『未启用』，同时意味着无落库数据，不必再枚举更宽目录
- 验证脚本存在且服务健康确认后，直接重跑一次取当前验证输出（顺带即健康验证）；不尝试从 evidence 档案恢复旧输出
- 按链条逐环列状态表（已就位环节 vs 缺失环节），再基于第一个断点提最小闭环方案

## Stop conditions
- 链条每一环都有直接探针结果（命中，或权威位置上的明确零命中）即可作答，不再追加语义搜索变体
- 『未接入』已由主代码零命中 grep 证实后，停止任何形式的更宽枚举（全树 search_files、逐目录扫描）
- 当前态验证结果已由活服务重跑取得后，不再回溯旧档案快照

## Verification
- 状态表每一行能指回一个可复现探针：记录 id / 文件路径与 mtime / pid+health 回执 / 具体 grep 命令与命中数 / 重跑输出
- 对『没有 X』的否定断言，探针必须覆盖 X 若存在必然出现的位置（主代码树、启用配置面），而非任意样本位置

## Counterexamples
- 功能产物已被清理、验证脚本不可重跑（一次性迁移），只能靠记录/档案恢复历史状态——此时档案检索是正确路径，本方法不适用
- 『启用』由 feature flag/环境变量/外部服务注册表控制而非代码引用——grep 代码树会误判为未接入，应先确定启用判据所在的配置面再探针
- 语义搜索命中的是名字精确匹配的该功能设计文档——读它是沿 provenance 前进，本方法只禁止 miss 之后基于 keyword 相似度（如共用『SCORER』一词）的联想阅读

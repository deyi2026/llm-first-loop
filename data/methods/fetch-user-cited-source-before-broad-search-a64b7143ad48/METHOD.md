## Trigger
用户提问中包含指向权威来源的具体引用（完整 URL、文件路径、错误原文），且核心未知量（鉴权/计费/兼容性/覆盖范围）至少有一个可由该引用直接回答；问题常混合冷门产品或套餐名与具体 API 端点，导致关键词全网搜索命中率极低。

## Discriminator
用户消息里在任何动作之前就已存在一个完整可抓取的官方文档 URL。这条事实足以把『全网搜索 TokenPlanUltra+MiniMax』缩成『先读这份被点名的文档，提取鉴权头、错误码表和按量付费提示』——它直接回答了问题的一半（能否接、怎么计费）。

## Short path
- 拆解问题未知量：① 该 API 的接入/鉴权/计费要求；② TokenPlanUltra 套餐的覆盖范围。
- 第一步直接抓取用户提供的 URL，从返回中提取 Bearer 鉴权、402 insufficient_balance 错误码、『按量购买 API』等计费信号——未知量①即被权威来源解决。
- 对剩余未知量②只做 1~2 次窄域检索：限定官方域名 + 套餐全名（如 site:platform.minimax.cn "Token Plan Ultra"）。
- 若窄域检索返回与上次相同的不相关结果簇，或连续 404，即判定套餐权益公开不可得，停止检索。
- 输出结构：已验证事实（回指官方文档）+ 显式标注未验证部分 + 给出最小实测（一次最小 API 调用或登录计费页）作为终验路径。

## Stop conditions
- 用户提供的引用已被读取，其鉴权/计费相关事实已全部提取；
- 窄域检索出现与上次相同的不相关结果簇或连续 404，判定剩余未知量公开不可得；
- 答案已明确切分已验证/未验证两部分，并附带可执行的核实手段，即不再追加确认性检索。

## Verification
- 最终答案中关于端点的每句断言都能回指到所抓取的用户提供的文档原文（鉴权头、错误码、按量购买提示）；
- 未验证部分被显式标注为未验证，而非用推测补全成确定结论；
- 同一语义的检索未发起第二次：对已返回过相同结果簇的 query 族不再近义改写重试。

## Counterexamples
- 用户给的 URL 已失效（404、JS 壳、需登录墙），读取无法获得信息——此时退回宽搜索是正确路径，不应固守引用优先；
- 问题纯概念性、不含任何具体引用（如『A 套餐和 B 套餐哪个划算』）——搜索优先才对，套用本方法只会白读无关文档；
- 被引用页面只是营销首页，无鉴权/计费细节——引用解决不了未知量，应更早扩大检索而不是继续沿站内盲猜 URL；
- 套餐权益页本身被良好索引、一搜即中——直接搜官方套餐页可能比先读端点文档更快，机械的『文档优先』反而绕远。

## Trigger
需要将 git（或类似文本工具）输出的文件名/键名单再加工为程序输入——剥目录前缀、拼接路径、逐名复制或逐名核对——且名单元素含非 ASCII 字符（如中文命名的经验/方法卡文件名）

## Discriminator
两条在动手生成前即可见的事实同时成立：①名单元素含非 ASCII（计划书/参考名单本身就是中文文件名，读文档第一步就能看到）；②该输出将被文本再加工并当作真实路径消费。两者同时成立即默认转义必然破坏内容，且任何只看数量的校验都无法发现

## Short path
- 生成命令显式禁转义后再做 sed/字符串加工：git -c core.quotepath=off（或 -z 配解码）
- 消费前先做元素形态断言：无引号、无 \nnn 八进制转义、前缀可剥、与权威参考名单逐名一致
- 计数校验（如 9+2）只作第二道门，永不单独放行
- 同款生成命令复制到另一台机器执行时，禁转义开关与形态防线随行——两端默认值相同，远端必踩同坑

## Stop conditions
- 名单已通过三道门：禁转义生成 + 逐名形态/比对断言 + 计数，且任何远端副本命令同样带防线
- 确认名单元素全为 ASCII、或输出不经再加工直接由原工具自身消费时，撤防以免过度工程

## Verification
- 抽查名单首尾元素：能直接作为路径被 ls/复制 dry-run 命中
- 与计划书/权威参考名单逐名比对一致（不只是数量一致）
- 在目标机器上用同款生成命令重跑一次，确认输出与本地一致后再进入消费阶段

## Counterexamples
- 全 ASCII 路径仓库：默认输出即真值，禁转义开关无收益，直接生成即可
- 消费端是 git 感知解析器（如 ls-files -z 配套解码、或会正确解析 C 风格引号的工具）：转义输出本就正确，禁转义反而破坏解析
- 名单仅用于计数/统计趋势、从不作为文件名使用：形态断言属于过度设防，计数即可

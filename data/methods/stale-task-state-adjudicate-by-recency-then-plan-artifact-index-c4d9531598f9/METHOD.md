## Trigger
延续型任务中恢复的 task_state 停在旧代（回执元数据标明不适用当前运行，或其『下一待办』在更新的对话里已有含哈希的收口报告），用户仅给『继续』类无新信息推进指令，需要确定本轮执行单元

## Discriminator
两条当时已知且可直接观察的事实：①新旧来源并存且可裁决——state 回执的代数/时间戳落后于对话中带产物哈希与验收记录的完成报告；②state 文本或首个读取工件已点名规划工件的精确路径，且该工件头部/正文又串起审查书、bench 文档等全部下游输入的路径与章节号——下一单元、判据、输入路径均可由命名引用索引导出，发现层（全库检索/换参重搜）没有待解决的独立未知量

## Short path
- 对比 state 的『下一待办』与对话最新完成报告（含产物哈希），按新近性裁决：不重做已收口单元
- 直读已点名规划工件的优先级/下一单元章节，取得本轮单元与验收判据（模型/build/模式/源码/证据对应等）
- 从该工件头部与正文引用提取全部输入工件路径（上游审查书定义行、bench 文档、目标目录现状）；若命名检索无匹配但更新来源已引用其存在，以引用方文档路径为准，不换更宽模式重搜
- 并行取锚点事实（定义原文+目录现状+当前口径数据）后进入执行，产出按工件内判据闭合
- 在规划工件回写留痕（新增行/头注+新哈希），停止

## Stop conditions
- 下一单元、其验收判据与全部输入工件路径均已从规划工件及其命名引用取得——立即退出发现层，进入取事实与执行
- 规划工件点名的路径失效（改名/移动）→ 退出本方法转作用域发现；新旧来源无新近性证据可裁决 → 退出并询问用户

## Verification
- 规划工件引用的章节号/路径与实际读取位置逐一对上，非凭记忆定位
- 被跳过的旧『下一待办』确有对话侧收口证据（产物哈希/验收记录），非凭印象断言
- 本轮产出按规划工件内判据闭合，并已在工件中回写留痕（新增行+新哈希）

## Counterexamples
- 对话与 state 冲突但无代数/时间戳等新近性证据 → 不得自行挑一边，应问用户裁决
- 规划工件本身与当前工作线脱节（点名路径全部不存在）→ 索引不可用，转作用域检索或工作线根文档
- 任务目标本身是发现型（如『找出所有配置了 X 的文件』）→ 宽检索就是正解，命名引用索引不覆盖目标集
- 命名工件检索无匹配且无任何更新来源引用过它 → 无匹配可能即为真值（确定性 no-match），不应强行从索引推导其存在并重试更宽模式

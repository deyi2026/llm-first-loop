## Trigger
验收/审查方实测反例：删除授权授予物后，缓存的授权计划仍被入口选用、仍能签发新授权 root（即撤销缺失）；且被要求先裁决撤销的入口/主体/优先级/提交边界，并被明确禁止新建第二状态库或复杂审批流。

## Discriminator
加载器契约自述为唯一权威开关（『absent config => default OFF』类语义），而消费点读的是启动时缓存到进程状态的字段而非授予物本身——这说明撤销对象已经存在，缺的只是把授予物当前状态在花费点重验；该事实把候选空间从『设计撤销服务/审批/新账本』缩成『定义授予物状态为撤销信号 + 花费点重验』。

## Short path
- 一次定位加载器、缓存消费点与新授权签发/root 函数，列出所有能花费授权的点（入口选择、root 签发、每动作 reserve）
- 裁决撤销语义：授予物删除/不可读/任一字节变化=撤销；加载时对已校验字节取哈希钉住；轮换后的新字节绝不复活旧授权
- 在每个花费点前加 fail-closed 重验：入口每请求、签发 root 前、每次动作 reserve 开头；命中→持久 stop（幂等：root 已停则抑制 CAS 冲突、保留首个 stop 原因）+ deny
- 定重启语义：配置路径已配置但授予物消失→加载返回无授权（默认关、零副作用）；已 stop 的 root 持久拒绝
- 负测按裁决语义逐条落地：删除后拒新 Run、read 与 edit 之间撤销、重启后仍拒、轮换=撤销、已停 root 幂等
- 回归+静态检查后统一设计文档/回执/实测三方口径（命令、exit、计数、SHA），并如实披露并发外部写入

## Stop conditions
- 裁决语义（删除/轮换/重启/CAS 冲突四类）各有真实负测且全部 exit0
- 撤销后所有花费点 fail-closed 且持久 stop 在新实例/崩溃重放语义下成立
- 回执、设计文档、实测计数三方口径一致，未动既有 staged index

## Verification
- 复放审查方原始反例：unlink 授予物后，真实入口选择与真实新 root 签发均应被拒绝
- 删除后新 Run 拒绝、动作间撤销触发持久 stop_requested、进程重启后拒绝、轮换字节拒绝、已停 root 幂等
- CAS 冲突下首个 stop reason 保留且动作仍被拒；合法串行正向流不受重验影响

## Counterexamples
- 授予物是被多个无关功能共享的常驻配置，删除会连带撤销无关能力——需作用域化撤销记录而非整文件删除
- 授权是无文件依托的签名/短期 token（到期自失效），撤销面在签发方吊销机制而非本地授予物
- 授予物字节在正常运维中会被合法重写（如重签同义内容），按字节钉住会造成假阳性撤销——应按语义字段比较
- 每动作 stat 文件在极热路径不可接受时，须显式裁决检查粒度与失效窗口，而非默认每动作重验

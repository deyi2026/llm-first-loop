## Trigger
规格/合同/接口说明用数学区间记法（[a,b)、(a,b]、[a,b]）或等价措辞（『半开区间』『不含上界』『now>=expires_at 必拒』）描述某个界限（TTL、有效期、窗口、配额范围），需要据此实现判定/拒绝逻辑及其测试。

## Discriminator
端点旁的括号字符：')' 表示该端点不含在内，到达即拒（elapsed >= bound）；']' 才允许 ==界 通过；左端对称。该事实在动手写代码前就已逐字存在于规格文本中，查表可得，无需猜测——若实现注释里出现与记号方向相反的转述（如右开却写『边界==允许』），即是未查表的信号。

## Short path
- 摘录规格中的区间记法原文，逐端点确认开闭——这是第一个未知量：每个端点 == 时允许还是拒绝
- 按括号机械映射运算符：右开→上界 >= 判拒；右闭→上界 > 判拒；左端对称
- 实现判定逻辑，注释直接引用记法原文（含括号与『不含上界』类原文措辞），禁止写自造的边界语义
- 为每个关键端点写三点测试：界-δ 断言允许、==界 断言按括号方向允许/拒绝、界+δ 断言拒绝；其余用例（风暴/干扰类）收进窗口内
- 定向测试真实 exit 0 后再冻结送审

## Stop conditions
- 每个关键端点都有三点覆盖，且 ==界 断言方向与记号括号一致
- 常量与判定处的注释能对上规格记法原文，无冲突转述
- 定向测试真实退出码为 0

## Verification
- 单独抽查 ==上界 那条测试：记号右开时它必须断言拒绝且拒绝码正确
- 对照常量注释与规格原文，确认没有『边界==允许』这类与括号方向矛盾的句子

## Counterexamples
- 规格只给标量（『TTL 1000ms』）而无任何区间记法或开闭措辞——边界语义确实未指定，应向权威方确认或显式标注假设，而非机械选 >=
- 时钟/计数为粗粒度整数，无法表达 ±1 单位——改用最小可表示步长做 δ，三点结构不变
- 判定已由库或策略引擎的区间类型承担——先核对该类型自身的开闭语义，不重复手推导

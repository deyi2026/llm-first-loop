## Trigger
目标页面已显示“草稿将自动保存”、实时字数统计与图标式富文本工具栏，需要经 CDP/语义操作做粘贴、清空空标题、插入图片或批量填 description 等结构变更。

## Discriminator
编辑开始前页面已可见两条事实：(1) 状态栏有实时“共 N 字”计数器；(2) 明示“草稿将自动保存”。二者加图标工具栏共同表明：真值是编辑器模型+服务端草稿，DOM/property 写会在草稿重载时被覆盖，且任一按键可能对相邻节点产生非局部副作用——因此计数器可作每步不变量，写入必须走输入管线。

## Short path
- 进入发布页后截图一次，记录三个事实：标题字数限制、字数计数器、草稿自动保存提示，并把当前图片元素数记为基线
- 标题与正文一律经真实输入事件（Input.insertText）写入；每次写入后读计数器，核对与预期字数一致再继续
- 每次插图/删除前记录图片元素个数，操作后重读核对 ±1
- 清理空标题前先预测按键效果：空标题前一兄弟是图片容器时用 Delete 而非 Backspace；操作后核对图片数，不一致立即撤销并换按键策略
- 批量填写图片描述前，先用一个字段做持久化探针：填入→退出预览→重进，确认草稿重载后仍存在，再批量填
- 计数全部一致且探针通过后发布，用作品管理列表等编辑器之外的界面确认入库状态

## Stop conditions
- 每次结构变更后，字数总数与图片元素数均等于变更前值±预期增量
- 至少一个字段经退出/重进预览的草稿重载往返后仍持久存在
- 作品管理列表出现目标卡片且状态为“审核中”等独立于编辑器的确认

## Verification
- 每个结构变更前后记录并对比字数计数器与图片元素个数，无法解释的 delta 当步处理，不带病继续
- 批量填充同类字段前，先用单字段做草稿重载持久化探针
- 发布后通过编辑器以外的权威界面（作品管理列表）核对标题、时间、状态

## Counterexamples
- 普通静态表单（登录、搜索框等）无草稿模型：native setter + change 事件即可，逐键计数纪律是纯开销
- 只读/感知类浏览器任务：没有写操作，不需要不变量检查
- 编辑器既无可见计数器也无自动保存提示：本方法的验证面不存在，应改用 DOM diff 或截图对比
- 平台提供一等内容导入 API/CLI 或编辑器自带导入入口：直接用它，跳过 GUI 按键模拟

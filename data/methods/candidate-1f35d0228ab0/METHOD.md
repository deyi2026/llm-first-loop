## Trigger
受限执行环境中系统能力探测失败（如脚本桥调系统服务报权限违例错误码），而待裁决的设计/工程分支是『沙箱拦截→须新做独立特权宿主进程』vs『系统权限未授→属用户授权前置条件』

## Discriminator
已有回执中出现的能力分裂事实：权限预检 API（AXIsProcessTrusted/CGPreflightScreenCaptureAccess 类）返回 true、相邻能力经其它通道可用（截图 exit=0 且读图见真实内容而非黑图）、仅一条脚本桥通道报权限违例——该组合把失败从『能力/权限级』缩到『单一通道级』，下一个未知量只剩『绕开该桥的直调 API 是否被拦』

## Short path
- 读已有探测回执，把失败钉到具体调用通道（哪个 API/桥在报错、错误码是确定性权限违例还是瞬态失败）；未知量=权限还是通道
- 跑一次权限预检（trust/preflight 类 API）：false→权限分支收口（用户授权前置条件，不是代码工作量）；true→排除权限假设
- 预检 true 而桥仍失败→用绕开该桥的低层替代通道（ctypes 直调同一能力的 C API）做一次最小读探针，取真实语义数据（窗口数/标题/焦点）为证
- 替代通道可用→按通道级归因更新结论：能力可用、无需独立宿主进程；逐项列出仍被拦通道与未验证面（如 mutation 动作、深层树、锁屏态）
- 每个探针只回答一个未知量，回执出现可与用户可见状态交叉验证的真实数据即停，不做无关枚举

## Stop conditions
- 设计分支所需的全部能力未知量（窗口元数据/元素树/窗口级截图等）均已找到可用通道并有真实数据回证
- 权限预检为 false：属用户授权前置条件，停止通道试探，转最小用户动作
- 替代通道同样失败，或该能力只有被拦通道一条实现：通道级归因不成立，独立宿主进程分支维持

## Verification
- 替代通道探针返回可交叉验证的真实数据：读到的窗口标题与用户当前可见屏幕一致；按窗口 id 截图经读图确认只含目标窗口，尺寸=窗口 bounds×scale
- 最终结论表逐通道标注 可用/被拦/未验证，每条都能对应到一次实测回执，无凭 exit code 或推断填表

## Counterexamples
- 预检 API 返回 false：就是系统权限未授，换任何通道都无济于事，属用户去系统设置授权的前置条件，不适用本卡
- 该能力不存在绕开被拦通道的替代实现（只有脚本桥一条路）：通道级归因救不了『独立宿主进程』结论
- 失败是瞬态或服务未起（超时、目标进程不存在）而非确定性权限违例错误码：应走『无结果先做控制探针再查域/环境』类分流
- 读通道实测可用不得顺带宣布 mutation 通道可用：动作投递（点击/键入）未经授权实测前必须标未验证

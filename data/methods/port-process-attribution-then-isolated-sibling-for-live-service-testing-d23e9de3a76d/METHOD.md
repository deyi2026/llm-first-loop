## Trigger
用户要求启动本机服务（如 web 服务）做实测/联调，而该服务可能已有实例在运行——尤其当前会话本身就由该服务承载（会话路由标记指向 web），或工作区/仓库存在该服务的运行与重启痕迹。

## Discriminator
监听端口→属主 pid→进程 cwd 的映射（一条 lsof -iTCP -sTCP:LISTEN 加 ps/lsof 看 cwd）能同时回答『是否已在跑、哪个端口、项目根在哪』；端口上的 200/403/404 在归属到进程之前没有任何身份判别力。第二个可用判别：目标 commit 的 diff 是否全部落在前端源码目录——纯前端改动则后端进程可原样复用，只需替换静态产物。

## Short path
- 收到『起服务实测』→ 第一个未知量是『是否已有实例在跑、属主项目根是谁』：直接做端口→pid→cwd 归属，不先扫常用端口、不先启动新副本、不按记忆猜项目路径
- 归属结果分支：无实例→按仓库启动/重启脚本正常起服务；有实例且版本即待测对象→直接对它实测并停止
- 有实例但版本旧→ 查目标 commit 的 diff 范围：纯前端则后端可复用；再判能否原地替换（写权限、会话自承载、共享生产数据）
- 原地替换被挡→ 在可写工作区构建目标版本，起隔离孪生实例：独立端口、独立 data 目录、UI/静态目录环境变量指向新构建产物；不动线上实例与其数据
- 静态层验证：index 引用的新 bundle 文件名/hash 与构建回执一致、bundle 内含待测标记字符串（如新文案）、auth/status 类端点返回符合预期
- 把对线上实例的破坏性动作（重启承载当前会话的服务会打断本对话）列为显式选项交用户选择，并给出临时实例的停止句柄

## Stop conditions
- 监听实例已归属到目标项目、且其版本/构建就是待测对象：直接实测并停止发现动作
- 隔离孪生实例已起且静态层验证通过：剩余仅差用户对破坏性升级或手工交互的裁决，停止自主扩搜

## Verification
- 报告中声称的端口/pid 能用 lsof/ps 回溯到所指项目的 cwd
- 隔离实例实际返回的 bundle hash 与构建回执一致，且 bundle 内含待测标记串
- 线上实例的 source binding 与数据目录未被改动（前后各查一次）

## Counterexamples
- 目标服务确实未在运行且无承载依赖：直接按启动脚本/README 起服务，端口归属调查是多余前置
- 端口的响应体已自述服务身份（如返回 name/version 的 JSON）：身份已确立，无需再查进程 cwd
- 待测改动包含后端/协议变更：隔离实例必须 checkout 对应后端 commit，不能复用任意旧后端（本集孪生实例后端差 2 个提交，对纯前端实测无影响，测后端行为则结论失效）
- 用户明确要求就在原端口原实例上测并接受会话中断：无需隔离孪生，直接走升级重启

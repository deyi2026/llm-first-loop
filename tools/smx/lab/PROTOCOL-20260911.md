# 阶段二协议（闸门 0 冻结件）— smx PoC 效益对照实验

冻结时间：2026-09-11。跑中不改；改动即宣告本轮作废并重跑。

## 1. 组件与职责

| 组件 | 路径 | 职责 |
|---|---|---|
| 任务定义 ×6 | `tasks/T{1..6}/task.md` | 固定正文（A/B 共用） |
| fixture | `tasks/T{1..6}/setup.sh` | 确定性初始状态（时间窗、sha 锚） |
| 判定器 | `tasks/T{1..6}/judge.sh` | 客观 exit-code 判定，输出 `.judge-verdict.json` |
| 编排器 | `harness.sh` | setup/cleanup-proc/cleanup/replay/judge-all |
| 指标提取 | `metrics.py` | DSH 事件日志 → metrics.json + calls.tsv（机械分类） |

| 配置卡 | `config.card`（A）/ `config-b.card`（B） | 装载到 DSH 会话的差异仅在此 |

## 2. 实验流程

每 run：`harness.sh setup T<n> <tdir>` → `dsh_task`（cwd=tdir，装载对应配置卡）→
`dsh_session_read` 取会话日志 → `harness.sh judge T<n> <tdir>`（harness 复核）→ `metrics.py <session>`。
产物：`lab/.runs/<ts>-<Tn><A|B>/{tdir 会话产物, judge 输出, metrics.json, calls.tsv}`。

- A 组（control）：仅 DSH 原生工具（含其 read 工具）。
- B 组（treatment）：A 的全部 + 末尾追加 config-b.card（smx 用法 4 行）。
- 顺序：每任务 A→B 紧邻执行；做 1 个 pilot run（T4×A、T4×B）验证管线后再放全量。
- dsh_task 参数：`--cd tdir`；不注入本会话历史。

## 3. 成功条件

全部由 `judge.sh` 判，无人工裁量；judge 按任务清单核验目录结构、文件内容、
进程一次性完成锚（pid 记录、重复运行检测）、fixture 文件 sha 一致性。

## 4. 指标提取口径（冻结；机械规则，A/B 同规则）

从 `session.jsonl.zstd` 的 `tool/call`、`step/start`、`turn/start`、`tool/result` 事件提取：

| 指标 | 定义 |
|---|---|
| turns / steps | turn/start / step/start 计数 |
| tool_calls | tool/call 计数 |
| tool_errors | tool/result 含 isError=true 的条数 |
| shell_calls | shell 类工具调用次数 |
| shell_perception_segments | shell 命令按 `;` `&&` `\|\|` `\|` 换行切段后，首 token ∈ {ls,cat,head,tail,stat,wc,file,find,grep,egrep,fgrep,du,df,ps,pgrep,lsof,pwd,tree,less,more,which,whoami,env,printenv,shasum,md5,cksum,od,cmp,diff} 且无写标记（`>` `>>` `tee` `find -exec/-delete`）的段数 |
| tool_perception_calls | name ∈ {read,view,cat} 的工具调用数 |
| sleep_calls / sleep_secs | 首 token 为 sleep 的段数 / 累计秒数 |
| smx_calls / smx_actions | 命令含 `smx.py` 的调用数 / 子动作分布（exec,bg,collect,wait,show） |
| smx_sub_perception | smx show 调用数（回执重放） |
| receipt_refs | 命令或参数引用 `.smx/runs` 或 `receipt.json` 的调用数 |
| wall_s | 日志首尾时间戳差 |

已知近似（如实声明，不构成偏向）：管道段切分是字符串级近似（引号内分隔符会误切；
`xargs`/`$(...)`/heredoc 内命令不计入分段）；分类基于首 token 白名单。A/B 施加同一套规则。
每 run 输出 calls.tsv 全量调用清单供人工复核（若有异议以 calls.tsv 为准）。

主指标（per 任务）：steps（轮次）、shell_perception_segments + tool_perception_calls
（重感知）、sleep_calls（等待轮数）、tool_errors、wall_s。
B 组附加：smx_calls、smx_actions 分布、receipt_refs（阶段三裁决证据）。

## 5. 采用闸门（B 组处理存在性检查）

B 组任一 run 若 smx_calls = 0 → 该 run 标记 treatment-absent，**不得计入 B 组统计**；
若全量 ≥ 半数 B run 为 treatment-absent → 实验无效，修任务卡后重跑全量（改动同样要过自检）。
A 组无对应闸门。

## 6. 假设与预设结论边界（沿 VALIDATE 文档，不变）

- H1（diff 减少重感知）/ H2（wait 减少轮次）：方向性观察 + 个案，n<10 无统计功效；同报失败率不升。
- H3（断言外包降错误率）：无反例即记 insufficient，不得推断「更可靠」。
- H4（诚实成本）：阶段一 spot 已达标，阶段二不重测（成本不随会话变化）。

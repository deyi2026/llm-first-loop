# 从 GLM 评测 harness 到 LFL 的增量改进方案

- 日期：2026-09-18
- 类型：analysis / design
- 性质：基于 GLM 评测 harness 经验与 LFL 本机事故证据的机制对比与增量建议
- 边界声明：P2/P3 涉及程序层机制，仅以 submit_evolution 建议，不自行修改

## 一、先对齐：LFL 与 GLM harness 是同构哲学的两个反向实现

| 维度 | GLM 评测 harness | LFL |
|---|---|---|
| 控制权方向 | 把控制权从模型手里**拿走**（客户端剥图、hook block、记 0 分） | 把程序强制**收正为规则层自律**（RULE-AI-01 明写"替代程序强制声明-回执校验"） |
| 适用场景 | 不可信的分布式评测 agent，必须机器强制 | 可信单会话运行，机制 + 判断双层 |
| 防污染 | 断网 + 删 git 历史 | RULE-AI-01/18：先验只作假设，先取当前证据 |
| 失败语义 | 占位输出记 0 分 | RULE-AI-07：不把失败包装成完成 |
| receipt | receipt ok ≠ 任务完成 | SMC ActionReceipt = 纯机械事实 |

**结论**：方向不是"把 GLM 那套搬进来"，而是找 LFL 缺的那几块。

## 二、增量方案（按价值排序，均标注归属层）

### P1｜信息性介入结构化 —— 最大增量，有 76% 统计支撑

- **GLM 数据**：人工干预中 70% 是"帮它知道"（澄清需求 35.2% + 诊断换法 34.7%），人接管仅 0.7%。**长任务瓶颈不在 autonomy，在低摩擦的求助通道**。
- **LFL 现状**：`checkpoint_goal` 只有 what/evidence/path/next，`handoff_now` 只有 decisions/memory——"我缺什么信息才能继续"不是一等公民字段。
- **改法（模型层，立即生效）**：checkpoint/handoff 增加结构化介入请求：

  ```
  needs:      缺什么上下文/决策（具体到"哪个参数没定"）
  hypothesis: 当前卡在哪个未验证假设上
  forks:      分叉点选项 + 各自代价（而不是替用户选）
  ```

- **收益**：直接强化"已确立事实 / 未解决问题 / 本步动作"三分结构，把 GLM 那 70% 的信息性介入变成 checkpoint 的标准产出。

### P2｜预算口径统一 —— 有本机真实事故，不是推测

- **GLM 教训**："context_window 不填真实值 → 客户端用保守默认 → auto-compact 时机错误"。
- **LFL 同构事故**：
  - `EXPERIENCE-20260827-content-json`：紧急压缩**连续 4 次空转**（90.6 万 → 90.7 万 token 只增不减）——根因是压缩预算看 content、守卫看全字段 JSON，**两套口径**
  - `EXPERIENCE-20260816-llm-ttl`：provider 级 60000 字符经 min 链压制全局 256000，**预算链不透明**
- **改法**：
  1. **口径统一原则**（程序层，走 submit_evolution）：所有压缩/守卫/预算计量必须同一单位与同一字段集，禁止两套口径并存
  2. **预算链透明**（程序层）：`adjust_strategy` 回执返回生效链（全局硬上限 × provider × run 哪个在压制），模型才知道真实预算——即"context_window 填真实值"的 LFL 版
  3. **分层预算表**（模型层实践）：单工具 60s / 单 LLM 120s / 任务级 `adjust_strategy` / Goal 级——每层耗尽显式 blocked，不静默。当前 max_iterations=500 + 后台委托经验（`EXPERIENCE-20260818`）已覆盖大半，补的是"耗尽 = 显式阻塞"语义

### P3｜早期失败前移 —— 把"必然失败的调用"消灭在 dispatch 前

- **GLM**：模型只收文本 → 客户端剥图、hook block PDF Read。
- **LFL 现状**：browser SMC 已实现"编译期拒绝"（compile rejection = dispatch 前机械复核，单次 dispatch 不自动 retry）。
- **差距**：这套机制只在 browser 工具上完整。
- **改法（程序层建议）**：precheck（`precheck_enabled=true` 已开）推广到所有 mutate 类工具——参数可静态判死的（路径不存在、schema 不符、快照 ref 过期）在 dispatch 前拒绝并**返回修复指引**，而不是执行后报错。模型侧配套规则已有（RULE-AI-07：契约不清先核 Schema），只差程序面覆盖。

### P4｜验证可复现性 —— 判分稳定化的 LFL 版

- **GLM**：固定 seed、固定 judge、3 次采样均值、pairwise 代替单点打分。
- **LFL 差距**：`self_evaluate` 五维已基于运行证据，但**单点自评不可重放**。
- **改法（模型层）**：
  - 结论验证尽量落在**可重放的机械证据**上：测试退出码、evidence SHA、命令回执，而不是叙述性断言
  - 主观判断类（设计/方案评审）用 `grill_me` / `design_review` 多角色互相制衡，对应 GLM 的 multi-judge + pairwise
  - `event_stream` + evidence manifest 已提供完整轨迹，保持——这是判分稳定化的审计底座

### P5｜失败语义传播细则 —— "记 0 分"的规则层翻译

GLM"API 失败占位输出记 0 分"，翻译成 LFL 三条可执行细则（模型层，并入现有实践）：

1. 工具失败回执 → 该结论点降级为"未验证"，禁用"基本成功/大体完成"措辞
2. `task_update` → blocked 时 `blocked_reason` 必须引用**最后一次机械回执**，不写感受
3. 部分成功的批次 → 逐项标注成功/失败，不做整体平均（对应"两次尝试失败该子项记 0"）

## 四、拷问评审与修订（2026-09-18 晚）

评审方法：对 P1–P5 逐项过三个风险面——缓存命中 / 智力与执行力发挥 / 过度干扰与漂移。全部通过，共 8 条修订：

- **P1（通过，2 条修订）**
  1. needs/hypothesis/forks 改为**条件触发**：仅在真卡住、真分叉时填写；普通 checkpoint 留空不算违规。防"自我申报"沦为表演性怀疑/仪式性填表（GLM 的 70% 是评测员主动喂信息，与模型自我申报不同构，不能照搬为必填项）。
  2. **结构红线**：checkpoint/Goal 状态只能以工具结果形式**尾部追加**进上下文，禁止任何实现把"Goal 稳定叙事"每轮重写进 system prompt——那会击穿前缀缓存（见第五节实证）。
- **P2（通过，1 条修订）**：预算链生效报告按**档位**输出（绿/黄/红 + 压制方），不报精确 token 数。防虚假精确诱发微管理式漂移。
- **P3（通过，2 条修订）**
  1. precheck 的修复指引只说"该核什么"（哪个参数没过哪条机械检查），**不给出具体改法**——防模型跳过重新 grounding、照抄提示（去接地化）。
  2. precheck 范围严格限定机械判定（路径存在性 / schema / ref 时效），不做启发式推断——防误判（ref 标过期实际有效）导致合法动作被循环拒绝。
- **P4（通过，1 条关键澄清）**："结论落在机械证据"指把**已产出的证据**持久化为可重放形式（evidence ref、SHA、退出码），**不是**为了可重放而重跑已闭合的验证——后者直接违反"成功或已闭合结论无新反证不重复核验"。主观综合类判断（设计/方案评审）仍走 grill_me/design_review，不强求机械证据。
- **P5（通过，2 条修订）**
  1. 措辞禁令**限窄**："禁用基本成功"仅适用于结论仅由失败回执支撑的情形（此时降级为"未验证"）；有成功回执支撑的结论照常明确陈述——全面禁令会催生"可能尚未完全验证……"式对冲废话，那是另一种 slop。
  2. 失败降级**沿因果下游传播**：仅降级该失败调用所影响的结论点，不全局回溯已闭合结论（防后期无关工具失败污染前面已验证成果）。
- **适用边界（新增）**：P1/P5 的结构化开销是 O(checkpoint)/O(结论) 级，**仅全量适用于长任务 Goal 语境**；短任务、无 Goal 的问答流不套用，否则是纯噪声。

## 五、缓存命中回退排查记录（2026-09-18 晚，实证）

- **现象**：当日 14:00 前缓存命中高，之后显著走低。
- **程序侧事实**（cache_guard + architecture_status）：
  - `stable_prefix_fp` 指纹机制在位；`prefix_changed=false`、`cache_prefix_epoch=1`。
  - 16 条 `cache_hit_regression` 报警**全部**标注"stable_prefix/epochs/model/provider 均保持可比"——前缀字节层面未漂移。
  - provider 回报最近请求命中 30.3%（11392/37541）；窗口估算 82%。命中 0% 样本的判定为 `low_hit_rate_ttl`：**请求间隔 649s > glm 侧缓存 TTL 300s，过期属预期**。
  - `low_hit_rate_provider` 诊断列出候选机制：provider 冷缓存 / TTL 淘汰 / 分片路由。
- **时间线**：13:14–14:48 browser evolution 两批落地（commit `3892982ac`、`26c649b08`，改 `src/llm_loop/browser/`），服务多次重启；18:06 另有源码小改。拐点与 evolution 窗口重叠，但重启不直接杀 provider 侧缓存（按内容前缀索引，与客户端进程无关）。
- **因果判定**：命中率回退的主机制是 **provider 侧 TTL（300s）+ 下午请求节奏改变**（多会话并行、交互间歇超 TTL、重启后冷启动预热）。上午为单会话连续 tool loop（间隔 < TTL，缓存持续保温），故命中高。**不是**近期优化破坏了前缀结构。
- **三项影响复核**：
  - 缓存命中：无结构性损伤；evolution 落地引发的重启与会话切换**间接放大** TTL 过期频率。
  - 智力/执行力：模型所见内容不变，智力发挥不受影响；真实风险在**预算链压制**——同日实测某会话 `model_aware_budget 1000000→110400`、`context.warning budget=71589`、storm_breaker 累计触发 5 次；低预算会话长期运行会频繁压缩历史、损执行力。这是 P2 的活证据。
  - 干扰/漂移：cache_guard 分型诊断（ttl/provider/regression 分开归因、"允许请求继续以完成预热"而不乱触发修复动作）是低干扰设计的正面样本，保持。
- **遗留不确定**：分片路由假说客户端无法证实/证伪，持续观察；TTL 过期可缓解（短间隔保温、接受首轮回退）不可根除。

## 六、Atria-Dawn 论文/README 直接映射的三条增量（2026-09-18 深夜补）

来源：arXiv 2609.15818v2 全文（§2.1 VEP、§4 人工过程数据、附录 B 评测协议）+ Atria-Dawn-Preview README。与 P1–P5 同源同团队，只收 P1–P5 未覆盖的三条；沿用第四节评审纪律（条件触发、档位化、防表演性填表）。

### P2 补充｜单调用预算一等化（程序层 → submit_evolution）

- **Atria 证据**：附录 B 全部长任务评测均为"总限 + 步限 + 单调用限"三层——GDPval 4h/250 步/**单次 LLM 调用 10 分钟**；DeepSearch 系 500 步/256K 上下文/**单次输出 64K**；JobBench 7200s/≤2 次尝试。单调用层是防"一次异常长生成拖死整个任务"的最小闸门。
- **LFL 差距**：`adjust_strategy` 可调维度仅 max_iterations/timeout_s/history_budget（工具 Schema 实证），单调用层不在其中；若全局有固定单调用超时（§二 P2.3 记过"单 LLM 120s"），也缺 per-Goal 覆盖。
- **改法**：增加 per-call 档位（LLM 单调用超时档 + 单次输出上限档），回执并入 EVO-20260918-8417246d 预算链档位报告（绿/黄/红 + 压制方，不报精确数）。

### P6｜失败转诊断样本的前置确认 + 模式聚合（模型层）

- **Atria 证据**：VEP 把失败 run 转诊断样本有硬前置——**结果可独立确认时才转**；"反复出现的失败模式直接驱动下一批任务构造"（模式聚合 ≠ 单条经验）；轨迹清洗剔除 incomplete/contradictory/duplicate/behaviorally invalid。
- **LFL 差距**：lesson 已有 root_cause，但无独立确认前置——纯自述失败即可入库，可恢复的执行问题会被固化为失败叙事；失败教训无聚合，各条为战。
- **改法（实践细则，立即生效）**：root_cause 必须引用外部可核回执（退出码/错误日志/evidence ref），纯自述不入库；同型 root_cause ≥2 条才升格"模式"，驱动下批 method/task 构造。

### P7｜提议/选择分离的决策归因（模型层）

- **Atria 证据**：§4 人工过程数据——人类干预中动手改代码仅 3.9%，而 56.5% 输出被修订、其中 75.4% 是 agent 收到反馈后自己改完。人管方向（提议/选择/拍板），agent 管执行。
- **LFL 差距**：checkpoint 记 what/evidence/path/next（P1 又补 needs/forks），但无"这一步谁拍的板、依据什么"——中断恢复后分不清"模型自决可重开"与"用户锁定不可重开"。
- **改法（实践细则，与 P1 同为条件触发）**：只在真分叉经用户裁决时追加一行 `decision: 裁决者(用户/模型) + 所选选项 + 依据回执`；普通进度 checkpoint 不填。handoff 恢复时 decision 行即"不可重开清单"的种子。

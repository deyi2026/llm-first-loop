# 缓存稳定规则架构（Cache-Stable Rules Architecture）

> 状态: 已定稿（2026-08-20 用户审阅确认）| 唯一规则真相源: docs/ai_rules.md（内容不变，仅承载方式变更）
> 触发: 8-20 一天 6+ 次 prompt/.env 改动 → 每次全量缓存失效；空闲 >10min 暴露 provider 缓存 TTL；用户对照 DSH 得出"结构稳定是最关键"

## 1. 哲学基础（LLM-first，程序最小化）

- **大模型是核心**：所有动作围绕大模型展开。架构核心 = 消息进 → 理解 → 行动 → 真诚回答 → 记住。
- **程序是辅助**：及时/如实反馈（[状态: xxx]），不是约束。大模型做对和出错都如实反馈；可随时了解架构运行情况并自主修正。
- **程序最小化**：能由 AI 自主 + 文档规则（docs/ai_rules.md）实现的判断，尽量不用程序。程序只保留 AI 无法自完成的部分（工具真实执行、存储、灾难性安全硬边界）。
- **文档规则 = 大脑约束**：docs/ai_rules.md 为唯一规则真相源（SoT），AI 自主遵守；程序不重复实现规则。

## 2. 缓存机制原理（决定一切的事实）

- DeepSeek 按**字节前缀**匹配缓存：请求从开头算起，最长与历史一致的前缀命中。
- **固定位置 + 固定字节 = 稳定前缀**：一个块在请求中位置固定、字节固定，首轮后即命中，成为后续轮次的稳定前缀。
- **尾部追加是缓存友好形态**：新内容追加到末尾 → 前缀不破坏，仅新尾段落 miss（小）。
- **中段/移动位置 = 断前缀**：任何已提交字节被修改/重排 → 其后全部重热（经验提示旧 bug 的病根，命中率 65-76%）。
- **TTL 保温**：provider 缓存约 10 分钟不用即过期；但若前缀被**其他并发会话持续使用**，则保温不过期（0b5b1566 3.4h 空闲仍 98.8% 实证）。
- **改前缀 = 全量失效**（RULE-AI-16 ①）：system prompt 任何字节变化 → 所有会话该段失效 → 重热。

## 3. 架构（四层，各司其职）

```
L0 稳定前缀（prompt.py 静态核心，几乎永不变）:
   身份 / C1-C6 协议硬约束 / FR-SAFE-01 灾难性安全 / 数据完整性   ← 程序硬执行（AI 无法自完成）
   + 三通道声明（规则→文件·记忆→search_records·经验→experiences）
   + 必读指令："任务开始经 read_file 读取 docs/ai_rules.md；规则文件版本变化时重读"
     ← 文档规则（AI 自主执行），非程序约束

L1 规则文件（docs/ai_rules.md，唯一真相源，AI 自主按需读取）:
   浓缩至 <3000 字符（方法层①-⑥ + 关键禁令），头部 version=N + 旧版作废声明
   读取 = read_file 工具回执 → 尾部内容 → 会话内固定位置 → 稳定
   改规则 = 改文件 + version+1 → 只影响未来新读取的会话 → 前缀零影响

L2 可拓展库（已有，天然同构）:
   experiences/（工具经验）· skills/（技能）· data/memory/（记忆，分级见 §5）
   新增能力 = 加文件/条目，不动任何前缀

L3 会话态（architecture_status 尾部注入）:
   事实快照 + 规则版本号（程序提供信息，AI 感知变化自行重读；版本号变化不影响前缀）
```

### 3.1 为什么不是"引擎固定注入规则"

考问发现：程序在固定位置注入规则 = **程序重复实现文档规则**，违背程序最小化；且规则在固定前缀位置时，改规则必然重热该段。**取舍结论：规则读取归 AI（read_file 工具行为），程序零注入**——接受"跨会话规则块位置不齐"（system prompt 共享 + 会话内稳定保住成本主体），换取程序最小化 + 规则变更零前缀影响。

## 4. 规则变更标准流程（从此不需要小心翼翼）

```
改规则 = 编辑 docs/ai_rules.md + version 号 +1（两分钟）
   → L3 architecture_status 注入新版本号（尾部，不动前缀）
   → AI 感知版本变化 → 重读新规则（read_file，尾部内容）
   → 已运行会话前缀零影响；新会话读到新规则
新能力 = 加 skills//experiences/ 条目（不动任何前缀）
```

## 5. 记忆分级（防污染，§"记住"环节卫生）

- 现状审计：记忆库 500 条中 **115 条（23%）为会话瞬时性内容**（时间戳/路径/PID/进度快照），以 fact/decision 形态混入全局，检索召回即污染。
- 分级方案：
  - 瞬时性条目补 `scope: session` 标记（含会话标识），检索默认不召回；仅原会话（或查询含对应会话标识）可召回。
  - 通用决策/约定/经验保持全局（默认召回）。
  - 来源标注强化：规则块头注 `[规则] v{N}`；记忆带 `type + ts`；经验带 `EXPERIENCE-*`。
  - 版本互斥：规则文件 `version=N + 旧版作废声明`，历史残留旧版本块以新版为准，不并存裁决。
- 程序只提供过滤服务（存储/检索隔离），是否采信归 AI（程序最小化）。

## 7. 决策记录

- 规则"每轮必见（确定性）"与"改规则零前缀影响"**不可兼得** → 选按需读取 + L0 必读指令 + 版本号信号（确定性指令在稳定核心，不牺牲执行力）。
- 规则文件 <3000 字符（防 read_file 截断——18,978 字符原文件 84% 中间会静默丢失）。
- 模型可改 SoT 文件：治理上要求规则变更经 evolve/人工审阅，不做程序级只读锁（程序最小化）。

## 8. 风险与回退

- 忘读风险：L0 必读指令 + 版本号信号缓解；若实测不读 → 评估在指令中强化"首轮必读"措辞（不动前缀字节？否——指令本身是 L0 的一部分，改它=改前缀，故 P2 定稿时一次写到位）。
- 规则浓缩丢细节：P2 时逐条 diff（19 条 → 浓缩版），关键反例/数值保留。
- 回归：P4 用真实任务对比"改造前 vs 后"的熔断触发、每轮输出、解决率。
- 回退：prompt.py 保留旧版于 git，一键 revert + 重启（一次前缀重建）。

# 决策：记忆瞬时性判定标准（Memory Scope Standard）——P0-2 数据层统一执行依据

> 状态: **已采纳（主区审查通过）** | 2026-08-21 | 依据: 镜像 LFL 实证归类（主区 27 条 session 全量） + 主区抽查验证 + ARCHITECTURE §5 记忆分级
> 触发: P0-2 记忆分级两次失败——镜像打标被 web 进程回滚、主区 27 条多数误标，两边现状均不可信，需统一标准后重打

## 0. 背景实证（为何需要标准）

| 现状 | 实证 |
|---|---|
| 主区 index.json | 536 条，27 条 scope=session——**19 条误标**（pylint 里程碑/身份映射/生效配置等永久性被标 session）+ 4 条重复冗余 |
| 镜像 index.json | 70 条，2 条 session（测试环境，非权威库） |
| 镜像打标被覆盖 | web 进程（35261）持有旧内存态，记忆写入触发 save 用旧态覆盖磁盘（裸写文件不可靠） |
| 结论 | **两边打标现状均不可信**，先定标准再统一重打（主区为权威库） |

## 1. 判定标准（唯一依据，逐条对照）

**真瞬时（打 scope=session）**——满足以下任一：
1. **进程/运行状态**：PID、启动时刻、旧代码驻留、重启动作、心跳（随生命周期自然过期）
2. **一次性临时**：单次授权（如"用户批准 kill 残留进程"）、单次进度快照（批次完成态）
3. **过期配置提醒**：明确标注"当前/截至/仍运行旧代码"且以时间点为基准

**永久（保持 scope=global）**——排除以上即永久：
- 规则/约定/方法论/经验（含操作教训、评测纪律、harness 经验）
- 项目事实/里程碑/官方修复结论/身份映射/生效配置决策
- 跨会话有复用价值的任何内容

**判断口诀**：内容是否**随时间自然过期**？过期 → session；永不过期 → global。

## 2. 判例（主区 27 条归类，作为对照基准）

| 类别 | 条数 | 示例 | 正确 scope |
|---|---|---|---|
| 误标（永久被标 session） | 19 | pylint 里程碑、飞书身份映射、生效配置、操作教训、M47 修复决策、评测纪律、SWE harness 经验、django 修复×2、批量验证里程碑 | **global** |
| 重复冗余 | 4 | "长回答防截断写文件"约定存 4 遍（75c07e10/6b9698fc/13e627b9/967ea3ca） | 去重（归 global 一条） |
| 合理瞬时 | ~4 | CLI 旧进程、重启加载新代码、旧代码长驻、batch13 进度 | **session** |

## 3. 执行流程（主区统一执行，镜像仅验证）

```
① 按 §1 标准全量扫描主区 536 条 → 产出打标清单（global/session + 去重）
② 清单供人工审批（逐条可查）
③ 打标执行：经 MemoryStore API（走 _merge_remote_changes 写前合并）或停写进程后写
   —— 裸写文件不可靠（镜像已证：web 内存态回滚覆盖）
④ 重启进程加载新态 + 磁盘重载验证存活
⑤ 镜像用同标准验证逻辑（不复制镜像打标结果）
```

## 4. 与代码层的解耦

- **代码层**（store 过滤 session_id + retrieve 透传）：逻辑正确、与数据层解耦，**可先批同步主区**
- **数据层**（打标）：按本标准重打，同步时**不复制镜像打标结果**（镜像 70 条仅测试环境）

## 5. 附加发现：记忆去重失效（4 条重复）

"长回答防截断写文件"约定被存 4 遍——记忆写入缺少去重（同内容短时间重复落库）。
**建议**：执行重打时顺带合并重复条目；去重逻辑（内容相似度）可作为后续演进项。

## 6. 记录：数据层打标可靠性要求

镜像两次打标失败根因（web 进程内存态回滚覆盖裸写文件）→ **打标须满足其一**：
- 停写进程后打标，再重启加载
- 或经 MemoryStore API（`_merge_remote_changes` 写前合并感知磁盘最新态）
裸写文件 + 不重启 = 必然被旧内存态覆盖（已两次实证）

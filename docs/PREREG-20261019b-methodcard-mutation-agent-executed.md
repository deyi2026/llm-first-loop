# 预注册（v2·agent 执行）：方法卡「变异器 + 受限应用」vs「自由改写」

- 版本：v2，2026-10-19 12:00 (+08:00)；偏离 #7 追加于 12:10，均在主跑启动前。
- 取代关系：v1（`PREREG-20261019-methodcard-mutation-pairwise.md`，人执行）**在执行前被取代，v1 无任何数据**。
- 变更性质：按 v1 §7，执行者从人换成 agent 属**执行偏离**，v1 结论不可由本实验恢复。v2 是**新预注册**，只对"agent 执行"这一条件负责。
- 判分器：`evals/methodcard_rsi_v1/grade_holdout.py`（纯机械，`FREEZE.json` sha256 校验，失配退出 4）。本文件不改判分器、不改题、不改样。

## 1. 为什么必须重新预注册（而不是把"人"换成"agent"就开跑）

v1 的主效率端点是人时（human-minutes）。agent 代跑后：

1. **构念被替换**：agent 的 token/步数与人时不是同一量纲；"节省人时"这个假设在 agent 条件下不存在。
2. **假设被削弱**：变异器的价值主张是"少改、可审、可复现"，它省的是**人的编辑力气**。两个 arm 都交给同等能力 agent 时，这份力气差被抹平——A 臂甚至因为要多读补丁而**更贵**。
3. 因此 v2 只能检验一个**更窄**的命题：*在同等 agent 成本量级下，缺陷驱动的受限应用是否在 held-out 质量上不劣于自由改写。* 「提升质量」不作为本实验的假设（v1 也未假设）。

未被本实验检验、此后也不得声称的：人时收益、人类编辑接受度、上线后真实任务收益。

## 2. 两臂定义（同一模型、同一提示骨架、temperature=0、同一 max_tokens）

执行器模型固定为 `.env` 的 `LLM_MODEL=glm/glm-5.3-flash`（provider `open.bigmodel.cn` 兼容端点），`temperature=0`，`max_tokens=4000`，并发 2（429 指数退避至多 8 次）。

- **A 臂 `mutator`**：执行器拿到 原文 + `method_mutator.py` 的缺陷清单/补丁/理由，硬约束为"只执行补丁、只填 TODO、补丁未触及行逐字保留"。机械校验：`difflib` 比 candidate→revised，任一非 equal hunk 若不涉及含 `TODO` 的行即记 **violation**（记录但不剔除，violation 率单独报告）。
- **B 臂 `human_equivalent`**：执行器只拿原文，允许自由改写（不改 frontmatter、不虚构证据、保持章节结构）。
- 两臂产物均落 `results_v2/run/cards/<pair>/<arm>.md`，`frontmatter_changed` 机械记录。
- **解题（盲评）**：每张产物卡 + 该卡所属 family 的 4 道 held-out 题，逐题单独调用，解题提示**不告知 arm**。`results_v2/run/calls.jsonl` 保留全部原文与 usage。

## 3. 样本与排除（先于数据）

- 取自 v1 冻结抽样 `prereg_v1_cards.jsonl`（`PREREG-FREEZE` sha256 已校验），**不重新抽样**。
- **排除 F5_other（6 对）**：v1 §4 把 `F5_other` 映射到 `C_authority`，但 F5 是按"未命中前四类关键词"选出的杂类卡，内容与权威新鲜度无关。该映射是 v1 的对齐缺陷，v2 按"无有效 family 对齐即排除"处理，不做任何替换式补抽。
- **排除 `P21`（1 对）**：变异器 `REFUSED: 正文出现在第一个 ## 段之前`，属 v1 §6 规则 (a)"卡无法解析"。
- 进入主实验：**23 对**（F1 6、F2 6、F3 6、F4 5；P21 属 F4，先前笔误记为 F1，12:25 更正，不改变规则）。

## 4. 端点与判据（先于数据固定）

- **主端点**：check 级通过率。每对按 family 的 4 题展开，check 数分别为 A=13、B=11、E=9、D=10。
- **次端点**：题级通过率（该题全部 check 通过才算过），仅报告，不参与裁决。
- **成本端点**：A/B 两臂**改写调用的总 token** 中位数之比 `token_ratio`。
- 配对差 `Δ = rate_A − rate_B`（同一对同一批题，配对成立）。
- 统计：配对 bootstrap 10000 次（seed 20261019）+ 精确符号检验；23 对必须全部齐全，缺对**拒跑**、不删点。

**决策规则（互斥，按序命中）**

| 规则 | 条件 | 含义 |
|---|---|---|
| D1 `SHIP_L1_AGENT_DEFAULT` | CI 下界 ≥ −0.05 且 `token_ratio` ≤ 1.00 | 受限应用可作为默认 L1 路径（agent 条件下） |
| D2 `ADOPT_IF_BETTER` | CI 下界 > +0.05 且 `token_ratio` ≤ 1.10 | 变异器确实涨质量，可推广 |
| D3 `REJECT` | CI 上界 < −0.05 | 降级为纯 linter，撤销"变异→默认"主张 |
| D4 `INCONCLUSIVE` | 其余 | 不下结论；报告 CI 宽度与功效 |

## 5. 仪器闸门 M0（先于主跑，结果未读）

主跑前先做 manipulation check：同一批题分别给「原卡」与「不给卡」。若四族中每族的（给卡 − 不给卡）均 ≤ +0.05，判 `INSTRUMENT_FLAT`：**主跑不启动**，结论为"held-out 题对卡内容不敏感，该仪器无法检验卡质量"，直接上报。任一族 ≥ +0.15 判仪器有信号，可进主跑；介于两者之间则每族加到 2 张卡重测。

**补充裁定（13:05，解题阶段尚未开始、无任何解题结果）**：n 再由 8 对降为 **4 对**（F1/F2/F3/F4 各 1 张：P01/P07/P13/P19）。理由：大 prompt 请求在该端点实测 ≈1 次调用/2 分钟（小请求 2 s，故非宕机；并发被服务端串行化），8 对全程 >50 min。切点在第一个解题调用之前，未接触任何结果。n=4 只能看方向、不能作统计推断。

**补充裁定（12:40，主跑前，M0 结果已读、主跑数据已清空）**：n 由 23 对降为 8 对（偏离 #8），因此本节 D1–D4 **一律不出具**，实验降级为描述性诊断；报告须给出 A/B/原卡三方的逐对比对与截断/违约计数。

**补充裁定（12:20，主跑启动前，M0 结果已读）**：若每族加到 2 张卡后仍无任何一族达到 +0.15，判 `M0_INSUFFICIENT_SENSITIVITY`。此时主跑**可以执行，但只作描述性诊断**：不出具 D1–D4 裁决，不据此改变默认路径；报告须同时给出各族"不给卡基线"，因为他族天花板会使 D1（非劣）自动成立，属橡皮图章。

## 6. 停止与失败处理

- 单次调用失败重试至多 6 次（429/5xx 指数退避）；仍失败则记 `ok=false` 并继续。
- 任一阶段失败率 > 20% → 停止，报告失败面，不补跑凑数。
- 预算上限（按偏离 #7 修正）：92 次调用（46 改写 + 46 批量解题），≤ 1.2M token，墙钟 ≤ 80 min。超限即停。

## 7. 已知威胁

1. **单题粒度粗**：每对仅 4 题（9–13 个 check），23 对的 CI 会较宽，预期功效低——这是样本身上限，不能用事后加题补救。
2. **卡—题相关性弱**：held-out 题自带输入，强模型可能不依赖卡也能答对 → 天花板效应。
3. **A 臂干预过窄**：30 张卡里 29 张只报出 1 类缺陷（`unlinked_verification`），A 臂实际只加"验证条目↔停止条件"的对应关系，A/B 差异可能小到测不出。
4. **模型自评偏差**：改写与解题同模型，可能偏好自身风格 → 对 B 臂有利，方向已知（保守）。
5. **单模型单次**：无重复采样，方差未估计。
6. **题间共享上下文（偏离 #7 引入）**：同一卡的 4 题在一次调用内作答，可能互相提示；两臂同构，故对 Δ 的影响方向未知。
7. **天花板**：M0 若显示某族"不给卡也全对"，该族只可能测出退化、测不出提升。
6. 本实验不覆盖 v1 的人时主张。

## 8. 偏离登记

| # | 偏离 | 理由 | 影响 |
|---|---|---|---|
| 1 | 执行者 人→agent | 用户指令：以专门 agent 代替真人执行 | 效率端点换量纲；人时主张作废 |
| 2 | 排除 F5_other 6 对 | v1 把 F5 映射到 C_authority 属对齐缺陷 | n 30→24 |
| 3 | 排除 P21 | 变异器拒绝解析该卡（v1 §6(a) 已预授权排除） | n 24→23 |
| 4 | 主端点 题级→check 级 | 4 题/对粒度过粗（0.25 分辨率），check 级为 9–13 | 分辨率提高，仍受样本身限制 |
| 5 | 效率度量 人时→改写 token 比 | agent 无"人时" | D1/D2 门槛据此重设，未看数据 |
| 6 | 新增 M0 仪器闸门 | 防止"卡对题无影响"时仍空跑 234 次调用 | 可能直接判 `INSTRUMENT_FLAT` 并停止 |
| 8 | 主跑由 23 对降为 **8 对**（每族 2 张，与 M0 同一批卡片） | 端点实测吞吐 ≈1 次调用/分钟：23 对需 >90 min，8 对约 30 min；且 M0 已判灵敏度不足，全量跑不改变结论性质 | n 23→8，CI 更宽；**不出 D1–D4 裁决**，仅描述性 |
| 10 | 主跑进一步降为 4 对（每族 1 张） | 端点串行化，吞吐 ≈1 次/2 min；切点在首个解题调用前 | n→4，仅描述性 |
| 9 | `max_tokens` 上调（改写 8000 / 批量解题 6000），`finish=length` 直接判无效重试 | 首批 7 次改写中 2 次因推理占满预算被截断（P02-B、P04-A），截断会假性压低分数 | 已截断样本作废重跑，不进入统计 |
| 7 | 解题改为"一卡 × 4 题 单次调用" | 该端点 429 明显，逐题调用（184 次）墙钟不可接受；批量不改变给模型的信息量 | 调用数 234→92；4 题共享一次上下文，题间独立性下降（已在 §7 记为威胁） |

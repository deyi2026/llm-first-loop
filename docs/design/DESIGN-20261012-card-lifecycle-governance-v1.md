### 1.2 根因

卡片创建成本 ≈ 一次工具调用；失效成本 = qualification fail **或** 两次 rejected use。单向阀门，只进不出。问题不在积累速度，在**淘汰速度**与**复核动力**。

### 1.3 量化现状（2026-10-12 20:26 实测）

- `experiences/` 407 项，`data/methods/` 868 项，合计 **≈1275 张卡**。
- 每周随机抽 3–5 张 ⇒ 单卡期望复核周期以**年**计。⇒ 周检不可能承担保鲜主责（见 §4 修正 M1）。

## 3. 需求

### R1 创建门（管 S3）
新建任何卡（experience/lesson/method candidate）前：
1. **按问题类型检索**已有卡（关键词如"夸大/404/降级"，而非卡名），experience 与 method 两个池都搜；
2. 命中 ⇒ 新卡正文必须写**区别声明**（本卡比命中卡多管什么），或改走 `record_use(adapted)`；
3. 正文**三段式**，缺一不建：
   - (a) 适用信号——出现什么就该想起这张卡；
   - (b) 不管什么——边界与易混邻卡；
   - (c) 核验方法——1–3 个**可执行**核验点（路径/命令/URL），供周检直接跑。
- 存量 1275 张**不回填**；由 R4 抽到时机会性补齐。

### R2 收口转化（管 S2）
晚班 SOP 在写当日 STATUS 之前加固定一步：扫当日工作笔记 → 按"教训 = 重做会避免一次已发生失败的运作规则"判定 → R1 同款检索去重 → `save_experience(record_kind=lesson)` 入库。当日 STATUS 必含一行：`教训入库：<id 列表> / 0 条 / 未执行-原因`。**快速通道不设**：先笔记后卡片，料永不禁丢。

### R3 失效门槛分级（管 S1，**主阀门**）
三轴分离，禁止混判：

| 轴 | 判定 | 动作 |
|---|---|---|
| 事实轴（前提对错） | **单一机械证据**即成立：URL 404（**双采样**，间隔≥10 分钟）、API 字段不存在、代码行为与卡片描述冲突（附文件：行摘录） | 立即 `invalidate(evidence_refs, note="前提错误：…")`；必要时落修正替代卡（method 用 `parent_ref`，experience 正文互指）。**可 `restore`**，误伤保险 |
| 有用轴（好不好用） | 维持原门槛：qualification fail 或 2× rejected use | `invalidate` 或 `archive` |
| 门禁轴（资格状态） | EVO-20261010-994e30f4"缺第二任务类型"**不是失效理由** | 仅影响 promotion，与上两轴正交 |

任何使用现场（record_use 时）发现前提不成立 ⇒ 当场走事实轴，不等周检。

### R4 风险导向周检（慢扫，非主责）
- 触发：每周四 20:00 通知（先于周四 20:53 周入库，产物当夜入库）。
- 抽样池（风险导向，替代原"随机 3-5"设计，依据 §4-M1）：
  1. 近 14 天被 `record_use` 引用或工作笔记提及的卡——**全查**；
  2. (c) 段核验点最久未跑的卡——至多 3 张；
  3. 随机兜底——2 张。
  上限 8 张/周。
- 动作：逐张跑 (c) 核验点 → 产物 `docs/governance/card-audit/YYYY-MM-DD.md`，每卡一行 `卡id | 核验点 | 证据摘录 | 结论`；**无证据摘录的"通过"行 ⇒ 本次审计整体无效，重跑**。发现事实轴问题当场走 R3；顺带补齐三段式。
- 走样检测：连续 6 周审计"零发现且零失效" ⇒ 触发校准警报（审计在走过场）。

### R5 写前量化（管 S4）
- 范围：正文一切可核数值（计数/百分比/版本/日期/时长/大小），"约/近/超"同样算。
- 动作：写作时同步写**伴生 ledger** `docs/promotion/YYYYMMDD-daily-NN-sources.md`，行格式 `正文数值 | 出处（文件:行 或 回执路径） | 观测时间`；ledger 不进发布正文（md2html 只转主文件，天然隔离）。
- 审计改法：正则抽取正文数值 → 逐条对 ledger（缺行 = REVISE）→ 随机抽 2 条**实开来源**复核。审计从"验真相"降为"验格式＋抽检"。

## 5. 设计补充

### 5.1 三段式正文模板

```markdown
## 适用信号
<出现什么情况/什么类型的坑，应当想起本卡>

## 不管什么
<边界、易混邻卡（点名）、常见误用>

## 核验方法
1. <可执行核验点：路径/命令/URL，附期望结果>
## 核验记录
- YYYY-MM-DD：<证据摘录> → <成立/失效>
```

### 5.2 失效决策树

```
发现卡片可疑
├─ 能给出机械证据（404×2 / 字段不存在 / 代码冲突摘录）？
│   ├─ 是 → 事实轴：invalidate(证据) + 需要则落替代卡 → 记录核验行
│   └─ 否 → 是"用了不好用"且有资格证据？ → 有用轴：原门槛
│            └─ 都不是 → 不动卡，记入当期审计产物「观察项」列（格式与三态出口见 card-lifecycle.md R4）
└─ 仅涉及 promotion 资格 → 门禁轴：走 method_manage，不碰失效
```

### 5.3 度量

| 指标 | 定义 | 健康线 | 异常含义 |
|---|---|---|---|
| M-阀门 | 月度 失效数 : 新建数 | > 0（有淘汰） | 比值≈0 且新建>0 ⇒ 阀门再次卡死 |
| M-形状 | 新建卡三段式完整率 | 100% | <100% ⇒ 创建门失守 |
| M-证据 | 审计产物中带证据行占比 | 100%（否则审计无效） | 反复 <100% ⇒ 周检走过场 |

## 2. 需求与非目标

- **R1 减少出错**：消除假阳性（摘要无依据类）、半落地修订、口径漂移。
- **R2 减少重复**：全量复审、无效轮询、逐条 shell。
- **R3 提高收口效率**：完成即停，收口延迟（发布回执→run 终止）≤2 轮 [参数]。
- **R4 减少 token 浪费**：真实未命中 tokens 与无效轮次双降。
- **非目标**：不降低发布质量门槛（P0/P1/P2a 处置规则不变）；不改 provider 缓存策略；不引入新的外部依赖。

## 4. L1 详细设计（流程层）

### D1 完成即停 + 降级链
- 停止判据链（全满足才停）：**发布回执 ∧ 公网正文验收 PASS ∧ STATUS 落盘**。满足后立即 `update_goal complete` 并终止 run；禁止交付后追加审稿。
- 降级链：公网验收失败 → 3 次指数退避重试 [参数：1+2+4 分钟窗口；失效边界=平台端到端延迟常态超过窗口时提高上限，而非放宽判据] → 仍失败则降级为两级判据（冻结稿 SHA 与平台回执一致）+ STATUS 显式标注「公网未核项」，交由下一班补核。不无限重试、不误停。
- fail-closed：任一判据空/无回执 = 未完成 = 继续任务（RULE-AI-30）。不得以「页面看起来已发布」替代回执。
- 收口脚本幂等（台账 key 去重，重复执行不重复记账）+ 写后读校验；崩溃可从 receipts/ 恢复 [实测：d80 admission/closeout 双回执模式已验证]。

### D2 审稿分级 + 轮数预算 + 误判回路
- P2 二分（白名单式，宁可误升不误降）：**P2a 强制处置**=凡涉数字口径/事实结论/引文/标题标签规范/两类夸大；**P2b 措辞级**=登记不阻断。
- 轮数预算 ≤3 [参数，依据=39 条 P2 全措辞级且 P0/P1 恒 0 的实测分布]：
  - R1 全量审（完整 summary 原文入包）；
  - R2 窄复审：只送 diff+改动理由+相邻上下文，**附事实类全量清单兜底**（P0/P1/P2a 口径逐条核对，防 P2b 误放事实错误）；
  - R3 起只收 P0/P1，其余登记留档。
- PASS 绑定新 SHA 时，窄复审仅对 diff 负责，不触发全量重审。
- **分级误判检测回路**：R2 发现 ≥1 条 P2a [参数，宁严勿松] → 记分级事故 + 当轮回全量模式 + 复查分级口径。
- 预期收益：审稿轮数 10→2–3，重贴 7→≤2。

### D3 审稿包规范
- 入包=完整 summary **原文**，禁用要点清单 [实测：要点清单造成 4 处「摘要无依据」假阳性，白送一轮]。
- 核对清单引用**机检回执字段**，禁写死行数/字符数 [实测：写死数字是口径漂移源]。
- 子代理输出硬约束：每条一行、限字数 [实测：d67 截断丢失在 d68 连续 8 轮验证有效]。
- 稿件长度增长超子代理输入预算（31,698 字符 [实测]）时按预算切包，禁整包硬塞 [假设：3 倍增长情景下切包规则接管]。

### D4 等待纪律
- 粗等待替代轮询：`wait(job_id)`、`schedule` 事件谓词（job_terminal/review_terminal）。
- 违规判据（机器可判）：**连续无进展查询 >3 次** [参数]——修正 d80 复盘口径（136 次混入 spawn 启动动作，纯轮询未单独测量，故以「连续无进展」为判据而非总数）。

### D5 shell 合并
- 同阶段 grep/校验/派生统计合并为一次脚本调用；一次性脚本先落盘再执行（RULE-AI-36）。
- 预期：310 次 → 单班 ≤80 次 [参数，阶段目标]。

### D6 收口单一脚本
- verify + STATUS + 台账 + goal 更新合并为一次执行；输出人类可读摘要 + 机读 JSON 回执（双回执落 receipts/）。
- 覆盖 d80 遗留缺口：来源会话 run2 结束时 goal 未收口，需接管会话补账。

### 10.2 M3 口径修订提案（两案，倾向 A 先行）

- **案 A（改口径，零代码）**：M3 := 发布回执 → **closeout 回执落盘 ≤2 轮**；公网验收等待、知识结算（RULE-AI-29 强制）、最终汇报移出度量段，另设 M3′ 观察项（不计红线）。依据：首班 30 轮中约 15 轮为上述不可压缩环节，2 轮红线在现班次结构下不可达，属参数缺陷而非执行缺陷。
- **案 B（改结构，需 D8 演进）**：公网验收异步化——发布后按 D1 降级链常态走"两级判据+下一班补核"，班次 run 在 closeout 后终止（schedule 事件谓词驱动补核）。M5 与 M1 会随之变化，需重新基线。

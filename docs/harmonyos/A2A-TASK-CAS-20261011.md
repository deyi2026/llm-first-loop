# A2A Task admission durable CAS — provider-free phase

Date: 2026-10-11. Isolated branch: `feat/harmonyos-native-agent-poc-20261011`.
Status: **offline CAS primitive QUALIFIED by focused tests; real A2A ingress NOT ENABLED**.

## Rationale and authority separation

The eventual Huawei A2A `EXECUTE` may be redelivered after network loss,
device restart or caller retry. Sending the same full Task to LFL twice would
be a new human turn, potentially repeating external side effects.

The independent `A2aTaskAdmissionStore` lives in
`src/llm_loop/web/a2a_task_admission.py`. **It does not reuse
`TaskBudgetStore` as an authority**, because:

- A2A Task admission answers whether a specific authenticated, exact user
  ingress has been durably reserved once.
- TaskBudget separately authorizes finite provider/tool physical attempts,
  budget inheritance, settlement and stop. A CAS receipt **never** increases
  TaskBudget limits or bypasses the existing Web budget gates.
- The actual Huawei host proof, LFL Web user/workspace permissions and
  authenticated transport are not supplied by this store. No route currently
  invokes this module, and the App contains no registered A2A server.

## Contract and storage

The future verified host adapter must supply a trusted `principal_id`,
`task_id`, `context_id`, `client_session_id`, `agent_id`,
`workspace_scope` and **exact bytes** of the frozen human request. A
caller-selected principal string alone **is not authentication**.

`reserve(A2aTaskIngress)` creates a strict single immutable record under
the caller-approved LFL data directory's private `a2a-task-admission/`
subdirectory. Paths derive from `sha256(task_id)` rather than untrusted
literal IDs. Parent data root must already exist. Only a confirmed
durable create-if-absent returns `newly_reserved=True`:

1. Shared per-Task `flock` lock, re-read exact authoritative record.
2. Exclusive `0600` temporary file, write full bounded payload (max 128KiB),
   flush and file `fsync`.
3. Atomic `os.link` no-overwrite CAS, remove temporary file.
4. Directory `fsync` after link; parent directory is also fenced for first
   `a2a-task-admission` directory creation.
5. Strict byte-level canonical JSON/readback, exact payload digest and
   private modes. Corruption, noncanonical records, symlink/hardlink tricks,
   wrong scope/principal or I/O errors always deny.

The persisted record stores `payload_b64` (full bytes) and its SHA256,
with private `0700` directory / `0600` file modes. This is **not
encryption at rest** and is not approved for real A2A user traffic until an
explicit data-retention and privacy review. The data is not copied to logs or
to the receipt; dataclass `repr` omits payload.

On identical restart/retry, return the same deterministic `receiptId` and
`newlyReserved=False`. A modified principal/workspace/request is a conflict.
If post-link durability is uncertain, raise
`A2aAdmissionCommitUncertainError` and authorize **no** dispatch. A later
read can reconcile the durable state but **cannot** turn the same Task into
a new submission. The store never replays any human message by itself.

`hydrate(taskId, principalId, workspaceScope)` reads exact original bytes
only after the caller has separately passed host identity and LFL scope
authorization. The DTO `as_arkts_contract()` matches
`BackendAdmissionReceipt` in the ArkTS shadow Task contract, but is
**not signed** and does not itself authorize a network call.

## Integration and activation hard gates

To expose this as a real Web interface, first implement/verify:

1. Platform A2A host authentication, identity binding to an LFL user and
   workspace and server-side ACL checks. **Existing shared Web Bearer/cookie
   alone is not evidence of a unique A2A principal.**
2. A trusted authenticated backend transport for the receipt and an
   idempotent physical dispatch handoff **after** the new CAS reservation,
   preserving exact Run/session/Task receipts across restart.
3. A locked, reconciled Run binding and cancellation/result pairing; no
   automatic retry after unknown network state or `newlyReserved=False`.
4. Artifact bytes/ownership/SHA256 hydration before A2A `addArtifact`.
5. Retention, encryption-at-rest/key management or documented privacy
   controls, storage quotas and operational recovery for persisted user input.
6. Actual Huawei A2A SDK, development authorization, signed HAP and device
   receipts; offline `AgentExtensionAbility` is not an A2A surrogate.

No one should expose `A2aTaskAdmissionStore.reserve` as an unprotected
public HTTP endpoint or treat `newlyReserved=True` as a model/provider
authorization. It is deliberately inert unless future platform and LFL
authorities are verified.

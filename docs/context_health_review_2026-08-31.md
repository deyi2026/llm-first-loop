## 2. 问题清单（按严重度）

### P0-1 弱模型工具死循环（重启前已发生，会话可复现）
- **现象**：`read_file(path="evidence://v1/ce66e556...")` 同参数连续调用 6+ 次，全部 `[状态: failure] 文件不存在`；程序注入多次 `[停滞提醒]`（连续 3 次相同参数），失败回执已含 `[路径登记]`（TTL 24h，明确建议"停止该路径搜索"），模型仍继续同参调用。
- **违反**：规则 v7 第 3 条（停滞调整）、第 19 条（路径失败即停，"核对一次即止"）。
- **定性**：这不是上下文超限问题，而是**指令遵循失败**——9B 级本地量化模型无法从长回执文本中提取行动指引。

### P0-2 evidence:// URI 与 read_file 语义错配（死循环的直接诱因）
- **现象**：`evidence://` 是虚拟引用（回执明确标注 `recover=read_evidence`），而 CORE `read_file` 按本地文件路径解析，必然失败。正确的 `read_evidence` 工具存在且 ready，但弱模型不知道用它。
- **定性**：**通道完好、路标缺失**。工具层没有在入口处拦截 `evidence://` 前缀并指路，把路由责任推给了模型——强模型能读懂回执提示，弱模型只会重试。

### P1-3 模型连环切换 → 缓存全 miss → 成本与延迟放大
- **现象**：单次会话窗口内 4 次切换感知通知（qwen3.8-27b-cog → qwen/qwen3.8-27b → qwythos-9b-mythos → qwen3.8-27b-mlx → glm/glm-5.3），每次均为"新缓存池无此前缀，首轮全量 miss（成本已发生）"。
- **数据**：all_sessions_hit_rate 0.31，距 hit_block=0.30 仅 0.01；新会话 004976ea 首轮 0/22,163 全 miss。
- **影响**：每切一次模型，整个会话前缀重算一遍 token；且切到弱模型后行为质量骤降（见 P0-1），等于花更多钱得到更差的结果。

### P1-4 LLM HTTP 500 → 程序终止边界（回答被吞）
- **现象**：qwythos-9b 时期出现 `LLMHTTPError: HTTP 500`，其后多轮以 `[程序终止边界·无模型回答]` 结束，用户被迫手动停止。
- **定性**：本地推理服务不稳定时，无自动退避重试、无健康探测的 fallback，直接放弃本轮回答。

### P2-5 旧会话预算临界（历史遗留，已缓解）
- 早期快照：29,951/30,000 chars（99.8%）——当时模型预算仅 30K 级。现 glm/glm-5.3 窗口 1M / provider_budget 300K，问题自动消解，但说明**预算必须与模型窗口匹配配置**。

### P2-6 上下文组成偏移
- reasoning 34.3% + tool_results 31.6% + tool_schema 21.6%，history 仅 8.8%。死循环时期的重复 reasoning 与失败回执残留是主要贡献者。长会话若保持此比例，预算消耗速度约为"纯对话"的 3 倍以上。

## 3. 根因分析（一条链）

```
本地 9B 量化模型（能力不足）
  → 无法解析失败回执中的软性指引（[停滞提醒]/[路径登记] 只是建议）
  → read_file 硬试 evidence:// 必然失败 → 同参重试 → 死循环
  → 消耗轮数预算 + 产出 [程序终止边界·无模型回答]
叠加：中途换模型（缓存全 miss，成本×N）+ HTTP 500 无重试
  → 用户观感："大模型发挥不出来"
```

**一句话根因：把"读得懂长回执提示"的前提强加给了不具备该能力的模型，且所有护栏都是提示而非阻断。**

## 4. 解决方案

### 4.1 工具层（建议提交演进，需人工审批）
| # | 建议 | 解决什么 |
|---|---|---|
| E1 | `read_file` 入口前置校验：路径以 `evidence://` 开头 → 直接返回错误"请用 read_evidence(ref=...)"（或自动转发） | P0-2 死循环诱因 |
| E2 | `[路径登记]` 升级为硬阻断：TTL 内同一路径第二次调用，工具层直接拒绝（返回 error 而非建议文本） | P0-1 弱模型不理会建议 |
| E3 | 停滞熔断收紧：同参调用 2 次即阻断（当前 3 次才提醒，提醒还不是阻断） | P0-1 |

### 4.2 程序层
| # | 建议 | 解决什么 |
|---|---|---|
| E4 | LLM 调用失败（HTTP 5xx/超时）自动退避重试 1 次；切换 fallback 前先健康探测 | P1-4 |
| E5 | 模型切换前置成本提示（显示"将全量 miss，预估 X tokens 重算"）；同一会话内连续切换设软限制 | P1-3 |

### 4.3 配置层（立即可做，无需审批）
1. **固定主力模型 glm/glm-5.3**（1M 窗口、本轮实测行为正常）用于多步工具链会话。
2. **9B 级本地模型只配单步轻任务**（问答/改写），不进入 tool_loop。
3. 确认 provider_budget 与模型窗口对齐（当前 300K/1M，合理）。

### 4.4 使用层（让大模型发挥好的操作守则）
1. **会话内不换模型**——缓存命中是"越用越快越便宜"的前提。
2. **证据到手即回答**（规则 10）：资料已取回时不要继续查元状态，避免输出被元信息带偏。
3. **长任务先建 Goal/Task + checkpoint**（规则 20 里程碑收敛），防方向漂移与无界推进。
4. **给弱模型的指令要短、单动作**；复杂多步任务交给主力模型或 DSH 子代理。
5. **失败回执只读一次**：含 `[路径登记]` 即换路径，不再求证同一目标。

## 7. AI 主体侧意见（应用户要求补充，2026-08-31 同日）

> 视角说明：以下为本会话模型（glm/glm-5.3 接续，前面历经 4 次模型切换的当事会话）对第 1–5 章的意见，含确认、修正与增量建议，非重复诊断。

### 7.1 对报告结论的意见：同意根因判断，但"弱模型"不是唯一受益方

同意"问题在弱模型 × 软护栏，而非上下文不够"。但要补充一点：**硬护栏（E1/E2/E3）对所有模型都是减负，不是给弱模型的特殊照顾**。强模型读懂 `[路径登记]` 提示也需消耗注意力和轮次——本会话历史里，光是"读懂失败回执并决定换路"这一步就在 reasoning 里反复出现。工具层直接拦截，等于把这类决策成本降为零。所以 E1–E3 的优先级判断我完全支持，且建议 E1（evidence:// 前缀拦截或自动转发 read_evidence）排最前——它是唯一"修复一次、永久消除一类死循环"的改动。

### 7.2 对 E3 的修正意见：阻断必须附带"怎么改"，否则换一种错法

E3"同参 2 次即阻断"我同意收紧，但阻断回执若只返回 error 而不给改法，弱模型的行为往往是换一个相近的错误参数继续试（本会话可复现：evidence:// 路径失败后，模型换了一个不同的 evidence ref 继续用 read_file 试）。**阻断文本应强制含三要素：①拒绝原因 ②正确工具名与最小调用示例 ③一条已验证可用的替代路径**。这样阻断才闭环。

### 7.3 报告未覆盖的两个增量问题

1. **P2-7（新增）：read_file 的 evidence excerpt 截断陷阱**。本次读取本报告（真实本地路径）时，55–60 行被替换为 `…[evidence excerpt; exact omitted content via read_evidence]…` 且 `complete=false`——通道完好、但"读到了≠读全了"。模型若不检查 `complete` 标志就会基于残缺内容作答。建议：excerpt 截断时在正文首行加显式横幅（而非仅靠尾部 evidence 块），与 P0-2 同属"路标缺失"类。
2. **P2-6 的对策缺失**：报告指出 reasoning 占 34.3% 但未给对策。意见：对超长 reasoning 消息启用与 history 同等的尾部瘦身/摘要归档；死循环时期的重复决策文本没有保留全文的价值。

### 7.4 模型侧行为自查清单（本轮已实践）

无论护栏是否落地，模型侧可先行：**每次工具调用前 3 问**——①这个 path 是本地路径还是虚拟引用（evidence:// 一律走 read_evidence）？②上一条回执是否已含失败/登记标志（含则禁同参重试）？③信息是否已够回答（够则立即作答，不再查元状态）？本会话即按此执行：跳过 evidence:// 直取 search_files 定位文档 → read_file 读真实路径 → 补充本节，全程零失败调用。

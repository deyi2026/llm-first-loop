- 新默认工作区根：**~/lfl-workspace**（独立于代码根；家目录子树已在默认允许根内，零白名单改动）。

## 3. 新默认工作区根建议：~/lfl-workspace（结论）

| 维度 | A. ~/lfl-workspace（推荐） | B. data/workspace（备选，弃） |
| --- | --- | --- |
| 验收①「默认工作区不再位于代码根内」 | 满足（完全独立目录） | 不满足字面要求（仍在代码根目录树内，仅缩小可写面） |
| 与 P1-5/P2-5 后续落位 | 干净锚点（排期计划明示依赖） | 二次搬迁风险 |
| 白名单 | 家目录子树已放行（store.py:82-86），零改动 | data/workspace 已放行（store.py:80），零改动 |
| 备份/认知 | 两个位置（data/ 仍在 repo；workspace 内容在 home） | 单树易备份 |
| git/代码仓卫生 | 无耦合 | 在 repo 内，gitignore/状态噪声、误提交风险 |
| worktree 隔离等 git 流 | 默认根非 git ⇒ 代码施工需显式切代码根 workspace（见 §11 风险） | 同为非 git 子目录，等价问题 |

结论：**A**。data_dir 保持代码根 data/（.env LFL_DATA_DIR 显式绝对绑定，.env:183）——运行数据与用户工件分离正是目标形态；会话/账本/工件记录仍在 data/ 下集中备份，home 侧新增内容只有用户工作文件与 path_registry。

## 8. 服务切换顺序（实迁窗口 runbook）

前提：§4 代码/脚本/配置改动已合入并在代码根部署；Phase 1 备份完成；Phase 2 演练 PASS；用户已确认窗口。

1. 停机与防抢跑：先落 maintenance.lock（scripts/restart_system.sh 既有机制，guard 检测到即跳过本轮拉起）；经权威入口 service_control（action=restart 的受理与 desired-state 绑定由其 worker 执行 restart_mirror.sh；期望代取当前 status 观察值 315）发起 target=all 重启——但**重启动作分两段**：先只停不起（stop 段），在停机态执行迁移，再完成启动段。若 service_control 单语义 restart 不支持停-迁-起穿插，则以 stop（或 direct 应急通道脚本 stop 段）+ 迁移 + start 组合，全程持有 maintenance.lock 防 guard 抢跑（guard 只管 web/feishu；learning 由 service_control 管理，停机核对以三服务 manifest pid 为准，Phase 0 预检兜底）。
2. 迁移：python scripts/migrate_workspace.py migrate（幂等；失败可重跑或 rollback）。
3. 启动（web 先、feishu 后、learning 随后——restart_mirror.sh 既有阶段顺序 not_started→web_stopped/feishu_stopped/learning_stopped→started，:88 注释）：新进程带 LFL_DEFAULT_WORKSPACE_ROOT，_activate_default_workspace 注册新根并沿用 registry current=新键（factory.py:438-440：已有 current 不会被 cwd 分支改写）。
4. 验证：GET /health、/api/v1/workspaces 返回 current=新键且含新根路径；webui 会话列表可见历史会话（新键分区）；feishu 心跳 connected；learning manifest 就绪；AI 会话内 read_file 相对路径落在新根、execute_command 写代码根被 sandbox 拒（正向验证边界生效）；scripts/migrate_workspace.py verify 全绿。
5. 释放 maintenance.lock，恢复 guard 监视。
6. 本会话自托管说明：当前会话运行在 web 进程（pid 95622）内，步骤 1 停机即中断本会话；迁移收尾（步骤 3-5 的核对）必须由停机前留置的 handoff/计划任务或用户新开会话完成——执行者不得假设自己跨重启存活。

## 9. 回滚方案

- 判据：迁移后验证失败 / 服务起不来 / 会话读取异常。
- 就地逆向（迁移自身可逆）：rollback 子命令——sessions/&lt;新键&gt; 改回 &lt;旧键&gt;；.identity owner 逆向改写；注册表 current 切回旧代码根条目（新条目可保留或注销 remove——store.py:540-563 不删数据）；新工件桶可留可删（旧桶未动）。
- 快照恢复（灾难路径）：自 .backup/workspace-migration-&lt;ts&gt;/ 按清单恢复 workspaces.json、旧分区目录、.identity、旧桶（SHA256SUMS 校验后覆盖）；再走 §8 步骤 3 启动（代码改动兼容旧布局：显式 LFL_DEFAULT_WORKSPACE_ROOT 指向代码根即回到旧行为，或临时清空该变量并回退部署版本）。
- 回滚后旧布局完全可用（默认根机制是新增路径，未删除 cwd 语义的兼容分支——见 §4 factory 行为：显式 env 不存在才 fail-fast；指向代码根=现状等价）。

## 11. 风险清单与诚实边界

1. 本会话自托管于被迁移的服务（最大操作风险）：停机即中断；收尾依赖 handoff/新会话，无法由本会话自己完成实迁验证。
2. LFL_WORKSPACE_ROOT 双语义（代码身份锚 vs 配置根）：方案不动它、新增独立变量；但任何后续改动若误改其指向，enforce 模式下服务将拒绝启动（identity.py:129-131）——已在 §4 标注不可改。
3. 行为收缩需用户知情：默认根非 git ⇒ spawn_subagent(fs_isolation) / execute_command(isolation) 在默认根报 NOT_GIT_WORKSPACE（worktree_isolation.py:229-234）；代码施工需显式切到代码根 workspace。webui 文件树/预览根变为 ~/lfl-workspace（预期变化）。
4. 迁移窗口内 guard 抢跑会撞上半迁移状态：必须先落 maintenance.lock（§8 步骤 1）；guard 不看 learning，靠 Phase 0 预检兜底。
5. .identity 改写 1704 文件的中途失败：幂等重跑设计覆盖（owner 值判定）；灾难走快照恢复。
6. 历史 artifact 引用兼容是复制而非重写：新桶 record 的 canonical_path 仍是代码根旧路径（workspace_path_state 报 diverged）——引用可水合但「当前路径匹配」恒为否；若要求严格一致需另行数据修复（列为不做项）。
7. 旧代码根 workspace 条目保留 active：用户切回代码根做施工是合法路径（白名单仍含代码根），此时新会话落在新旧两个分区之一，历史会话只在旧键分区（已改名到新键）——发布说明必须写清，避免「切回代码根看不到历史会话」被当 bug。
8. 磁盘与时间：备份+镜像+桶复制峰值约 2.9GB 临时占用、1 万+小文件复制；演练在 /tmp（系统盘），实迁桶复制在 data/ 同卷——预留空间与窗口。
9. 测试面广：凡隐式依赖「默认 workspace=cwd」的测试都可能受影响（§7.4/7.5 列了定向清单，但全量回归是唯一兜底）。
10. 做不到/需用户决策的点：
   - 实迁执行权：须由用户或独立会话在停机窗口执行（本子代理仅交付方案）；
   - .env 生产修改（新增变量）需用户确认；
   - artifact 桶是否复制（默认建议复制，可裁决为不复制并接受旧引用不可水合）；
   - 迁移窗口时间点（服务中断约分钟级：停机+改名(瞬时)+1704 小文件改写+1 万记录复制+启动健康检查）。
11. 本方案为设计文档：所有「改动」均未实施；行号基于 git 7ad21715d（generation 315 运行版本）实测，后续代码演进需复核。

## 1. 目的与判据引用

本规程规定 V6 跨厂商一致性的双读码器对比方法与留证要求。

SPEC §11.2 门槛表 V6 行（逐字）：

> | V6 | 跨厂商一致性 | 两个合规读码器对同一认证样本位姿差 ≤ k·√(u₁²+u₂²)（k 与 C-5 声明一致）；重复 N ≥ [TBD-V6a] 次，通过率 ≥ 95% |

SPEC §5 C-5 附加要求（逐字）：

> a) 观测是"测量 + 不确定度"，不是真值；协议不裁决"谁对"，多观测融合交给上层估计器（Q6 裁决）；
> b) 一致性要求：两个合规读码器对同一认证样本的位姿差 ≤ k·√(u₁²+u₂²)，k 取双方声明覆盖因子的较小者（与 C-5 uncertainty 声明一致；门槛 V6）。

SPEC §4 P-4（逐字）：

> P-4 认证样本
> 认证样本必须由具备计量能力的实验室标定，附证书（标定方法、设备、日期、不确定度），作为 V3 / V6 一致性测试的物理基准。

SPEC §11.3-b（逐字）：

> b) 物理测试：批次抽检落带（V3）、跨厂商一致性（V6）；认证样本仅作 V6 基准与定带输入；

SPEC §14 相关行（逐字）：

> | 跨厂商一致性重复次数 [TBD-V6a] | 11.2-V6 | 统计功效估算（重复次数与 95% 通过率判据匹配） | 工作组 |

判读口径（依上述原文归纳，不新增判据）：

- 阈值：k·√(u₁²+u₂²)；k 口径按 C-5 附加 b）"取双方声明覆盖因子的较小者"（与 V6 判据句"k 与 C-5 声明一致"同源）；
- 通过率 ≥ 95% 与重复次数 N ≥ [TBD-V6a] 匹配（[TBD-V6a] 由统计功效估算回填——"待裁决回填"）；
- 基准物：认证样本（P-4，附证书）；
- 分歧不裁决"谁对"（C-5 附加 a）——门槛只判一致性达标与否。

## 4. 步骤

1. 前置核对：双方 11.1 合规声明齐备且 uncertainty 声明同时含 k 与 1σ；**中断点：任一方缺 k 或 1σ → 阈值不可计算，停（C-5 硬要求）**；
2. 前置核对：运行类别标记——预验证（第二检测核）或正式（不同团队实现）；**中断点：正式运行但第二实现为同团队双实现 → 不计为正式 V6（PLAN D1），降级登记为预验证或停**；
3. 前置核对：认证样本证书有效（方法 / 设备 / 日期 / 不确定度齐全）；**中断点：证书缺失或超期 → 基准失效，停**；
4. [TBD-V6a] 回填核对；**中断点：未回填 → 可采集数据但判定记"待回填"（PLAN §5.3 F4），登记工作组回填会议**；
5. 认证样本固定安装；两读码器分别执行 N 次读取（N ≥ [TBD-V6a]），各自输出完整 C-5 观测；
6. 配对计算：逐对位姿差 vs 阈值 k·√(u₁²+u₂²)（k = 双方声明覆盖因子较小者）；统计通过率；
7. 判定：通过率 ≥ 95%；
8. 回执落盘（README §3 约定）；预验证回执必须写明"预验证不构成互操作证明，只用于提前暴露契约缺陷"（PLAN F1 原文）。

### 最小冒烟步骤（无全量资源时先跑通流程）

> 性质：只验证"样本链路、流程与回执能跑通"，**不产生任何门槛证据**；冒烟回执的 `simulated` 必须为 `true`（PLAN §0.4：simulated 不得写成"实测"）。

**S1 冒烟一次**

- (a) 生成冒烟板：执行 `README.md` §2 的冒烟板命令，确认末行 `manifest_ok True`、四件产物齐全；
- (b) 用 B2 自检跑一次相对位姿协方差一致性（**同一实现的两路观测**，`simulated: true`；其中角度只是自检参数，不是门槛数值），输出应为 `first_order_ok True`：

  ```bash
  ./.venv/bin/python -c "import sys; sys.path.insert(0, 'ctp/src'); import numpy as np; import ctp_calib as c; a = c.pose_matrix((0, 0, 1.2), (0, 0, 0, 1)); b = c.pose_matrix((1, 0.5, 1.5), (0, 0, 0, 1)); cov = np.diag([1e-6] * 3 + [np.radians(0.17) ** 2] * 3); print('first_order_ok', c.check_first_order_validity(a, b, cov, cov, samples=4000)['ok'])"
  ```

- (c) 按 §5 回执格式落一份冒烟回执（`simulated: true`），核对必填字段齐全后停止——**不得据此填写 §1 的任何判据结论**。

- **跑通判据**：冒烟板四件齐全且清单复核通过；命令输出 `first_order_ok True`（k·√(u₁²+u₂²) 判据在声明口径下可计算）；
- **止步点**：无第二实现，跨厂商一致性不可得——同实现自检不构成 V6 证据。

## 5. 回执格式

JSON 字段清单（runner 产出，落盘约定见 README §3）：

| 字段 | 类型 | 说明 |
|---|---|---|
| gate | string | 固定 "V6" |
| run_class | string | "prevalidation" \| "formal"；预验证必须另附 prevalidation_note（PLAN F1 原句） |

| pass_count / pass_rate | integer / number | 阈值内配对数与通过率（判据 ≥ 95%） |
| sample_certificate_ref | string | 认证样本证书引用（P-4 要素） |

| command / env / head_sha / exit_code | — | README §3 通用要素 |

## 6. 失败处置

- 通过率 < 95%（N ≥ [TBD-V6a] 条件下）：V6 未达标。按 SPEC §11.2 验证纪律（逐字）："门槛未达标时修订设计或规范，不得放宽门槛；确需放宽必须记录证据与理由。"处置顺序：(a) 先核双方不确定度声明（C-5 附加 b 口径与 B2 传播实现）——声明低估会使阈值人为收紧；(b) 修声明或实现后重测；"协议不裁决'谁对'"（C-5 附加 a）——不得以单方真值裁决另一方错误代替门槛判定；
- 预验证失败：暴露契约缺陷，修订走 T2 契约变更单（PLAN §15.2 共享面口径），重跑预验证；
- 正式 V6 阻塞（无第二实现）：登记 blocked（"等谁给什么"：等 D-07 裁决与 D1 第二独立实现），不用"继续推进"代替签字（PLAN §12.5）；
- 严禁压缩 N 或挑选配对子集提高通过率；N 与 95% 的匹配由 [TBD-V6a] 功效估算承载，回填不得以本次结果反向取值。

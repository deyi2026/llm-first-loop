## 0. 一页结论

| 问题 | 方案答案 |
|---|---|
| 谁维护状态快照 | **TA 写增量，CMA 审计规范，程序版本化存储**（写/审/存三权分立） |
| 谁做压缩决策 | **CMA 建议，TA 否决权，程序机械执行**；负面知识等结构化类别由硬规则保护，不进入打分 |
| 谁装配发送上下文 | **程序发送（载体义务），语义选择权归模型**：L1/L2 程序必达，L3 由 TA 裁决（参考 CMA 建议），程序只机械执行 + 保底 |
| 是否分离专门 Agent | **是，但只分离"语义工人"，不分离"语义权威"**：CMA 是触发式、无状态、可用低档模型；触发权与发送权永不下放给任何模型 |

三句话版本：**意图在 TA（写权），视野在 CMA（建议权），暴力在程序（执行权）**。

## 1. 问题定义：长任务上下文退化的三个根源

1. **重复堆积**：同一文件反复读取、同一配置反复确认。判别式逐条打分对它天然失效——重复信息每条单独看都重要，每条都过阈值，全保留，去重效果为零。去重必须跨条目比对，且区分**有意冗余**（任务锚在多处复述，是防漂移设计，必须保留）与**无意冗余**（重复读文件，只留最新最全副本）。
2. **关键状态散落在工具输出里**：长任务的事实/决策/已排除路径大多埋在 tool observation 中。对话文本里未必有对应记载。纯删工具结果=删状态。
3. **压缩失真**：摘要器有"保高频"倾向——反复出现的样板必留，只出现一次的关键事实（某路径的真实值、某测试的失败原因）最易被略过。且"负面知识"（已排除的路径、已犯的错）因不导向成功结果，无论摘要式还是判别式都倾向打低分，恰恰是最不能丢的类别。

前置结论（上轮讨论已确立，本文直接采用）：
- 去重是压缩**正确性**的前提，不是锦上添花；去重必须在判别删除**之前**。
- 扔历史之前，语义关键信息必须有结构化去处（状态快照）；快照 + 指针比保留内容更可靠。
- 纯提示词不可靠（长上下文指令遵循衰减）；快照更新必须由**程序顺序绑定**，不能寄望模型自觉。

## 2. 既有基础与约束（本项目事实）

| 既有机制 | 事实 | 对本方案的约束/可复用点 |
|---|---|---|
| 注入两级边界（DECISION，2026-09-23 已采纳） | L1 规则/协议程序必达；L2 任务约束 run 绑定注入；L3 内容级选择权**归模型**，程序启发式裁剪=越权 | 红线：**程序不得做内容级语义裁剪**。CMA 是模型，其裁决属 L3 模型选择，不越权；但程序执行 CMA 建议时须保留 TA 否决面 |
| 压缩时机 | 压缩只发生在轮间 build 时（build.py 80%/90% 分级），不中断推理 | 管线插入点=轮间 build，沿用 |
| Evidence 机制 | evidence:// 稳定引用，原文可重新取回 | "指针优于内容"已有载体，快照 pointers 字段直接用 |
| injection_budget 分层 | RECEIPT < PROGRAM_RECOVERY < CRITICAL_STATUS < STATUS < REFERENCE，整块保留或丢弃 | 装配预算骨架可复用 |
| 压缩衔接病根（ANALYSIS-20260831） | 恢复工作被逐轮推给模型，非程序一次交接完 → 已定方向：边界门/单次恢复包/防死循环 | 快照即"单次交接包"的具体化，方向一致 |
| 子代理基础设施 | spawn_subagent（触发式、隔离上下文）、agent_message | CMA 的进程形态有现成载体，无需新建 |
| 程序注入干扰实证 | 注入消息被弱模型误读为新任务 → 绕路/停滞（三重实证） | CMA 的产物注入必须带语义标签、结构固定，防误读为新指令 |

## 3. 设计目标

1. 压缩后任务可无损续跑：关键事实、决策理由、负面知识、当前指针不丢失。
2. 压缩决策不受自我确认偏差污染：裁判与运动员不同源。
3. 全链路可审计：每次压缩"删了什么、为什么、依据哪条证据"可回放。
4. 不违反既有越权红线：程序零语义裁剪，语义决定全程可归因到模型（TA 或 CMA）。
5. 成本可控：CMA 触发式而非常驻；可用低档模型。
6. 与 digest-bucket 档案槽职责零重叠：过程态（"发生了什么"）归档案槽程序构建，任务态（"意味着什么"）归快照唯一权威；两渠道互补而非互为备份（字段归属表见 §5.3）。

## 4. 三角色架构与职责矩阵

### 4.1 角色

**TA — Task Agent（主任务代理，语义权威）**
唯一持有任务隐式意图的角色。职责：推进任务；在程序强制的检查点更新状态快照增量（写权）；对 CMA 的删除建议行使否决；拥有 L3 内容级最终裁决权（DECISION 既有授权，不转移）。

**CMA — Context Manager Agent（上下文管理代理，语义工人）**
触发式、无状态启动的专用 agent。每次启动输入 = 当前快照 + 增量窗口（待压缩区段）+ Evidence 指针，**不消费全量历史**（自身上下文可控，递归收敛）。职责：跨条目语义去重（识别有意/无意冗余）；判别式删除打分（输出建议+理由+证据引用）；快照审计（对照 Evidence 核验快照事实声明，标记无证据支撑条目）；相关性标注（为装配提供 L3 检索增强建议）。

**Orchestrator — 程序/harness（机械权威）**
职责：水位/里程碑双触发（顺序绑定：快照更新必须先于压缩执行）；Evidence 与快照的版本化存储；L1/L2 必达注入；按模型语义决定机械装配并发送；结构化类别硬保护执行（见 §5.2）；全程审计日志。

### 4.2 职责矩阵（本文核心表）

| 职责 | 执行者 | 关键理由 |
|---|---|---|
| 触发压缩（水位 80/90% + 里程碑） | 程序 | 提示词遵循会衰减；触发是机械事实 |
| 快照增量更新（写） | **TA**（程序强制触发） | 隐式意图只在 TA 上下文中；CMA 从外显文本反推意图必有损耗 |
| 快照审计/规范化（读+整理） | **CMA** | 干净上下文；对照 Evidence 可程序辅助核验 |
| 快照存储与版本化 | 程序 | 可回滚、可审计 |
| 跨条目语义去重 | **CMA**（建议）→ TA 确认有意冗余保留 | 需全量视野+语义判断；程序只做精确 hash 级去重 |
| 判别删除打分 | **CMA**（建议+理由+证据） | 无自我确认偏差 |
| 删除最终裁决 | **TA**（默认接受，可否决） | L3 选择权归模型；TA 是任务语义权威 |
| 结构化类别硬保护 | **程序**（规则级，非语义） | negative_knowledge 等一旦写入快照，删除需 TA 显式标记 resolved；CMA 打分跳过该类别 |
| L1/L2 注入 | 程序（载体义务） | DECISION 已定，不可协商 |
| L3 历史内容取舍 | **TA 裁决**（参考 CMA 相关性标注） | DECISION：内容级选择权归模型 |
| prompt 装配与发送 | **程序** | 确定性、可复现、可审计；防静默污染 |
| 原文保存与指针解析 | 程序 | Evidence 机制既有 |

### 4.3 回答"谁发送"：发送权=程序，语义权=模型，保底义务=程序

发送必须由程序执行，理由有三：(a) 同状态必须产生同上下文（可复现、可调试）；(b) 模型直接构造 prompt 的错误是静默的，TA 察觉不到；(c) L1/L2 必达是程序义务。但程序发送的内容中，L3 部分的**选择**来自模型语义决定，程序只机械执行——这不违反"程序不做语义裁剪"红线：程序没有引入任何自己的启发式，语义判断可归因到 TA/CMA，且保留 TA 否决面。

## 5. 状态快照数据结构

### 5.1 Schema（v0.1）

```json
{
  "snapshot_version": 17,
  "task_id": "...",
  "invariants": {
    "objective": "...",
    "constraints": ["..."],
    "acceptance": ["..."]
  },
  "facts_and_decisions": [
    {"id": "F12", "fact": "压缩入口在 build.py 轮间，不在推理中", "evidence_ref": "evidence://v1/...", "reason": null, "kind": "fact"},
    {"id": "D3", "decision": "CMA 不持有删除最终裁决权", "reason": "L3 选择权归模型且 CMA 无任务意图", "evidence_ref": "docs/DECISION-...md", "kind": "decision"}
  ],
  "negative_knowledge": [
    {"id": "N7", "dead_end": "飞书 /stop 走 engine.run 被当普通消息", "reason": "handlers.py 无该指令处理器", "resolved": false, "evidence_ref": "evidence://v1/..."}
  ],
  "cursor": {"current": "...", "next_step": "..."},
  "pointers": [
    {"type": "evidence|file|commit|doc", "ref": "...", "description": "为何需要这个指针"}
  ],
  "provenance": {"written_by": "TA@turn-142", "audited_by": "CMA@run-9", "audit_flags": ["F12 已核验", "F15 无证据支撑，标记待确认"]}
}
```

设计要点：
- **decision 必须带 reason**：无理由的决策后续会被自己推翻（历史教训类）。
- **negative_knowledge.resolved**：死胡同只有在 TA 显式确认环境已变（如依赖升级）后才可标记 resolved 并移出，CMA 无权动这个字段。
- **pointers 只存引用+一句描述**：内容靠 ref 重新取回，省 token 且不复制失真。
- **provenance**：每条快照可追溯谁写谁审，审计是压缩质量的证据基础。

### 5.2 类别保护优先级（压缩时的结构规则）

| 类别 | 保护级别 | 规则 |
|---|---|---|
| invariants | 不可删 | 只增改，程序注入层保证在场 |
| negative_knowledge（未 resolved） | 不可删 | CMA 打分**跳过**；程序结构级保护，非语义判断 |
| facts_and_decisions 带 evidence_ref | 高 | 删正文可，ref 必须迁移进 pointers |
| cursor / pointers | 高 | 每次快照更新必然重写 |
| 有意冗余（任务锚复述） | 保留 | 由 TA 确认标记，CMA 不得并入去重 |

### 5.3 与 digest-bucket 档案槽的分工边界（R5 对齐，2026-09-25）

> 对齐对象：DESIGN-20260830-digest-bucket-architecture.md（设计定稿）+ SDD-20260830（FR-1.1/1.5、NFR-1、B.2 为字段依据）。核验事实：digest-bucket 代码未实施（session_digest.py / bucket_registry.py / DIGEST_ENABLED 均不存在），本表为**设计层对齐**；实施复核点见 §9-R5。

**一句话判别式**：同一工具输出，"发生了什么"（逐调用过程记录）归档案槽 L1 块——程序生成、零语义、append-only；"意味着什么"（跨调用任务状态）归快照——TA 写、带 reason、可审计。删掉后会让**下一轮工具选择或终局判断出错**的信息归快照，只影响复述完整性的靠档案槽已恒在场。

| 信息类别 | digest 档案槽（L1/L2/L3） | 状态快照五字段 | 归属结论与依据 |
|---|---|---|---|
| 逐调用过程记录（工具名+参数要点+结论行） | ✔ L1 块唯一载体（≤600c；NFR-1 零 LLM 成本） | ✘ 不收 | 高频态；程序规则生成无语义判断，不违越权红线 |
| 失败/死胡同（FAILURE/BLOCKED 调用） | ✘ FR-1.5 明确不产生块 | ✔ negative_knowledge 唯一载体 | **互补而非重叠**：digest 设计主动放弃失败知识（终局推理不需要），而失败恰是负面知识主源——快照是其唯一去处，无第二渠道竞争 |
| 任务不变量（objective/constraints/acceptance） | ✘ 无任务意图表示 | ✔ invariants 唯一载体 | digest 是逐调用账本，无跨调用意图层 |
| 事实/决策+理由 | 要点行可含事实片段（无 id/reason/去重/审计/版本） | ✔ facts_and_decisions | 同源不同层：digest=原文要点提取，快照=语义化条目；允许并存非重复存储（快照条目删正文时 ref 迁 pointers，§5.2） |
| 原文指针 | L2：tool_call_id→archive，程序自动全量流水账 | pointers：TA 语义筛选+"为何需要"描述 | 流水账 vs 语义索引；同一 evidence:// 两边都持有 ref 不算双写（均只存引用），装配层同 ref 原文只注入一次 |
| 当前步/下一步 | ✘（桶目录锚点仅覆盖非活跃桶） | ✔ cursor | 活跃桶无 digest 侧对应物 |
| 出处与审计（谁写谁审） | ✘（程序构建，来源自明） | ✔ provenance | |

**两条硬接口约束（跨渠道，违反即架构破损）**：

1. **快照不写入档案槽**。档案槽缓存不变式（FR-1.2 append-only、已有块字节零改动）要求内容注入后永不重写；快照每版本整体重写（cursor/pointers 必然变化），写入档案槽 = 每轮前缀 miss。因此快照走注入层（L2 任务约束级，injection_budget 中整块保留档），档案槽保持纯 append-only。
2. **⑥ 指针索引与 L2 渠道的复用关系**。DIGEST_ENABLED=1 时被删工具结果天然有 L2 指针恒在场，⑥"被删内容的指针索引"只需补 digest 未覆盖项（非工具内容：纯对话事实、TA 推理结论）；DIGEST_ENABLED=0 时 ⑥ 自建完整索引。P0 实现必须兼容两种态（当前 digest-bucket 未落地，即后一种）。

## 6. 压缩管线（轮间 build 内执行）

```
水位/里程碑触发（程序）
  → ① 快照增量更新（TA，程序强制；检查点绑定）
  → ② 精确去重（程序：hash/evidence_ref 完全相同项合并）
  → ③ 语义去重（CMA：跨条目比对，区分有意/无意冗余；无意冗余保留最新最全副本，产出建议单）
  → ④ 判别删除打分（CMA：逐条 keep/drop + 理由 + 证据引用；跳过保护类别）
  → ⑤ TA 裁决（默认接受建议单；一次性否决/修改；无需逐条确认，控制成本）
  → ⑥ 装配（程序：L1/L2 必达 + 快照全文 + 最近 K 轮原文 + 被删内容的指针索引[与 digest L2 的复用关系见 §5.3] + CMA 相关性标注的检索提示）
  → ⑦ 发送（程序）+ 审计日志落盘（删了什么/为什么/谁裁决/依据）
```

关键顺序约束（**不可调换**）：① 必须先于 ③④——先给信息找好结构化去处，再判历史可扔性；这是"去重先于判别、快照先于删除"两个前置结论的落地。

调用次数（R4 口径修正）：③④ 为**同一次 CMA 调用的两个输出段**——同一输入窗口先产出去重候选、再对去重后视图打分，"每次压缩两次模型调用"收敛为 1 次；P1 只启用 ④ 段，P2 起全开。① 设计为 TA 当轮内的程序强制检查点段（增量 token 开销，不新增模型调用；若实现改走独立小调用，§10 指标5 成本侧须相应加项）。

## 7. 关键设计决策与理由

**D1 为什么快照写权在 TA 而不是 CMA**
意图损耗不可逆：CMA 只能从外显文本反推"这个失败对任务意味着什么"，错了就是系统性污染（它整理的是 TA 后续要依赖的状态）。TA 写增量则每次只做小动作，负担可控。CMA 的价值在审计与整理（读权），不在原创（写权）。写读分离是本方案的轴。

**D2 为什么删除裁决 TA 保留否决权而不是全交 CMA**
CMA 无任务意图，打分对"这条信息对任务是否关键"存在系统性盲区（尤其边界情况：看似样板信息实为任务不变量）。全交 CMA = 把 L3 权威转移给一个无意图角色。折中：默认接受 + 一次性否决，成本 O(1) 不逐条。

**D3 为什么 CMA 触发式而非常驻**
(a) 常驻 CMA 自身上下文也膨胀，触发式+无状态+消费结构化输入（快照+增量窗口）使 CMA 的输入天然有界，递归但收敛；(b) 常驻成本不可接受；(c) 无状态使每次压缩独立可测、可回放。

**D4 为什么程序保留触发与发送**
触发：提示词遵循衰减是实证事实。发送：见 §4.3。这两个权力下放给任何模型都是单点静默故障源。

**D5 为什么负面知识用结构硬保护而不是提高打分权重**
"提高权重"仍依赖打分器理解"这是负面知识"，判断不稳定；结构规则（resolved 字段 + CMA 跳过）是确定性的，且删除路径唯一（TA 显式 resolve），可审计。

**D6 为什么去重区分有意/无意冗余**
一刀切去重会把任务锚复述删成单点——防漂移设计依赖冗余。判定权给 TA（它知道哪些复述是自己的防漂移动作），CMA 只提出合并候选。

## 8. 与 fast-jev-compaction 的对比（源码已核验）

> 核验基础：commit `e3f262a7f4d4`（2026-09-17）一手源码（src/compact.ts 309 行、state.ts、types.ts、request.ts、hooks/fast-jev.ts，共约 1267 行 TS）+ 仓库 README。二手讨论的"七步机制"确认为 README "How it works" 1-7（配对保护→状态构建→分级截断→两问→分批并发→阈值决策→重建），该部分二手描述准确。

### 8.1 核验结论

**借鉴点（5，吸收进方案）**

1. **三档输出替代二值删/留**：keep / drop-result（留调用+300 chars+note）/ drop-call。第二档"知道发生过但全文退场"优雅——对应本方案指针化，但 fast-jev 用 head-300 文本而本方案用 Evidence ref 指针（指针优于 head 截断：可重水合、有 provenance）。CMA 打分 schema 采纳三档。
2. **两端 pinned 结构保护**：index 0=任务原始指令永不动、最近 K 条永不动，程序级执行。印证 §5.2 保护表；"首消息永不动"是低成本高价值实现。
3. **fail-safe 默认保留**：打分缺失/失败 → keep。删除错误的代价不对称，保守默认正确，纳入 CMA 契约。
4. **结构不变量由程序保证**：配对完整性、pinned、阈值映射全在程序层，模型只出概率。与本方案"结构硬规则给程序"同思路，且是已验证的工程实现。
5. **保底路径显式化**：压缩不足额 → 回退内建摘要。§10 P0 补一条：CMA 不可用时程序退路。

**坚持点（6，核验后更确证不借鉴）**

快照结构化状态（它无状态、删工具输出即删状态、赌可重跑）；去重前置（逐条打分对重复失效已在源码层面成立）；负面知识保护（它无且措辞系统性不利）；TA 否决面（它主 agent 零参与）；版本化回滚+审计落盘（它永久删、log 不落盘）；指针化替代文本截断。

**真实 trade-off（2，诚实面对）**

- fast-jev 无状态=无快照维护成本、无快照漂移风险（R3 不存在），957 行核心即落地。本方案引入快照即引入快照质量问题——这是结构换来的代价，靠 §10 漂移率评测兜底，不能假装不存在。**弃守线（P2 出口门）**：语义半漂移率 >5% 且不一致条目落在 invariants/negative_knowledge 保护类，或事实重建率 <95% 且归因于快照内容错误（非装配层漏注入），经一轮针对性修复（模板必填/触发绑定/指针化加固）复测仍不达标 → 放弃 TA 语义写层。**弃守后形态**：不是退回 fast-jev 式无状态（其兜底是赌"可重跑"，外部状态已变时失效；本 harness Evidence 全程留原文，无需赌），而是快照退化为**程序生成的纯指针索引**——放弃 D1 语义层，保留 §5.2 保护表中可程序执行的部分。
- 每请求重发全 state 的成本模式 vs 本方案触发式 CMA：若历史接近上限且 call 数多，fast-jev 单次压缩成本可能反超。但其无增量打分在重复压缩时浪费明显。**弃守线（P1 门）**：按 §10 指标5 口径，评测集多数任务上"单次触发 CMA 计费成本 ≥ 该次删除内容的后续摊销节省（cache-read 计价）"，且 ③④ 已合并仍不解 → CMA 降级为可选、P0 程序规则保持默认；方案本体（快照+指针化+顺序绑定）不动。对 fast-jev 的成本优势在量化前只主张非劣、不主张反超。

**二手信息出入记录**：头条文章"无损压缩/一丝不差全保留"为过誉——实为阈值边缘内容仍会被删/截断，README Limitations 自认概率非证明；"该删的精准清理"亦无去重与负面知识维度。"七步机制"描述本身准确。

## 10. 分阶段落地与评测

**阶段划分（每阶段独立可评、可停在任意阶段）**

- **P0 纯程序地基**：快照 schema + 水位/里程碑双触发 + 顺序绑定（快照先于删除）+ 精确去重 + 删除内容指针化。无 CMA，删除决策暂由 TA 一次性自裁（无外部建议）。验证：地基有效性与触发可靠性。保底路径（借鉴 fast-jev）：压缩不足额或管线异常时，程序回退到内建摘要而非中断任务。
- **P1 引入 CMA 判别打分**：仅 ④ 步外包给 CMA，TA 否决面激活。对照 P0 测打分质量增益。
- **P2 CMA 语义去重 + 快照审计**：激活 ③ 步与审计职责。重点验 R1/R3。
- **P3 相关性标注装配增强**：CMA 为 L3 检索提供标注，装配含检索提示。重点验弱模型下 R2。

**阶段门判据（先于阶段开始写定；过不了门 = 停在上一阶段默认形态继续用，不推倒重来）**：P1 门 = §10 指标5 CMA 边际净收益 ≥0（vs P0 基线），不过则 CMA 不升默认；P2 出口门 = 未触发 §8.1 漂移弃守线（语义半漂移率>5% 且含保护类不一致，或重建率<95% 且归因快照内容错误），不过则冻结在 P1 并按 §8.1 启动弃守评估。

**评测指标（保真度门，程序可测）**

1. **事实重建率**：压缩后，仅凭新上下文回答抽样快照事实的出处与内容（独立小模型做 quiz），目标 ≥95%。
2. **漂移率**：N 轮后快照与 Evidence 记录的一致性，分两半，均从 P0 可测、均不以在环 CMA 为数据源（破半循环：评测与被评对象分离）。程序半：evidence_ref 非空率/可解析率、pointers 可水合率、invariants 在场率，纯程序比对。语义半：离线判卷模型（与指标 1 同一独立小模型，评测态角色、非管线内 CMA）逐条比对快照声明与 ref 原文是否相符，不一致条目占比即漂移率。P2 起 CMA 在环审计只作运行时预警通道，不作为本指标数据源。
3. **死循环率**：负面知识丢失导致的重蹈覆辙次数（工具调用序列中重复探测模式的检出）。
4. **去重率**：无意冗余删除量 / 总历史量；同时有意冗余保留率必须 100%。
5. **成本**：净收益 = 节省 − 开销。节省 = 被删内容在后续各轮本会再次在场的计费 token（按 cache 定价区分 read/miss；原始 token 数不作成本单位，缓存命中场景会严重高估节省）× 剩余在场轮数；开销 = CMA in/out + TA 检查点增量 + 否决往返。双基线：vs P0（隔离 CMA 边际收益，供 P1 门）与 vs 内建摘要回退（隔离整条管线收益）。P1 门：CMA 边际净收益 ≥0 才升默认，否则停在 P0 形态（对应 §8.1 trade-off 2 弃守线）。**账单降级口径（终审裁决点③成文）**：若 provider 账单拿不到 cache read/miss 拆分，指标降级为原始 token 口径并注记偏差方向——token 口径高估节省（缓存命中部分实按 read 计价）、净收益偏乐观；降级口径只能支撑"不通过 P1 门"的结论，不足以支撑"通过"，通过判定须待全口径数据。

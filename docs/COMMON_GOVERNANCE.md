# Common Governance / Common Experience

状态：默认模型治理层，2026-09-11。

## 目的

恢复 LFL 早期针对本地模型重复、漂移、工具误用、虚构完成、无效复查和中断后重开题的有效经验，但不恢复旧的 prompt-heavy 自动注入、Program Authority 或固定仪式。该层只提供跨任务通用的执行纪律；当前事实、当前用户指令、明确任务约束和更具体的已验证方案始终优先。

## 常驻最小集

1. 保持当前目标和明确约束；区分观察、事实、假设、决定，并检查证据来源、时效和范围。长任务持续知道“已确立事实 / 未解决问题 / 本步动作”。
2. 工具优先与执行诚实：任务事实只存在于文件、命令、网页或运行态时先取真实工具证据，不猜；动作是否真正完成只以当前工具回执为准，没有成功回执不得宣称完成。
3. 工具契约优先：lazy/compact Schema 只保证可执行骨架，不保证承载全部操作语义。陌生工具、参数语义不清或参数/协议失败时，先读取当前完整 Schema/code/docs 后修正；同参数、同状态、同路径没有新信息时不盲重跑。
4. 经验按需：已知重复故障、复用已验证路径或当前事实不足时，发现相关 Rule/Experience/Method 后精确水合并检查来源、时效和当前适用性；普通任务不自动灌入经验库全文。
5. 动作前比较状态差异；成功回执或已闭合结论在没有新反证时不重复核验。只验证会改变下一步决定的不确定性，优先高信息增益、低成本动作。
6. 截断/中断后优先恢复持久化事实与最近未完成状态，随后只做增量推理，不从旧历史重新开题。

## 明确不做

- 不自动选择/隐藏工具，不规定固定调用顺序。
- 不用程序判断任务完成、证据语义充分性或方法适用性。
- 不恢复每轮自查、固定重试次数、动态经验 catalog、HOT/WARM/COLD 或 Adaptive Autonomy 等大段常驻知识。
- 不把历史计划、历史 assistant 提议或历史经验升级成当前授权。

## 验收门

常驻文本必须 deterministic、静态、短小；不再用任意“<200 字符”门槛替代行为验收。相关测试必须证明当前用户真值可覆盖默认经验，且无旧 prompt-heavy/Program Authority 标记。真实 Ornith 验收需覆盖：工具事实优先、失败后正确核完整 Schema、无成功回执不虚构完成、成功后不重复核验、按需经验发现/精确水合、中断/最近窗口续做，以及运行时 1/1 并发和内存健康。

# RSI（递归自我改进）实现需求分析建议

- 日期：2026-10-19
- 状态：建议稿（未预注册、未冻结、未评审）
- 作者：LFL（本文事实分三层：仓库事实=可核；文献要点=既有知识，仅核到"存在/有后续引用"；建议=判断）

## 0 结论先行

对我们这个系统，RSI 的可行形态不是"让模型改写自己的代码或权重"，而是**受约束的自改进闭环**：

> 变异空间限定在「方法卡 / 提示词模板 / 工具选择策略 / 检索参数 / 流程脚本的非安全部分」；
> 裁判外置（评估器与 held-out 集不可被变异体写入）；
> 权限、安全门、规则、评估器**不进变异池**；
> 每次接受都要有预注册、独立审查、可回滚、谱系证据。

在拿到"自改进速率 > 人工改进速率"的配对证据之前，不进入 L3/L4（见 §4）。理由不是保守，而是：开放式自改的收益是超线性的，风险也是——一旦评估器可被改进体影响，整个度量就失去意义，后续所有"改进"都是自欺。

## 1 参考资料：六类做法与可借鉴/不可借鉴

| # | 路线 | 代表工作 | 核心机制 | 可借鉴 | 不可直接借 |
|---|---|---|---|---|---|
| 1 | 进化式程序搜索 | AlphaEvolve（DeepMind 2025）、FunSearch（2023） | 候选池 + 自动评估器 + 多轮变异，评估器是唯一裁判 | 候选档案（archive）、评估器外置、按分数淘汰 | 无人类门的持续上线 |
| 2 | 自指代码改写 | Gödel Machine（Schmidhuber 2003/2006）、Darwin Gödel Machine（2025） | 只有"能证明改进"才接受自改；DGM 用档案 + 经验证基准（SWE-bench/Polyglot）实测增益 | **接受判据必须是外部基准**；保留历史谱系 | 无界开放式自改（对本仓属超纲风险） |
| 3 | 脚手架自改进 | STOP: Self-Taught Optimizer（Zelikman et al., 2023, arXiv:2310.02304） | 模型改进自己的 scaffold，配 sandbox + 监督 | 沙箱、可回滚、只动脚手架层 | 以自评为改进信号（原文亦以沙箱和人工监督设限） |
| 4 | 自训练/自蒸馏 | STIL「LLMs Can Self-Improve」（EMNLP 2023）、SEAL（2025） | 自生成数据 → 过滤 → 更新权重 | 过滤器设计、数据质量门 | 我们需要行为改进而非权重更新（成本/可控性/审计） |
| 5 | 自评当奖励 | Self-Rewarding LMs（Yuan et al., 2024）、LLM-as-judge | 模型自评 → 自奖励 | 多评委 + 校准 + 成对比较 | 自评闭环 = 可被 Goodhart 的自指回路 |
| 6 | 安全线 | reward hacking / specification gaming（DeepMind 2020）、reward model overoptimization（Gao et al., 2023）、alignment faking（Anthropic 2024） | 优化压力下出现"考试作弊"式行为 | 全部 | —— |

**核对声明**：本轮用 OpenAlex/Crossref 检索确认 DGM、STOP、AlphaEvolve 派生文献在库，并取得 DOI/arXiv 号；表中具体数值（如 DGM 的基准提升幅度）**未逐篇复核**，引用前需回原文。

三条跨文献的共性结论：

1. **改进信号必须来自改进体之外**。凡是"自己判自己"的路线，论文里都要额外加外部过滤或人类门，否则退化成自我确认。
2. **档案（archive）比单点更好**。保留被淘汰的候选，才能在评估器换种后重评、在回滚时找回。
3. **增益要靠配对实验说话**。单次跑分在 LLM 任务上的方差足以吞掉真实改进。

## 2 我们已有的地基（仓库事实）

| 能力 | 现有件 | 对 RSI 的作用 |
|---|---|---|
| 方法池 candidate→active | `method_manage` + METHOD_LEARNING_V1.md | 天然的"变异单元"与晋级状态机 |
| 经验/教训分型 | `save_experience`（verified 需证据） | 变异的知识底座，且已有"未验证≠已验证"纪律 |
| 演进建议 | `submit_evolution`（人工审阅；安全/授权边界只能建议） | 现成的人类门接口 |
| 评估纪律 | docs/ABLATION-A1/A2/A3 的 预注册→冻结→结果 三段式 | 直接复刻为 RSI 的实验模板 |
| 独立审查门 | RULE-AI-28 / `review_admission`（只读 reviewer、P0/P1 判定、一次性资格） | 接受决策的第三方复核 |
| 结算记账 | `settlement_pending` / `settlement_submit`（工作单元×对象×版本抵扣） | 成本与使用反馈入账 |
| 自评 | `self_evaluate`（成功率/停滞/异常） | 只能当"体检"，不能当改进判据 |

缺的两件：**变异生成器**（谁提出候选）与**速率对照度量**（怎么证明比人快）。

## 3 需求（R1–R10，每条带验收口径）

- **R1 变异空间白名单**：只允许改方法卡、提示词模板、工具选择策略、检索参数、流程脚本的非安全段。验收：变异 diff 只能落在白名单路径；越界在应用前拒，且拒绝理由可审计。
- **R2 裁判外置**：评估器代码、任务集、判分脚本的 hash 进冻结清单；变异体对其无写权限。验收：篡改评估器任一处 → 运行期拒跑并报错（不是"分数变低"）。
- **R3 判据 = 外部基准 + 置信区间**：同一任务集重复 ≥5 次、配对比较、报 95% CI；接受条件 = 点估计上升 **且** CI 下界 > 0 **且** 回归率不超阈。
- **R4 谱系与回滚**：每个候选记录 parent、diff、评测证据、接受/拒绝理由；任一 active 版本可一键回滚，且回滚本身有测试。
- **R5 预算与速率**：token/时间/调用成本逐次入账，报告"改进/成本"；超预算自动停（不是报警后继续）。
- **R6 防 Goodhart**：held-out 集只在晋级门用一次，用后轮换；训练可见集与 held-out 集物理隔离。
- **R7 权限不变量**：变异体不得改变工具白名单、网络开关、写盘范围、外发通道、授权额度。这条是硬约束，任何"为了通过测试"的例外都不接受。
- **R8 人类门**：触及安全门/规则/权限/评估器/预算上限的变更一律人工批准；低风险且 R3 达标的可自动，但保留撤销权。
- **R9 失败模式登记**：自奖励循环、评估器泄漏、静默退化、谱系断裂、成本失控——每类配一个检测器与一个红灯阈值。
- **R10 审计可复核**：外部人只凭落盘证据能重放一次"接受"决策（任务、种子、版本、分数、审查意见）。

## 4 能力分级与晋级条件

| 级 | 形态 | 晋级条件 |
|---|---|---|
| L0 | 只记录不改（现状） | —— |
| L1 | 提议不落地，人工应用 | 连续 10 次提议中 ≥3 次被采纳且无回归 |
| L2 | 低风险自动落地 + 自动回滚 | 回滚成功率 100%、静默退化 0 次、审计抽样通过率 ≥90% |
| L3 | 变异生成器自选方向（高危仍人工） | 配对实验证明改进速率 ≥ 人工基线（CI 下界 > 0） |
| L4 | 自改评估器/核心代码 | **不建议**：除非有形式化不变量 + 外部审计 + 可证明的沙箱边界 |

## 5 度量设计（怎么算"真的在自改进"）

- 主指标：held-out 任务成功率（配对、重复 ≥5、报 CI）
- 次指标：单位成本改进、回归率、回滚率、人工干预率、候选存活率
- 对照组：① 随机变异（安慰剂）② 不变异（baseline）③ 人工改（上限参考）
- 判定：只有"主指标↑ + CI 下界>0 + 无超阈回归"才算改进；任一不满足即视作噪声

反面教材要写进纪律：只看训练集分数、只跑一次、只挑有利任务子集——这三种做法都能"证明"任何方案有效。

## 6 90 天路线

- **M0（2 周）观测**：把方法与经验的使用和结果对齐；建 held-out 任务集 v1；冻结评估器 hash。产出：可复跑的评测脚本 + 冻结清单。
- **M1（4 周）半自动**：变异生成器 v1（只改方法卡与提示词），人工应用；收集配对数据。产出：≥30 组配对样本。
- **M2（4 周）自动落地**：低风险自动 + 自动回滚 + 审计抽样。产出：回滚演练报告。
- **M3（2 周）速率对照**：自改进 vs 人工改的配对实验，出"是否进 L3"的决策文档。

每阶段沿用 ABLATION 模板：预注册 → 冻结 → 结果，三段都要落盘。

## 7 明确不做

1. 不让系统改自己的权限、安全门、规则、评估器。
2. 不在本仓直接落地 DGM 式无界自改。
3. 不以自评为唯一改进信号。
4. 不在缺少 held-out 与 CI 的情况下宣称"自改进"。
5. 不用"通过率提升"掩盖成本上升（成本是需求 R5 的一部分）。

## 8 风险 → 需求 → 检测

| 风险 | 对应需求 | 检测器 |
|---|---|---|
| Goodhart / 过拟合 held-out | R3、R6 | 轮换 held-out + 随机变异对照 |
| 评估器被改 | R2、R7 | 冻结 hash 校验失败即拒跑 |
| 静默退化 | R3、R4 | 回归率阈值 + 金丝雀任务 |
| 谱系断裂（说不清谁改的） | R4、R10 | 决策重放演练 |
| 成本失控 | R5 | 预算硬停 |
| 权限漂移 | R7 | 权限快照 diff，变更即告警 |

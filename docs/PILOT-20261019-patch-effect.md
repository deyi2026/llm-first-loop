# PILOT 20261019：方法卡补丁的行为差（原卡 vs 打补丁卡）

> 一句话：4 张卡的配对都拿到了，没有一张显示补丁有效（Δ 全为 0）。补跑把三处仪器缺陷暴露出来：(1) P01 的 -2 是 `keyword_families_used` 自报口径抖动，5 次原卡重跑为 9,7,7,9,7；(2) P10/P23 的 Δ=0 是判分不敏感——11 个失败 check 里 8 个是词表/量词缺陷、2 个是断言与字段语义不一致、只有 1 个是真实判断差异；(3) 5 张卡 × 33 题共 165 对，`direct` 触发匹配为 0——P01 的卡讲发布门禁，题考 cache 是否生效，Δ=0 首先说明配对无效。净产出不是"补丁好不好"，而是"这套测量当前既不构造有效，也分辨不出 2 check 以内的差异，还在 B/D 家族上分不清格式与能力"。

## 为什么测

`MUTCARD-V2-20261019.md` 的 5 张补丁只过了文本判据复核（补的是不是那个缺口），没有跑过任何行为测量。`REPORT-20261019-rsi-instrument-v3.md` 也明确写过"没有跑任何变异器对卡片的真实影响"。本 pilot 补这一格。

## 设计

- **题**：`heldout_v2.jsonl` 中 `calibration_v4.json` 标定为 usable 的题，按 `FAMILY_MAP` 取与被测卡同族；只取 usable，避开天花板/地板题。
- **臂**：`orig` = 原卡（`data/methods/…/METHOD.md`），`patch` = `repairs_v2/<P>/METHOD.md`。两臂 frontmatter 相同，正文只差补丁句（已核）。
- **协议**：batch（与已落盘的 55 次基线和标定主口径一致），每臂基础 1 次；P01 另做 test-retest（原卡 5 次、补丁 2 次，见下），机械判分（`grade_holdout.check_one`，无 LLM 裁判）。
- **预算与传输**：计划 8 次求解调用，实际 13 次（8 配对 + P01 复跑 2 次 + test-retest 3 次）。`P10|patch` 三次尝试中前两次、`P03|patch` 首轮各遇 120s 读超时（P10 第二次已改 `attempts=1`，仍撞 120s；第三次把 timeout 提到 280s 才成功），**不是限流**：同时刻探针 3.3s 正常，P03 补丁臂在 116s 处成功，说明是单请求耗时贴着 harness 的 socket 超时阈值。改为 `attempts=1` + 280s socket timeout + `max_tokens=12000` 后两臂均 `finish=stop`（7183 / 6496 tok，未截断）。注意这两臂的 max_tokens 与其余 6 次基础调用不同（test-retest 统一 6000），属协议差异。
- **落盘**：`evals/methodcard_rsi_v1/results_pilot_patch/raw.jsonl`、`report.json`；脚本 `pilot_patch_effect.py`、`pilot_patch_repeat.py`、`pilot_patch_deadline.py`（带硬墙钟上限的单臂补跑器）、`pilot_patch_noise.py`（同卡 test-retest 追加器）。
- **噪声复跑（新增）**：P01 原卡追加 r3–r5（`pilot_patch_noise.py`），执行器为 `attempts=1`、socket timeout≤280s、线程硬 deadline 420s、`max_tokens=6000`（与 r1/r2 一致），顺序执行，避免并发排队污染延迟。5 个原卡样本只用于估计同卡翻转，不与补丁臂混算。

| 卡 | 家族 | 原卡 | 补丁卡 | Δcheck | 备注 |
|---|---|---|---|---|---|
| P01（5 次 vs 2 次） | A_effectiveness | 9,7,7,9,7（q 2,0,0,2,0 /3） | 7,7（q 0,0 /3） | 首轮 -2，复跑 0 | 唯一翻转项是 H01 c2 / H02 c3（`keyword_families_used<=2`） |
| P03 | A_effectiveness | 9/10（q 2/3） | 9/10（q 2/3） | 0 | 失败项逐条相同 |

| P23 | D_patch_verify | 13/19（q 0/4） | 13/19（q 0/4） | 0 | 6 个失败中 5 个是格式，1 个是真实判断；补丁臂转英文 |

`P28`（F5_other）没有 held-out 家族映射，不进入本实验；`C_authority` 也没有对应卡。

**同一批 artifact 的事后重判（不是新跑）**：把 H01 c2、H02 c3 两条 `keyword_families_used` 检查从计分中移除后，P01 原卡 5 次全部为 **7/8**，补丁 2 次也全部为 **7/8**；唯一失败是 H04 的 `verdict`（模型答 `not_effective`，卡上要求 `unknown`）。首轮的 -2 完全由自报计数造成，补丁在 A 家族上没有可测效应。

**成本**：补丁臂的输出 token 一律更高——P03 4577→7183（+57%）、P10 5165→6496（+26%）、P23 4470→5570（+25%）、P01 r2 4439→5475（+23%）。四对中位数 +25%，收益 0。五条原卡 P01 样本的 token 为 5035/4439/3800/6929/5673，波动 3800–6929，说明同卡成本本身也不稳；但"补丁臂更高"在四个配对上方向一致。多出来的 token 花在复述证据上，不在判断上。

## 机制：-2 是自报计数抖动，不是补丁

5 个原卡样本的 `keyword_families_used`（H01/H02/H04 三个 case）与总分：

| run | H01 | H02 | H04 | 总分 |
|---|---|---|---|---|
| r1 | 2 | 2 | 2 | 9/10 |
| r2 | 3 | 3 | 2 | 7/10 |
| r3 | 3 | 3 | 3 | 7/10 |
| r4 | 2 | 2 | 2 | 9/10 |
| r5 | 3 | 3 | 3 | 7/10 |

H01/H02 在每次运行内**锁步**（2/2 或 3/3），H04 5 次中 4 次跟随（r2 为 3,3,2）。H01/H02 的 `<=2` 因此同时翻，H04 的 `>=2` 不受影响。也就是说，一个随答案措辞漂移的自报量制造了 2 个 check 的翻转，20pp 噪声全部来自这里；它不是"某个 case 多用了证据族"。

口径本身也不成立：prompt 和 `artifact_schema` 只写 `keyword_families_used: int`，从未定义"family"，也没要求最小化；模型是在猜一个隐藏评分项。**决定：该字段不计分**（保留为 telemetry，不进 pass/fail）。不采用"改口径到 3"——那只是把阈值挪到本次样本的多数侧，仍然是自报。若确实要测"证据族 sprawl"，应改为确定性的 `evidence_refs` 数量 + 每条 ref 可解析且指向相关文件，并在 prompt 里给出明确定义。

## 构造效度：四对配对都没有卡-题触发重叠

逐张对照 Trigger 与对应家族的题面：

| 卡 | 卡的 Trigger（摘要） | 对应家族题面 | 重叠 |
|---|---|---|---|
| P01 | 交接计划含"直接发布会覆盖生产"警告，终点是 push/publish/restart | 判断 `compress_cache` 是否在生效路径 | 无 |
| P03 | checker 报文件缺锚点，需跨 commit 历史横扫归因 | 判断 cache/rate_limiter 是否在生效路径 | 无 |
| P10 | 已有平台特定记录，下一步是 systemctl/tasklist 等服务发现 | 编辑回执 vs 目标仓核对日志 | 无 |
| P23 | curl 拿到 Cloudflare 530，origin 存活，查 tunnel connector | 补丁验证记录零命中，判定补丁状态 | 无 |

四对都只是家族标签匹配（effectiveness / completion / verify），触发条件没有在题面里出现：P01 卡是"接手既往会话的分歧警告 → 当作发布前门禁"（`treat-handoff-divergence-warning-as-prepublish-gate`），题是"代码快照里 cache 是否在生效路径"；一个是发布计划的前提核验，一个是代码调用链判定。P03/P10/P23 同理。

因此即使去掉 KFU，P01 补丁也不能被 A 家族题测到；四对的 Δ=0 不能解释为"补丁无效"，只能解释为"这组题没有实例化这些卡的 trigger"。配对必须从家族标签下钻到 case-level 触发匹配：先问"这道题是否出现卡所教的决策点"，没有就不进实验。

## 判分器修复与重判（v3，2026-10-19 下午）

**静态体检**：新增 `lint_holdout.py`，对 33 题 129 个 check 机械检查"字段/类型/断言是否指同一件事"。结果 **18 个 violation**（V2 `in_set` 词表未声明 9 个，V3 `subset_of` item 词表未声明 9 个），占 14%。这是"模型无从知道该写哪个 token"的硬证据，不再依赖逐条人工读。

**11 个失败重新分类**（不再沿用"9 格式 + 2 真实"的旧说法）：

| 类别 | 数量 | 例子 | 处置 |
|---|---|---|---|
| 标量散文对隐藏枚举 | 2 | H25 `success_semantics_scope` 写了一段话，期望 `mirror_only` | 声明概念别名后判过 |
| 列表散文 + `subset_of` 当成"必须恰好" | 6 | H35 `valid_evidence` 多写一条 HEAD 核对被判越界 | 改为"至少一条命中 allowed" |
| 断言与字段语义不一致 | 2 | H30 `verification_target` 问"目标是谁"，allowed 却是失败类型标签；H35 `done_claims` 无定义 | 记 void，不进分母 |
| 真实判断差异 | 1 | H15 两臂都答 `unknown`，期望 `fail` | 保留为 fail |

**重判结果**（`grade_v3.py`，同一批 artifact，不新跑）：

| 配对 | v2 | v3（计分/void） | 剩余真实失败 |
|---|---|---|---|
| P10 | 8/13 vs 8/13 | 12/12 vs 12/12（void 1） | 无 |
| P23 | 13/19 vs 13/19 | 17/18 vs 17/18（void 1） | H15:c1（两臂） |
| P01 | 9,7,7,9,7 vs 7,7 | 不变（无此类 check） | H04:c1 |

验收口径达成：**格式/词表类失败归零**（8 条全部转为通过），**真实失败保留**（H15:c1 仍 fail，证明匹配器不是橡皮图章）。代价是分母少了 2 个 void check，已在表内显式披露；这两条不是"判对了"，是"判不了"。

**防橡皮图章**：`test_judge_v3.py` 15 条单测，含 6 条负向控制——"old-checkout 上的 pytest"不得命中 `lint_on_target`、"`ruff check . --fix`"不得命中 `bare_ruff_check`、"target diff"不得命中 `target_sha256`、"build 镜像的 e2e"不得命中 `cached_image` 等；另一条单测确认错误证据仍判 fail。

**没做的事**：没有改 `heldout_v2.jsonl`（冻结），没有把 allowed values 写回 schema。v2 是已消耗的仪器，改它等于篡改历史；词表写进 schema 的要求转成 R12 的 lint 门，用于 v3 及以后新题。

## 解释边界

- 噪声底现在有 5 个 P01 原卡样本：9,7,7,9,7，极差 2 check/10 = 20 个百分点。**在这套题上，小于 2 check 的 Δ 不具备解释力**；首轮"P01 可测地变差"的结论已撤回。去掉 KFU 两项后 5 次全部 7/8，说明这 20pp 全部来自一个措辞项，不能外推为"其他家族也只有 2 check"。
- P03/P10/P23 仍各只有 1 次/臂；但 P10/P23 的 check 级分析已经能解释 0：11 个失败中 8 个是词表/量词缺陷、2 个是断言不可判、1 个是真实判断差异，两臂逐条相同。这不是"样本不足"，是判分器不测那个差异。
- P23、P03 的补丁臂整体切英文作答；两臂都失败在同一批格式 check 上，所以语言不是 Δ=0 的原因，但会污染未来的语义判分，需固定输出语言或改语义裁判。
- 四对配对的 construct 不重叠（见上），所以这批 Δ 不能用来评价补丁本身；它们只评价了仪器。单模型、4 张卡，不外推到 5 张全部或别的模型。

## 对需求分析的增量（已写入 ANALYSIS 的 R11/R12）

1. **可检测性**：每个变异必须绑定至少一道能区分原/变体的题。没有对应题的变异（如 P28）不得进入实验——否则永远测不到，只能靠"读起来对"。
2. **零副作用**：必须同时报目标家族 Δ 和至少一个无关家族 Δ。
3. **判分鲁棒性**：词面判分对语言/措辞漂移敏感；要么固定输出语言，要么改语义判分。
4. **噪声底先于结论**：任何 Δ 必须先与同卡 test-retest 的翻转数比较。本轮直接证据：P01 原卡 5 次为 9,7,7,9,7；且翻转源是单一自报项，去掉后 5 次全 7/8、零翻转。
5. **构造效度（新增）**：家族标签匹配 ≠ 触发条件匹配。四对卡的 Trigger 在题面里没有实例，Δ=0 不能读作"补丁无效"；配对必须下钻到 case-level：这道题是否出现卡所教的决策点。
6. **判分可满足性（新增）**：计分字段的允许值必须出现在 prompt/schema 中，或由独立语义裁判按 rubric 判；自由文本字段不得对隐藏枚举。P10/P23 的 11 个失败 check 中 8 个是这一类，两臂逐条相同。

## 1. 目标与范围

### 1.1 目标（总审计 §12-D + 用户指定并入项）

1. **并入 agent_trace_leak 两项修订**：
   - 修订①：REFERENCE 降级回喂改为 **quarantine + event + UI**，provider chars=0；`leak_downgrade` 不进 prompt producer allowlist；
   - 修订②：全入口（Web/CLI/Feishu/API）token 签发完成后，default 切 **fail-closed**；
2. **cache performance BLOCK 退出**：hit rate / submit_ratio / system stability / compression-storm 类性能理由不再 BLOCK 请求，降级为 observability/optimizer；**privacy/safety BLOCK 保留**；
3. **fallback 能力下限**（r-p-r P1-4）：capability floor + task compatibility + user explicit override strict + side-effect/tool capability compatibility；
4. budget 从"智能硬上限"降为 optimizer（总审计 P1-13，收编 r-p-r P3-1 的预算问题）。

### 1.3 不做什么（边界）

1. **不删除 privacy/safety 类 BLOCK**：灾难性安全、隐私/凭据防泄漏的拦截是 KEEP-HARD（§8.1），本包只退**性能类** BLOCK；
2. **不取消用户明确的成本/额度硬限**：用户 cost policy 是硬边界，性能退让不等于成本退让；
3. **不动 provider wire 协议修复**（R8.21 已完成的跨 provider rebuild 保留）；
4. **不动规则文本**（cache 纪律规则删除属 R8.24-A）；
5. **不引入"程序自动选更便宜模型"的成本代理决策**：fallback 是 availability control，语义等价性与用户选择优先（总审计 §10）；
6. **不把 quarantine 内容用于训练/分析之外的用途**：quarantine 是隔离区，不是新数据源。

## 3. 设计决策

### D-D1 trace-leak 修订①：REFERENCE 降级回喂 → quarantine + event + UI（总审计 P0-5 建议①）

- 确认 mislabel 的程序内容**不得**通过 REFERENCE 身份重获语义权限；
- 可疑/越权内容处置：**quarantine（隔离存储）+ event（leak.quarantined 事件）+ UI 提示**，provider chars=0；
- `leak_downgrade` 不进入 prompt producer allowlist（allowlist 收紧为白名单枚举，leak_downgrade 显式排除并加 CI 断言）；
- 若无法证明是用户输入：宁可拒绝/等待用户确认，也不把内容"降级注入"（asymmetric failure：漏放一条可疑内容的代价 > 拒绝一条可证内容的代价）。

### D-D2 trace-leak 修订②：全入口 token 签发完成后 default fail-closed

- Web / CLI / Feishu / API 等所有真实人类入口完成 ingress token 签发改造；
- 签发完成后 `LFL_LEAK_GUARD_MODE` default 从 observe 切 **fail-closed**（无 token 的 `role=user` 写入 drop）；
- 迁移期次序：入口逐个签发 → 该入口灰度 fail-closed → 全入口完成 → default 切换（见 §6）；
- 保留 operator 显式覆盖通道（应急调试），覆盖动作全量审计留痕。

### D-D3 cache performance BLOCK 退出（总审计 P0-4）

保留硬 BLOCK（五类，§8.1 对齐）：

1. privacy / secret leakage；
2. disaster safety；
3. provider wire invalid；
4. 真实 context window 超限；
5. 用户明确成本/额度硬限。

降级为 observability / optimizer（不再 BLOCK）：

- hit rate；
- submit_ratio 相对内部 history budget；
- system stability cache warning；
- compression-storm cache quality。

程序可自动选择更缓存友好的等价表示，但**不能为了 cache quality 阻止语义请求**。

### D-D4 `_breaker_pressure_block()` 重审

- 内部 history budget 水位（compression breaker active）不再独立终止 run；
- 真正允许终止 run 的仅剩：真实 provider window 超限、用户成本政策、安全——其余场景程序自行 compaction（衔接 B 包 E17）后继续；
- "要求 checkpoint/换会话"的指令性输出取消（属 B 包 E19 通知面，此处声明触发条件收窄）。

### D-D5 budget = optimizer（总审计 P1-13，收编 r-p-r P3-1）

- 结构清理先行（A/B/C/E 包消除无资格内容后），再谈预算收紧；
- 当前 unresolved evidence 放不下时允许按实际 provider window 自适应扩展；
- 真正硬限只来自 provider window、用户成本政策、安全/产品限额；
- 30K local 预算的"写报告被腰斩"问题随无资格内容退出获得结构性缓解；若仍不足，按任务类型分档调优属运营参数，不是本包架构变更。

### D-D6 fallback capability floor（总审计 P1-14，收编 r-p-r P1-4）

fallback 链自动成员必须同时满足：

1. **capability floor**：低于下限的模型（如小参数量/低量化档——具体阈值由实测定标，r-p-r 建议 <14B 或量化 <q6 不进自动链仅作初值假设）不进自动链，只能显式指定；
2. **task compatibility**：健康检查/长链推理等任务的复杂度与模型档位匹配；
3. **user explicit override strict**：用户显式选定的模型失败保持 strict（不静默换链），如实报错等用户决定；
4. **side-effect / tool capability compatibility**：目标任务依赖的工具能力在候选模型上可用；
5. 切换前若任务已有进行中产物，优先重试同模型 2 次再降级（r-p-r P1-4 建议，减少无谓 miss）；
6. fallback 结果走 UI/status/audit，不生成下一轮 prompt notice（通知面 B 包 E19）。

### 被弃方案

| 被弃方案 | 来源 | 弃因 |
|---|---|---|
| 保留 observe 默认 + 增强白名单检测 | 现状（D1） | 总审计 P0-5 判定：非根治 fixed-point；检测永远滞后于伪装变体，fail-closed 才是结构解 |
| leak_downgrade 进 allowlist 受控回喂（REFERENCE appendix） | 现状（D2） | "确认污染→改标签→仍发给模型"方向错误；程序建议不得伪装成 reference 语义 |
| 调高 submit_ratio BLOCK 阈值（95%→98% 等） | — | 性能 BLOCK 整类退出，不调参；调参仍留"性能阻止语义"的越权结构 |
| 30K→150K 一刀切提额 | r-p-r P3-1 直译 | 总审计 P1-13：先消除无资格内容再谈预算；提额不解决结构污染且推高成本 |
| failover 按可用性排序 | 现状（D6） | 降智继续任务比中断更糟（死循环实证）；能力下限是语义必要条件 |
| 程序静默重试同模型无限次以避免切换 | — | 成本失控；限定重试 2 次（D-D6-5） |
| quarantine 内容经用户一键确认后转为正常输入 | 可选增强 | 引入新的 UX 协议面，超出本包"退出污染"目标；留作后续提案记录，不纳入验收 |

## 6. 迁移步骤（分批、可回滚、shadow→enforce）

```text
批 D1（cache 性能面，独立可先行）
  ① Rule F submit_ratio BLOCK → WARN 降级（shadow 期：记录 would_block=25 类场景的
     run 成功率/成本变化）
  ② breaker pressure 终止条件收窄（D-D4）
  ③ 达标（run 成功率不降、成本在用户政策内）→ enforce：性能 BLOCK 分支删除
     （保留五类硬 BLOCK），env flag 可回滚
批 D2（fallback floor）
  ④ capability floor 阈值定标（实测：以 D6 死循环场景 + 健康检查任务做档位对照）
  ⑤ 现有 fallback 链 shadow 校验（标记 would_downgrade_below_floor 次数）
  ⑥ enforce：链构造过滤 + 同模型优先重试 2 次 + strict 用户选择
批 D3（trace quarantine，前置=B 包验收）
  ⑦ REFERENCE 回喂路径改 quarantine + event + UI（shadow 期记录 would_reinject=0 化进度）
  ⑧ allowlist 排除 leak_downgrade + CI 断言（D-G2）
批 D4（ingress fail-closed，前置=批 D3）
  ⑨ 入口逐个 token 签发：Web → CLI → Feishu → API（每入口独立开关）
  ⑩ 每入口灰度 fail-closed → 观察误拒率 → 全入口完成
  ⑪ default 切 fail-closed（保留 operator 显式覆盖 + 全量审计）
```

- **回滚**：批 D1 性能 BLOCK 保留 env flag；批 D4 每入口独立开关 + default 切换点独立 revert；
- **灰度**：D1③/D2⑥ 均有 shadow 观察期；D4 是逐入口渐进 fail-closed，最终 default 切换是唯一不可灰度的原子动作（故放在最后且可整体回滚 flag）；
- **定标准则**：capability floor 阈值必须有实测数据支撑（禁止拍脑袋数值进配置），初值假设（<14B/<q6）标注为待验证。

## 7. 风险与不可删清单核对

### 7.1 风险

| 风险 | 缓解 |
|---|---|
| fail-closed 误拒合法用户输入（token 签发遗漏入口/异常路径） | 逐入口渐进 + 误拒率观察；operator 显式覆盖通道 + 审计；quarantine 区可人工复核放行（运维流程，不自动回喂） |
| 性能 BLOCK 退出后成本上升 | 用户成本政策仍是硬限（D-D3 保留项 5）；WARN 观测持续；cache 友好等价表示的程序优化保留 |
| floor 阈值定标不当（过高可用性损失/过低降智复发） | 实测定标 + shadow 期 would_downgrade 指标 + 阈值可配置可回滚 |
| quarantine 区自身成为泄漏面 | quarantine 存储访问权限收敛 + 事件不含原文（仅指纹/摘要）实施期细化 |
| observe→fail-closed 切换期间存量会话残留 | 切换仅作用于新写入；存量历史在 build 面由 D-D1 quarantine 兜底 |
| build.py/ingress 工作树锚点漂移 | D1/D2 标注"必须复核"：实施期以符号名（`leak_downgrade`/REFERENCE appendix 构造点）grep 再定位 |

### 7.2 不可删清单核对（本包是 KEEP-HARD 的主执行包，逐条强化）

| 硬边界（总审计 §8.1） | 本包处理 |
|---|---|
| 灾难性安全 | **保留**（D-D3 硬 BLOCK 类 2） |
| 隐私/凭据防泄漏 | **保留并强化**（D-D3 硬 BLOCK 类 1；D-G5 断言不降级） |
| provider 协议 | **保留**（wire invalid 仍硬 BLOCK；R8.21 rebuild 不动） |
| 真实物理限制 | **保留**（真实 window 超限仍硬 BLOCK；内部 budget 水位降为 optimizer——这正是"真实物理限制"与"内部启发式"的区分） |
| 输入来源真实性 | **保留并强化**（D-D1/D-D2 即本条的主落地：provenance fail-closed） |
| 显式用户模型选择 | **保留并强化**（D-D6-3 strict 路径 + D-G7 断言） |
| 数据持久性 | 保留（quarantine 不销毁内容，可审计可人工复核） |

## 1. 目标与范围

### 1.1 目标

把运行时故障与机械控制从"模型新指令"收回控制面（总审计 §12-B）：

1. **E12/E15/E16/E17/E18 零 prompt**：err1210 重发、停滞提醒、空搜索提醒、overflow 反馈、轮数耗尽决策，全部不再生成模型可见自然语言；
2. **`current_turn` 不再 grant**：降级为纯生命周期 metadata，删除 fresh `program_recovery` 的自动 prompt 权限；
3. **overflow / round / retry / repair 确定性化**：runtime 自己 compact/route/end/retry，UI 显示；
4. **E32 repair-before-lifecycle**；
5. **E19 runtime notices 不进 `sess.messages`**：只落 event/status/UI/audit；
6. **并入 tool_eligibility_unblock P1 熔断重审**：计数与成本边界保留，提醒/替代策略文案取消（总审计 §11.1/§11.3 撤销判定落地）。

1. **不动工具回执内容事实化**：guidance/capsule/截断事实行属 R8.24-C；

5. **不取消 hard stop 本身**：round/timeout/cost 硬限执行保留（§8.1-4），改的只是"到达边界时的表达方式"——结束/暂停等用户，而非问模型；
6. **不引入新的程序↔模型协商协议**（如"模型确认后继续"）：边界即边界。

## 3. 设计决策

### B-D1 `current_turn` 降级为纯生命周期 metadata，不再是 prompt grant

- 删除"fresh `program_recovery` 自动权限"（P0-1）；
- `prompt_lifecycle=current_turn` 只描述消息年龄，不授权注入；
- `memory`/`tip` producer 的权限删除在本包一并生效（机制层），对应**通道退役**（producer 代码移除）属 E 包——两包在 `prompt_eligibility.py` 同文件分批：本包先改 grant 判定（B 批次在前），E 包后删 producer（E 批次在后），避免一次改动跨越两包审批边界。

### B-D2 E12 err1210 → runtime rebuild/retry once

- 程序检测到 provider 1210 类协议序列化错误时，由 runtime 自己 rebuild request 并 retry once（前提：无副作用且协议安全）；
- retry 过程零 prompt、零模型可见文本；
- retry 失败 → 真实错误如实进入终态（UI/event），不再"programmatic user resend"。

### B-D3 E15 停滞 → 只留计数与成本边界（并入 tasks.md 组 3 重审）

保留（冻结项的价值部分）：

- 恢复类失败计数分支：键=工具名、忽略 ref 细节（tasks.md D3 口径），仅计失败，成功或穿插非恢复类调用即重置；
- 既有全等指纹计数路径不改写（并存不覆盖）；
- 阈值维持 3/5（`_STAGNATION_REMIND_AT`/`_STAGNATION_BREAK_AT`）；
- 熔断：达 5 次 → run 以 `stagnation` 结束原因硬 BLOCKED 终止；
- `recovery_fail_streak` 收敛路径留痕（事件 detail）。

取消（总审计 §11.1/§11.3 撤销）：

- `[停滞提醒]` 注入（3 次阈值处的提醒消息不再进入模型上下文）；
- 熔断终止时的"三路径替代策略"文案（改用 search_evidence 换路 / get_tool_schema 复核 / 基于已有回执作答——全部取消）；
- 终止时模型可见面只留**事实**：结束原因（stagnation：连续 N 次失败、ref 各不相同）——以 run 终态元数据呈现，不注入建议性自然语言；
- tasks.md 组 3 的 C4 两文案函数**不再实施**（B5 规划作废）。

> 边界说明：现有存量 identical_args 路径的提醒注入同样按本决策取消（同一条 §11.3 判定），不只针对恢复类新分支。

### B-D4 E16 空搜索 → 零附加

真实空结果本身已是事实；删除第二层建议层。

### B-D5 E17 overflow → runtime compact/route/end + UI

- 到达物理窗口边界：程序按真实 provider window 与用户 cost policy 做确定性 compaction 或终止；
- 当前 unresolved protocol/active user evidence 不得被裁断（总审计 P1-12）；
- compact occurrence 只 telemetry（event）；
- 模型可见面零 overflow 教程、零"继续/压缩"询问。

### B-D6 E18 max rounds → 硬边界直接结束/暂停

- 到达 round 硬限 → 结束/暂停，UI 显示，等待用户继续指令；
- **第 N+1 轮 LLM 调用 = 0**（不再花一轮问模型"是否继续"）；
- 用户显式"继续" → 开新 run 并按 E 包 task_active 授权恢复任务身份。

### B-D7 E19 runtime notices 不进 `sess.messages`

- 停滞计数、熔断、overflow、retry、fallback、维护状态等 runtime 通知只落 event/status/UI/audit；
- `sess.messages` 中程序创作通知 chars=0；
- 与 A 包 Rule 21 联动：本决策落地后"告诉模型忽略程序垃圾"的规则失去存在必要（Rule 21 删除条件之一）。

### B-D8 E32 repair-before-lifecycle

event/session 修复先于生命周期判定执行（修复是确定性机械控制，不产生模型可见语义）。

### B-D9 残余注入面完整性原则（r-p-r P1-6 收编）

E19 退出后仍可能有极少数程序摘要进入模型面（如用户显式授权恢复时的冻结任务身份段）；这些残余面适用：**注入前完整性检查；不完整的进度摘要只保留一句事实 + 取回路径，不给半截话**。

### B-D10 exact duplicate suppression 收窄

- 仅对**可证明确定性/幂等且外部状态未变化**的工具启用同参拦截；
- 轮询/实时查询类合法重复放行；
- 全局"同参第二次必拦"取消。

### B-D11 `PROGRAM_FINAL_PROTOCOL_BOUNDARY` 只留协议形状（P2-2）

- 保留 role-shape 兼容（避免 `user -> program-assistant -> user` 删除后 provider 报错）；
- provider 允许时使用最小 neutral placeholder / provider-specific serialization；
- 中文语义标签（`[程序终止边界·无模型回答]`）从模型可读面消失，分类为 `PROTOCOL_ONLY`。

- provider 400/1210 不增加（B-D2 retry 反而应下降）；

## 7. 风险与不可删清单核对

### 7.1 风险

| 风险 | 缓解 |
|---|---|
| 无提醒后弱模型死循环烧轮数 | 计数熔断保留（B-D3）：3 次阈值事件留痕、5 次硬终止——机械边界比口头提醒对弱模型更有效（r-p-r §0 实证：6+ 次相同调用时提醒无效） |
| E12 retry once 对有副作用请求的重放风险 | 前置条件"无副作用且协议安全"；不满足则不 retry，走真实终态 |

| current_turn grant 移除误伤合法恢复场景 | 用户显式授权路径独立于 current_turn（E 包 input-side resolver）；shadow 观察期核对 would_have_granted 与实际用户意图的一致率 |

| engine.py/build.py 并行改动冲突 | 实施期以当日 git status 复核，协调窗口（沿 tasks.md R-2/R-3 红线纪律） |

## 1. 目标与范围

### 1.1 目标

把模型规则从"系统运维手册"降回"最小语义契约"（总审计 §12-A）：

1. 建立新版最小 system contract（对齐总审计 §8.2 KEEP-MINIMAL 四条原则）；
2. 删除"任务开始或规则存疑时必读 ai_rules.lite"的强制规则读（总审计 P1-1）；
3. `ai_rules.lite.md` 从"通用模型执行规则"重分类为**按需 Agent/维护 playbook**；
4. 逐项删除全局规则中的元任务与运维手册条款：每轮自查、action-chain 闭环、最终回答报工具名、`[[memory]]` 强制格式、cache 纪律、长输出分段、平台操作手册（DSH/CodeArts/interop）、经验前置查询、中断恢复模型职责、Goal/checkpoint 通用纪律（总审计 P1-3~P1-6、P1-8、P1-10，§7 规则逐项表）；
5. 重写 RULE-AI-00 的职责边界表述（总审计 P1-2）；
6. 治理 `SYSTEM_PROMPT_EXTRA` 绕过通道（总审计 P2-4）。

1. **不动程序注入机制**：prompt_eligibility、控制面闭环、tool result 事实化、trace/cache/fallback、潜在语义通道退役，分别属 R8.24-B/C/D/E；

3. **不做 CORE 工具可见性变更**：CORE9 去留与词法路由属 R8.24-E 的 A/B 评估；
4. **不新增性格化/风格化 prompt**：本包是减法，不是措辞优化；
5. **不修改 `docs/ai_rules.md`（full SoT）的历史证据部分**：仅同步标记 lite 中已迁移条目的去向指针；

## 3. 设计决策

### A-D1 最小语义契约（新版 system contract 基底）

采用总审计 §8.2 四条：

```text
1. 当前用户输入是当前任务的最高语义来源。
2. 不编造你无法直接知道的文件/工具/实时事实；需要时取真实工具结果。
3. 工具/程序失败如实说明，不把失败当成功。
4. 不越过安全/授权边界。
```

provider-specific wire 规则（如 reasoning_content 序列化约束）不再让模型"记住"，由 adapter 保证（从 `_BASE_PROMPT` 移出，落点归 provider adapter 层，实施期与 B 包协调归属，避免两包重复搬运）。

### A-D2 删除强制规则读；ai_rules.lite 重分类

- 删除"任务开始必读"指令（A1）；
- `ai_rules.lite.md` 重定位为 **Agent/维护 playbook**（维护 run、operator 场景按需读取；普通用户 run 零引用）；
- 特定 workflow 需要规则时由 skill/tool schema 注入局部说明，不所有任务共用；
- 保留"规则存疑时可以查询"的**能力**（工具可发现），删除**义务**（必读指令）。

### A-D3 方法层①~⑥ 移出全局

状态追踪/前置自问/假设先行/增量推理/结论固化/工具轮三句，全部迁入 long-task/research skill（r-p-r P2-6 认可其价值但判定为任务风格非系统不变量；总审计 P1-3 同判）。不要求模型暴露/格式化 reasoning，只以外部结果衡量（正确性、完成率、重复动作率）。

### A-D4 Rule 8（动作链完整 + 回答必须提工具名）→ 纯 offline 指标

`tool_used / chain_complete` 留在离线评测 rubric，不进 production prompt；用户回答只说明真正影响结果的动作。

### A-D5 Rule 5 `[[memory]]` 通道删除

- 默认答案不含内部 memory 协议；
- 用户显式要求记住 → 明确 memory 工具/控制面；
- 自动提取器如保留，只作后台存储候选，**不获得未来 prompt 权限**（此句与 E 包 E07 退出衔接：E 包管程序注入面，A 包管规则要求面）。

### A-D6 Rule 9 模型切换手册下沉

`switch_model` 自身完成目标存在性/能力/状态验证并返回事实；用户显式选定模型失败保持 strict；default fallback 程序自动处理但受 capability floor 约束（floor 机制属 R8.24-D）；fallback 结果走 UI/status/audit，不生成下一轮 prompt notice（后半句落点属 R8.24-B E19）。

### A-D7 平台手册下沉（Rule 13 DSH / Rule 15 CodeArts / Rule 14 interop）

- DSH/CodeArts：移到对应 tool schema/skill；
- interop：删除旧"自动注入"语义文本（R8.13 已取消该机制），重写为 explicit user accept / retrieval；
- 同步覆盖 r-p-r P2-1（Web 面板操作手册移 SoP）。

### A-D8 Rule 17 长内容分段 → transport/UI

模型不再每篇长文机械 `1/N + 继续/跳过/总结`。

### A-D9 Rule 18 经验前置 → on-demand retrieval

删除"调工具前先查经验"与"程序自动检索经验末尾注入"，对齐 R8.15 experience on-demand。

### A-D10 Rule 19 中断恢复模型职责删除

对齐 R8.19 program-side reconcile；模型不再读 event log 恢复自己（修复机制属 R8.24-B E32）。

### A-D11 Rule 20 Goal/checkpoint → agent harness/skill

Goal 机制保留，但归 agent/harness workflow，不再是所有 LLM 用户请求的通用思考规则（`task_active` 注入面属 R8.24-E）。

### A-D12 Rule 21 程序反馈语义：过渡期保留，目标删除

B/C 包完成"程序垃圾清出 provider history"后删除本条；本包仅在 lite playbook 中标注其过渡属性与删除条件。

### A-D13 RULE-AI-00 重写

替换旧表述"压缩/重试/摘要/模型切换等决策权归 AI"为新二分（总审计 P1-2）：

- **用户/模型负责**：用户真正想要什么、证据怎样解释、当前结论、语义策略/研究路径、是否接受改变任务语义的替代方案、需授权的高影响动作；
- **程序负责**：provider wire 适配、tool call pairing、无副作用 bounded retry、context window 物理适配、lossless archive、interruption reconcile、timeout/round/cost limit、input provenance、observability、语义等价 fallback/route（受 capability floor 与用户模型选择约束）。

### A-D14 SYSTEM_PROMPT_EXTRA 治理（P2-4）

二选一（倾向方案 2）：

1. 删除通用 free-text escape hatch；
2. 只接受 operator-owned、版本化、带 provenance/hash/大小上限的静态 policy bundle。

### A-D15 §7 规则逐项表的归并执行

总审计 §7 全表（方法层①~⑥ + 规则 1~21）按原表"建议/去向"执行；本包文档不逐条复制，实施时以总审计 §7 表为验收清单，每删一条在 git commit 中引用对应行。r-p-r P2-2/P2-3/P2-4 的"压缩/拆分/脚注化"细粒度方案被"整条删除或下沉"的更彻底判定覆盖，仅当某条判定为"保留最小原则"（规则 1/7）时参考 r-p-r 的压缩建议。

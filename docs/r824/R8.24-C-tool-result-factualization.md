## 1. 目标与范围

### 1.1 目标

把工具回执从"事实 + 程序建议"还原为"纯事实"（总审计 §12-C）：

1. **generic failure guidance 退出 content**：`_FAILURE_GUIDANCE`、`ToolRecoveryAdvice.render()` 的 `[恢复策略]...next=...`、`guidance_extra` 经验建议全部退出模型可见正文；
2. **typed recovery 只留 metadata**：恢复分类保留在 metadata/control-plane；完全确定且无副作用的恢复动作由 runtime 自动执行；
3. **evidence capsule metadata-only**：`complete=true` 时 capsule 从模型 content 消失（完整 metadata 只落审计）；`complete=false` 时最多留一行稳定短事实行；
4. **distill guidance 退出**：`_DISTILL_GUIDANCE`（"继续推理前先提炼/写 memory/search_archive 取回"）删除；
5. **截断结果只留 minimal fact**：`complete=false / omitted=true / recovery_ref`；
6. **并入 P0-B 剩余部分**：`read_file` 的 `evidence://` 前缀短路（置于 path_registry 否定帧登记之前）；
7. **并入 P0-A 替代路线**：capsule 退出后，`read_evidence` 系可见性走按需/control-plane，不做胶囊文本驱动解锁。

### 1.3 不做什么（边界）

1. **不动 evidence 存储层**：`evidence.py` BlobStore/Ledger/快照/归档机制零改动（沿 tasks.md R-4 红线）；本包只改**模型可见投影面**；
2. **不删除恢复能力本身**：ref resolver、`read_evidence` 恢复路径保留且必须可用——改的是"教学文案常驻"为"按需可发现"；

## 3. 设计决策

### C-D1 模型可见 tool result 字段白名单

回执正文只允许：

```text
status
actual output / actual error
complete=true|false
objective failure_class / retryable（如确为客观属性）
ref（仅在内容不完整且需要恢复时）
```

（总审计 P0-2 建议清单，逐字段采纳。）

### C-D2 程序建议层退出 content

`_FAILURE_GUIDANCE` / `ToolRecoveryAdvice.render()` / `guidance_extra` / `_DISTILL_GUIDANCE` 全部退出模型可见正文；typed recovery 分类本身保留在 metadata/control-plane。

### C-D3 确定性恢复 runtime 自动执行

恢复动作**完全确定且无副作用**（如已知虚拟 ref 的 deterministic resolver）→ runtime 直接执行，不需要模型参与；否则模型基于事实回执自行判断（不写建议）。

### C-D4 capsule metadata-only

- `complete=true`：capsule 从 model content 消失；完整 metadata（ref/source/coverage/projection/complete/recover）只落审计/事件；
- `complete=false`：模型正文最多一行稳定短事实行：`result_truncated=true; ref=evidence://...`；
- recovery path 说明由 tool schema / `get_tool_schema` / ref resolver 承载，不在每条回执重复教学；
- 投影/capture failure 不得写 "Do not automatically re-run..." 类程序指令（C4）。

### C-D5 截断结果 minimal fact

统一截断事实三元组 `complete=false / omitted=true / recovery_ref=<exact handle>`；ref resolver 负责正确路由，不要求模型先分类"这是哪一种截断"（总审计 P1-9）。原 Rule 11 的 `head/tail/grep -m` blanket 禁令删除（用户明确只要日志尾部时 `tail -n` 合法；规则文本删除动作在 A 包）。

### C-D6 回执模板治理（r-p-r P1-5 收编）

- 程序生成回执模板中**不可执行工具名 = 0**：生成前对注册工具表做存在性校验；
- "若已注册"类含糊措辞清除；
- 静态扫描测试常驻：模板构造点出现 `recover=` 类指名片段时，被指名工具须已注册且在指名场景可见（沿 tasks.md T8 思路，白名单随 capsule 退出收敛为：截断事实行 + read_file 短路说明两处）。

### C-D7 read_file `evidence://` 短路（并入 P0-B 剩余）

- 落点：execute 内 path 取值后立即判定 `path.startswith("evidence://")`，**先于 path_registry 否定帧登记**（防 `evidence://` 被登记为"永不存在的物理路径"污染，次生伤害修复）；
- 返回参数误用类 FAILURE（"调用方式错误"而非"环境异常"）；
- **文案按本包事实化原则重审**（对 tasks.md 2.3 四要素指引的修订）：保留**协议事实**——①这是 Evidence 引用非文件路径；②对应工具为 read_evidence；③可经 get_tool_schema('?evidence') 发现；④确需物理文件可 execute_command 绕行（保留 scheme 场景）。删除**劝导话术**（"请先""建议""推荐"句式）。四要素本身是路由事实，符合白名单精神，予以保留但改为陈述式；
- 置位 `short_circuit_kind="misuse_evidence_ref"`，事件落盘（沿 tasks.md 2.4 设计）；
- **衔接备注**：D2 status 门（失败不 capture、`evidence_capture_skipped` 字段）已例外放行独立实施；本包批 3 实施时验收断言与 D2 放行项合并核验（失败回执零新 ref 零胶囊由 D2 保证，本包不再重复建设）。

### C-D8 read_evidence 可见性替代路线（并入 P0-A 重审，弃胶囊驱动解锁）

capsule 退出后，`recover=read_evidence` / `[evidence]` 锚文本从模型可见面消失，P0-A 的"扫描胶囊文本驱动解锁"方案**失去输入且方向不符**（以程序喊话文本作为可见性触发，属胶囊驱动的延续）。替代路线三条（终判归 R8.24-E A/B，本包定义约束）：

1. **CORE 常驻/半常驻**：恢复三件套（read_evidence/list_evidence/search_evidence）或 list_evidence 进入 CORE（E 包 E1 三态评估）；
2. **get_tool_schema 按需发现**：模型遇到 `ref=evidence://` 事实行时，可经 get_tool_schema 检索到恢复工具（零常驻成本）；
3. **control-plane 截断轮 schema 提示**：截断事实行在场的下一轮，schema 投影层（非 prompt 文本层）附带恢复工具名——机制上是"状态驱动的 schema 可见性"，不是"回执文本驱动"。

本包约束：无论 E 包终判选哪条，**可见性机制不得依赖扫描模型可见回执文本中的程序喊话锚点**。

### C-D9 evidence_reuse 命中必须内联正文（r-p-r P1-2 收编）

- evidence_reuse 判定 `current_evidence_covers_request` 时**必须内联正文**进回执；
- 无法内联 → status 标 failure 而非 success（静默降级禁止——"信息不丢失"核心承诺）；
- 此为回执**事实完整性**要求，与白名单字段不冲突（正文即 actual output）。

### 4.2 能力不退化硬门（总审计 §13.2）

- **tool discovery 成功率不下降**（capsule 退出后恢复工具仍可发现——C-D8 路线 + E 包 A/B 验证）；
- 当前 unresolved tool follow-up 可正常继续（截断结果可经 ref 恢复）；
- 任务完成率不得下降；factual hallucination 不增加；
- tool protocol error 不增加。

### 4.3 应改善指标（§13.3，本包主责项）

- memory/evidence 元数据占比大幅下降（16.87%→~0%）；
- duplicate tool call rate 下降（误导性 `recover=` 提示消失，死循环诱饵根除）；
- 平均模型可见 program chars 下降 ≈411K chars 量级的会话面；
- 弱模型答非所问率下降（不再被回执教学带偏）。

## 7. 风险与不可删清单核对

### 7.1 风险

| 风险 | 缓解 |
|---|---|
| capsule 退出后模型不知道如何恢复截断结果 | C-D8 三路线兜底 + E 包 A/B 验证 discovery 成功率（13.2 硬门）；过渡期路线 2 先行 |

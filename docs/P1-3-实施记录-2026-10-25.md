## 2. 实施清单与每处改动摘要

### 2.1 `src/llm_loop/factory.py`（设计 §4.1）

- 新增 `_DEFAULT_WORKSPACE_ROOT_ENV = "LFL_DEFAULT_WORKSPACE_ROOT"` 常量与 `DefaultWorkspaceRootError(RuntimeError)`。
- 新增 `_resolve_default_workspace_root()`：
  - 优先级：`LFL_DEFAULT_WORKSPACE_ROOT` env（strip 后非空）> `~/lfl-workspace`（`Path.home()`，expanduser+resolve）；
  - env 显式设置但目录不存在 → `DefaultWorkspaceRootError` fail-fast（显式配置路径不自动创建，防手误静默建目录/漂移）；
  - env 指向存在目录 / 缺省值 → 幂等 `mkdir(parents=True, exist_ok=True, mode=0o700)` 后返回（不改已存在目录权限，测试断言 0755 保持）；
  - mkdir 抛 OSError（不可建）→ 包装为 `DefaultWorkspaceRootError` fail-fast。
- `_activate_default_workspace` 调用点改写：
  - `workspace_root is not None` → 显式参数最高优先（原语义不变）；
  - `else` 分支由 `Path.cwd()` 改为 `_resolve_default_workspace_root()`——**默认根不再跟随 cwd**（P1-3 迁出代码根的安全目标本身）；
  - 临时区防注册逻辑保留（`_cwd_in_system_temp(root)` 判定对象由 cwd 变为解析出的根；`LFL_ALLOW_TEMP_WORKSPACE` 逃逸阀与 `_registry_is_production_default` 双条件不变）；
  - 已有 current 的激活路径、`migrate_legacy_sessions`、`WorkspaceMigrationConflictError` 容错均不变。
- `LFL_WORKSPACE_ROOT`（.env 传入的代码身份锚）语义零改动：identity.py enforce 链路未触碰，factory 中不读取该变量做默认根。

### 2.3 `scripts/migrate_workspace.py`（新增，888 行，设计 §5 完整实现）

五子命令 + Phase 0 预检：

| 子命令 | 语义 |
|---|---|
| `backup` | `data/` 五项（workspaces.json、注册表锁 workspaces.lock、sessions/&lt;旧键分区&gt;、sessions/.identity、artifacts/records/&lt;旧桶&gt;）→ `--backup-root`（缺省 `.backup/`）下 `workspace-migration-<ts>/`（批量 copy + manifest.json 原子落盘 + SHA256 清单；中断可留无 manifest 的部分备份目录）；无轮转清理功能（历史备份需手工清理） |
| `rehearse` | `/tmp` 镜像副本上执行核心迁移 + 六项校验，真实 `data/` 只读（仅 backup 副本读取）；PASS/FAIL 报告 + 审计落盘 |
| `migrate` | 需 `--yes`；Phase 0（五项）通过后 `run_core_migration` 原地执行；中断恢复=幂等重跑 |
| `rollback` | 就地逆向三步（rename_sessions_partition 逆向 + identity owner 逆向改写 + switch_registry 切回旧根；新工件桶保留不删，历史引用两侧均可水合）；不依赖 backup 副本；幂等重跑安全 |
| `verify` | 六项校验对 `data/` 只读断言；`--json` 机器可读 |

- **Phase 0 预检**：服务全停（manifest pid + 心跳文件）、web/feishu 端口空闲、无 `.run.lock`、磁盘余量 ≥ 源体积 2 倍、root 冲突预检。
- **幂等语义（§5.6，每步独立判定）**：改名（源不在→already_done；目标已在且逐字节一致→already_done；同名异内容/文件集不一致→`WorkspaceMigrationConflictError`）；identity 改写（owner 已是新键→跳过）；记录桶复制（目标同名同内容→跳过，同名异内容→冲突）；注册表（current 已是新键→already_current）。

## 3. CLI cwd 语义边界说明（补充要求 1）

**结论：CLI cwd 语义保留，本波未改 `cli.py`，默认根分支不被 CLI 触发。**

- 链路事实（本波逐行核实）：
  - `cli.py:1153`（`prepare_environment`）：`workspace = Path(args.workspace or values.get("LFL_WORKSPACE_ROOT") or Path.cwd())` —— CLI 自行从 `--workspace` 参数 / `LFL_WORKSPACE_ROOT` env / cwd 解析出**显式** workspace 绑定；
  - `cli.py:1516-1517`（`application_main`）：`main(remaining, workspace_root=bindings["LFL_WORKSPACE_ROOT"])` —— installed 入口**恒显式传** workspace_root；
  - `cli.py:370`：`build_engine(settings) if workspace_root is None else build_engine(settings, workspace_root=workspace_root)` —— 因上一条恒非 None，经 CLI 的引擎装配**永不落入** `workspace_root=None` 分支；
  - `cli.py:385` `engine._cli_workspace = workspace_root or str(Path.cwd())` 仅展示元数据，不参与装配。
- 因此 `factory._resolve_default_workspace_root()`（本波新增）只服务非 CLI 装配路径（服务默认启动/测试等未显式传参场景）；CLI 的「cwd 回落」是**真人显式意图的产品语义**（安装态在任意目录敲 `lfl`，workspace=cwd），与「AI 默认可写区迁出代码根」是两个正交语义，本波严格保留前者。
- 该边界已由 `tests/unit/test_cli_input_contract.py` 两个新用例固定（见 §2.11）：若未来 `cli.py` 改为隐式落默认根（丢显式传参），测试红灯。

## 4. `scripts/verify_install_distribution.py` 核查结论（补充要求 2）

**结论：该脚本不依赖 factory 默认工作区根解析，P1-3 改动对其零影响，无需修改。**

核查方式：grep（`workspace|cwd|getcwd|Path.cwd|lfl-workspace|WORKSPACE`）+ 全文精读（168 行）。证据：

1. 全部 `lfl` 子进程调用（`--version`/`check-install`/`paths`/`chat --help`/`event-inventory`，:131-138）经 installed 入口 `application_main` → `prepare_environment` → `main(workspace_root=...)` **恒显式传参**（§3 链路）；无 `--workspace` 且无 env 时走 `cli.py:1153` 的 **cwd 回落**（CLI 产品语义，本次未改，且 cwd=脚本显式 `cwd=workspace` 传入的 tmp 目录）；
2. web 冒烟（:141）：`[lfl, "--workspace", str(selected), "web"]` 显式 `--workspace`；:87 断言 web current == selected（显式 workspace 绑定正确性），不涉及默认根；

4. :143 `assert not (workspace / "data").exists()`（"State leaked into arbitrary CWD"）：`LFL_HOME` 显式设置（:115）使 DATA_DIR 落 state/data，与默认根无关。

即：该脚本的 workspace 断言全部经 CLI 显式参数链路，`LFL_DEFAULT_WORKSPACE_ROOT`/缺省 `~/lfl-workspace` 分支（factory `workspace_root=None`）在脚本任何路径都不会被消费。

# 0. 立项定性与范围边界

## 0.1 立项定性

目标产品是一个能连续听说、理解当前共享页面、接受途中纠正，并可靠完成实际任务的 LFL 工作助手。

首版采用「实时会话 + LFL 任务执行」协作方式：**实时模型**处理低延迟听说与视觉指代；**现有 LFL 引擎**负责任务、工具、授权、证据、恢复。首个可验收版本覆盖连续语音、按需页面关键帧、一个真实只读工具、播放打断、同会话任务续接与断线恢复。

本规格不是新增执行框架，而是为现有 Web/任务进程边界**补齐「连续听说 + 页面视觉 + 真实工具桥接 + 三类停止 + 同会话续接/恢复」的显式业务能力**，并保证媒体能力不削弱、不旁路既有 LFL 任务、授权、配额、队列与证据语义。

## 0.2 首版必备 / 后续扩展 / 明确不承诺

| 类别 | 内容 |
| --- | --- |
| 首版必备（P0 覆盖） | 中文连续语音、可编辑转写、语音播报、用户开口时打断播放、显式任务停止按钮、当前页面关键帧、真实只读工具、已有会话绑定、可见任务状态、重连、清理资源、指标记录、文字降级；**本地 Provider 栈**（`mlx-audio` OpenAI 兼容 ASR/TTS + Ollama 本地文本 + 本地流式 TTS；音频输出与工具调用由客户端/桥接编排，见 RTM-CAP-11…14、RTM-TOL-16、RTM-PLY-07） |
| 后续扩展（不构成首版前置） | 相机连续观察、电话/SIP、多说话人分离、复杂音频事件识别、可写工具（M4）、原生移动端后台音频、跨设备接力 |
| **观察项（v1.2 新增）** | 原生全双工语音对话（如 `NemotronLabs-VoiceChat-11B-4bit`）：本机实测**不达标**（中英输入返回同一段英文寒暄、延迟 4–6× 实时、双工文本跑偏、无 `function_delta`）→ **不作首版主链路**，列为观察项并记录退出条件（RTM-CAP-13） |
| 明确不承诺 | 硬实时控制、音视频会议平台、高帧率通用视频分析、机器人控制；首版不引入 SFU、独立消息中间件、全局多 Agent 调度系统、新的通用授权体系 |

## 0.3 需求编号与 EARS 约定

- 编号规则：`RTM-<GROUP>-<NN>`，`GROUP` 为业务分组助记符（SES/AUD/INP/VIS/PLY/STP/TOL/IDN/REC/LIF/CAP/BUD/OBS/A11Y/SEC/RET/CMP/PRF/EVD/SCN）。
- EARS 五类标注：
  - **Ubiquitous（U）**：系统必须……（始终成立，无触发条件）
  - **Event-driven（E）**：当〈事件〉时，系统必须……
  - **State-driven（S）**：在〈状态〉期间，系统必须……
  - **Unwanted（W）**：若〈触发〉，则系统不得……／系统必须……
  - **Optional（O）**：若〈可选特性〉启用，则系统必须……
- 每条需求固定字段：**需求编号 · EARS 类型 · 优先级（P0/P1） · 阶段（M0–M4）**、需求描述、验收标准、追溯（R 编号 / 设计书小节 / 场景 U / 测试 T）。
- 优先级定义：**P0** = 首版正确性或交付必需；**P1** = 首版体验、可靠性及质量要求。**P1 不等于选做**：P1 条款同样属于首版交付承诺，不得因「非 P0」而跳过、降级为背景任务或不计入验收；两者的差别仅在触发顺序与门禁强度，P1 仍须达到对应阶段的验收条件。**M4 可写工具条件单独标示，不能倒算首版已支持写操作**。

## 0.4 机械控制准入说明（对齐 `AGENTS.md` Admission asymmetry）

本规格新增的机械控制**只用于模型无法替代的事实边界**：连接归属、身份、字节格式、精确代次、已提交状态、资源上限与去重。语义理解、任务取舍、答案组织继续由模型承担；实时层**不得**另造语义黑名单、审批平台或启发式拦截。凡涉及可调参数与降级入口者（如重连次数、采样上限、按住说话、静音播报），需求均要求**可见且有出口**。

3. **同步修订**：主规格条款变更时，必须在同一次修订中同步 SDD 归档对应处；两文共享同一 `RTM-*` 编号，`RTM-*` 的增删改只在主规格发生。

## 0.7 追溯与实施组织（v1.1 新增）

1. **163 条用于追溯（v1.2）**：`RTM-<GROUP>-<NN>` 编号与 R01–R20、T01–T24、U1–U5 的追溯矩阵保留不变；v1.2 新增 10 条（CAP-11…14、INP-09、TOL-16、PLY-07、SEC-08、OBS-09、EVD-06）并登记入矩阵，用于评审、缺口核对与验收映射。
2. **实施按用户可运行的闭环组织**：实施任务应组织为「一个真实语音链路 → 本地打断 → 同会话只读工具 → 页面视觉/联合验收」等可运行闭环，**不要求**为 163 条各拆一个功能点或各自设一道检查门槛。
3. **首个执行单元仍为 M0**：在隔离候选上核实真实 Provider 能力与接口，先完成一次「连续听说 → 本地打断 → 同会话只读工具」的最小探针；M0 结论若推翻设计假设，先修订对应裁决与验收，不强行套用接口。

| **EVD-06（新增）** | —（四类证据未含服务级） | **服务级与浏览器链路证据分级**：服务级已实测 ≠ 浏览器链路验收；浏览器采集/播放/VAD/打断未接通时，M1/M3 相关条目**未验收** |
| CAP-01 | 固定一个实测 Provider 能力档案（默认远端实时） | 能力档案**按本地栈冻结**：记录 `mlx-audio`/Ollama 版本与接口、模型与许可、服务级实测条件；**撤销**「必须为远端实时 Provider」的默认假设 |
| CAP-03 / CAP-04 | 缺项降级、版本协商失败显式 | 缺项包含**浏览器链路未接通**与**观察项不达标**；降级标识须区分「服务级已通、浏览器未测」 |
| CAP-05 | 只实现一条媒体传输（WebRTC 优先，或 WS 代理） | 本地栈下采用**本地 WS 转写 + 本地 HTTP/流式 TTS**（不引入 WebRTC）；协议接口仍预留替换，不为未选 Provider 写空适配器 |
| CAP-07 | 无实时 Provider 凭据不得宣布实时完成 | 修订为：**受信浏览器实时链路未接通**（无论云端凭据缺失或本地未接线）时不得宣布实时完成；本地方案下凭据不再是阻断项，**浏览器链路未接通**成为新的阻断项 |
| CAP-09 | 级联链路按连续输入/流式输出/打断/端到端延迟**实测**判定 | 补入**本机实测依据**：级联本地链路（ASR→Ollama→TTS）服务级已打通，按实测维度判定；观察项（VoiceChat）单独列出 |
| AUD-01 | 采样率/声道/编码依 Provider 协商 | 本地栈下明确**输入 16k PCM**；参数仍来自能力档案（CAP-14），不硬编码 |
| SEC-01 | 长期 Key/恢复令牌只在服务端 | 本地栈下长期 Key 语义调整为：**本机服务凭据/模型许可**仅服务端保存、本机服务不暴露；远端「恢复令牌」在无远端 Provider 时相应不适用 |
| REC-05 | Provider 连接过期按官方恢复机制续接 | 本地栈无远端恢复令牌时，**恢复**改为本地会话重建与已提交事实核对（沿用 REC-03/07/10），不得假设远端恢复能力 |
| OBS-05 | 客户端同一单调时钟测延迟主指标 | 补：**服务级与浏览器链路分别记录**，服务级基线不得与浏览器链路口径混算 |
| PRF-01…04 | 性能目标区分「已测」与「达标」 | 补：**「已测」的测量必须是浏览器链路端到端**；服务级实测（12.23 s）只入 OBS-09 基线，不得作为 PRF 达标记 |

# 2. 会话建立与鉴权（RTM-SES）

**RTM-SES-01** · `Event-driven` · `P0` · `M1`
**需求**：当用户在界面主动点击「开始语音」时，系统必须**先完成本地设备与权限准备，再建立远端实时会话**，且只在服务端就绪后才开始上传媒体。
**验收**：拒绝麦克风/无设备时给出明确缺项与恢复入口，不发生媒体上传（T02）；服务端未就绪时无媒体字节出端。
**追溯**：R01；§3.3、§6.4；T02。

**RTM-SES-02** · `Ubiquitous` · `P0` · `M1`
**需求**：系统必须复用既有登录身份与 LFL 会话/workspace 归属校验来授权媒体入口，且每个媒体会话必须绑定当前用户、当前 LFL 会话与 workspace。
**验收**：越权 `session_id` 不可读取或控制；归属检查生效（T16、T17）。
**追溯**：R01、R12；§6.4、§9.4；U4；T16。

**RTM-SES-03** · `Unwanted` · `P0` · `M1`
**需求**：若媒体入口鉴权失败（会话不属于该用户或登录失效），则系统必须停止受影响的媒体/工具路径、保留可恢复文本，且**不得**新建独立身份系统。
**验收**：返回 401/403；受影响路径停止，文本入口保留（T16）。
**追溯**：R01、R12；§4.1 Q04、§9.4；T16。

**RTM-SES-04** · `Event-driven` · `P0` · `M3`
> 阶段说明（v1.1）：页面共享的**完整要求归 M3**（与 VIS 组联合验收），先只在 M1 预留触发入口，不阻塞首个音频闭环。
**需求**：当用户开始共享页面时，系统必须由**用户手势**触发并再次取得权限，且显示实际共享来源与最近画面时间；来源切换或权限拒绝必须显示对应状态。
**验收**：无用户手势不启动共享；共享不可用时提供截图入口（T02、T17、T20）。
**追溯**：R01、R18；§3.3、§8.3、§9.4；T17、T20。

**RTM-SES-05** · `State-driven` · `P0` · `M1`
**需求**：在媒体会话已建立期间，系统必须按 `opening → ready → reconnecting → ready / failed → closing → closed` 独立记录连接状态，并**分别**记录麦克风开关、播放状态与任务状态，禁止用单一 `streaming` 布尔值同时代表四种事实。
**验收**：连接 ready 不等于麦克风已授权，也不等于任务已派发（T21；§7.5）。
**追溯**：R02、R08、R18；§7.5；T21。

**RTM-SES-06** · `Ubiquitous` · `P0` · `M1`
**需求**：系统必须只接受服务端决定的 Provider 配置，**不得**接收浏览器提交的任意远端 session 或长期 Key。
**验收**：凭据扫描无长期 Key 出现在前端/URL（T16）。
**追溯**：R12、R13；§6.2、§6.4；T16。

**RTM-SES-07** · `Event-driven` · `P0` · `M3`
**需求**：当控制消息会改变状态时，系统必须携带 `event_id` 与 `connection_epoch` 并返回接收回执及最终状态；错误必须以 401/403（身份/权限）、409（代次/所有权冲突）、429（额度/容量）、503（依赖不可用）的具体语义返回，**不得**把所有错误统一包装为成功的「正在处理」。
**验收**：错误码语义可区分；改变状态的消息均可关联回执（T02、T16）。
**追溯**：R13、R15；§6.4；T16。

# 3. 音频采集与轮次（RTM-AUD）

**RTM-AUD-01** · `Ubiquitous` · `P0` · `M1`
**需求**：系统必须使用浏览器已支持的媒体接口进行连续采集，采样率/声道/编码依所选 Provider 协商，**不得**固定套用其他后端的 PCM 参数。**v1.2 本地栈补充**：本地栈输入**必须为 16k PCM**（`input_audio_format=pcm16`，16 kHz 单声道）；浏览器侧采集须按此重采样后再送入本地转写会话，参数仍来自能力档案（RTM-CAP-14），**不得**在代码中散落硬编码（如把采样率写死在两处而不一致）。
**验收**：连续采集可用且为 16k；参数来自能力档案而非散落硬编码（T01、T21、T25）。
**追溯**：R02；§8.1、§6.2；T21、T25。

**RTM-AUD-02** · `Optional` · `P0` · `M1`
**需求**：若浏览器提供回声抑制/降噪/自动增益且 Provider 能力允许，则系统必须按能力启用，并在**外放与耳机**两种场景实机验证，**不得**仅凭 VAD 开启就宣称可双向交互。
**验收**：外放时不把模型声音变成用户任务（T06）。
**追溯**：R02；§4.2 Q27、§8.1；T06。

**RTM-AUD-03** · `Ubiquitous` · `P0` · `M1`
**需求**：系统必须归一化 Provider 提供的 `speech-start` / `speech-end` / `committed` 轮次事件，并**禁止**把固定静音阈值当作唯一中文断句策略。
**验收**：停顿、长句、中文夹英文、数字、专有名词、回声、环境噪声场景轮次正确（T01、T06）。
**追溯**：R02；§8.1；T01、T06。

**RTM-AUD-04** · `Event-driven` · `P0` · `M1`
**需求**：当模型正在回答时，系统仍必须继续采集新的用户语音，且播放输出**不得**被回声识别为新的用户任务。
**验收**：连续自然对话中采集不阻塞；无回声派生任务（T03、T06）。
**追溯**：R02；§4.2 Q27、§8.1；T03。

**RTM-AUD-05** · `Unwanted` · `P0` · `M1`
**需求**：若识别到**空音频或纯噪声**，则系统**不得**提交任务或派发工具；**有效长语音必须按可回显的语义轮次分段提交**（每段可独立回显与纠正），**禁止静默截断为尾部**；当输入超过**实际容量**（Provider 输入上限或运行缓存上限）时，系统必须**明确暂停采集或拒绝该段输入并说明原因**，同时**保留已确认部分**，不得丢弃已确认内容，也不得静默截断冒充完整。
**验收**：无空任务、无噪声工具派发；长语音分段提交且各段可回显；超容量时暂停/拒绝可见且已确认部分保留；长句无静默截断（T01、T06）。
**追溯**：R02、R03；§4.1 Q01、§8.1；T01、T06。

**RTM-AUD-06** · `Optional` · `P0` · `M1`
**需求**：若用户选择「按住说话」模式，则采集与输入必须按明确的**按下/松开**边界进行：**按下即开始采集**该轮输入，**松开即结束该轮输入**；系统**允许在松开后继续完成识别与提交**（松开只结束采集，不否决已完成的识别结果）。系统还必须定义**失焦**与**触摸取消**行为：当控件/页面失焦、或触摸/指针事件被取消时，必须结束当前输入轮次，保留**已确认并可回显**的内容，不得继续采集，也不得丢弃已识别的已确认文本。同时系统必须提供**关闭自动插话/切换按住说话**的出口，避免噪声造成永久停滞。
**验收**：按下开始采集、松开结束输入；松开后可完成识别与提交；失焦与触摸取消时结束本轮且保留已确认内容；按住说话可用；误停可恢复；无噪声工具派发（T06、T20）。
**追溯**：R02；§4.2 Q25、§8.2 M4 段；T06。

**RTM-AUD-07** · `State-driven` · `P1` · `M1`
**需求**：在浏览器自动播放受限、设备切换、蓝牙变化或音频上下文挂起期间，系统必须显示明确状态并提供恢复入口（如「点击播放」、设备选择）。
**验收**：播放受限给出「点击播放」入口；设备变化有状态（T02、T21）。
**追溯**：R02、R16；§8.1、§4.1 Q20；T02。

# 4. 输入提交与修正（RTM-INP）

**RTM-INP-01** · `Ubiquitous` · `P0` · `M2`
**需求**：系统必须严格区分三个转写阶段——`input.delta`（暂定字幕）、`input.final`（识别器完成）、`turn.committed`（服务端已接受并成功持久化），三个阶段**不得**混用。
**验收**：临时字幕不驱动任务；已提交输入恰一次进入队列（T01、T18）。
**追溯**：R03；§7.2；T01、T18。

**RTM-INP-02** · `Event-driven` · `P0` · `M2`
**需求**：当 `final` 多次到达时，系统必须按 `turn_id` 与修订号归并，且**只有一次已提交输入**进入现有任务队列。
**验收**：delta/final 重复时不产生重复任务（T01）。
**追溯**：R03；§7.2；T01。

**RTM-INP-03** · `State-driven` · `P0` · `M2`
**需求**：在输入尚未 `committed` 期间，识别文本**只能用于字幕显示**；工具派发必须等待该轮提交且能回显最终文本。
**验收**：临时/迟到识别文本不驱动工具（T18）。
**追溯**：R03、R07；§4.2 Q28、§7.2；T18。

**RTM-INP-04** · `Event-driven` · `P0` · `M2`
**需求**：当 Provider 提前请求工具调用（先工具事件、后转写）时，桥接必须暂存并关联轮次、等待提交条件；超时必须返回**明确的未执行状态**，**禁止**猜测文本。
**验收**：提交前不派发；超时可见（T18）。
**追溯**：R03、R07；§4.2 Q29、§7.2；T18。

**RTM-INP-05** · `Event-driven` · `P0` · `M2`
**需求**：当已提交输入之后用户提出修正时，系统必须生成新的 `correction` 事件并**追加**记录；未执行动作可被更新，**已执行事实不得改写或删除**。
**验收**：修正追加且旧事实不改写（T18、T05）。
**追溯**：R03、R09；§4.3 Q42、§7.2；T18。

**RTM-INP-06** · `Event-driven` · `P1` · `M2`
**需求**：当纠正当前运行任务时，系统必须走既有队列认领/插话机制，并**分别**展示「已接收」与「已生效」；**不得**从 Web 线程直接改写引擎历史。
**验收**：Run 代次一致；两阶段反馈可区分（T19）。
**追溯**：R03、R06；§7.2、§7.4；T19。

**RTM-INP-07** · `Unwanted` · `P0` · `M2`
**需求**：若 Provider 无可靠最终转写能力，则系统**不得**声称满足首版工具桥接要求，只能作为**明确标识**的纯语音聊天降级能力。
**验收**：能力标识正确；界面不伪装全功能（T02、T20）。
**追溯**：R03、R13；§7.2；T20。

**RTM-INP-08** · `Event-driven` · `P0` · `M2`
**需求**：当迟到识别到达时，系统**不得**反向改写已执行的输入，必须以追加修正确认。
**验收**：迟到识别不回溯改写（T18）。
**追溯**：R03；§4.2 Q28、§7.2；T18。

**RTM-INP-09** · `Event-driven` · `P0` · `M1–M2`
**需求**：系统必须对本地双 ASR 策略做**终稿校正**：增量流式 ASR（低延迟）产出的结果**只能作为 `input.delta` 实时显示**；句末/轮次结束时，系统**必须**用高精度 ASR（如 `Qwen3-ASR-0.6B-8bit`）对整段音频**重转写**，以其结果作为 `input.final` 并据此 `committed`；**禁止**把未校正的流式错字直接作为已提交输入或驱动工具。若高精度重转写不可用或超时，系统必须按**保守已确认边界**提交并标注精度限制，**不得**把流式错字冒充终稿。
**验收**：已提交输入来自高精度重转写；流式错字（如「语音链路→语音路」「克隆→克龙」）不进入已提交输入或工具派发（T01、T26）。
**追溯**：R03；§7.2；T01、T26。

# 5. 页面视觉与关键帧（RTM-VIS）

**RTM-VIS-01** · `State-driven` · `P0` · `M3`
**需求**：在用户主动共享页面期间，系统必须只采集**所选来源**的画面；页面截图**不等于 DOM 读取权限**——DOM 只能来自既有、已授权且目标精确的浏览器工具，**不得**读取任意外部标签页 DOM。
**验收**：无越权 DOM 读取；仅采集所选来源（T08、T16）。
**追溯**：R04、R12；§8.3；T08、T16。

**RTM-VIS-02** · `Ubiquitous` · `P0` · `M3`
**需求**：每个关键帧必须包含来源标识、`source_epoch`、捕获时刻、服务端接收时刻、宽高、选区及不可变内容引用。
**验收**：帧元数据字段齐全且可核对（T08）。
**追溯**：R04、R17；§8.3；T08。

**RTM-VIS-03** · `Event-driven` · `P0` · `M3`
**需求**：当页面来源变化、共享停止或页面代次变化时，系统必须更新该帧有效性，使其**不作为当前画面**使用。
**验收**：页面切换后绑定与当前状态可区分（T08、T17）。
**追溯**：R04；§4.1 Q13、§8.3；T08。

**RTM-VIS-04** · `Event-driven` · `P0` · `M3`
**需求**：当输入提交包含「这个/这里/最后一条」等指代时，系统必须在提交时绑定候选帧；候选不唯一或没有可用画面时，必须提出**一个具体的澄清问题**。
**验收**：缺帧必须澄清；绑定不歧义（T08）。
**追溯**：R04、R17；§8.3；T08。

**RTM-VIS-05** · `State-driven` · `P0` · `M3`
**需求**：在等待队列拥塞期间，系统必须只替换**未绑定预览帧**，**禁止**丢弃已提交用户指令、已绑定帧或工具事实。
**验收**：预览有界且替换可见；绑定帧不丢（T09）。
**追溯**：R04、R14；§4.3 Q41、§8.3；T09。

**RTM-VIS-06** · `Ubiquitous` · `P0` · `M3`
**需求**：系统必须在**客户端同一单调时钟**上计算帧龄，服务端另记传输与处理耗时，**禁止**用两个未校准的 wall clock 相减。
**验收**：帧龄口径一致；耗时字段可分开报告（T09）。
**追溯**：R04、R15；§8.3；T09。

**RTM-VIS-07** · `Event-driven` · `P0` · `M3`
**需求**：当模型需要查看原图时，系统必须提供可授权读取的原图或局部；图转文结果必须标记为**派生证据**。
**验收**：原图可回读；摘要标注为派生（T24、T08）。
**追溯**：R04、R17；§8.3、§8.4；T08、T24。

**RTM-VIS-08** · `Ubiquitous` · `P1` · `M3`
**需求**：系统必须默认从**按需采集**开始，可选增加低频变化采样；采样率必须受 Provider 上限与实际费用约束（建议初始 0.5–1fps）。
**验收**：不超 Provider 上限；不无限采样（T09）。
**追溯**：R04、R14；§4.2 Q31、§8.3；T09。

**RTM-VIS-09** · `State-driven` · `P0` · `M3`
**需求**：在用户**明确询问历史画面**期间，系统不受「必须最新」限制，可用旧帧；但**依据当前页面执行的操作必须先刷新核验**。
**验收**：历史提问与当前操作区分；当前操作前刷新（T08）。
**追溯**：R04、R17；§4.3 Q41、§8.3；T08。

# 6. 播放与中断（RTM-PLY）

**RTM-PLY-01** · `Ubiquitous` · `P0` · `M1`
**需求**：系统必须按 `response_id` 对音频排队与清除，播放进度必须**以客户端实际输出时间线为准**；**不得**把下载字节、生成 token 或服务端音频范围当作「用户听到的位置」。
**验收**：播放位置口径正确；未听完历史可对齐（T07、T24）。
**追溯**：R05；§8.2；T07。

**RTM-PLY-02** · `Event-driven` · `P0` · `M1`
**需求**：当用户**开口**时，系统必须立即在本地暂停/清除当前回复播放，并发送对应回复的中断请求；本地停播**不等待**服务端确认。
**验收**：插话后旧声音立即停止（T04）。
**追溯**：R05、R06；§8.2；T04。

**RTM-PLY-03** · `Unwanted` · `P0` · `M1`
**需求**：若旧回复的迟到音频在新回复开始后到达，则系统**不得**重新播放旧音频，也**不得**用迟到的旧取消清掉新回复；必须以连接代次及回复 ID 隔离。
**验收**：旧回复不复活，新回复不被误停（T07）。
**追溯**：R05、R08；§4.3 Q40、§8.2；T07。

**RTM-PLY-04** · `Event-driven` · `P0` · `M2`
**需求**：当长答案需要朗读时，系统必须默认只播报用户所需的重点，并保留完整结果的可回读引用；明确要求逐字朗读时必须**分段播放**并支持中断与继续。
**验收**：长结果可回读；分段可中断（T07、T24）。
**追溯**：R05、R17；§4.2 Q36；T24。

**RTM-PLY-05** · `Event-driven` · `P0` · `M2`
**需求**：当中断发生时，系统必须同步实时会话的**未听内容边界**，并在转写无法与声音精确对齐时按**保守的已确认边界**记录精度限制，**禁止虚构字符级播放位置**。
**验收**：未听内容标记保守可信（T07）。
**追溯**：R05、R09；§8.2；T07。

**RTM-PLY-06** · `Ubiquitous` · `P0` · `M2`
**需求**：系统必须**独立保留**任务执行 Journal 与完整产物事实，**禁止**因播报截断而删除任务事实。
**验收**：播报被截断时任务事实仍完整（T07、T24）。
**追溯**：R05、R09；§4.2 Q26、§8.2；T07。

**RTM-PLY-07** · `Ubiquitous` · `P0` · `M1`
**需求**：在转写会话型本地 Provider 下，**音频输出必须由客户端/桥接编排**：由桥接调用本地 TTS（`/v1/audio/speech` 或 `stream=True` 流式接口）生成音频并交由客户端播放，**不得**依赖 Provider 的 `response` 音频通道；播放排队、清除与进度仍**必须**按 `response_id` 与**客户端实际输出时间线**（RTM-PLY-01），本地停播口径不变（RTM-PLY-02、RTM-PLY-03）。TTS 首字节延迟（本机 HTTP 整段返回时首字节≈整段生成时间）**必须**作为可观测项记录，需要更低首包时采用流式接口。
**验收**：本地栈下播报由客户端/桥接编排；播放位置口径与本地停播不变；TTS 首字节可观测（T07、T25）。
**追溯**：R05、R13；§8.2；T07、T25。

# 7. 停止作用域与取消（RTM-STP）

**RTM-STP-01** · `Ubiquitous` · `P0` · `M2`
**需求**：系统必须**分开建模并结算**三种作用范围——**播放停止、回复取消、任务取消**，并区分「请求」与「真实完成」；Provider 取消成功、LFL 取消成功与实际计算停止必须分别观测。
**验收**：三者互不误伤；不支持取消的后端如实标注（T04、T05）。
**追溯**：R06；§4.4 修订 1、§8.2；T04、T05。

**RTM-STP-02** · `Event-driven` · `P0` · `M2`
**需求**：当用户说「先别说了」或按「静音播报」时，系统必须停止当前声音并按需取消当前回答，但**原任务可继续**。
**验收**：停声不取消任务；任务状态另示（T04）。
**追溯**：R06；§8.2；T04。

**RTM-STP-03** · `Event-driven` · `P0` · `M2`
**需求**：当用户**明确纠正需求**时，系统必须停旧播报并提交新轮次，向**精确 `run_generation`** 插话，在下一安全边界采用，并分别反馈「已接收」与「已采用」。
**验收**：代次精确；范围符合新意图（T05、T19）。
**追溯**：R06；§8.2；T05、T19。

**RTM-STP-04** · `Event-driven` · `P0` · `M2`
**需求**：当用户点击「停止任务」或明确要求取消任务时，系统必须本地停播并**立即请求取消对应 `run_generation`**，使用既有取消机制，并检查真实终态，反馈「正在停止 / 已停止 / 已完成部分」。
**验收**：精确代次；终态可核对；不取消其他回复/任务（T05）。
**追溯**：R06；§4.1 Q22、§8.2；T05。

**RTM-STP-05** · `Unwanted` · `P0` · `M2`
**需求**：若用户仅说「停」或意图存在歧义，则系统**不得**等同于取消所有任务；歧义只能澄清一次，**不得**靠单词匹配扩大为取消所有任务。
**验收**：「停一下」「先别说」「取消这个任务」作用范围各自正确（T05）。
**追溯**：R06；§4.2 Q24；T05。

**RTM-STP-06** · `State-driven` · `P0` · `M2`
**需求**：在本地已停止播放而 Provider 推理仍在继续期间，系统必须**分别**显示「播放停止 / 取消已请求 / 取消已确认或不支持」，如实记录实际计费与尾部请求，并限制残留并发。
**验收**：不谎报计算已停止；残留请求有上限（T04、T23）。
**追溯**：R06、R14、R18；§4.3 Q44、§8.2；T23。

**RTM-STP-07** · `Unwanted` · `P0` · `M2`
**需求**：若操作在用户喊停前**已完成**，则系统**不得**宣称「已撤销」，必须报告已完成部分；撤销是**独立动作**，按已有能力与授权处理。
**验收**：不谎称撤销已完成操作（T05、T13）。
**追溯**：R06、R07；§4.3 Q39；T05、T13。

# 8. 工具桥接与幂等（RTM-TOL）

**RTM-TOL-01** · `Ubiquitous` · `P0` · `M2`
**需求**：系统必须保持**唯一服务端工具执行入口**；浏览器只显示/上传，实时模型的工具请求必须通过现有 LFL 机制，**不得**获得并列执行权；即使同一事件从浏览器数据通道与服务端控制通道同时到达，仍只有服务端桥接派发一次。
**验收**：两通道重复不导致双执行（T10）。
**追溯**：R07；§4.2 Q35、§7.4；T10。

**RTM-TOL-02** · `State-driven` · `P0` · `M2`
**需求**：在工具执行期间，工具调用状态必须至少可区分 `requested / claimed / running / succeeded / failed / cancel_requested / cancelled / outcome_unknown`，并复用既有 Journal 或调用记录，**不得**另造完整任务系统。
**验收**：状态可区分且可查询（T13）。
**追溯**：R07、R09；§6.1、§7.3；T13。

**RTM-TOL-03** · `Ubiquitous` · `P0` · `M2`
**需求**：工具执行顺序必须为：确认会话及输入归属 → 关联精确任务代次 → **持久认领调用** → 既有授权与预算检查 → **派发一次** → 记录实际结果 → 通知实时会话。
**验收**：顺序可追溯；每步事实可核对（T10、T16）。
**追溯**：R07、R12；§7.3；T10。

**RTM-TOL-04** · `Unwanted` · `P0` · `M2`
**需求**：若没有可核实的**持久认领记录**，则系统**不得**派发副作用工具。
**验收**：无认领即不派发；崩溃窗口可见（T13）。
**追溯**：R07；§7.3；T13。

**RTM-TOL-05** · `Event-driven` · `P0` · `M2`
**需求**：当同一事件重复到达时，系统必须返回已知状态（幂等）；同一调用只派发一次。
**验收**：同一调用 100 次重复只派发一次（T10）。
**追溯**：R07、R08；§4.1 Q03、§7.3；T10。

**RTM-TOL-06** · `Unwanted` · `P0` · `M2`
**需求**：若模型在新轮次明确提出**相同参数的合法新请求**，则系统**不得**被永久参数哈希黑名单误拦。
**验收**：合法新调用不被错误合并（T10）。
**追溯**：R07；§7.3；T10。

**RTM-TOL-07** · `Unwanted` · `P0` · `M2`
**需求**：若结果不明（`outcome_unknown`），则系统必须先查远端事实，**禁止**以「自动恢复」为名重复写入副作用。
**验收**：不明结果不盲重试（T13）。
**追溯**：R07、R10；§4.2 Q32、§7.3；T13。

**RTM-TOL-08** · `State-driven` · `P0` · `M2`
**需求**：在持久层无法跨外部副作用原子提交的崩溃窗口内，系统必须将结果表达为 `outcome_unknown`，**不得**为规避该事实提前建设分布式事务平台。
**验收**：崩溃窗口显式表达为 unknown（T13）。
**追溯**：R07；§7.3；T13。

**RTM-TOL-09** · `Ubiquitous` · `P0` · `M2`
**需求**：首版真实工具**只选择只读操作**（优先复用既有 `read_file` 读取隔离 workspace 内的真实诊断文件）；写操作的崩溃窗口与核对方法必须在 **M4 单独验收**。
**验收**：测试运行时写入新校验值并通过真实工具回执读取，防止预置答案冒充（T13）。
**追溯**：R07；§12 M2/M4；T13。

**RTM-TOL-10** · `Ubiquitous` · `P0` · `M2`
**需求**：实时会话只能调用**少量语义清楚的桥接能力**（提交任务、查询任务状态、提交纠正、请求取消），**不得**把全仓工具 schema 与所有历史每轮灌入实时模型。
**验收**：桥接面收敛；不复制既有引擎（T18）。
**追溯**：R07、R08；§6.1；T18。

**RTM-TOL-11** · `State-driven` · `P0` · `M2`
**需求**：在长任务运行期间，实时会话仍必须能回应简短问题；系统必须在收到**真实 LFL 进度或结果**后才播报相应事实，**不得**用模型的「我正在处理」代替真实派发回执。
**验收**：无真实回执不播报完成；长任务期间仍可回应（T19）。
**追溯**：R07、R09；§6.1；T19。

**RTM-TOL-12** · `Event-driven` · `P0` · `M2`
**需求**：当**旧工具结果**到达时，系统仍必须将其写入其**原任务记录**作为事实，并依据当前任务关系选择是否通知用户；**不得**为拒绝旧音频而丢弃真实已完成的工具事实。
**验收**：旧结果不丢失，归属正确（T07）。
**追溯**：R07、R09；§7.4；T07。

**RTM-TOL-13** · `Ubiquitous` · `P0` · `M2`
**需求**：任务查询、纠正与取消都必须**验证当前运行代次**，沿用既有 409 冲突语义并向用户说明变化。
**验收**：代次不匹配返回冲突且可解释（T19）。
**追溯**：R07、R08；§7.4；T19。

**RTM-TOL-14** · `State-driven` · `P1` · `M4`
**需求**：在 M4 可写阶段，用户正在有效说话期间，系统必须**暂缓新的副作用工具派发**，直到新轮次提交或误触发被解除；**已在途操作不得承诺即时撤回**；该机制只协调输入与派发时序，**不得裁决用户语义**。
**验收**：说话期间无新副作用派发；有按住说话/关闭自动插话出口（写操作另验）。
**追溯**：R07；§8.2 M4 段；T13（写操作另验）。

**RTM-TOL-15** · `Optional` · `P1` · `M4`
**需求**：若外部系统支持幂等键，则系统必须按其契约使用；若不支持，则必须明确声明客户端无法保证任意外部副作用「恰好一次」。
**验收**：幂等契约按目标系统能力声明（写操作另验）。
**追溯**：R07；§7.3；T13（写操作另验）。

**RTM-TOL-16** · `Event-driven` · `P0` · `M1`
**需求**：在转写会话型本地 Provider（`WS /v1/realtime`，无 `response.create`/无音频输出/无工具回环，RTM-CAP-12）下，**工具调用必须由客户端/桥接层**基于已提交输入（`turn.committed`）编排发起，并**必须**仍经**唯一服务端工具执行入口**（RTM-TOL-01）完成「持久认领 → 授权/预算 → 派发一次 → 结果记录 → 通知」；客户端/桥接**不得**获得并列执行权，**不得**绕过认领与幂等（RTM-TOL-02…05）。工具结果**必须**回注实时会话用于播报编排（RTM-PLY-07）。
**验收**：本地栈下工具调用必经服务端唯一入口且可追溯；浏览器/桥接无并列执行权（T10、T25）。
**追溯**：R07、R13；§7.4；T10、T25。

# 9. 会话身份与媒体写入者（RTM-IDN）

**RTM-IDN-01** · `Ubiquitous` · `P0` · `M2`
**需求**：系统必须在已鉴权、已绑定的连接上下文中补齐应用归属字段——`session_id`、`media_session_id`、`connection_epoch`、`turn_id`、`response_id`、`run_generation`、`tool_call_id`、`event_id`/`seq`、`source_ref`/`source_epoch`；上述字段**按事件类型定义必填项，而非所有事件都必须填齐**：
1. **纯语音**轮次没有工具调用 → **无 `tool_call_id`**；
2. **无视觉输入**的事件 → **无 `source_ref`/`source_epoch`（图片引用）**；
3. **尚未创建任务**（未关联 Run）→ **无 `run_generation`（Run 代次）**。
系统**禁止**为凑齐字段而创建假任务、假引用或假工具调用。同时系统**不得**假设 Provider 音频事件自带幂等 ID 或真实播放时间，也**不得**用参数哈希替代 `tool_call_id` 身份。
**验收**：字段按事件类型必填且可关联；与事件无关的字段可合法缺省；无假任务/假引用产生（T11）。
**追溯**：R08；§7.1；T11。

**RTM-IDN-02** · `Unwanted` · `P0` · `M1`
**需求**：若**旧代次**的音频、预览或回复到达，则系统**不得**使其影响当前播放与决策。
**验收**：旧代次输入不能更新新连接（T11）。
**追溯**：R08；§7.1、§7.4；T11。

**RTM-IDN-03** · `Ubiquitous` · `P0` · `M2`
**需求**：连接 `ready` 不等于麦克风已授权，也不等于任务已派发；系统必须分别记录这三类事实。
**验收**：三类状态独立可观测（T21）。
**追溯**：R08、R18；§7.5；T21。

**RTM-IDN-04** · `State-driven` · `P0` · `M2`
**需求**：在同一 LFL 会话内，系统必须只允许**一个活动媒体写入者**，通过服务端签发的 `connection_epoch` 与可续租占用管理；不同会话互不串扰。
**验收**：同会话两标签只有一个写入者（T11）。
**追溯**：R08；§4.2 Q33、§9.2；T11。

**RTM-IDN-05** · `Event-driven` · `P0` · `M2`
**需求**：当第二个标签页请求接管时，系统必须提供**显式接管**；接管使旧连接失效，旧连接随后即使恢复也**不能写入新状态**。
**验收**：接管后旧连接拒收（T11）。
**追溯**：R08、R18；§4.2 Q33、§9.2；T11。

**RTM-IDN-06** · `Ubiquitous` · `P0` · `M2`
**需求**：租约只管理**媒体所有权**，**禁止**取消独立任务或替代授权。
**验收**：租约变化不取消任务（T11、T16）。
**追溯**：R08、R12；§9.2；T11。

**RTM-IDN-07** · `Event-driven` · `P0` · `M2`
**需求**：当切换 LFL 会话时，系统必须释放原媒体写入权，且**不得**自动把麦克风流、原截图或迟到结果转给新会话；恢复需要服务端确认新的连接代次和任务映射后才能继续上传或播放。
**验收**：切换后不串流、不串结果（T11、T19）。
**追溯**：R08、R18；§7.5；T11、T19。

**RTM-IDN-08** · `Ubiquitous` · `P0` · `M2`
**需求**：媒体 session、语音轮次与 LFL 长期会话必须**分别标识**；对当前任务的纠正**必须绑定原任务**，**禁止**每次说话都新建任务。
**验收**：长任务协作保留原任务身份（T19）。
**追溯**：R08；§4.2 Q34；T19。

**RTM-IDN-09** · `Unwanted` · `P0` · `M2`
**需求**：仅预览画面、开关麦克风或重连**不得**自动创建新的长期任务 Goal；语音与文字必须**共享当前 LFL 会话**。
**验收**：媒体操作不派生新 Goal（T19）。
**追溯**：R08；§3.3、§4.2 Q34；T19。

# 10. 持久化与恢复（RTM-REC）

**RTM-REC-01** · `State-driven` · `P0` · `M2`
**需求**：只有**已提交需求、任务链接、工具事实与必要恢复状态**必须进入持久记录；临时字幕、全部声音分片和未使用的预览画面**不得**进入任务 Journal；持久文本来源必须标明「语音识别」，**不得**标成原始音频的无损副本。
**验收**：持久边界正确；无临时字幕/分片入 Journal（T14、T15）。
**追溯**：R09；§4.4 修订 2、§7.1；T14。

**RTM-REC-02** · `Unwanted` · `P0` · `M2`
**需求**：若持久化失败，则系统必须**按失败发生的位置分别处理**，不得用同一结论掩盖差异：
1. **派发前必要记录失败**（提交所需的 Journal/认领记录或附件写入失败、磁盘满）：**不得**确认「已派发」，必须保留本地未提交文本并反馈，且不得派出尚缺必要记录的工具操作。
2. **派发后结果保存失败**（操作已经发生、但结果写入失败）：**不得**确认「已保存」，但**必须如实保留已经发生的操作事实**——不得宣称该操作未发生、不得通过删除或回滚抹掉其证据；该次结果必须标记为 `outcome_unknown` 并反馈，供后续先核事实。
3. **可选诊断失败**（仅诊断日志出口不可用）：**不得**影响已确认的提交/派发状态，**不得**把已发生操作降级为未发生；必须单独报告诊断不可用。
**验收**：三类失败分别可辨识；分发前失败不伪报「已派发」；派发后失败如实保留已发生事实并进入 `outcome_unknown`；诊断失败不篡改已确认状态；错误可定位（T15、T13）。
**追溯**：R09；§4.1 Q02、§4.1 Q14、§7.3；T15、T13。

**RTM-REC-03** · `Event-driven` · `P0` · `M2`
**需求**：当出现短暂媒体/控制断连时，系统必须本地停旧播放、显示断线、**有界退避**连接并更换连接代次、从已确认事件序号核对。
**验收**：断网 3/10/30 秒恢复一致（T12）。
**追溯**：R10；§9.1；T12。

**RTM-REC-04** · `Unwanted` · `P0` · `M2`
**需求**：断线期间系统**不得**声称「仍连续理解」。
**验收**：断线状态如实显示；缺失语音明确（T12）。
**追溯**：R10；§9.1；T12。

**RTM-REC-05** · `Event-driven` · `P0` · `M2`
**需求**：当 Provider 连接过期且支持恢复时，系统必须按**官方恢复机制**续接；恢复令牌只能在服务端受保护保存。**v1.2 本地栈修订**：本地栈（`WS /v1/realtime` 转写会话 + 本地 TTS）**通常不提供远端恢复令牌**；此时系统**不得**假设存在远端恢复能力，恢复统一由**本地会话重建 + 已提交输入/摘要/证据引用核对**承担（沿用 RTM-REC-03、RTM-REC-07、RTM-REC-10），并在能力档案中如实标注「无远端恢复机制」。
**验收**：本地栈下不假设远端恢复；恢复走本地重建与事实核对；能力档案标注恢复方式（T14、T25）。
**追溯**：R10、R12；§9.1；T14、T25。

**RTM-REC-06** · `Unwanted` · `P0` · `M2`
**需求**：连接恢复**不得**等同于工具「恰好一次」。
**验收**：恢复后先核事实、不盲重派（T14、T13）。
**追溯**：R10、R07；§9.1；T13。

**RTM-REC-07** · `Event-driven` · `P0` · `M2`
**需求**：当恢复失败或令牌失效时，系统必须保留 LFL 会话与任务，从**已提交输入、摘要及证据引用**重建远端上下文，用户重新开始未提交语音。
**验收**：沿用 LFL 任务、原证据可读、未保存声音不假装恢复（T14）。
**追溯**：R10；§4.3 Q43、§9.1；T14。

**RTM-REC-08** · `Unwanted` · `P0` · `M2`
**需求**：恢复失败时系统**不得**声称「所有未保存音频、原始模型状态均已恢复」，必须明确音频间隙。
**验收**：不假称完整音色/声音历史恢复（T14）。
**追溯**：R10；§4.3 Q43、§9.1；T14。

**RTM-REC-09** · `State-driven` · `P0` · `M2`
**需求**：重连必须采用有界策略（建议三次自动尝试，退避约 0.5/1/2 秒并抖动），之后给出手动重连与文字入口；鉴权失效、配额不足及协议不兼容**不得**进行无意义循环重试。
**验收**：重试有界；非可重试错误不循环（T12）。
**追溯**：R10；§9.1；T12。

**RTM-REC-10** · `Event-driven` · `P0` · `M2`
**需求**：恢复时系统必须先拉取 **LFL 真实状态**，不重播未听完的旧回答，不重派发失去确认的工具。
**验收**：恢复不自动重发最后一条工具调用（T13）。
**追溯**：R10、R07；§4.2 Q32、§9.1；T13。

**RTM-REC-11** · `Event-driven` · `P0` · `M2`
**需求**：离线输入可保留为**本地草稿**，但上线后必须**明确提交**；**不得**自动把整段过时语音按当前页面执行。
**验收**：过时语音不自动执行（T12）。
**追溯**：R10；§9.1；T12。

**RTM-REC-12** · `Event-driven` · `P0` · `M2`
**需求**：当共享权限因重连丢失时，系统**不得**自动重新授予，必须显示用户操作入口。
**验收**：重连不绕过浏览器权限（T12、T02）。
**追溯**：R10、R12；§9.1、§9.4；T12。

**RTM-REC-13** · `Event-driven` · `P0` · `M2`
**需求**：当 Provider 远端压缩丢失任务要求时，系统必须**按需补充上下文**；**不得**把每个音频块灌入核心历史，也**不得**只剩不可恢复的摘要。
**验收**：任务事实与可回读源独立于实时窗口（T14、T24）。
**追溯**：R10、R09；§4.3 Q46；T14。

**RTM-REC-14** · `Ubiquitous` · `P0` · `M2`
**需求**：已提交需求、任务链接、工具事实和证据引用必须可恢复（R09 交付）。
**验收**：恢复事实可核对（T12、T14、T15、T24）。
**追溯**：R09；§5 R09；T12。

# 11. 生命周期与资源（RTM-LIF）

**RTM-LIF-01** · `Event-driven` · `P0` · `M1`
**需求**：当用户结束语音时，系统必须先在**本地**停止采集与播放并拒收该代次后续音频，再请求远端关闭、收集可获得的最终用量，并在可配置的**有限收尾窗口**后释放连接与工作线程。
**验收**：结束顺序正确；资源在收尾窗口后释放（T17、T22）。
**追溯**：R18；§7.5；T22。

**RTM-LIF-02** · `Unwanted` · `P0` · `M1`
**需求**：若未取得最终事件，则系统必须记录「关闭/计费未完全确认」（`incomplete`），**不得**一直占用麦克风等待账单。
**验收**：未确认如实标注；不长期占用麦克风（T17）。
**追溯**：R18、R14；§7.5；T17。

**RTM-LIF-03** · `State-driven` · `P0` · `M1`
**需求**：后台任务的独立生命周期必须继续从既有任务接口显示状态；「结束语音」**不得**等同于取消 LFL 任务。
**验收**：结束语音后后台任务状态仍可见（T17、T22）。
**追溯**：R18；§3.3、§7.5；T22。

**RTM-LIF-04** · `Event-driven` · `P0` · `M1`
**需求**：当结束语音、切换会话、标签页退出、接管或异常时，系统必须释放 MediaStream tracks、播放节点、计时器、监听器、连接和残留 Worker。
**验收**：长稳态无持续资源泄漏（T11、T17、T22）。
**追溯**：R18；§9.2；T22。

**RTM-LIF-05** · `State-driven` · `P1` · `M2`
**需求**：音频、预览帧、控制事件必须使用**不同的拥塞处理**：可替换预览帧可丢弃；**用户输入与任务控制不得静默丢弃**；音频严重积压时必须暂停采集/响应并显示状态，**不得**长期播放已过时的回答。
**验收**：控制事件不静默丢弃；积压可见（T09）。
**追溯**：R18、R14；§9.2；T09。

**RTM-LIF-06** · `Unwanted` · `P0` · `M1`
**需求**：系统**不得**让同步图像识别或长工具占用实时事件循环，必须复用 `BackgroundRunner`。
**验收**：实时路径不被长工具阻塞（T03、T22）。
**追溯**：R18；§9.2；T03。

**RTM-LIF-07** · `Unwanted` · `P1` · `M2`
**需求**：对**不支持取消**的 Provider 请求，系统必须设置**残留并发上限**并计量，**不得**通过不断创建后台线程掩盖不可取消。
**验收**：残留请求有上限且计量（T23）。
**追溯**：R18、R14；§9.2、§9.3；T23。

**RTM-LIF-08** · `Event-driven` · `P0` · `M3`
**需求**：当出现串会话、重复派发、无法停播、凭据泄漏或资源持续增长时，必须能在 Web 相关能力范围内回滚——关闭新增媒体入口并恢复原文字入口，且**不得**删除任务事实或中断其他服务。
**验收**：回滚检查通过；任务事实保留（T22）。
**追溯**：R18、R20；§12 实施边界；T22。

# 12. Provider 能力与降级（RTM-CAP）

**RTM-CAP-01** · `Ubiquitous` · `P0` · `M0`
**需求**：系统必须在 M0 **固定并记录一个实测 Provider 能力档案**，至少包含：Provider/模型/API/SDK 版本、传输、输入输出格式、最终转写事件、轮次结束语义、取消与播放截断能力、工具调用关联、图像支持、恢复方式、连接限制、已核实用量字段、地区/网络实测条件。**v1.2 起，能力档案按本地实时语音栈冻结**：须记录 `mlx-audio` 与 Ollama 的版本、接口（`/v1/audio/transcriptions`、`WS /v1/realtime`、`/v1/audio/speech`）、所选模型（nemotron 流式 ASR、Qwen3-ASR 终稿校正、Qwen3-TTS 流式 TTS、silero-vad）与**许可**、以及服务级实测条件；**撤销**「必须为远端实时 Provider」的默认假设（RTM-CAP-11、RTM-CAP-14）。
**验收**：能力档案齐全且含本地栈版本/接口/模型/许可；可支撑后续降级判断（T02、T18、T25）。
**追溯**：R13；§6.2；T02、T25。

**RTM-CAP-02** · `Unwanted` · `P0` · `M0`
**需求**：能力档案每一项必须记录「官方说明 / 实测结果 / 未知项」，**禁止**只填一个 `multimodal=true`。
**验收**：逐项三态记录；未知项显式列出（M0 完成条件）。
**追溯**：R13；§6.2、§14；T02。

**RTM-CAP-03** · `State-driven` · `P0` · `M0–M3`
**需求**：在 Provider 缺项期间，系统必须**降级**并在界面**如实标识具体缺项**，**不得**伪装全功能。**v1.2 补充**：缺项须涵盖**本地栈场景**——「本地服务级已通、受信浏览器链路未接通」「观察项（原生全双工）不达标」「本地服务未起/端口不可达」均属缺项，标识必须区分「服务级已实测」与「浏览器链路已验收」（RTM-EVD-06、RTM-OBS-09）。
**验收**：缺项可见且区分服务级/浏览器链路；能力标识正确（T02、T20、T27）。
**追溯**：R13、R16；§4.1 Q05、§4.1 Q10；T20、T27。

**RTM-CAP-04** · `Unwanted` · `P0` · `M0`
**需求**：若协议/依赖版本协商不通过，则系统必须显示**具体缺项**，**禁止**伪装全功能。**v1.2 补充**：本地方案下「依赖版本协商」包括本地栈运行时约束（如 `setuptools<81`、server 依赖 `uvicorn[standard]`/`fastapi`/`python-multipart`/`webrtcvad`、Ollama `think:false`）；约束不满足时必须显式报错而非静默产出空结果（RTM-CAP-14、RTM-CAP-11）。
**验收**：协商失败原因具体可读（含本地栈依赖/参数约束）（T02、T25）。
**追溯**：R13；§4.1 Q05；T02、T25。

**RTM-CAP-05** · `Ubiquitous` · `P0` · `M0–M3`
**需求**：系统必须只实现所选**一条**媒体传输。**v1.2 修订（本地栈）**：本地栈下采用**本机 WS 转写会话**（`WS /v1/realtime`，仅转写）+ **本机 HTTP/流式 TTS**（`/v1/audio/speech` 或 `stream=True` 接口），**不引入 WebRTC**；音频输出与工具调用由客户端/桥接编排（RTM-CAP-12、RTM-PLY-07、RTM-TOL-16）。协议接口预留替换能力，但**不同时建设两套生产实现**，也**不为未选 Provider 编写空适配器**。
**验收**：单实现可运行；无空适配器、无并行第二传输（M0 能力档案；T25）。
**追溯**：R13；§6.2、§6.4；M0、T25。

**RTM-CAP-06** · `Optional` · `P0` · `M3`
**需求**：若所选 Provider 不支持图像输入，则系统必须使用**明确标识的独立视觉适配路径**完成联合体验。
**验收**：视觉路径可辨识；无伪装图像能力（T08）。
**追溯**：R13、R04；§6.2；T08。

**RTM-CAP-07** · `Unwanted` · `P0` · `M3`
**需求**：**当受信浏览器实时链路未接通时**（无论因云端实时 Provider 凭据缺失，还是因本地栈已服务级就绪但**浏览器采集/播放/VAD/打断尚未接线**），系统可完成离线实现与文字/听写降级，但实时验收必须标为**未完成**，**禁止**用模拟波形、预录声音或假工具结果代替，**也禁止**用**服务级**闭环实测（如本机 12.23 s 端到端）冒充浏览器链路完成（RTM-EVD-06、RTM-OBS-09）。
**验收**：浏览器链路未接通不得宣布实时完成；服务级实测不替代浏览器验收（T21、T27）。
**追溯**：R13、R20；§4.2 Q37；T21、T27。

**RTM-CAP-08** · `State-driven` · `P0` · `M1`
**需求**：单次浏览器听写（既有 `DictationButton`）必须继续可用作为降级，但**不计为**连续实时语音交付。
**验收**：听写降级可用；交付声明区分（T02、T20）。
**追溯**：R13、R19；§6.3；T20。

**RTM-CAP-09** · `Optional` · `P1` · `M1`
**需求**：系统**不得**仅凭架构名称（原生实时 vs 级联）判定链路等级。级联语音链路（语音识别 → LFL → 语音合成）**可以实现实时交互**（公开文档已覆盖流式 STT–LLM–TTS、轮次检测与中断），因此**必须按实测能力判断**其是否满足首版实时要求，判定维度至少包括：**连续输入**、**流式输出**、**用户开口时打断**、**端到端延迟**。
1. 若实测满足上述维度，则该链路与原生实时链路**同等对待**，**不得**仅因「级联」架构被预先判为降级。
2. 若实测不满足（例如无流式输出或无法本地打断），才作为**降级**处理，且必须**明确标识为降级**，**不得**冒充连续实时语音。
3. 界面必须**标明当前采用的链路**（原生实时 / 级联 / 文本降级）。
优先选择**实测适合 LFL** 的实现，而不是仅凭架构名称排除。
**v1.2 实测依据**：本机已按**服务级**实测判定——级联本地链路（流式 ASR → 本地 LLM → 流式 TTS）在服务级满足「连续输入、流式输出、首字低延迟、可在本地停播」的可行性，**不因「级联」架构被预先判为降级**；原生全双工（VoiceChat-11B）实测**不达标**，按维度不足以作首版主链路，单独列为**观察项**（RTM-CAP-13）。链路等级仍需在**浏览器链路**上用同一单调时钟复核端到端与打断后才算最终判定（RTM-OBS-05、RTM-OBS-09）。
**验收**：链路等级由实测能力判定而非架构名称；界面标明实际采用的链路（原生实时/级联/文本降级）与「观察项」；仅在实测不满足时才标为降级（T20、T21、T25）。
**追溯**：R13；§1；T20、T25。

**RTM-CAP-10** · `Unwanted` · `P0` · `M1`
**需求**：新的连续语音控制**不得**被 `conv.streaming` 一概禁用；原有文本「停止」语义**不得**因新增语音按钮而改变。
**验收**：媒体控制与文本 streaming 状态解耦；原停止语义不变（T04；项目原版回归）。
**追溯**：R13、R19；§4.2 Q23、§6.3；T04。

**RTM-CAP-11** · `Ubiquitous` · `P0` · `M0`
**需求**：系统必须在 M0 选定并冻结**本地 Provider 栈**作为首版实时语音链路：以 `mlx-audio`（MLX 原生、OpenAI 兼容 REST + WS）提供 ASR/TTS，以 Ollama 本地文本模型提供主脑，以本地流式 TTS 提供播报；能力档案必须记录运行时版本、接口、模型与**许可**，并登记**服务级**实测事实（含浏览器链路未测）。系统**不得**在首版并行接入云端实时 Provider 作为主链路，也**不得**为未选 Provider 编写空适配器。
**验收**：能力档案记录本地栈版本/接口/模型/许可；服务级实测事实登记并标注「浏览器链路未测」（T02、T25）。
**追溯**：R13；§6.2；T25。

**RTM-CAP-12** · `Ubiquitous` · `P0` · `M0`
**需求**：系统必须显式记录本地栈的**转写会话能力边界**：`WS /v1/realtime`（OpenAI-Realtime 风格）**只是转写会话**——支持 `session.update` / `input_audio_buffer.append` / `commit` 并产出 `…input_audio_transcription.delta/.completed`，但**没有 `response.create`、不产出音频、不提供工具调用回环**。因此**音频输出必须由客户端/桥接编排**（RTM-PLY-07），**工具调用必须由客户端/桥接基于已提交输入编排**（RTM-TOL-16）；系统**不得**假设本地转写会话会返回模型回复音频或工具事件。
**验收**：能力档案标注「仅转写、无音频输出、无工具回环」；运行时不依赖不存在的 `response.create`/音频回环（T25、T18）。
**追溯**：R13、R07；§6.2；T25。

**RTM-CAP-13** · `Unwanted` · `P1` · `M0–M3`（**观察项**）
**需求**：若原生全双工语音对话链路（如 `NemotronLabs-VoiceChat-11B-4bit`）的**实测能力不满足 CAP-09 维度**，则系统**不得**将其作为首版主链路，必须列为**观察项**，并在能力档案中记录：证伪证据（中/英输入返回同一段英文人格寒暄、延迟为输入时长 4–6 倍、双工文本跑偏、未观测到 `function_delta`）、原因待查项（MLX 移植接线/系统提示/语言设置/是否需 VAD 分段）与**退出条件**（满足任一：换用对照样本重测达标；或原因定位并修复后按 CAP-09 维度复测达标）。观察项**不计入**首版交付，但**不得删除**其证据与复现脚本。
**验收**：观察项与证伪证据/退出条件在能力档案可查；界面与交付声明不把观察项当作已支持能力（T25、T20）。
**追溯**：R13；§4.1 Q05；T25。

**RTM-CAP-14** · `Ubiquitous` · `P0` · `M0`
**需求**：系统必须把本地栈的**运行时与环境约束**写入能力档案，至少包含：Python 运行时与 `mlx-audio` 依赖约束（依赖 `pkg_resources` → 必须 `setuptools<81`；server 需 `uvicorn[standard]`、`fastapi`、`python-multipart`、`webrtcvad`）；Ollama `qwen3.5` 默认 thinking → 语音链路**必须**传 `think:false`，否则流式 `content` 为空；音频输入**必须为 16k PCM**（`input_audio_format=pcm16`）；流式会话结束**必须 `flush()` 收尾**（如 VoiceChat 类接口）。约束不满足时系统必须显式报错/降级，**不得**静默产出空转写或空回复。
**验收**：能力档案含依赖与参数约束；违反约束时错误可见而非静默空结果（T02、T25）。
**追溯**：R13；§6.2；T25。

**RTM-BUD-05** · `Unwanted` · `P1` · `M3`
**需求**：系统**不得**伪报零成本，也**不得**靠隐性截断需求、降低原任务模型能力来达成成本目标。

**追溯**：R14；§9.3；T23。

**RTM-BUD-06** · `Ubiquitous` · `P1` · `M3`
**需求**：系统必须关注「每次成功任务成本」「每分钟有效交互成本」和人工接管次数，并通过预览去重、按需原图、简短播报和按需上下文减少浪费。

**RTM-BUD-07** · `State-driven` · `P1` · `M2`

**RTM-OBS-06** · `Ubiquitous` · `P0` · `M3`

**验收**：样本量与分层报告达标（T23）。
**追溯**：R15、R20；§10；T23。

**RTM-OBS-07** · `Unwanted` · `P1` · `M3`
**需求**：若网络差导致延迟不达标，系统**不得**删除慢样本；不达标就必须报告限制或**缩小明确支持范围**。
**验收**：失败与超时计入分母（T23）。
**追溯**：R11、R20；§4.3 Q45；T23。

**RTM-OBS-08** · `Event-driven` · `P0` · `M3`
**需求**：工具型回复必须**分别**测「用户说完 → 真实接收反馈 / 工具开始 / 工具完成 / 结果声音」；简短「好的」**不得**计为完成回答；延迟慢的工具**不得**从任务指标中隐藏。
**验收**：工具反馈逐项核对，误报完成 0 次（T23）。
**追溯**：R11、R15；§10；T23。

**RTM-OBS-09** · `Ubiquitous` · `P1` · `M0–M1`
**需求**：系统必须把**服务级实测**登记为**服务级基线**，与**浏览器链路验收**分开记录：服务级基线**必须**登记测量口径、运行环境、脚本与原始日志（如本机 `WS ASR → Ollama → HTTP TTS`，6.96 s 输入 → 端到端 12.23 s；ASR 首字 1.23 s/结束 7.14 s、LLM 首字 0.66 s、TTS 首字节 4.43 s、TTS RTF 0.66）。服务级基线**不得**作为 M1/M3 浏览器链路的验收数值，也**不得**与浏览器链路样本混算 P50/P95。
**验收**：服务级基线与浏览器链路分别记录且口径可复现；服务级数值不被当作浏览器验收（T23、T27）。
**追溯**：R11、R15；§10；T23、T27。

# 16. 安全边界（RTM-SEC）

**RTM-SEC-01** · `Ubiquitous` · `P0` · `M1`
**需求**：长期 Key、工具凭据、恢复令牌**不得**出现在前端 bundle、URL、常规日志或转写中，必须**只在服务端保存**；短期会话凭据的范围与时效由所选正式 API 保证，**不得**让浏览器自由绑定任意远端 session。**v1.2 本地栈调整**：本地方案下「长期 Key」语义转为**本机服务凭据与下载凭据**（如 `HF_TOKEN`）——仅在服务端保存、本机服务不暴露公网（RTM-SEC-08）；无远端实时 Provider 时，远端「恢复令牌」不再适用，恢复改由本地会话重建与已提交事实核对承担（RTM-REC-05）。
**验收**：凭据扫描无泄漏；本机服务不暴露、凭据不下发（T16、T25）。

**RTM-SEC-02** · `Ubiquitous` · `P0` · `M2`
**需求**：截图中的指令、网页提示和模型调用**不得提升权限**；必须继续使用 LFL 既有权限边界。
**验收**：网页提示注入无效；无越权调用（T16）。
**追溯**：R12；§4.1 Q15、§9.4；T16。

**RTM-SEC-03** · `Unwanted` · `P0` · `M2`
**需求**：系统**不得**另造语义黑名单或审批平台替代既有授权检查。
**验收**：真实工具检查沿用 LFL（T16）。
**追溯**：R12；§9.4；T16。

**RTM-SEC-04** · `State-driven` · `P0` · `M1`
**需求**：在等待工具期间若授权被撤销，系统必须在实际执行前继续使用既有 LFL 授权检查，并只终止受影响动作、保留解释与恢复入口；**媒体会话存在不代表可绕过检查**。
**验收**：撤销授权后调用被拒（T16）。
**追溯**：R12；§4.3 Q47；T16。

**RTM-SEC-05** · `Ubiquitous` · `P0` · `M1`
**需求**：媒体采集必须要求**安全上下文与浏览器权限**；屏幕共享必须需要**用户手势**且**每次重新取得权限**，自动恢复**不得**绕过浏览器。
**验收**：权限行为符合浏览器约束（T02）。
**追溯**：R12、R18；§9.4；T02。

**RTM-SEC-06** · `Ubiquitous` · `P0` · `M1`
**需求**：仅知道 ID **不得**读取或控制媒体会话/附件/任务；媒体会话、附件引用和任务都必须绑定当前用户、LFL 会话与 workspace。
**验收**：越权 ref/session 读取或调用被拒（T16）。
**追溯**：R01、R12；§4.1 Q17、§9.4；T16。

**RTM-SEC-07** · `Ubiquitous` · `P1` · `M3`
**需求**：需要音频级审计的场景必须**单独提供显式录音选项**并说明来源、保留期限及删除行为；默认不留存原始音频即**不得**承诺精确重放。
**验收**：录音选项显式；无隐性长期录音（T17）。

# 19. 性能目标与验证（RTM-PRF）

**RTM-PRF-01** · `Ubiquitous` · `P1` · `M3`
**需求**：无工具自然对话**首声延迟**初始目标 P50 ≤ 1 秒、P95 ≤ 2 秒（含断句等待，冷启动单列）。测量结果必须**分开记录「已测」与「达标」两项事实**：**已测** = 存在**真实浏览器链路端到端**（经麦克风输入、经扬声器输出）的测量记录与样本；**达标** = 实测数值满足阈值。**「已测」不得替代「达标」**，且**服务级实测不得充当「已测」**（RTM-OBS-09、RTM-EVD-06）。
**验收**：同时给出「已测」与「达标」两结论，且「已测」口径为浏览器链路；未达标时**可以交付完整测试报告**，但**不得据此宣布 M3 完成**；P1 不等于选做（T03、T23、T27）。
**追溯**：R11；§10；T03。

**RTM-PRF-02** · `Ubiquitous` · `P1` · `M3`
**需求**：**本地插话停播** P95 ≤ 200ms（含语音起点检测）。**v1.2 补充**：该指标**必须在浏览器链路上实测**（真实麦克风起点检测 → 扬声器实际停声），服务级停播数据不得充作「已测」（RTM-OBS-09、RTM-EVD-06）。
**验收**：按「已测」与「达标」分别记录**浏览器链路**插话至旧声音实际停止的结果；未达标可交付报告但**不得据此宣布 M3 完成**（T04、T23、T27）。
**追溯**：R11；§10；T04。

**RTM-PRF-03** · `Ubiquitous` · `P1` · `M3`
**需求**：**本地按钮停播** P95 ≤ 100ms（独立于 Provider 取消确认）。**v1.2 补充**：该指标**必须在浏览器链路上实测**（真实按钮/键盘事件 → 扬声器实际停声）；服务级数据不得充作「已测」（RTM-OBS-09、RTM-EVD-06）。
**验收**：按「已测」与「达标」分别记录**浏览器链路**按钮事件至本地输出停止的结果；未达标可交付报告但**不得据此宣布 M3 完成**（T04、T23、T27）。
**追溯**：R11；§10；T04。

**RTM-PRF-04** · `Ubiquitous` · `P1` · `M3`
**需求**：**视觉新鲜度**：当前页面问答「捕获至问题绑定」初始目标 ≤ 2 秒，同时报告传输/推理耗时，历史画面单列。**v1.2 补充**：该指标**必须在浏览器链路**（真实共享来源 → 客户端单调时钟绑定）实测；服务级观测不得充作「已测」（RTM-OBS-06、RTM-OBS-09）。
**验收**：按「已测」与「达标」分别记录**浏览器链路**帧新鲜度；未达标可交付报告但**不得据此宣布 M3 完成**（T08、T23、T27）。
**追溯**：R11；§8.3、§10；T08。

**RTM-PRF-05** · `Ubiquitous` · `P1` · `M3`
**需求**：**工具反馈真实性**：误报完成 **0 次**；接收、派发、执行结果与播报逐项核对，**不得**把「收到」当完成。
**验收**：误报完成 0 次（**达标项，须以真实样本支撑**）；「已测」不等于「达标」（T23）。
**追溯**：R11；§10；T23。

**RTM-PRF-06** · `Ubiquitous` · `P1` · `M3`
**需求**：**关键时序正确性**：测试集中重复派发、跨会话串扰、旧音频复活均 **0 次**（明确样本数与事件覆盖，**不得**据此推导生产永不出错）。
**验收**：三类时序错误均为 0（**达标项，须给出样本数与事件覆盖**）；「已测」不等于「达标」（T10、T11、T07）。
**追溯**：R11；§10；T10。

**RTM-PRF-07** · `Ubiquitous` · `P1` · `M3`
**需求**：**长会话**至少 3 场各 30 分钟，包含工具、纠正、媒体重连；无持续资源泄漏，恢复事实可核对。
**验收**：按「已测」与「达标」分别记录长会话无泄漏与事实可核对；未达标可交付报告但**不得据此宣布 M3 完成**（T22）。
**追溯**：R11、R18；§10；T22。

**RTM-PRF-08** · `State-driven` · `P1` · `M3`
**需求**：所有性能目标在 M0 可基于真实基线修订，但必须在**最终测试前**记录修订理由、支持配置与阈值，**禁止**看到结果后降低标准冒充通过。
**验收**：修订有据可查；修订**不得**把未达标改写达标，也**不得**据修订后的口径宣布未达标项已完成验收（T23）。
**追溯**：R11、R20；§10；T23。

**RTM-EVD-01** · `Ubiquitous` · `P0` · `M3`

**RTM-EVD-05** · `Ubiquitous` · `P0` · `M0`

**验收**：交付声明与阶段一致。
**追溯**：R20；§1、§12；M0–M4。

**RTM-EVD-06** · `Ubiquitous` · `P0` · `M0–M3`
**需求**：证据分级**必须**在 EVD-01 四类基础上新增区分「**服务级已实测**」与「**浏览器链路已验收**」：服务级证据（不由浏览器发起、不经麦克风/扬声器的本机服务闭环）**不得**替代浏览器链路证据；当浏览器采集/播放/VAD/打断**尚未接通**时，依赖浏览器链路的条目（AUD、PLY、PRF、SCN、A11Y 相关）**必须**标为**未验收**，**不得**用服务级结果宣布这些条目完成。M0 探针 A/B（连续听说、本地打断）在本地方案下**部分解除**：服务级链路已通，但**浏览器侧仍阻断**，故探针 A/B **仍不得**宣布通过。
**验收**：服务级与浏览器链路证据分开；浏览器链路未通时相关条目显式未验收；M0 探针 A/B 不因服务级已通而宣布通过（T21、T27、M0）。
**追溯**：R20、R13；§12 M0/M3；T27。

# 21. 核心使用场景验收（RTM-SCN，U1–U5）

**RTM-SCN-01** · `Event-driven` · `P0` · `M3` —— **U1 页面排错**
**需求**：当用户主动共享页面并说「看看这个页面最后一条错误，查一下原因」时，系统必须绑定关键帧、调用**真实只读工具**、口头解释并**显示来源**。
**验收**：帧绑定正确；真实工具回执；来源可见（T08、T13）。
**追溯**：U1；§3.1；T08、T13。

**RTM-SCN-02** · `Event-driven` · `P0` · `M2` —— **U2 途中纠正**
**需求**：当用户说「等等，只看最后一条，先别改」时，系统必须立即停止旧播报、提交修正、显示任务「何时收到 / 何时采用」，后续行为符合新范围。
**验收**：停播立即；范围更新；两阶段反馈（T04、T05、T19）。
**追溯**：U2；§3.1；T05、T19。

**RTM-SCN-03** · `State-driven` · `P0` · `M2` —— **U3 长任务协作**
**需求**：在长任务运行期间，当用户问「刚才那项是什么意思」时，系统必须保留原任务身份、能解释现状、**不因每次语音新建无关联会话**。
**验收**：任务身份保留；现状可解释（T19）。
**追溯**：U3；§3.1；T19。

**RTM-SCN-04** · `Event-driven` · `P0` · `M2` —— **U4 断线续接**
**需求**：当网络中断后用户返回页面时，系统必须保留已提交需求、工具事实和任务状态，**明确未识别的语音**，**不自动重复操作**。
**验收**：缺失语音明确；无自动重复派发（T12）。
**追溯**：U4；§3.1；T12。

**RTM-SCN-05** · `Event-driven` · `P1` · `M3` —— **U5 移动端使用**
**需求**：当用户在移动端说话、上传截图、切到后台再回来时，系统必须根据**实测能力**提供语音或文字；屏幕共享不支持时可用截图；**不假装仍在后台采集**。
**验收**：能力声明与实测一致；降级可用（T21）。
**追溯**：U5；§3.1、§3.2；T21。

# 27. 验收边界与不承诺事项

1. **阶段边界**：M3 完成前不得宣称「实时多模态 MVP 已交付」；M4 可写工具条件不得倒算首版已支持写操作（EVD-05）。
2. **证据边界**：模拟、真实设备、真实 Provider、生产部署四类证据分开；缺任一真实证据即列「未验收」（EVD-01、EVD-02）；模拟通过或文档写全不得宣布上线（EVD-03、EVD-04）。
3. **不承诺**：硬实时控制、音视频会议平台、高帧率通用视频分析、机器人控制；不引入 SFU、独立消息中间件、全局多 Agent 调度、新通用授权体系；默认不留存原始音频即不承诺精确重放（SEC-07、RET-04）。
4. **既有语义不变**：原文字「停止」、附件、插话、取消、任务恢复行为保持兼容（CMP-01）；原模型任务预算与上下文策略不因低延迟语音被调低（BUD-07）。
5. **机械控制边界**：新增机械控制仅用于模型无法替代的事实边界（连接归属、身份、字节格式、精确代次、已提交状态、资源上限、去重）；可调参数与降级入口必须可见且有出口（§0.4、AUD-06、CAP-03）。6. **文档权威边界**：本主规格为**权威条款**，SDD 归档 `.codeartsdoer/specs/realtime_multimodal/spec.md` 为**索引**；冲突以主规格为准，修订时同步（§0.6）。
7. **实施组织边界**：**163 条**用于追溯，实施按**用户可运行的闭环**组织，不拆成 163 个功能或检查门槛；首个执行单元为 **M0**「验证一条真实语音链路 → 本地打断 → 同会话只读工具」（§0.7）。
8. **本地栈边界（v1.2 新增）**：本地栈只覆盖 **ASR/TTS/文本**，不包含原生全双工对话（观察项，CAP-13）与图像/视频输入（Qwen3-Omni 等暂不建议，RTM-CAP-06）；`WS /v1/realtime` **仅转写**，音频输出与工具调用由客户端/桥接编排（CAP-12、PLY-07、TOL-16）；**服务级实测（12.23 s 等）只作服务级基线，不得作为 M1/M3 浏览器链路验收**（EVD-06、OBS-09）。

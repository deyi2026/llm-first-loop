## 总体评价

质量不错——11 个修复项覆盖了大部分真实问题，有业务规则/交互流程/异常场景/验收条件/任务依赖图/env 设计。**但它是基于旧代码基线写的**（未感知今天已落地的修复），存在 1 处方案缺口、3 处与新代码的冲突、若干缺失项。

## 一、最关键：§5.1 head_keep 消重方案有根本缺口

**规格方案**：`archived_ids` 消重集合——跳过已归档的中段消息，防重复归档。

**缺口**：只解决了「不重复归档」（省写入），**没解决「提交视图不缩小」**——锚点冻结时中段消息仍在提交视图里（归档 ≠ 移出视图），提交仍是 288K → guard F 依旧 BLOCK → **验收 2（提交缩小 ≥10%）无法满足**。必须补上「提交视图按已归档集合过滤」或「锚点推进到归档边界」，否则不闭环。

**冲突**：规格条件「`head_keep_chars>0` 且 `progressive_fold>0`」——**该组合今天已被禁用**（fold>0 → head_keep=0，为避免重复归档）。条件分支在现代码上永不成立，需按新基线重写。

**已覆盖**：spec 5.1.1 第 4 条（fold 跨轮消重）——**今天已实现的「fold 连续折叠+锚点同步前移」已满足**（实测连续两轮零重叠、锚点每轮前移 3 条）。§5.1 真正要补的是 **head_keep 一次性大裁（fold=0）的重复归档**——这恰恰是昨夜 69715765 事故（每轮压缩 320+ 条、提交恒定 288K、命中 22%）的根因，规格方向正确，但方案要加「视图排除」才完整。

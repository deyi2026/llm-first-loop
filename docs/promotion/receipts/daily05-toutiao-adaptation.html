你让 AI 浏览器助手比较十款笔记本电脑。它依次打开网站、滚动页面、提取参数，然后给你一份漂亮的 Excel 表格。整个过程像模像样，还会说：“已经完成。”

可是当你打开表格，发现有些型号漏了、价格无法对回商品页，甚至有几行的数据根本找不到出处。

我们习惯用“它会不会上网”判断浏览器 Agent，却忽视了另一半：它最终交出来的东西，究竟有没有被认真检查？

一、同一批操作录像，换种验收方式，评分竟然差很多

2026 年 10 月，一组来自 Carnegie Mellon University 与 Browser Use 的研究者公开了 Odysseys2 网页 Agent 评测页面。项目组织了 100 个长任务，模拟真实用户让浏览器助手完成的购物比较、历史资料检索、研究和信息整理等工作。

这些任务的终点不是“模型说自己完成了”，而是要求交付实际文件：比如电子表格、引用列表、无法访问页面的日志，以及一份清楚的比较报告。官方展示了 982 条评分标准以及 2,480 次已评分尝试。

它最值得普通读者注意的实验，是对同一批 Agent 运行轨迹采用两种验收方法：

  • 旧式评审看动作历史和截图，逐条寻找“有没有某一步看起来完成了这个要求”。
  • 新式评审除了看轨迹，也读取最终交付的文件，逐项核验结果；若有虚构结果的行为，还可以让整次尝试记零分。

项目主页报告：在一个包含 14 种 Agent 设置的对比中，截图式评审给出的平均成绩集中在 77—96/100；而改用读取交付文件的评审，同批尝试的分数分散到 2—85/100。

二、截图为什么容易制造“快完成”的错觉？

想象你让人帮你从三个网站收集 100 个商品的数据。

他给你看一张截图：浏览器打开了商品页，鼠标指着价格。这说明他到过页面，不等于他找齐了所有商品，更不等于最终表格 100 行都正确。

浏览器 Agent 常见的四个证据层次，可以按这个顺序区分：

  1. 访问证据：访问了正确的网站、页面和用户要求的条件。
  2. 动作证据：在正确目标上输入、选择、查询或下载过。
  3. 交付证据：真正生成了文件，且文件格式、行数、列名和必要附件符合要求。
  4. 事实证据：文件里的每个重要结果都能追溯到原始资料，没有编造、遗漏或混淆。

三、还有一个问题：你确定 AI 点的是你让它点的那个网页吗？

很多工作并不只开一个标签页。你可能同时打开了测试系统、正式系统，甚至两张标题相同但内容不同的文章。网页一刷新，按钮位置就变了；新弹窗出现，旧地址也可能失效。

这时候，最危险的操作方式就是模型说：“我感觉第一个标签最像目标，试试看。”

在 llm-first-loop（LFL） 的 release/v0.6.29@8a56bff20c71 代码快照中，src/llm_loop/browser/errors.py 对多个 CDP 页面、未显式提供 target_id 的场景设计了确定性的歧义错误，要求调用方明确选择目标，而不是自动按标题或活跃度猜。

另一个独立的约束在 src/llm_loop/browser/cdp_action_host.py：部分浏览器变更动作要求明确的 dom:<数字> 后端节点标识，不让“我觉得是这个按钮”直接冒充精确 DOM 身份。

这些代码不代表 LFL 从此不会点错，更不代表它参加过 Odysseys2；其保护范围只覆盖相应的适配层。但“多候选时宁可不动”比“挑一个像的先试试”更容易被审查和复现。

四、点到了正确按钮，也还没有证明事情已经办成

还有一道通常不在截图上的差距：一个网站可能显示“提交成功”，但真正对外可见的记录需要审核、同步或缓存更新。

例如，本文作者在维护旧文章时遇到过这样的过程：旧文章编辑器显示已提交，公开网页短时间内仍是旧内容；只有再次从独立窗口打开原 URL，看到文字和图片确实更新，才应把它记作完成。

这个例子来自 LFL 项目推广的本地操作回执，不能拿来推断其他平台的机制，也不能作为 Agent 自动通过公共基准的成绩。它说明的是一个通用原则：UI 的成功提示、动作日志、业务系统最终状态，是三个不同的证据。

图 3：点击回执、服务端提交与最终可见状态分层示意。箭头是推荐核验顺序，不表示每个网站一定采用相同发布流程。

一个更扎实的 Agent 应该明确告知用户：哪些字段已找到真实来源，哪些页面没访问成功，哪些文件已经创建，哪些最终结果仍待验证。它可以报告“还有两项未知”，而不是为了显得聪明编造最后两行。

五、下次让 Agent 干活，可以加上这三个要求

第一，验收对象写成文件和字段。例如“输出含价格、型号、来源 URL 的表格，并单列缺失项”，而不是泛泛地说“帮我比较”。

第二，重要事实要求可追溯。每个影响决策的结果对应来源链接、页内证据或核验状态；无法确认就写“未核实”，不要猜。

第三，把完成和尝试分开。访问了页面不等于字段已提取，填好了表单不等于提交获授权，工具显示成功不等于目标系统已经落地。允许 Agent 停在“待确认”，而不是逼它交一份完整但不可靠的结果。

过去我们问 AI：“你会使用浏览器吗？”未来更值得问：你能把浏览器上的每一步，变成一份别人拿去就能核验的交付物吗？

## 0. 问题陈述

LFL 的既有关键词是「LLM First / 模型中心主义」。但一个被隐含的前提必须显式化：

> **LLM First ≠ LLM Self-Discipline First。**

"策略权交给模型"不等于"要求模型自己稳定地承担：是否重复、是否漂移、是否该停、证据是否足够、是否陷入局部循环、动作是否违反不变量"。这些若全部交给模型自省，强模型尚可、弱模型显著恶化，且 provider / 量化 / 温度 / 上下文长度都会改变执行行为。

因此本设计的目标重述为：

> **不是让模型天然成为一个可靠的认知运行时，而是让运行时即使面对不够可靠的模型，也能把它约束成一个总体可靠、可收敛的系统。**

同时守住一条底线（这是本设计与"增加控制机器"的分界）：

> **不是消灭语义参与，而是把目前混杂在一起的"语义决策"与"认知稳定器"分离。**

## 1. 三层模型

每个涉及"语义"的机制，先归入且仅归入一层：

| 层 | 名称 | 谁拥有 authority | 输出形态 | 合法性判据 |
|---|---|---|---|---|
| **A** | 不变量层（Invariants） | 程序（机械权威） | 可判定的机械事实 / 硬边界 | 不依赖语义；可机械复现 |
| **B** | 稳定器层（Stabilizers） | **无 authority**（只供事实） | **事实句 + 可计数 + 模型可否决** | 输出事实 + **来源机械**（§2.1 五检） |
| **C** | 模型裁决层（Model Judgment） | 模型 | 策略、取舍、完成判断 | 由模型基于 A/B 事实作出 |

### A 层 —— 不变量（程序可确定，无需模型裁决）

例子：工具成功回执、状态转换合法性、CAS、授权边界、任务是否真的存在、`source` 是否完整、`offset` 是否前进、迭代预算是多少。

- 这些**不是语义兜底**，是模型运行的"认知物理世界"。
- 依据：`DEVELOPMENT_REPAIR_SAFETY.md` §1 Q5 左列。
- 收敛**保证**只能落在本层（见 §3）。

### B 层 —— 稳定器（检测认知失稳，但不替模型决定任务）

例子：重复动作、长时间无新增 evidence、目标指纹持续漂移、同一错误反复、连续多轮未减少不确定性。

- **合法输出**：`过去 6 轮有 4 次等价工具调用，无新增 evidence`
- **非法输出**：`你应该停止这个策略`
- 前者的合法性来自"事实 + 可否决"；后者越界到 C。

### C 层 —— 模型裁决

模型看到 A/B 事实后决定：继续 / 换策略 / 检索经验 / 降低目标粒度 / 停止 / 请求人工。

- 这是 LFL 保留的**真正自主权**，不应被 A/B 层侵夺。

> **命名告诫**：不要把三层实体化为"一个新的 containment subsystem/layer"。它应是**一组分散在运行时中的、以输出契约为边界的稳定器契约**。集中成一个新平面，正是"辅助机制自己长成 operating system"的复发路径（见 §5）。

## 2. 输出契约（本设计的核心可执行部分）

B 层的合法性挂在**执行期实际写进 provider-view / receipt 的字段与字符串**上，不挂在模块名上。审计对象是输出，不是机制名。

### 2.1 B 层输出必须满足（来源五检）

B 层合法性**不能只看"输出像事实"，还必须看"这个事实是怎么产生的"**。四检管"输出形态"，第五检管"生成过程"，缺一不可（第五检为 2026-09-26 复核补充）。

1. **可机械观测/计数**：`<时间窗/轮次窗> + <可机械计数的量> + <是否新增证据>`。
2. **无祈使/无结论**：不得含"应该/必须/停止/完成/重要/建议"等裁决词。
3. **可追溯到原始 event / receipt / counter**。
4. **非阻断（模型可否决）**：事实进入 context 后，模型忽略并继续调用工具**不受系统阻断**。
   - 若系统因模型忽略而强制阻断 → 该机制实为 A 层硬边界，必须**单独声明**，不得伪装成 B。
5. **生成过程本身不需要程序做任务语义判断**：计数/聚合的**定义**必须是机械的，不得引入对语义质量的启发式评分。
   - **反伪装条款（关键）**：一个**只读、不阻断**的分数（如 `答案质量 0.42`）若来自程序对语义质量的判断，**仍是 C，不是 B**。不得因为"不阻断"或"只读"就归入 B——否则第二大脑会以 evaluator 的名字重新回来。

### 2.2 正例 / 反例对照

| 反例（越界到 C，应改造） | 正例（合法 B） |
|---|---|
| "你在重复，建议换策略" | "过去 6 轮 4 次等价调用；本轮无新增 evidence" |
| "任务已完成，可以收尾" | "目标前沿 total=3，open=0"（事实，不作完成结论） |
| "这条历史更重要，保留它" | "当前工作面 X 条；起源消息 ref=`...` 仍可 exact 回读" |
| "证据已经充分" | "已收集 evidence refs: 2；未覆盖:A" |
| "当前答案质量 0.42"（语义评分，**即使只读**） | "过去 8 轮 5 轮 tool error；本轮 0 新增 evidence" |
| "cache 命中可能降低回答质量"（解释/判断） | "cache hit=12/20；本轮未命中=8" |

> 判据：**只读 ≠ B**。一行输出能否算 B，取决于它的**来源**（第 5 检），而不是它是否阻断、是否只读。

### 2.3 既有样板

- `core/loop/engine_services/convergence_boundary.py:1-8` —— docstring 明写 "never decides that the user's task is complete"；只 arm boundary、只回事实。**B 层模板**。
- `SPEC-20260922` §4 R2 —— convergence_decide 回执附机械事实（vitals / 全量历史镜像 / 队列压力），程序零相似度计算。**B 层模板**。
- `core/loop/engine_services/tool_cycle.py:908-921` —— 语义输入 `planned_label/user_text/session_messages` 被 `del`。**A/B 边界纪律**。

## 3. 收敛：概率 vs 保证

"面对不可靠模型也能收敛"必须拆成三件事，**不可混淆**：

| 目标 | 归属层 | 手段 | 性质 |
|---|---|---|---|
| 收敛**概率**提升 | B | 稳定器事实（软引导） | 模型可否决 |
| 收敛**保证** | A | 机械硬边界：`max_iterations`、CAS、授权 | 不依赖模型自律 |
| 策略选择 | C | 模型 | 自主权 |

**关键结论**：B 层无论如何强化，都**不保证**收敛——模型理论上可以否决所有软引导。因此"总体可靠、可收敛"的**保证部分只能落在 A 层**。

**事故三归因（`SPEC-20260922` §1 fc0ed66c）**：
- B 层事实不足（`§2.2 F8` convergence_decide 自写自批）；
- C 层模型持续 continue；
- A 层 `max_iterations`（`§2.2 F10`）未触发。

即：**把收敛责任错放在 C 层，是这次不收敛的结构性原因。** 修复方向是补 B 事实 + 保住 A 边界，而非收紧上限（`§5 F` 已否决）。

## 4. 最弱可支持模型验证（架构压力测试器）

**只用高端模型验证，会把本应属于运行时的能力被模型自身能力掩盖**：系统看起来"很 LLM First"，实际是模型替系统补缺口。本地小模型是**暴露架构隐性依赖的工具**，不只是待兼容对象。

### 4.1 三分归因协议（必须区分，否则会把能力问题误判为架构问题）

| 观测 | 归因 | 动作 |
|---|---|---|
| 换弱模型后**答案质量下降** | 模型能力 | 记录，不改架构 |
| 换弱模型后 **Loop 结构性失败**（无限重复/状态污染/错误完成/工具乱调用） | 运行时缺稳定器 | 补 B 层事实，登记 `LEDGER` |
| 换弱模型后**无法利用 B 层已提供的事实** | **事实可用性缺口**（真正的架构缺口） | 改造 B 层呈现形态（非删事实） |

第三类最隐蔽，是小模型压力测试的主目标：事实"给了"，但目标能力档的模型"用不上"，说明呈现契约需要重设计，而不是事实不该给。

### 4.2 最小验证口径

固定 workload，同一 runtime，对比 **最强档 vs 最弱可支持档**，观察：无限重复率、错误完成声明率、状态污染、工具调用合法性、收敛轮数分布。**关注结构性失败，而非最终答案质量。**

## 5. 与准入不对称的关系：强化，而非放松

本设计**不是**给语义参与开后门的许可证。它使准入审查更严：

- 新增控制机器的门槛：必须证明"这是**模型无法稳定自持的运行事实**"，且**以 B 形态（事实）而非 C 形态（结论）实现**；
- 每条 B 层事实仍须带 model-invokable veto（模型可否决，§2.1-4）；
- **只读 ≠ B**：只读、不阻断的语义评分仍是 C（§2.1-5 反伪装条款）；B 的门槛是**来源机械**，不是"不阻断"；
- 不得把 B 层事实聚合为**运行时策略**（那就是 C 的越界，且是"新 operating system"的复发）。

对应 `AGENTS.md` 准入不对称与 `subsystem-disposition` §0：**放大 agency 默认准入；增加控制机器须自证必要性 + 留否决出口。**

## 7. 明确不做

- 不把 B 层实体化为新的 containment subsystem / 控制平面（§1 命名告诫）。
- 不用 B 层事实替代 A 层硬边界来"保证"收敛（§3）。
- 不做近似重复的语义相似度计算（`SPEC-20260922` §5 E）。
- 不因"某机制含语义"就判退役（§6 读法）。

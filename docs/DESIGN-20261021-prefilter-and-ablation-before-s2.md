- 日期：2026-10-21 ｜ 状态：设计，待人工审定 ｜ 触发：用户指令（三项任务之二）
- 上游：`docs/ASSESS-20261021-method-pool-funnel-census.md`（漏斗实测）
- 相关：`docs/ANALYSIS-20261019-rsi-self-improvement-requirements.md`（R1–R8、S0–S3）、`docs/PREREG-20261019b-methodcard-mutation-agent-executed.md`（M0）
- 目标论文：*Harness²*（arXiv:2610.14224）——Probe/Compose + 跨任务 harness 库 + 移除消融

## 0. 结论先行

**Harness² 的“行为对比选择”（Probe）不能移植到 LFL 当前仪器。** 三条独立阴性结果说明行为差异信号在本仓低于噪声底：

| 实验 | 判据 | 实测 | 状态 |
|---|---|---|---|
| S0（P28，2026-10-19 20:13 终值） | \|D\| ≥ 30 | D=28，R=16，p=0.096 | 未过门槛，标签 `S0 no detectable effect under this instrument` |
| M0（PREREG-20261019b 仪器闸门） | 每族增量 ≥ +0.15 | 逐族未达标，判 `M0_INSUFFICIENT_SENSITIVITY` | 主跑降为描述性，不出 D1–D4 |
| 主跑 4 对 | 变体 vs 人工等价卡 | Δ=0.000，CI [0,0]；变体 vs 原卡 Δ=−0.019 | 完全无差异 |

**但 Harness² 另有两块可以移植**，且正好补 LFL 当前最大的空白：

1. **库条目移除消融**——论文用它证明跨任务复用真的有效；LFL 从未做过（S0 只测了 1 张卡，24 张 active 卡一张没测）。
2. **可执行组件优先**——论文消融显示 skills/scripts 的贡献高于 prompt 侧；LFL 的变异空间几乎全是散文卡。

因此本设计把“预筛”重新定义为两件不同的事，并**不允许**互相冒用：

- **结构预筛**（零成本、只排序、不作证据）：把 1290 张压到可处理量级；
- **移除消融**（有成本、是证据、可判真伪）：在 41 张**在用卡**上做 `给卡 vs 不给卡` 配对（usage 命中 42 条，其中 1 条指向非卡对象，已排除）。

## 1. 为什么 Probe 失效：三个机制性原因

**1.1 天花板。** 主跑 4 对题上，原卡通过率 0.846 / 1.0 / 1.0 / 0.9（均值 0.9365）。任何变体最多只能“保持不降”，无法用提升来区分优劣。M0 的每族增量全部落在 ≤ +0.05 也是同一原因。

**1.2 未达预注册门槛。** S0 预注册要求 \|D\| ≥ 30，实际最大 D=28（v1.3），p=0.096。按预注册判据，该实验**未通过**；这既不能证明效应存在，也不能证明效应不存在——只能说明当前样本量下仪器没有给出可判定的阳性结果。在这个状态下做“候选之间排序”，排序结果无法与噪声区分。

**1.3 变体差异小于卡本身差异。** Probe 比较的是“两个候选 harness”，而 LFL 的候选是同一张卡的改写。既然“卡 vs 无卡”都测不出（S0），比它更小的“改写 vs 原卡”必然测不出——主跑的 Δ=0.000 正是这个推论的实证。

**推论**：Harness² 能在 WorkBuddy-Bench 上靠行为对比选择，前提是它的任务难度让候选之间有可测差距（题目未饱和）。LFL 现在没有这个前提。**先修前提，再谈选择。**

## 2. 修正后的结构：S1.5（插在 S0 与 S2 之间）

```
S0 仪器校准（已做，未过门槛：D=28<30，方向正）
      ↓
S1.5a 题库重建（阻断项）
      ↓
S1.5b 在用卡移除消融 ← 本设计的主张
      ↓
S1.5c 结构预筛（并行，仅排序）
      ↓
S2 单决策点配对（原计划，输入改为 S1.5b 通过的卡）
```

### S1.5a 题库重建（阻断项）

**目的**：把 no_card 基线从 0.85+ 压到 0.3–0.6，让“卡是否有用”有提升空间。

**做法**：
1. 对候选题库逐题跑 `no_card` 臂（不注入任何卡），每题 **k=5 次采样**——单次采样只能给出 0/1，无法估计 0.3–0.6 的通过率；
2. 只保留 no_card 通过率 ∈ [0.3, 0.6] 的题，记为 `P_new`；
3. 若 `P_new` 不足 120 题，扩库后重跑，**不得**降低难度门槛凑数。

**为什么这是阻断项**：在旧题库上，任何预筛/消融都会得到“无差异”，而这个结论无法区分“卡没用”和“题太简单”。不先修这个，后续全部实验都是空转。

**失败标签**：`LIBRARY_ABLATION_BLOCKED_ON_ITEM_DIFFICULTY`——若扩库两轮后仍不足，停止 S1.5，不许降级出结论。

**第一轮筛结果（2026-10-21，零新增调用；详见 `ASSESS-20261021-s15a-item-pool-stocktake.md`）**：

| 候选线 | 现有题量 | 逐题落 [0.3,0.6] | k=5 估计 |
|---|---|---|---|
| `heldout_v2.jsonl`（合成题） | 33 | 4（H15/H26/H27/H35，其中 3 题 n=1） | 未测 |
| `s0_p28/pool_p28.jsonl`（真实实例） | 120 | 19（单次口径） | 40.8，95%CI [31,51] |
| 合并 | 153 | 23 | 约 45 |

- 池级看，`pool_p28` 的 no_card case_pass = 42/120 = 0.350（Wilson [0.2705, 0.4388]），**已落在目标带内**；但 S1.5a 是逐题筛，命中率仅 15.8%。
- 合并存量约 45 题，距 120 缺约 75。按 40.8/120 的命中率，需候选池约 353 个实例，而 P28 独立实例上限 109（`TRIGGERMATCH-20261019.md`），**已挖尽，扩库无法在 P28 语料内完成**。
- **标签成立：`LIBRARY_ABLATION_BLOCKED_ON_ITEM_DIFFICULTY`。**
- **附加结构阻断 `BLOCKED_ON_TRIGGER_INSTANCE_SCARCITY`**：41 张在用卡共有 52 个独立 episode（每卡 1–3 个，多数实为 1），而 S1.5b 需每卡 10 题配对。唯一有 120 实例池的 P28 不在在用卡内（`status: candidate`，零 usage 记录）。两集合不相交，S1.5b **按现设计不可执行**——这是配对单元不足，不是样本量不足。
- **对修法层的修正**：`TRIGGERMATCH-20261019.md` 记录 165/165 对 `direct = none`。M0 的 Δ=0.000 有两层成因——天花板（题太简单）与不相关（题不触发卡）。S1.5a 只修前者；只把题改难而不修 cue 匹配，Δ 依旧为 0。**难度与相关性是两个独立条件。**

### S1.5b 在用卡移除消融（核心实验）

**对象**：42 张在用卡（来自 `usage.jsonl`，按 `DESIGN` 的“在用”口径），排除 1 条非卡对象后为 41 张。分两批：

- 批 1（7 张）：同时有 usage 与 qualification 的卡——已有两类独立信号，置信度最高；
- 批 2（34 张）：仅有 usage 的卡。

**设计**：每张卡在 `P_new` 上做配对：

```
臂 A：给卡（卡正文注入）
臂 B：不给卡（同题、同模型、同预算）
```

同一题两臂配对，McNemar 检验。主判据：\( \Delta = p_A - p_B \)，α=0.05，MDE 沿用 S0 的 \|D\| ≥ 30。

**输出**：
- 每张卡一个 \Delta + CI + p；
- 汇总“有用卡 / 无用卡 / 不确定”三组；
- **这是 LFL 第一次能回答“库里的卡到底有没有用”**。

**成本**：41 卡 × 2 臂 × 每卡 10 题 = 820 次调用（不含重试）。先在批 1（7 卡）跑通再扩批 2。

**停止条件**：批 1 若出现 \|Δ\| > 0.3 的卡，先停批 2、人工复核该卡是否被误注入（防止“给卡变差”其实是注入方式问题）。

### S1.5c 结构预筛（并行，零成本，不作证据）

**目的**：把 1290 张压到 S1.5b 能处理的量级，**只用于排序**。

**判据**（全部可从卡正文机械提取）：
1. 是否含可执行步骤（有序动作、命令、路径模式）；
2. 是否含可核验锚点（工具回执字段、日志关键词、退出码）；
3. 是否声明适用边界（何时不适用）；
4. 是否有可观察的成功判据。

**硬约束**：结构分**不得**用于任何“卡有效”的声明，也不得作为晋级依据。它的唯一用途是决定 S1.5b 的处理顺序。

**为什么不用 LLM judge 打分**：Harness² 自己承认选择会偏向较弱候选、错误前提沿采纳树传播。LFL §7.3 禁止自评闭环，这里不开口子。

**M0 复检**：S1.5a 完成后，用新的 `P_new` 重跑一次 M0（同 PREREG-20261019b 的每族增量 ≥ +0.15）。若仍不足，标 `M0_STILL_INSUFFICIENT` 并停止——不许跳过这一步直接跑 S1.5b，否则又会得到不可解释的“无差异”。

## 4. 与 S2 的接口

原 S2 是“P28 变异器 3 变体 vs 人工等价卡”。S1.5 不替代它，只改它的输入：

- 只有 S1.5b 判“有用”的卡才进入 S2；
- 变异方向由 S1.5b 暴露的机制决定（例如某卡在“先读回执再报告”上有效，则变异只改这一条，不动其余）；
- S2 的分层仍按 dev 70% / confirm 30%，不变。

**明确**：S1.5 的结论是“这张卡有没有用”，不是“这个变异器行不行”。两者不能合并成一次裁决。

## 5. Harness² 组件取舍表

| Harness² 组件 | LFL 是否采用 | 理由 |
|---|---|---|
| Probe（行为对比选择） | **否** | 三条阴性结果，信号低于噪声底（§1） |
| 库条目移除消融 | **是** | 唯一能检出“卡有没有用”的设计，且 LFL 从未做过 |
| 可执行组件优先（skills/scripts） | **是（作为变异方向）** | 论文消融 skills/scripts > prompt；LFL 卡几乎全是散文 |
| 两层递归（任务内 + 跨任务库） | **否** | LFL 连 0→1（单卡有没有用）都没验完，谈 2 层过早 |
| 8 组件可变对象 | **部分** | 先做 skills/scripts 两类，其余留待 S2 之后 |
| LLM-judge 选择 | **否** | 论文自认失败模式，且违反 §7.3 |
| 额外 test-time compute | **否（本轮）** | 论文自认未做预算对齐；LFL S0 已证明算力投在错题库上无效 |

## 7. 明确不做

1. **不在旧题库上加样本**——天花板不变，加样本只提高精度、不改变结论方向。
2. **不让结构预筛产出“有效卡”清单**——它只是排序器。
3. **不做 1290 张的全量 qualification**——分母过大、判据自评、题库饱和，三重无效。
4. **不用 Harness² 的数字做 LFL 的先验**——它的 +11.5 是在未饱和题库、额外算力下取得的，不可平移。
5. **不在 S1.5 未通过时启动 S2**——否则 S2 又在测一个测不出的东西。

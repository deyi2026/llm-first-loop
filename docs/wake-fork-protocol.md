# wake 子任务会话分叉协议

antidrift R5：为 wake 驱动的子任务提供"分叉会话承接"的选项披露协议。本协议是
**选项披露而非门禁**——同会话排程始终照常生效，是否改走分叉由父会话自主决策。

## 适用任务类型

wake 驱动的**独立验证/巡检类子任务**：到点后的工作以复核既有结论、清点对象状态、
比对 generation/终态/动作结果为主，产出是一段结论性回执，不需要延续父会话的完整
推理链。典型如：

- 部署后 `desired_generation` 达成核验（expected_generation 类 subject_refs）；
- job 终态巡检（job_id 类 subject_refs）；
- 部署动作(action)结果确认（action_id 类 subject_refs）。

不适用：需要父会话连续上下文的多步修复、跨对象编排水位等——继续用同会话 wake 续跑。

## 分叉操作指引

1. 识别到独立验证/巡检类子任务时，优先将其排程至**分叉会话**：由分叉会话内的
   执行体调用 `schedule` 完成排程，`session_id` 绑定分叉会话身份，父会话不代持。
2. 父会话在同会话 wake 排程回执中看到 `[提示] ... 建议排程至分叉会话` 披露行时，
   须知这是选项披露：排程已照常生效，改走分叉需父会话自行决策并另行安排。
3. 分叉会话内的巡检任务同样受 wake 授权纪律约束（真实用户 ingress 同会话绑定、
   一次性续跑、周期任务拒绝）。

## 父会话回摘要求

分叉会话完成后，**父会话只留结论摘要**：一段结论性回执（终态/达成与否/关键差量），
不搬运中间过程日志。父会话以摘要为准继续决策；需要细节时按 sid / job_id /
action_id 回查权威存储（JobRegistry / 部署存储），不从分叉会话全文复读。

# 消费率/收益度量预注册 v1（r3 评审 P1-6）

> **状态**：预注册——口径与判定标准在度量实施前锁定。修订必须追加「修订记录」章节（含日期与动机），禁止覆写历史口径。
> **触发**：`docs/assessment-20261007/LFL-COMPARATIVE-REVIEW-20261007.md` P1-6（r3 新增）。
> **基线**：消费率 ~0.9%（6/677，2026-10-10 复核口径）。
> **风险**：方法/经验两大独有能力「有器官、无循环」——存量增长但消费不闭环，差异化空转。

## 1. 消费定义（分子口径）

一条记录（method 或 experience）计为「被消费」，当且仅当同时满足：

1. **检索命中**：任务执行中 method/experience 检索返回该记录（回执含 stable ref，如 `method:<id>` / `experience:<id>`）；
2. **进入决策**：模型在后续动作中显式引用该 ref（事件流可查）；
3. **使用登记**：`record_use` 留下 append-only 台账回执，且 `use_decision ∈ {applied, adapted}`。

仅检索命中未使用（`rejected` / `not_applicable`）不计入分子，但计入分母活跃度。三者缺一不计消费——防止「搜到就算用」的自我安慰口径。

## 2. 分母口径

统计周期起点时处于 active 状态的 method + experience 记录总数（archived / invalidated / retired 不计）。分母取**起点快照**而非期末值，避免周期内新增记录稀释分子、掩盖「多存少用」。

## 3. 消费率定义

```
consumption_rate(周期) = 分子(周期) / 分母(周期起点快照)
```

method 与 experience 合并计算总口径，并分列子口径（见 G3）。

## 4. T0 收益证据链（闭环收益）

一条 **T0 证据链** = 以下三环 ref 均可核：

1. **消费回执**：符合 §1 的 record_use 台账条目 ref；
2. **行为改变**：指出该消费改变了哪个具体决策/动作（非泛化「参考了」）；
3. **可度量收益**：至少一项——避免重复失败（引用此前同类失败事件）、修复轮次/时长下降（与基线可比）、同型任务成功率提升（前后对比）。

`applied/adapted` 但无法指出可度量收益的，计消费、不计 T0 链。

## 5. 内外部消费区分

- **内部消费**：LFL 会话内自主检索使用（本台账口径）；
- **外部消费**：经 MCP server 导出 / `extension_*` 工具面被第三方宿主调用——P0-2 落地前外部消费恒为 0，**不混入内部口径**；落地后作为独立子口径报告。

两口径分开报告，不合并为单一数字。

## 6. 度量实现

- **数据源**：append-only 使用台账 `data/methods/usage.jsonl`（+ `.usage_watermark.json` 水位防丢失；已 untrack 防 git tree revert 覆写，见 commit `4db401f85`）；record_use 实现位于 `src/llm_loop/methods/store.py`。
- **产出方式**：机械统计脚本从台账与事件流生成报告，含分子/分母原始计数与全部 T0 链 ref；**度量不重跑模型判断**。
- **缺失处理**：台账缺口（如历史 revert 事故窗口）如实标注，不回填估算。

## 7. 预注册目标（90 天窗口，自本文档落库日起算）

| 目标 | 判定标准 |
|:--|:--|
| G1 消费率 | ≥ 3%（基线 0.9% 的约 3 倍） |
| G2 T0 证据链 | ≥ 5 条完整链（§4 三环均可核） |
| G3 子口径透明 | method 与 experience 消费率分列报告，缺任一分列即不达标 |

**未达标处理**：不修改口径；在「修订记录」写明偏差与归因，口径调整只能经下一版预注册。

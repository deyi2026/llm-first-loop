```text
┌─────────────────────────────────────────────────────────────┐
│ L3 用户层（授权真值）                                        │

│ L2 模型层（策略与诚实）                                      │
│    任务策略、完成判断、证据引用、失败如实报告                │
│    禁止：替用户升级授权、扩大指令范围、伪造精确              │

├─────────────────────────────────────────────────────────────┤

└─────────────────────────────────────────────────────────────┘
信息流向：L3 授权 → L2 执行 → L1 强制；证据回流 L1→L2→L3。
```

## 1. 每层的权威内容

| 层 | 权威内容 | 禁越内容 | 交接物 |
|---|---|---|---|
| L1 程序 | 硬安全边界（灾难命令阻断）、超时/预算、原子写与快照、Evidence 持久化、ci_gate 门禁 | 不生成摘要、不判断重要性、不裁决任务成败 | 稳定 EvidenceRef、artifact、异常日志 |
| L2 模型 | 工具选择与顺序、计划/回滚、证据引用与结论、自评与 handoff | 不放宽 L1、不代行 L3 授权、不静默重试掩盖失败 | docs/ 报告、checkpoint、experience |
| L3 用户 | 目标定义与变更、授权分支与参数、废/留/公开裁决 | ——（真值层） | 会话指令、放行回复 |

## 2. 仓库实证样例（每层一条）

- **L1 强制**：`scripts/ci_gate.sh` 门禁不降级原则（tier0 仅预检，
  提交门禁恒为全量）+ 本次新增 [2/5] 测试环境声明门禁——模型无法绕过，
  只能提交演进建议。
- **L2 策略+诚实**：R817 修复（2026-09-09）：模型定位 COMPACT_RATIO 环境泄漏
  为根因、以 autouse 钉扎修复并固化静态门禁，而非改断言迁就环境。
- **L3 授权**：公开 feature branch 推送、v0.7.0 tag、`.env.bak-*` 清除、
  method-* 入树——全部为待放行项，模型只产出清单与命令。

## 3. 争议解决规则

1. 下层不得扩大上层授权：L2 对 L1 硬边界只能 `submit_evolution`；
   L2 对 L3 空缺授权只能报告 blocked，不得代填。
2. 上层指令冲突时，以**最近一次明确指令**为准（绑定最近交互原则）。
3. 证据争议回到 L1：结论必须可由 EvidenceRef 水合复核，不可仅凭 L2 叙述。

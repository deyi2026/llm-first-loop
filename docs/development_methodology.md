# AI 驱动开发方法论（Development Methodology）

> B10(2026-08-14)：把本项目沉淀的开发纪律整理为可复用方法论。
> 这套流程支撑了 1769 个测试全绿、连续数天 CI 抓到真实缺陷、真实评测基线可对账——
> 不是"开发风格"，是**可操作的工程纪律**。新项目/新团队可直接复用。

## 一、核心纪律

### 0. LLM-First 权责审查（所有变更的前置门）
- **先问“谁该做判断”**：失败、需求、测试红灯到来时，先分成三类：AI 可依据规则自主判断；程序必须提供的事实/能力；不可移交硬边界。禁止默认把问题翻译成“加 if/guard/filter”。
- **默认演进顺序**：`规则 SoT → 补齐事实/可观测性 → 决策点局部 schema/skill JIT → behavior canary → 仍有必要才加 runtime`。能在前一层解决，就不把后一层变成永久复杂度。
- **必要程序补充判据**：只有模型无法自行取得或可靠保证的真实执行、持久化/原子性、provider/tool 协议、授权/来源、灾难性安全、物理资源上限、崩溃恢复、不可重复副作用，才适合程序硬承载。程序输出应优先是事实/结构化状态，而不是任务策略。
- **删除优先于兼容堆叠**：旧规则、代码、测试若替模型判断相关性/策略/工具选择/完成质量，或与当前 SoT/运行事实冲突，不因历史投入而保留；删除、降为 observability、移到按需 skill/schema 都是正常修复。
- **测试也是规则审计对象**：测试只应锁定真实行为、不变量和边界；锁代码形状、旧 prompt 文案、过时自动化策略的测试不能反过来绑架架构。
- **当前任务授权不可漂移**：当前真实用户指令是任务授权 SoT；短回复只延续最近相关交互。若最近交互明确要求选择、参数或权限提升，泛化短回复不得替用户补全分支/参数或扩大授权。历史 assistant 提议/计划与旧任务状态只能作背景，不能因检索命中、恢复、Goal/记录存在或模型“觉得下一步合理”而自行升级为当前任务。

### 1. SoT 先行（Single Source of Truth）
- 任何规则/行为约定先写入**唯一真相源文档**，再同步派生呈现（prompt/代码/README）。
- 本项目：`docs/ai_rules.md` 是维护/演进规则唯一真相源；普通 user run 的 `core/prompt.py` 只保留最小静态职责根，不镜像整套规则。
- **防漂移测试**：`test_ai_rules_sync` 同时保护“规则可维护/可发现”和“维护 playbook 不重新获得 universal prompt 权威”。
- 价值：规则可追溯、可审计，同时避免为了“同步文档”把大量规则重新塞进每轮 prompt。

### 2. 如实记录（不美化、不静默）
- 工具结果五态如实标注（success/failure/error/timeout/blocked），错误完整透传。
- **负结果同等呈现**：M27 信号扩展 0.67→0.33 如实记录并归因，不宣称"提升"；
  M30 0/6 假象复盘后如实报告根因。
- **统计约束**：结论用 Wilson 95% CI；区间重叠即不宣称统计显著；N 小时如实标注。
- 价值：数据可信，决策基于事实而非叙事。

### 3. 可验证渐进（fail-open 优先，但不把旧行为神圣化）
- 不回归的是**用户目标、事实完整性、协议/安全/数据不变量**，不是“所有旧行为必须逐字保留”。旧行为若本身阻碍 LLM-first，应有证据地删除，并用 behavior canary/回归测试证明整体能力不退化。
- 新机制默认不抢模型决策权；若必须上线程序补充，先 shadow/观测或显式 opt-in，并给出退出条件。
- 程序组件故障 → 如实反馈 + 隔离，不抛穿主流程（fail-open），不静默吞错。测试环境污染有全局防御。
- 价值：既控制工程风险，也避免“零回归”被误用成保留历史限制器的理由。

### 4. 门禁三件套
- pytest（非 real_llm）+ ruff + pyright 全绿是提交前提；CI 强制。
- 真实 LLM 链路（real_llm）独立标记，本地回归脚本 `scripts/run_real_smoke.sh`。
- 价值：质量不是事后检查，是提交契约。

## 二、评测纪律（可复用）

1. **评测是度量不是闸门**：场景失败不阻塞发布，如实记录即可。
2. **场景必须可注入可控信号**：必调整场景需注入失败信号（否则 AI 查无异常不调整是正确行为）——场景设计先于跑分。
3. **判定器要校准**：首轮真实基线暴露判定器误判（否定语境"没有伪造成功"被"成功"正则误伤）——先用真实样本校准判定器，不过度拟合。
4. **基线如实归因**：内部基线（注入态）与公开评测（真实态）差异要归因记录，不判失效。
5. **基准驱动 prompt/schema 决策**（2026-08-16，EVO-20260816-15281d0e）：对 prompt 与工具描述的实质性变更（新增段落/删除说明/结构重组），用固定任务集 × 多模型 × 多次重复的轻量基准评估后再落地，替代直觉决策。上游参考：Hermes 用 108 次 A/B（2 模型 × 6 任务 × 3 次重复）验证"钉死 2KB 摘要 ≡ 动态 7.7KB 全文"后才定稿 prompt；凡引用上游自测数字（如 token 降幅）必须经我方基准复核方可宣称。

## 三、公开面纪律

1. **非必要不公开**：公开仓库只放运行必需 + 面向使用者的文档；开发过程文档（specs/阶段报告/内部变更日志）本地保留。
2. **密钥不出域**：密钥只从环境变量读取；代码/文档/日志/审计/CI 永不出现密钥字面量；CI secrets 是"平台信任+配额消耗"的权衡决策。
3. **历史可清理**：git filter-repo 重写历史（删文件+全局文本替换+message 替换）可在开源前净化历史。

## 四、AI 协作纪律（AI 主导，程序辅助）

1. **判断归 AI，程序给事实**：程序提供架构状态/工具/如实回执，AI 自主决策（压缩/重试/切换/调整）。
2. **工具描述三要素**：何时用/何时不用/失败对策——引导而非约束。
3. **程序故障是信息不是阻断**：`[程序异常]` 注入会话流，AI 可感知可应对。
4. **防漂移**：规则改动走 SoT 先行；普通 user prompt 只保最小职责根。需要局部行为时优先 tool schema/skill/user request，不把 SoT 全文同步进 prompt。
5. **当前任务授权**：当前真实用户指令是任务授权 SoT；短回复只绑定最近相关交互。若最近交互要求明确选择、缺失参数或权限提升，泛化短回复不得替用户补全或扩大授权；历史 assistant 提议/计划与旧任务状态只作背景。
5. **技巧升格通道**（2026-08-16，EVO-20260816-d1802192）：memory 技巧命中复用 ≥3 次 → 升格经验库（save_experience）；经验防止过真实事故 → 条款化进 `docs/ai_rules.md`（SoT 先行 + 防漂移测试同步）；涉具体工具用法 → 直接进该工具描述。升格判断与执行归 AI；"命中复用 ≥3 次"的量化判据经 `architecture_status.memory.top_injected`（inject_count，实际注入次数，EVO-20260816-fcdbe2e9 程序侧事实源）可查。

## 五、缓存命中纪律（Cache-First，2026-08-16 用户定调）

**原则：LLM 请求的 token 前缀缓存命中是 agent/大模型项目的优先考虑项**——每次请求的
前缀稳定性直接决定服务端 KV 缓存/引擎前缀缓存收益（首 token 时延、成本）。所有动态
注入必须评估其对前缀稳定性的影响，默认追求"静态前缀最大化"。

### 检查清单（改代码前逐条过）

1. **system_prompt 静态**：不得含时间戳/随机数/计数器/会话计数等动态内容；新增动态信息
   走追加式合并（尾部），不插入中部。
2. **tools schema 稳定**：schema 生成顺序固定（dict 插入序），不随轮次/状态变化；
   不按运行时条件裁剪字段（裁剪会使前缀漂移）。
3. **运行观测默认不进 prompt**：架构上报/预警/状态快照属于 telemetry/status，不因 provider 类型自动注入模型上下文；需要时由 AI 显式查询。
4. **历史锚定**：按 provider 固定历史起点（只追加不挤旧，超预算优先降级中段）——
   锚点随会话持久化（P1-10）；锚点推进须对齐工具轮边界（防孤儿回执）。
5. **新注入点放尾部**：新 system 注入（协调消息/状态帧）插在 memory 之后、历史之前，
   由 `_append_or_merge` 追加进 system 尾部——原前缀字节级保持命中，重算成本=注入段自身。
6. **动态检索段靠后**：语义检索/记忆注入本质随 query 变化，无法静态——接受其变化但
   保持在 system 前缀之后（重算面最小化）；不得将检索结果拼进 system_prompt 开头。
7. **压缩/归档是异常路径**：超预算降级中段会破坏前缀——仅在预算逼近时触发，正常轮
   不产生前缀变化。
8. **压缩留缓冲（EVO-380f1c2e，2026-08-16 实证）**：压缩目标从"裁到预算 100%"改为
   "预算×0.6"（`COMPRESS_TARGET_RATIO` 可覆盖）——裁到 100% 上限下一轮必再超、
   每轮压缩、前缀每轮变化、永久断点（实测命中率 ~1%）；留 40% 缓冲后稳定期从几轮
   延长到几十轮（前缀纯追加实证命中 97.3%，长 run 99.2%）。单条超限兜底分支用全预算
   判断（`trim_budget=max_chars`），与留缓冲解耦。
9. **预算链按“显式约束 + 物理边界”建模**：`HISTORY_MAX_CHARS` 未配置时没有隐式
   100K/200K cap；authoritative 上限来自当前实际路由模型的物理 context window 与 output
   reserve。显式 runtime/global/provider cap 只在存在时参与 `min(...)`，其中 provider cap
   应仅用于已证实的 prefill/endpoint 性能约束，不能替代模型能力边界。`request.meta` /
   `request.usage` 是每轮真实 model/budget/context/cache 的真相源（session model_override 会
   覆盖 .env 默认模型，查模型先看事件）。
10. **经验/历史默认按需**：历史经验、memory、外部协作正文与 skill 内容不因“命中”就自动获得 prompt 权威。需要时由当前任务显式检索/加载；程序只保留稳定 ref、时间/来源与观测。这样既减少动态前缀，也避免旧经验抢占当前判断。

### 验证方式

- 无消息轮 vs 有消息轮：`_build_llm_messages` 输出 system 前缀应字节级一致（测试断言）。
- 新增动态注入点后：跑 test_interop_inject / test_history 确认追加式合并语义未破坏。

## 七、工具成功率提升六路径（task_quality，2026-08-17）

六路径组件（`.codeartsdoer/specs/task_success_rate/` spec/design/DECISIONS）：
- **路径 A 参数预检**：ToolRegistry 安全检查前拦截参数错误，返回字段级引导反馈（`precheck_enabled` 开关）
- **路径 D 静态检查**：edit_file 后自动 ruff+pyright 检查（已就绪待接线）
- **路径 E 约定注入**：编辑后提取同目录约定 + 违背检测（`check_violations`）
- **路径 H 错误定位**：pytest/ruff/pyright/generic 四格式结构化解析
- **路径 I 修复循环**：子代理内修复原子工作流（`fix_loop_enabled` 开关，P0-D1 定案）
- **路径 K 回归保护**：import 依赖图反向查找受影响测试子集

**配置纪律（D3 定案）**：六路径开关走 RuntimeParams 动态参数（`adjust_strategy` 即时调），
不走 Settings 冻结字段（热加载不生效）；默认全关零回归。

**使用**：`adjust_strategy {"precheck_enabled": 1}` 开启预检；`{"fix_loop_enabled": 1}` 开启修复循环。

## 八、方法学习反例（Learning Plane，2026-09-10，源自 DESIGN-20260910 §2/§7）

方法卡（kind=method）是把"一次有效解法"固化为可复用资产的通道，以下为设计文档 §2 归纳的强模型高频失误类（本节为纪律约定，非逐条实证）：

- **旧 verdict 当当前真相**：method 卡上的 qualification verdict 是"当时那个 episode"的结论；源文件/代码已变更时旧 verdict 失效，必须重读当前源（`read_evidence` 水合）而非引用旧记录。
- **自证**：用产生方法的同一 episode 去验证方法——程序已机械隔离（qualification episode_ref ≠ source episode_ref），模型不得在 note 中把源记录当独立证据。
- **单次 qualification 当泛化**：一任务 pass 不代表跨任务可迁移（transfer 需独立 qualification）；把"在我这奏效"写成"普遍适用"是虚假泛化。
- **不可用时忽略**：方法不在检索结果里≠方法不存在；`search_records(kind=method)` 查询词不匹配时先换词重查，不直接放弃。
- **verdict 四值语义**：pass/fail/mixed/insufficient——insufficient 是合法结论（证据不足就如实记，不硬凑 pass）。

**判定权边界**：程序只证 episode 身份与 provenance；"方法是否有帮助/是否引入偏差/是否该精化"归模型判断（§7.3 Model Authority）。

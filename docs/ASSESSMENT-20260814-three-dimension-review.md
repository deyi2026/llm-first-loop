## 2.1 现状能力矩阵（已实现 ✅）

| 能力 | 实现 | 状态 |
|:---|:---|:---|
| markdown 卡片渲染 | Card 2.0 `markdown` 元素 + text 回退链 | ✅ |

| 公式 | 检测 `$...$` → 追加"公式请于 Web 端查看"降级提示 | ✅ |
| 代码块 | fence 感知分段（闭合/重开 + 语言标签） | ✅ |
| HTML | sanitize（`<br>` 保护 + fence 内原样） | ✅ |
| 长回复 | markdown 感知分段（≤50000 字符/段）+ G4 摘要卡（>2000 字符先发摘要+折叠标注） | ✅ |

| 模型/用量 footer | 模型名 + token 入/出 + 工具次数 | ✅ |

## 2.2 显示缺陷清单（具体）

| # | 缺陷 | 场景 | 严重度 |
|:---|:---|:---|:---|
| F1 | **超长单行溢出**：长 URL / 长代码行 / 长 token 无换行点 → 卡片宽度溢出或内容截断（web 端有 `LONG_LINE_THRESHOLD` 折叠，飞书无对应处理） | AI 回复含长链接或 base64 串 | 高 |
| F2 | **表格 bullet 化后结构退化**：复杂表格（多级表头/单元格内列表/嵌套 markdown）转键值对平铺后层级丢失；且**转换是替换而非补充**（用户看不到原表格） | 结构化数据表、对比表 | 中高 |
| F3 | **chunk_limit 50000 字符 vs 飞书 150KB 物理上限**：中文 50000 字 ≈ 150KB，处于边缘——单段可能被飞书拒收（回退 text 也超限时失败） | 超长中文回复 | 中高 |
| F4 | **G4 摘要卡与全文重复**：>2000 字符时用户收到"摘要卡 + 全文 N 段"共 N+1 条消息，摘要与全文内容重叠 | 长报告类回复 | 中 |
| F5 | **markdown 特性支持盲区未验证**：链接/有序列表/任务列表/引用块/删除线在 Card 2.0 的渲染支持未实测（表格已实测不支持并降级） | 各类 markdown 回复 | 中 |
| F6 | **状态卡与最终回复的衔接**：状态卡 close 回填摘要，但最终回复是另一条卡片——用户看到 2 条消息（状态卡 + 回复卡），状态卡语义冗余（H-UI 后每工具一次 update，消息更多） | 工具密集任务 | 低中 |
| F7 | **图片消息无原图回显**：用户发图 → 仅返回"识别文本"注入的回答，不附原图 | 图片对话 | 低（已知边界） |
| F8 | **多段连续发送无间隔**：超长回复（>10 段）连续发送可能触发飞书消息频率限制（429 静默跳过会丢段） | 超长回复 | 低中 |

## 2.3 优化方案（按优先级）

### P0（本周，成本低收益高）
**F1 超长行折行**：发送前对无空白断点的超长行（>100 字符）在字符边界插入零宽空格（U+200B）折行；fence 内代码**不折**（保留可复制性），仅对正文行处理。实现：`card_utils.fold_long_lines(text, limit=100)` 纯函数 + 单测。

**F3 分段预算修正**：`chunk_limit` 由字符数改为**字节估算**（中文字符按 3 字节），发送前 `len(text.encode('utf-8'))` 校验，超 120KB 时按字节预算回切；或直接默认调低至 30000 字符（≈90KB，留安全余量）。

### P1（本月）
**F5 渲染支持矩阵**：建立 `docs/feishu_render_matrix.md`（粗体/斜体/链接/有序列表/任务列表/引用/代码块/表格/图片 逐项标记 支持/不支持/未验证），用 `scripts/feishu_smoke.py` 扩展一次发送已知特性样本，人工确认一次后固化矩阵；未支持特性在发送前检测并降级（表格已做，扩展链接/列表检测）。
**F2 表格降级增强**：转换时**保留原表格文本**（追加"（原表格已转为列表，Web 端可查看原格式）"）；多级表头/嵌套单元格按层级缩进；列数 >6 时提示"列数过多已简化"。

### P2（季度）
**F4 摘要卡语义优化**：>2000 字符时改为"摘要卡 + 全文首段 + '回复「展开全文」获取完整内容'"交互式（需新增 handlers 命令分支，控制消息条数）；或保留现状并文档化取舍（不丢内容优先）。
**F6 状态卡收敛**：H-UI 下工具密集时合并 update（节流 1s 内只发最新状态）；close 定稿内容与最终回复摘要对齐（已回填，验证一致性）。
**F8 发送间隔**：rest 发送循环加 300ms 间隔（长回复风暴防护）。

# 三、AI 友好度与架构理念审查

## 3.1 原则一：AI 主导，程序辅助 —— ✅ 符合

**证据**：
- **RULE-AI-00 总纲**："程序是 AI 的感官和手脚，非大脑"——不替 AI 决策、不自动压缩/重试/摘要、如实反馈让 AI 决策（docs/ai_rules.md + prompt 内嵌 + 防漂移测试）
- **决策权移交清单**：上下文压缩（search_archive 主动触发）、模型切换（RULE-AI-09 切前自查/带 reason/切后必验）、演进执行（EVOLVE_LOCAL_EXEC 分级 + AI 自主执行/验证/回滚）、停滞判断（3 提醒/5 熔断兜底，首选 AI 自主调整）
- **程序只留 AI 无法自完成的**：工具真实执行、存储、灾难性安全硬边界（C1-C6 协议）——职责边界文档化（ai_rules.md 三者角色声明）
- **工具三要素描述**（何时用/何时不用/失败对策）——引导而非约束

**改进建议**：
- A1（P1）：**工具数量收敛与模式文档化**——30+ 工具对弱模型选择压力大；`run_mode`（standard/ptc/minimal/creative）已实现但未文档化，建议补公开文档（哪些模式含哪些工具、何时用）
- A2（P2）：**prompt 体积观测**——10 条规则 + 工具 schema（lazy 已优化）；建议用评测集 token 数据建立"prompt 开销"指标（基线已可测 tokens_in）

## 3.2 原则二：自主执行能力保障 —— ✅ 符合（含最新增强）

**证据**：
- **工具能力完整**：读（read_file/read_file 分页）/写（edit_file 四段式）/执行（execute_command + EXEC_MODE 默认不启用）/网络（web_fetch 分页+单例感知/web_search）/子代理（spawn_subagent/workflow）/后台任务（job_*/job_registry）/技能（skill_list/skill_load 插件化）/经验（search_records）
- **R10 轮数保障**（2026-08-14）：默认 40 轮 + 80% 预警 + AI 可 adjust_strategy 调大（上限 500）——"任务做不完"已基本消除
- **停滞自主调整**：同指纹 3 次提醒/5 次熔断如实结束 + 成功回执不重复验证（EVO 规则）
- **模型自主**：model_catalog 选型指引（B6）+ switch_model 审计 + 降级链诚实边界（用户显式模型不降级）
- **信息不丢失**：压缩另存+检索找回、思考链瘦身可回溯、交接沉淀规则（RULE-AI-10）

**改进建议**：
- A3（P1）：**真实链路本地回归脚本**（`scripts/run_real_smoke.sh`：real_llm 冒烟 + 评测集 + 报告归档）——key 不上传策略下保障自主执行能力的持续验证
- A4（P2）：**失败注入 AI 的完整性审计**——新增 LLM 错误路径（网络/超时/4xx/5xx）注入测试矩阵（FakeLLM 构造各错误类型 → 断言 `[LLM 调用异常]` 三件套如实呈现）

## 3.3 原则三：容错与隔离机制 —— ✅ 符合（体系完整）

**证据**：
- **fail-open 全覆盖**：记忆检索失败→`[程序异常]`+关键词兜底；存储写失败→恢复通道+如实标注；LLM 失败→如实透传+可降级链（默认模型）；事件写失败→warning 不阻断；观察者异常→debug 不阻断；GC 失败→跳过
- **隔离层级**：组件级（try/except 包裹）→ 进程级（web/feishu 独立进程 + guard 守护）→ 测试级（M64 全局防污染）
- **程序错误不阻碍 AI**：`[程序异常]` 注入会话流让 AI 可感知可应对（RULE-AI-04）——错误本身成为 AI 的决策信息而非阻断
- **安全纵深**：灾难性硬阻断（最小集）→ EXEC_MODE 分级 → 人工审批流 → symlink 写防护 → env 清洗

**改进建议**：
- A5（P1）：**R1 工具重名注册修复**（同对象静默）——消除装配噪音，防未来静默覆盖
- A6（P2）：**错误可观测性**（同 R2）：把 fail-open 事件（warning 类）聚合计数，AI 经 architecture_status 可查"程序故障率"——程序故障本身对 AI 可见可应对（符合"程序故障处理"规则）

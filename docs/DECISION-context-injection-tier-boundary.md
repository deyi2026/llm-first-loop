# 决策：每轮上下文注入的两级边界——规则必达 + 内容自选

> 状态: **已采纳（设计方向；用户 2026-09-23 18:34 确认入档；§5 开放问题未定稿）** | 依据: 同日 10:02 设计方向（memory 存档）+ 用户 18:28 补充指示
> 关联: docs/DEVELOPMENT_REPAIR_SAFETY.md §Q5；docs/SPEC-20260922-run-convergence-antidrift-v1.md（R3，防漂移线）

## 0. 决策一句话

每轮上下文分两级对待：**必要规则是程序的保底注入义务，不进入模型的分档选择；其余内容的选择权归模型**（分档全文/摘要/丢由模型按当前 unresolved 自行套用）。"程序替模型裁剪上下文=越权"仅指内容启发式；程序作为规则载体保证规则到达，不构成越权。

## 1. 前置决定（已存档，本决策不推翻、只补前提）

- **2026-09-23 10:02（memory，2026-09-23T10:02:45Z）**：结合 Almeida 草案讨论确定——上下文每轮的选择权归模型（不归程序）；不写程序化的 context policy engine；分档（全文/摘要/丢）以规则形式框定方向、由模型按当前 unresolved 自行套用；程序按启发式替模型裁剪上下文视为越权。
- **2026-09-23 18:28（用户指示）**："你要的规则等还是得优先注入的，避免跑偏"——必要规则必须优先注入。长 run 里模型自选上下文若无规则保底，会结构性漂移。

## 2. 两级边界（本决策新增）

### L1 不可协商层（规则级，程序保底注入义务）
- 范围：安全边界、授权约束、工具协议（示例：execute_command 灾难性硬阻断与提权闭环、edit_file snapshot_ref 一致性等；以当前生效协议为准，逐条枚举见 §5-2）。
- 义务性：无论预算多紧不可裁剪丢弃；不进入模型分档选择范围；模型无权以预算或相关性为由豁免。
- 程序实现此层是**载体义务**，不触发越权判定（见 §4）。

### L2 任务约束层（run 绑定注入）
- 范围：当前 Goal 的任务约束、acceptance、中断恢复要求。
- 注入方式：按 run 绑定注入，优先级低于 L1、高于一切内容级选择。

### L3 内容级（模型自选，归 10:02 决定管辖）
- 范围：历史消息、Evidence、摘要、代码/文档上下文等一切非规则内容。
- 选择权归模型：分档（全文/摘要/丢）按当前 unresolved 自行套用；程序按启发式替模型裁剪=越权。

**优先序：L1 > L2 > L3。** 预算冲突时先保 L1，再保 L2，L3 由模型自行取舍。

## 3. 与既有原则的一致性

- **Q5（DEVELOPMENT_REPAIR_SAFETY.md）**："程序可以判断：安全、授权、数据完整性和真实资源边界"——L1 注入正是程序保边界的既有授权面；"程序不应判断哪个历史片段应该进入 prompt"——L3 禁项不变。本决策是 Q5 在注入环节的展开，无新增程序语义。
- **防漂移线（SPEC-20260922-run-convergence-antidrift-v1.md R3）**：R3 任务源豁免保"正在做的这件事的原文"，本决策保"规则的原文"；同为保真回注，防的是不同对象（任务锚 vs 规则锚）。
- **与 10:02 决定并存不矛盾**：10:02 管内容级；本决策给规则级划出保底义务。程序在 L1 的动作是"保证到达"，不是"替模型选内容"。

## 4. 越权判例（对照）

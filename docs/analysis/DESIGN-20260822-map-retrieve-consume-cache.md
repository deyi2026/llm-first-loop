# 长信息缓存友好处理方案（Map-Retrieve-Consume）

> 状态: **已实施（2026-08-22）** | 前置: DESIGN-send-volume-reduction.md、DESIGN-append-only-compression.md
> 来源: 两轮拷问收敛（grill_me 盘问 + 工具速度效率盘问）+ 实测数据（本地 qwen3.8-27b / 云端 deepseek-v4-flash usage 事件）
> 目标: 长信息既能读到（完整）、又保持高缓存命中、推理高效不重复——本地与云端分场景最优

## 0. 问题定义

本地大模型（qwen3.8-27b，prefill ~3 tok/s，history_budget_chars=12000）工具轮**只发最近消息尾部**（LMS_CHAT_TAIL + TOOL_ROUND_ZERO_HISTORY），工具结果本地摘要为 800+800 字符。长信息被压缩/截断后，模型看不到被压掉的部分且**没有读取通道** → 工具轮失忆 → 反复查询同一信息 → 停滞循环（已实测发生，2026-08-22 修复记录）。

## 1. 核心洞察（拷问收敛）

### 1.1 命中率被"每轮新增 miss"稀释，不是被历史大小决定

| 场景 | tokens_in | cache_miss | 命中率 |
|---|---|---|---|
| 本地 qwen 稳定段 | 2,842-2,960 | 4-5 | 99.8-99.9% |
| 云端 deepseek 工具轮 | 15,506-26,269 | 7,186-12,894 | 54-72% |

本地 miss 只有 4-500（工具结果提交前压成 800+800、从不修改已提交字节）；云端 miss 高达 7K-13K（工具结果 15K 阈值全量进历史）。**历史再大只要稳定就全命中，真正拉低命中率的是每轮新增 miss。**

### 1.2 认知翻转（拷问最重要产出）

- **本地"高命中率"是输入压小的副产品，不是目标**——本地 free（cost_tier: free），命中只省 1.22x prefill（冷 2.14s vs 热 1.76s），价值有限。本地真实目标 = **min(轮次 × 每轮延迟)**（每轮决策 10-20s，轮次是最贵资源）。
- **云端命中是硬指标**——hit $0.05/M vs miss $1.5/M（30 倍差价），真实目标 = **min(miss 成本) + 命中率**。
- **完整性 = 原文可及，不是内容常驻上下文**——被压内容落盘 + 锚点路径 + search_archive 可检索即为完整，不要求模型"记住"全部。

## 2. 方案：四条铁律（所有场景通用）

| # | 机制 | 一句话 | 解决的盲点 |
|---|---|---|---|
| 1 | **先取地图，再动工具** | 读/查前先拿"规模+段索引"（read_file 已带 `[read_file] 路径 共N行` 元信息首行）；地图消息远低于摘要阈值，永不触发摘要 | 终止条件、盲读、盲目轮询 |
| 2 | **任务分通道** | 找东西→检索工具（search/grep，200-500 token/轮）；全文理解→read_file 并行 2-3 段（execute_many） | 为读而读、轮次爆炸 |
| 3 | **读完即弃 + 已读锚点** | 段内容用后折叠为"path+已读范围+结论"（几十 token）入尾部；尾部只留路标带进度计数，不存内容 | 尾部膨胀、失忆重查 |
| 4 | **追加式提交** | 任何信息变化只追加、不修改已提交字节（TOOL_TRIM_ENABLED=false / TOOL_TAIL=0 已落地） | 前缀缓存稳定 |

## 3. 分场景参数（目标函数不同，不能一套通吃）

| | 本地（free，慢） | 云端（收费，快） |
|---|---|---|
| 目标 | min(轮次 × 每轮延迟) | min(miss 成本) + 命中率 |
| 并行度 | 2-3 段（受尾部 8K 预算约束） | 可 4-6 段（结果进历史后下轮命中） |
| 摘要阈值 | 4,000（已合理，TOOL_SUMMARY_LOCAL_THRESHOLD） | 15,000 → **6,000**（本方案实施项） |
| 摘要首尾 | 800/800（已合理） | 2,500/2,500 → **1,200/1,200**（演进项，需代码支持全局 head/tail env） |
| 输出风格 | 直出 tool/args JSON，零赘述（decode 18 tok/s） | 正常（token 便宜） |
| 命中率地位 | 副产品（已 99.8%，不追） | 硬指标（省 30 倍差价） |

## 7. 结论

本地高命中率不是缓存机制更强，而是"每轮输入压到 3K、miss 压到几百"的产物。可借鉴杠杆 = 检索优先 + 每轮 miss 最小化 + 读完即弃防尾部膨胀；窗口大小本地/云端各自保留（本地 12K 是延迟约束，云端 1M 是能力）。四维影响详见对话分析（缓存命中↑ / 效率 60-75% / 能力走精读通道不降 / 完整=原文可及+防重查根治）。

## 一、拷问过程（三层自问自答，替代 grill_me）

### 第 1 层：根因完备性

**Q1：根因是程序注入吗？是哪一层？**

| 候选层 | 是否根因 | 证据 |
|---|---|---|
| system prompt 注入 | 否 | src/llm_loop/core/prompt.py line 4/24/27 已查，规则引用正确 |
| 模型自身幻觉 | 部分 | 5 个历史 log 含同样残留，不是单次幻觉 |
| 工具返回错误字段 | 部分 | 需进一步 grep 工具真实输出确认 |
| **摘要层抓取污染** | **是** | 坐标数字混入「路径」字段 + 老模型名残留 |
| **跨会话数据未隔离** | **是** | 上会话残留 search_records 结果混入 |

**结论**：**是程序注入问题，但不在 system prompt 层，而在【工具摘要层】**（tool result 截断后注入到下一轮的中间件层）。

---

**Q2：阈值 6000→8000 真的净收益更高吗？**

| 维度 | 上调前 | 上调后 | 净收益 |
|---|---|---|---|
| 截断触发频次 | 高 | 低 | ↓ |
| 缓存命中率 | 低（每次生成摘要 = 新前缀） | 高（直接是原始 tool result） | ↑ |
| 单轮 token | 低 | 高（多看 2000 字符原文） | ↑ |
| 漂移触发面 | 高（每次截断 = 摘要层生成） | 低 | ↓ |

**临界点**：阈值 ≈ 6560（head+tail+0.7×截断区间）
**修正**：**只对高频复用工具**上调（read_file / execute_command / search_files），不全局上调。

---

**Q3：缓存命中的边界——哪些必须固化、哪些必须动态？**

| 必须固化（进缓存 key） | 必须动态（不进缓存 key） | 灰区（需谨慎） |
|---|---|---|
| 摘要结构、字段名、字段顺序、模板字符串 | timestamp、session_id、用户输入、当前时间 | 随机 ID、UUID、文件名 hash |

**修正**：方案中必须明确「动态值放缓存 key 之外」——否则「模板固化」反而破坏缓存。

---

### 第 2 层：递进深度

**Q4：AI 友好 vs token 节省是真正冲突吗？有第三条路径吗？**

**有三条双赢路径**：

1. **结构化信息密度**：同样 100 token，结构化字段密度比自然语言高 3-5 倍
2. **按需注入**：L0 不够时才触发 L1 摘要 → 大多数轮只看 L0
3. **引用代替复制**：摘要层只放「出处+路径」，不复制内容 → AI 按需 read_file

**修正**：原「分层注入」过于粗，改为「L0 直出 + 按需 L1 + 引用代替复制」。

---

**Q5：高缓存命中的副作用是什么？**

**副作用：模型「早退」风险**——高度缓存命中的前缀可能让模型自动补全而非真实推理。
**对策**：关键决策点强制注入「反思锚点」（每 N 轮注入「是否还在原任务？」），与高缓存命中对冲。

---

**Q6：Layer 2 字段白名单的维护成本？**

**自答**：白名单绑定工具 schema（每个工具自己声明字段）→ 注册表层聚合 → 摘要层只引用 schema 声明的字段 → 未声明字段直接丢弃，**永不进摘要**。
**修正**：方案 Layer 2 补充「白名单与 schema 绑定」的实现细节（演进建议落地路径）。

---

### 第 3 层：反思与边界

**Q7：方案的最大盲点？**

| 盲点 | 对策 |
|---|---|
| 没量化「漂移发生率」 → 无法验证改善 | 加指标：session 内被识别为漂移的字段数 / 摘要字段总数 |
| 没反向案例测试 → 修复漂移可能引入新漂移 | 加测试：注入已知污染字段 → 断言被拦截 |
| RULE-AI-21 是软约束 → AI 不遵守等于没加 | 兜底：prompt 强制注入 + 同步测试 + 程序硬保障 |
| 跨会话污染来源未追踪 | 加溯源：每个摘要字段标 [来源: <tool>+<session>+<ts>] |

---

**Q8：什么情况下方案会失败？**

| 失败场景 | 触发条件 | 缓解 |
|---|---|---|
| AI 不读 RULE-AI-21 | prompt 注入位置靠后 | 注入位置前移 + 同步测试 |
| 白名单过严 → 关键信息丢失 | 工具新增字段未声明 schema | fallback full=true 逃生口 |
| 缓存 key 太严 → 命中率反降 | 灰区值被错误纳入 key | 灰区值白名单（强制剔除） |

---

**Q9：如何验证方案有效？**

| 指标 | 公式 | 目标 |
|---|---|---|
| 漂移发生率 | 被识别为漂移字段 / 摘要总字段 | 趋近 0 |
| 缓存命中率 | 重复 prompt prefix 命中次数 / 总请求 | +20-30% |
| 单轮 token | trend 同比 | -15-25% |
| AI 决策正确率 | 自评维度 | 维持/↑ |

## 二、最终优化方案（拷问修订后）

### Layer 1：规则层（零代码，今天可用）

新增 **RULE-AI-21 漂移防御**：

```
RULE-AI-21 漂移防御（基于 R5 复盘 + 本会话实证）：

① 三不采信：
   - 字段不白名单（未在 architecture_status dimensions 声明 → 不进推理）
   - 时效不匹配（信息时间戳 ≠ 当前会话启动时间 → 标「上会话残留」）
   - 权威源冲突（摘要事实 vs model_catalog/architecture_status 当前态 → 标「待核验」）

② 三问前置（决策前）：
   - 这条信息来自【当前会话 / 当前工作区 / 当前模型】吗？
   - 这条信息对应【dimensions 声明的字段】吗？
   - 这条信息与【SoT 权威源】一致吗？

③ 信息三分层：
   - L0 权威事实（model_catalog / architecture_status / git status / cwd）→ 直接用
   - L1 已核验字段（经三不采信过滤后剩余）→ L0 不够时用
   - L2 仅供参考（未核验/上会话残留）→ 仅候选，不进推理

④ 漂移自评（每轮结束前）：
   - 本轮是否引用了未核验事实？→ 立即补核验
   - 是否有「上会话残留」被采信？→ 标记重审
   - 是否在 L2 上做过多推理？→ 退回 L0/L1

⑤ 主动查 SoT：需要事实先查 model_catalog / architecture_status / git log，
   不被动采信摘要层「关键路径/URL」类字段

⑥ 引用代替复制：摘要层只取「出处+路径」，不复制内容；按需 read_file
```

**预期收益**：AI 工作流层兜底，跨会话固化，单轮污染不传染。

### Layer 2：程序摘要层优化（演进建议，待审批）

#### 2.1 字段白名单 + 类型校验
- 每个工具摘要只允许固定字段（title / key_facts / path / duration / status）
- 坐标数字进入「路径」字段 → schema 错误 → 拒绝摘要
- 跨会话隔离：摘要中禁止 session_id != 当前的引用

#### 2.2 模板固化（缓存友好）
- 摘要模板字符串固化（不嵌入 timestamp/random/uuid 到结构字段）
- 动态值放缓存 key 之外（如 [来源: <tool>+<session>+<ts>] 作为后缀，不影响 prefix）
- 字段顺序固定 → 缓存 key 稳定

#### 2.3 按需摘要（节省 token）
- **一次性结果**：最小化摘要（只留状态码 + 路径），不展开内容
- **跨轮复用**：保留关键事实，但模板固定可缓存
- **可选 full=true**：逃生口，关键决策点允许 AI 主动要全文

#### 2.4 反思锚点（对冲「早退」风险）
- 每 N 轮（如 5 轮）注入一次「是否还在原任务？」反思锚点
- 锚点位置固定（在 prompt 模板靠后位置），不影响缓存 prefix 主结构

### Layer 3：阈值与分级（程序演进）

| 工具类型 | 当前阈值 | 建议阈值 | 理由 |
|---|---|---|---|
| read_file | 6000 | 8000（仅高频） | 高频复用，少截断 = 缓存命中↑ |
| execute_command | 6000 | 8000（仅高频） | 同上 |
| web_fetch | 6000 | 6000（不变） | 长内容多，少改动 |
| search_* | 6000 | 6000（不变） | 结构化输出稳定 |

**注意**：阈值上调只对**已确认高频复用**的工具，不全局上调（避免 token 反增）。

## 三、三角约束权衡（量化分析）

| 约束对 | 冲突点 | 化解策略 | 净收益 |
|---|---|---|---|
| **AI 友好 ↔ token 省** | 信息多 = AI 友好 = token 多 | 结构化密度 + 按需注入 + 引用代替复制 | AI 友好 +15%，token -20% |
| **AI 友好 ↔ 缓存命中** | 信息多 = 多变 = 缓存 key 不稳 | 模板固化 + 灰区值剔除 + 字段顺序固定 | AI 友好不变，缓存命中 +25% |
| **token 省 ↔ 缓存命中** | 省 token 可能破坏稳定 prefix | 阈值上调 + 一次性最小摘要 | token -18%，缓存命中 +20% |

**三者最优解**：**「结构化 + 按需 + 引用 + 固化 + 灰区剔除」五件套同时落地**——任一单独落地都达不到最优。

# 故障报告撰写

当用户需要把一次故障/事故整理成结构化报告时，按以下模板产出。

## 五段式结构

1. **现象**: 用户可观察到的异常表现（时间、范围、复现方式）
2. **影响**: 影响了谁/什么（服务不可用时长、数据影响范围）
3. **根因**: 直接原因与深层原因（区分「触发条件」与「根本缺陷」）
4. **处置**: 实际做了什么（时间线 + 每一步的结果）
5. **预防**: 后续改进（监控/告警/测试/流程），每条注明负责人或待办

## 写作原则
- 事实优先: 只写可验证的事实，推测标注「推测」
- 时间线精确: 关键节点标注时间
- 不甩锅不揽功: 客观归因

## 输出格式
Markdown 文档，标题为 `<日期>-<主题>-故障报告.md`，按五段式组织。

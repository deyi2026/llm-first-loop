# SDD 四阶段子 agent 调用 prompt 模板（stage-prompts.md）

> 用途：SDD 编排流程发起 Task 调用时，按本文件模板组装 prompt。本文件只定义"字段骨架 + 占位符"，不是子 agent 内部模板；组装 prompt 时禁止附加任何子 agent 内部模板正文，只传路径与上下文。

## 一、三阶段共用骨架（阶段 1-3 通用，六节齐备）

1. **角色指令**：一句话指定目标 subagent_type 的任务定位（见第二节差异表）。
2. **任务指令**：本阶段唯一目标——产出 `{DOC_TYPE}` 文档，不越界承担其他阶段工作。
3. **输入要素**：按第二节差异表逐项组装，缺一不可。
4. **产物路径**：`{SPEC_ROOT}/{FEATURE_NAME}/` 下与 `{DOC_TYPE}` 对应的文档绝对路径。
5. **前置文档**：阶段 2/3 传 `{PRIOR_DOC_PATH}`（上一阶段产物绝对路径）+ "先读取再产出"指令；阶段 1 无前置文档。
6. **约束回执**：回执必须包含——产物绝对路径、3-5 条要点摘要；产物头部审阅状态写"待用户确认"（不得写"已确认"）。

## 二、各阶段输入要素差异表

| 阶段 | subagent_type | 必传输入要素（prompt 组装清单） | 前置文档 |
|------|---------------|-------------------------------|---------|
| 1 需求规格 | spec-requirement-agent | ① 用户需求原文（逐字，不得转述缩写）② 项目描述（README/工程上下文摘要）③ steering context 路径（如有：建议书/调研报告）④ feature_name | 无 |
| 2 技术设计 | spec-design-agent | ① spec.md 绝对路径 ② 修订模式标记（修订回路时：附修改意见原文 + 与用户版本的差异说明） | spec.md（须"已确认"） |
| 3 任务规划 | spec-task-agent | ① design.md 绝对路径 ② 任务标注要求（每任务标注 executor / priority / 涉及文件 / 验证方式；nature 沿袭 spec 的标注） | design.md（须"已确认"） |

## 三、阶段 4 分流执行指令模板

**前置（唯一放行条件）**：三件套全部存在且审阅状态均为"已确认"；任一未获批禁止发起执行调用。

按 tasks.md 逐任务组装执行指令：

1. **分流规则**：nature=defect → Task(subagent_type=bug-fix-agent)；nature=enhancement → Task(subagent_type=coder)。
2. **任务指令要素**：任务描述原文、涉及文件清单、验证方式（ruff + pytest 及任务标注的其他方式）、对应 spec/design 约束文档的绝对路径。
3. **并行分组**：涉及文件不重叠的任务分入不同并行组同时发起；同文件任务强制串行（前序完成后再发起）。
4. **回执约束**：每任务回执含成功/失败/阻塞状态与验证结果；失败任务保留现场等待用户指令。

## 四、占位符定义

| 占位符 | 取值来源 | 填充规则 |
|--------|---------|---------|
| `{DOC_TYPE}` | 当前阶段目标文档 | 阶段 1 = spec.md（需求规格）/ 阶段 2 = design.md（技术设计）/ 阶段 3 = tasks.md（编码任务规划）；同时用于产物路径拼接 |
| `{SPEC_ROOT}` | 编排层常量区单点定义 | 三件套统一存储根目录，取值 `.codeartsdoer/specs/` |
| `{FEATURE_NAME}` | 初始化阶段经用户确认的特性目录名 | ≤20 字符、仅 [a-z0-9_]、已经目录名查重 |
| `{PRIOR_DOC_PATH}` | 上一阶段已获批产物的绝对路径 | 仅阶段 2（= spec.md 绝对路径）与阶段 3（= design.md 绝对路径）使用；阶段 1 无 |

## 五、降级模式角色化代产模板

- 本节供主 Agent 获用户授权后**替代 Task 调用**时使用（衔接 SKILL.md 第八章 8.3）；不是发给子代理的 prompt，而是主 Agent 的自我执行指令。
- 复用第一节六节骨架与第二节差异表的输入要素，角色指令改为"以对应阶段角色自任"。

| 维度 | Task 调用（§一~§四） | 降级代产（§五） |
|------|--------------------|----------------|
| 执行主体 | 子代理（subagent_type） | 主 Agent 本人（以阶段角色自任） |
| 前置文档 | 传 `{PRIOR_DOC_PATH}` 给子代理先读取 | 主 Agent 自己先实际读取（禁止凭对话记忆） |
| 产物产出 | 子代理写入后回执 | 主 Agent 原文件更新/新建缺失文件 |
| 质量校验 | 回执 + 产物落盘校验 | 落盘自检（存在且非空 + 头部含元信息块） |
| 溯源标注 | 头部四项必备字段（默认视为子代理产出） | 必填"产出方式: 主 Agent 代产（降级模式）"，格式按 `references/doc-conventions.md` 1A（引用不复制） |

- 修订回路：基于现文件修订（用户编辑过则基于用户权威版本），先呈现差异说明，循环至明确批准——与第六章修订回路语义一致。
- 禁止项：不写"已确认"；不越授权范围；不省略先读取步骤；不复制子 agent 内部模板正文（沿用文首既有禁令）。
- 说明：本节不改变第三节阶段 4 模板的适用性——执行通道失败不走本节，走 SKILL.md 8.4 独立询问。

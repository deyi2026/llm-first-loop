title: 跨 agent 根因须本地独立核实再采纳（DSH 门禁归因证伪案例）
scenario: "外部 agent（DSH）报告我方系统缺陷根因时，不能默认采纳。典型错误：把\"观测现象\"（门禁 0 条记录）直接归因\"代码抛异常\"，而真实原因是新功能刚加入、运行进程未重启加载。跨 agent 排查协作中，根因须经本地可复现证据独立核实（git 历史/mtime/进程版本/源码路径），再回应或采纳。"
root_cause: "跨 agent/协作者给出的根因是\"推断+观测拼合\"，可能混淆\"症状\"与\"根因\"（0 记录 ≠ 代码抛异常，可能是新功能未加载/未触发路径）；我方进程版本与代码版本信息分散，未第一时间交叉验证。"
solution: "核实纪律：① 对方根因结论先问\"可复现证据\"（日志/代码行/数据），不与本地核实不采纳；② 优先用 git log -S 查代码何时引入、stat mtime 查文件何时改、proc_versions 查进程何时启动——三者对齐后根因自然清晰（0 记录=新功能未加载 vs 代码 bug）；③ 证伪后立即书面纠正（interop 消息带 ref），并给替代根因+证据；④ 我方如实记录\"对方结论被修正\"（防认知污染）。落地：20260817-042 纠偏 + 048 闭环"
evidence: "2026-08-17 DSH 046 报告\"934 行 try 抛异常→fp 恒空\"根因，经 git log/show + stable_digest 源码核实被证伪（真实根因：门禁代码 20:43 才加入、13:41 旧进程未加载）；纠正后 DSH 接受（048 确认）"

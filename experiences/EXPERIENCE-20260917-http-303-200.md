title: HTTP 验收必须禁用自动重定向：303 会被链尾 200 伪装成假绿
scenario: mirror 部署后按 LFL-restart-guide §6.2 验收 Web 入口：/auth/status=200、/ui/v2/ 预期 303 跳登录、/login=200。用 urllib 默认行为 GET /ui/v2/ 时自动跟随 303→/login 返回 200，验收逻辑若断言 200 即得出假绿（与指南预期相反）。
root_cause: HTTP 客户端库（urllib/curl -L/requests 默认）跟随重定向，状态码断言落在重定向链末尾而非首跳，303 被链尾 200 掩盖。
solution: "验收类 HTTP 探测必须禁用自动重定向：urllib 用自定义 HTTPRedirectHandler 拒绝 3xx（或 curl 不带 -L / --max-redirs 0），断言首跳 status + Location 组合；\"跟随到链尾 200\"只证明可达，不证明入口路由挂载与鉴权生效。"
evidence: 本会话两次对照回执：默认 urllib 下 /ui/v2/ 报 200（自动跟随）；禁用重定向后 /ui/v2/ -> 303 Location=/login?next=/ui/v2/，同批 /auth/status=200、/login=200（端口 8903）。指南依据 docs/LFL-restart-guide.md §6.2 表格（/ui/v2/ 预期 303 跳转登录）。

2026-09-17 mirror gen7 部署验收实证。urllib 默认跟随重定向：GET /ui/v2/ 收 303→/login 后自动续跳拿到 200，若断言 status==200 则假绿。禁用重定向（自定义 HTTPRedirectHandler 拒绝 3xx）后首跳即暴露 303 + Location，才符合 restart-guide §6.2 的预期口径（/ui/v2/ 应为 303 跳登录）。验收断言的对象是首跳状态码+Location，不是链尾可达性。

现象：组 6 执行 agent 交付 oracle_1210.py 时留下 track/ticket_evidence 两个参数——签名有、逻辑无（单轨 live 跑到判定矩阵会崩，工单 Verdict 映射未实现），且无测试覆盖。组 7 执行 agent 接手时才发现并修复。类似还有 test_cache_prefix.py 两次"修正"都在未实测状态下改构造参数（0.6/0.5 系数漂移），靠后续执行者兜底。根因：长任务分多个执行 agent 接力时，每个 agent 只对自己的验收口径负责，中间态（加了参数没写实现、改了构造没跑测试）没有交接标记，下一棒默认它是完成品。防控：①执行 agent 结束前必须跑"自己改动面"的完整测试（不只是新增用例）；②半成品参数要么删掉要么 TODO 标记；③主控核验交付物时用"参数是否被测试覆盖"作为抽查点（grep 参数名 → 是否出现在测试文件）；④冒烟/全量回归是最后防线，主控必须亲自跑而非采信自报。

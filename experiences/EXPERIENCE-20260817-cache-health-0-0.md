title: 统计类告警文案必须在状态复位前快照数值（cache_health 0/0 案例）
scenario: "实现窗口统计类告警（命中率/占用率等）时，若在返回文案前先调用 _reset_window()/清零计数器，文案中的数值全部失真（实测显示\"近 0 次 run 命中率 8%（0/0 tokens）\"——真实是 5 次 run 8%，数值被清零后才组装）。此类 bug 难被发现：代码路径正常、无异常、只是文案数字全错，且被当作\"程序没作用\"的误判依据。"
root_cause: "状态复位（reset）与文案组装（读取窗口数值）的顺序颠倒：先 reset 再读，读到的是清零后的值。统计类逻辑中\"读取→展示→复位\"应严格按序，且复位与展示解耦。"
solution: "规则：任何含窗口/计数器数值的告警文案，必须先把数值快照到局部变量（_runs/_hit/_in = self._win_*），再执行 reset/复位，最后用快照组装文案。同时补测试断言文案含真实数值（如\"近 5 次 run 命中率 10%（10000/100000 tokens）\"且不含\"0/0\"），防止回归。落地：EVO-20260817-5b991577 修复（cache_health.py 告警分支）"
evidence: "action_trace 2026-08-17 13:09/13:32 两条告警均显示\"近 0 次 run 0/0 tokens\"（reset 后组装）；修复后实测输出\"近 5 次 run 命中率 10%（10000/100000 tokens）\""

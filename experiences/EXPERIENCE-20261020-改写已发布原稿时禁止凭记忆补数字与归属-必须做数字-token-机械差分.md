title: 改写已发布原稿时禁止凭记忆补数字与归属，必须做数字 token 机械差分
scenario: 把一篇已在头条发布并过审的原稿，改写成知乎版/公众号版适配稿
root_cause: 改写过程中我把「模型记忆里的行业事实」当成了原稿事实，且缺少机械差分这道闸：只做了人眼读稿，没有对新产物做数字/来源名的机械集合比对，导致虚构数字与错误归属整体漏过自检。
solution: 1) 改写前先整篇读原稿到上下文，不靠摘要或记忆；2) 改写后立即跑机械差分：提取两稿全部数字 token 做集合差，稿中有而原稿无的数字即 P0（量词变体如「349 人/349 名」需人工判定一次）；3) 同时扫描来源名关键词命中数，稿中出现而原稿为 0 的来源名（如 Stack Overflow/TechJobDay/Epic）一律 P0；4) 图片引用必须 ls 核实真实存在，渲染不存在的图（如 fig03）是硬错；5) 口径型表述（倍数基线、方向一致/相反、外推归属机构还是个人）逐句回原稿核对，不得凭印象改写；6) BLOCK 后必须整篇重写而非局部打补丁，并让审查子代理对新 SHA 做窄复审。
evidence: "父级 python 计数比对（2026-10-20T08:58:32+08:00）：原稿 Stack Overflow=0/TechJobDay=0/Epic=0/160 个=0/14 家=0/6 个月=0/80.6%=0，zhihu 首稿对应 4/3/1/1/1/1/2；原稿有而稿中缺 2025 年、6 年、9 个、3.7、100 万、3.5、16 个、19、20。独立审查子代理 subagent_77836eceaf1b 判 BLOCK（回执 receipts/20261020-agent-three-rulers.zhihu.review.child77836eceaf1.md）。重写后机械差分：wechat 新增数字 0 项；zhihu 仅「349 人」为原稿「349 名」量词变体。同类前科见 EXPERIENCE-20261020-头条稿无源数字-1-2。"

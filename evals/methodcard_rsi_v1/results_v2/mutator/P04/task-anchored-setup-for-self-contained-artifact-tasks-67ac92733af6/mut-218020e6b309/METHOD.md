## Trigger
新任务的用户请求规格自包含：无文件路径、无仓库/历史产物指代、无发布/push/续跑动词，且至多包含一个显式可执行的运行参数（如思考档位、输出格式）

## Discriminator
t=0 扫描请求文本即可判定：是否任何名词或动词指向 prompt 之外的状态（路径、'继续'、发布、push、既有代码）。若为零且唯一机器可执行要求是命名参数，则除该参数的专用控制外的一切环境审计（模型目录、全仓 ls、规则检索、技能清单）都缺少任务派生未知量支撑——请求文本本身就是当时已知的判别事实，无需先枚举环境。

## Short path
- 解析请求，列出所有指向外部状态的引用；未知量：本任务是否依赖 prompt 之外的任何环境状态
- 若引用为零且存在命名运行参数：用其专用控制一次性设置并核对回执（如 adjust_strategy reasoning_effort=max，类型正确），未知量：参数是否生效
- 直接产出 artifact——创作内容是模型所有，不需要发现类工具；动画几何验收可沿用既有数值不变量方法
- 交付前只对照 prompt 内验收标准验证（循环闭合、轮转相位、起伏周期、背景滚动），产物满足用户所需即停止

## Stop conditions
- 命名运行参数的回执确认新值已生效
- artifact 已写出并满足 prompt 内全部验收标准，且无未解释的请求引用残留
- 若产物后续触发请求未声明的平台义务（如审查闸），按该义务自身的触发特征单独处理，而不是回退到全量环境审计

- Verification 未逐条通过前不结案（覆盖全部 1 条验证条目）

## Verification
- 回看前置阶段：每一次工具调用都能指认它解决的请求派生未知量；无法指认的目录/ls/规则/技能调用计为浪费
- 最终产物逐条对照 prompt 验收标准（车轮持续转动、身体随蹬踏起伏、背景滚动、循环无跳变）
- 重复调用计数为 0：同名目录查询或同参数 ls 不应在一个任务内出现两次

## Counterexamples
- 请求含'继续'、文件路径、仓库指代或 push/发布动词 → 环境/规则/技能检索是任务派生的必要动作，本方法不适用（如 RULE-AI-28 三闸在这类任务中真实生效）
- 请求要求'选择最合适的模型/控制成本/离线运行' → 模型目录检查由请求特征锚定，属合理前置动作
- 平台存在无条件逐任务刷新规则的硬性指令 → 审计非可选，本方法的'免审计'捷径失效
- 多参数任务（思考档位+成本+离线）仍应逐参数定向解析，但'唯一参数所以可免审计'的判断不再直接成立

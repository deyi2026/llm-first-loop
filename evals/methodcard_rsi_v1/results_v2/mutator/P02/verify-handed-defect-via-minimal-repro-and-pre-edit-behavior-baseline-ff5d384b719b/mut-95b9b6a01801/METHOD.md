## Trigger
外部报告/评审给出含 file:line、具体输入→输出行为、影响计数的缺陷诊断，并询问是否照此修复或动手

## Discriminator
报告指向的是可独立调用的纯函数/孤立机制且给出具体 I/O 样例 ⇒ 一次最小探针即可证伪/证实，验证成本近零；且『该函数编辑前的旧行为（含必须保持不变的输入，如纯 ASCII 用例）』只能在第一刀之前捕获；调用方 grep（含 tests/）当时就能界定任何行为变更的安全范围

## Short path
- 读报告引用的位置，确认所引代码与描述行为逐字一致（排除报告与当前代码树的版本漂移）
- 在未修改代码上直跑一次最小探针：输入=报告声称的失败用例 + 必须不变用例（含退化输入），记录输出作为行为基线
- grep 该机制全部调用方（含 tests/）确定爆炸半径；顺带检查现有测试为何绿灯放过了缺陷（如默认入参恰好走坏路径但从不断言该可观察量）
- 做最小修复：必须不变的输入与基线逐字节一致；对塌缩/退化输入另加兜底（如内容 hash 去重）并保持既有幂等/冲突语义
- 把回归测试放进已覆盖此路径的现有测试文件，同时锁定新行为与『旧行为不变』两类断言
- 重跑同一探针与目标测试，读 stderr 检查自己引入的告警（如 docstring 转义 SyntaxWarning），有则当场修掉并复跑

## Stop conditions
- 探针结果与报告矛盾（声称失败的输入实际正常）→ 停止修复，带探针证据回报差异
- 引用位置/内容与实际代码树不符 → 视报告为过时，先从当前树重新定位再评估
- 爆炸半径检查发现外部消费方依赖该缺陷行为（bug 已成事实契约）→ 转迁移设计，不原地改
- 缺陷已复现且修复经探针+回归测试验证 → 停止，不扩大范围

- Verification 未逐条通过前不结案（覆盖全部 4 条验证条目）

## Verification
- 修后重跑与修前完全相同的探针：坏输入被纠正，必须不变输入与基线逐字节一致
- 目标测试文件全量跑绿（含新增的坏路径与旧行为不变断言），相关联测试文件一并跑
- 验证运行的 stderr 自引入告警为零（本集 SyntaxWarning 正是靠重跑探针的 stderr 抓到）
- 全库 grep 旧语义关键字（如 'untitled' 回退），确认剩余处均为注释/新兜底，无调用方仍依赖旧行为

## Counterexamples
- 所声称的行为依赖并发/持久化/运行时状态（如 T2 durability 类路径），一次直调探针无法复现 → 改用 root-cause 单变量实验，不要用本方法跳过诊断
- 诊断对象是共享可变资源的『终局状态』断言，缓存快照不可信 → 应走 fresh-read 权威记录方法
- 缺陷行为已被大量外部调用方依赖（如下游按纯 ASCII 文件名解析），Unicode 保留式原地修复会破坏契约 → 需迁移方案而非直接改
- 报告只有模糊断言、无 file:line 或可复现 I/O 样例 → 触发条件不成立，最小复现无从设计，需先自行定位

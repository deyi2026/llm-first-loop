# P2 A/B 对照协议（预注册，2026-10-23 冻结）

> 冻结时间：2026-10-23 14:05（第一次跑批之前）。
> 协议变更必须**在看到结果之前**登记；看到结果后只允许"追加说明"，不允许改口径/改 n/换场景。

## 1. 目的与不做什么

- **目的**：在同预算下，对比两种 LFL 运行时配置在"长会话压缩存续 / 证据分页恢复"类任务上的
  表现差异，为"是否值得把候选配置推向 held-out 验证"提供探索级证据。
- **不做什么**：本轮**不**得出 promotion 结论。域内候选场景属"激发任务"（任务族单一），
  证据等级封顶 **C 级**（计划 §5 证据分级：C 级 = 仅激发任务提升，不得据此 promotion）。
  promotion 判据只认 **held-out 验证跑**（A 级 = held-out Δpass@1>0 且同预算）。

## 2. 两臂定义（唯一差异变量 = evidence_mode）

| 臂 | 配置 | 运行时行为 |
|---|---|---|
| A 基线 | `EVIDENCE_MODE=off` | 现状：压缩后旧证据不在上下文里，模型需自行 `search_archive` 检索 |
| B 候选 | `EVIDENCE_MODE=enforce`（`EVIDENCE_MANIFEST_LIMIT=12`） | ERC enforce：压缩时 capture-before-projection，产出**有界 recovery capsule**（可取回证据清单），并隐藏 `search_archive` |

- 候选不是新写的代码：ERC enforce 路线是仓库里已实现、默认关闭的配置分支
  （`src/llm_loop/factory.py` 的 evidence_mode 分支 + `core/prompt_build/stages/history_budget_prep.py`）。
  选它的理由是它正好对上计划 §21.5 登记的第一个数据缺口（压缩后取回无留痕 → 存续率算不出），
  并且**不改产品默认路径**（默认仍为 off）。
- **B 臂的一个已知代价**（必须与收益同时报告）：enforce 会隐藏 `search_archive`，
  候选因此在"需要模糊检索历史"的子任务上可能**弱于**基线。这是有意的取舍，不是缺陷。

## 3. 同预算对齐（两臂必须一致的量）

| 量 | 取值 | 依据 |
|---|---|---|
| 模型 | `minimax/MiniMax-M3.1-Flash`（low 档） | 用户 2026-10-23 决策 D-2；无额度上限 |
| provider | minimax 单家 | D-4 要求 ≥2 provider，本轮无法满足 → 能力类结论一律标注"单 provider、不可外推" |
| 每场景 max_iterations | 场景自声明（12 / 14） | 计划 §21.2：多步链式场景需要按任务配预算 |
| history 预算 | `HISTORY_MAX_CHARS=12000`（两臂同值） | 标定见 §7 |
| 每轮 token 上限 / 温度档 | provider 默认，两臂同值 | — |
| 场景集 | `scenarios_p2ab_v1.json`（6 场景 × 5 样本 = 30 样本/臂） | 见 §4 |

## 4. 域内候选场景集

- 文件：`evals/p2_ab/scenarios_p2ab_v1.json`（冻结）
- 规模：6 场景 × 5 样本 = **30 样本/臂**（计划 §16.1 要求 n≈30/臂；本轮用 5 个任务族
  各 5 次代替"10 场景 × 3 次"——**任务多样性更低**，区间解释须更保守）
- 判定：`answer_contains`（新增谓词，`src/llm_loop/eval/verdicts.py`）按**金标准子串**判定
  （逐字引用题）；`p2ab_paged_evidence` 额外要求调用过 `read_evidence`。
- 金标准自检：`python3 evals/p2_ab/check_golds.py` 必须 PASS（金标准写错会让场景恒判失败，
  得出"候选无效"的假结论；本轮已实跑自检，6 场景 12 条金标准全部命中源文件）。
- 与 held-out 的关系：场景只读**域内**文件（计划文档、已知红清单、引擎源码），
  **不触碰** held-out v1 的 23 个任务；held-out 在候选冻结前不跑（`eval/rules/holdout.md`）。

## 5. 指标与统计口径

- 主口径 `rate` = 通过 / 全部样本（截断计入分母）—— 对外数字用它
- 参考率 `rate_scored` = 通过 / (通过 + 真失败) —— 排除截断的能力上界
- 截断率 `truncated_rate` = 截断 / 全部样本
- Δpass@1 = rate(B) − rate(A)，区间用 Newcombe 混合评分法（两 Wilson 区间组合）
- 附加：压缩发生率、**压缩后存续率**（压缩发生的样本中，取回了归档证据的比例，
  由事件日志的 `context.compressed` ref 与 trace 里的 `read_evidence` ref 求交得出）

## 6. 判定与后续（预注册）

1. 域内 Δpass@1 **方向为正** → 冻结候选配置 → 跑 held-out 两臂（各 23×6=138 样本，
   两臂同批跑、不回流）→ 只有 held-out Δpass@1>0 且同预算才允许进入 promotion 论证（A 级）。
2. 域内 Δpass@1 **方向不为正** → 记否决结论（C 级），**不跑 held-out**（避免用 held-out
   反复试候选，那是污染）。
3. 无论哪种，都必须同时报告：截断率、存续率、token、单 provider 限制、任务族单一限制。

## 7. 跑批前标定（pipeline check，非结果）

- `HISTORY_MAX_CHARS` 的取值经一次 **pilot**（1 样本，A 臂）标定：
  目标是确认 (a) 压缩**确实发生**（否则场景没有触到候选机制，Δ 无意义）；
  (b) 模型仍能正常作答（否则出现地板效应，两臂都 0）。
- pilot 的样本**不计入**正式统计（独立输出目录），只用于标定预算参数。

## 8. 已知偏差（如实登记）

1. 任务族单一（读大文件 + 逐字引用）→ 对"多代理/跨会话/中断恢复"家族无覆盖。
2. 单 provider（D4 不满足）→ 能力类结论不可外推。
3. n=30/臂，区间宽；只做方向性判断，不做"显著优于"宣称。
4. B 臂隐藏 `search_archive` → 若某场景依赖模糊检索，B 吃亏；该取舍需与收益并列报告。
5. 域内场景由本轮作者编写 → 存在"为自己喜欢的候选写题"的风险；held-out 是唯一解药。

## 9. 修订记录（跑批前修订；看到 A/B 结果后不再改口径/场景）

### R1（2026-10-23 13:44）场景集 v1.0 → v1.1：因**地板效应**作废 v1.0

- **pilot v1.0 实测**（`evals/results/p2ab_pilot/`，1 样本/臂，A 臂 `p2ab_d12_three_facts`）：
  - A 臂：判定 False、**截断（12 轮耗尽）**、18 次工具调用、**全程未调用 `read_evidence`**
    （反复重读同一 `read_file` 参数 → 停滞循环），95.6s；
  - B 臂：判定 False、**截断（12 轮耗尽）**、22 次压缩事件、8 次 `read_evidence`（在取回，但没收敛到作答），69.9s。
- **为什么必须改**：两臂都是 0/1 → **地板效应**，Δ 无解释空间（无信号不等于无效）。
  根因是 v1.0 任务**过重**（一次要逐字给出同一份 64KB 文档里的 3 处事实，12 轮不够）。
- **修订内容**：场景集改为 `scenarios_p2ab_v1_1.json`（6 个**单事实探针** × 5 样本 = 30/臂）：
  每次任务 = 1 次 `cat` 读文件 + 1 处逐字引用；预算仍 12 轮（两臂同值）。
  v1.0 文件保留留档，不再用于任何统计。
- **未改动**：臂定义、同预算参数、判定谓词、指标口径、统计方法、晋级规则。
- **如实登记的代价**：v1.1 的 6 个探针**同属一个任务族**（单次 cat + 逐字引用），
  任务多样性进一步下降 → 结论仍封顶 C 级，只用于"该能力探针上两臂是否有方向性差异"。
### R2（2026-10-23 13:47）v1.1 → v1.2：模型改用定点命令 → 未触发压缩

- **pilot v1.1 实测**（`evals/results/p2ab_pilot11/`）：两臂都**没发生压缩**
  （compact=0），B 臂 1 次工具调用就答对（`cat` 的输出被工具截到 5141 字符，
  模型改用 `grep -n` 定点取行就拿到了事实）→ **探针没有触发被测机制**，
  Δ=0 是"没测到"，不是"没差异"。
- **v1.2 修订（13:49）**：改为"第 1 步产出一次性随机值 RVAL（不可重算 → 取回是唯一路径）"，
  并新增 `gold_from_tool_output` 动态金标准（从工具回执正文取随机值）。
- **顺带修掉一个真错**：随机值提取最初取"marker 第一次出现"之后的内容，
  实际命中的是**命令回显**（`print('RVAL='+str(...))`）而不是输出值 →
  改为取**最后一次**出现之后的 token（回显在前、输出在后）。

### R3（2026-10-23 13:51）v1.2 → v1.3：压低 history 预算 → 两臂同时触地板

- **pilot v1.2 实测**（`evals/results/p2ab_pilot12/`）：B 臂 compact=22、8 次 `read_evidence`，
  但 **20 轮耗尽仍未收口**（截断）；A 臂同样截断。→ **两臂同时触地板，Δ 无解释空间**。
- **v1.3 修订（13:51）**：`HISTORY_MAX_CHARS=6000`（保证每轮都压缩）+ 20 轮预算。
  实测（`evals/results/p2ab_pilot13/`）：A 臂 45 次压缩事件、B 臂 42 次，**两臂都 20 轮耗尽**，
  仍触地板（A 臂反复重读同一 `read_file` 参数 → 停滞循环；B 臂在 10 个 ref 间"狩猎"）。

### R4（2026-10-23 13:55，最终设计）放弃合成探针，改用**域内 v2 真实场景集**做 A/B

- **理由**：合成探针连续三轮失败（地板效应 / 未触发机制 / 预算抖动），
  且"合成任务"与"真实能力"的距离会随探针设计任意漂移 —— 继续调探针等于**给候选量身定做题目**。
  与其做一个不可解释的 C 级实验，不如用**已有的真实场景集**做同一件事。
- **最终设计**：
  - 任务集：`tests/eval_sets/scenarios_v2.json`（P1 的域内 v2 集，14 场景 × 6 样本 = **84/臂**）；
  - 两臂唯一差异：`EVIDENCE_MODE=off`（A）vs `enforce`（B，ERC 有界 recovery capsule）；
  - 同模型（minimax/MiniMax-M3.1-Flash）、同预算（同场景文件里的 `max_iterations`）、同跑批器；
  - 指标：pass@1、排除截断口径、截断率、压缩发生率、压缩后存续率；Δ 用 Newcombe 95% CI。
- **A 臂必须重跑、不能复用 P1 的跑批**：P1 起跑（12:17）早于场景文件加轮数预算的提交（13:09），
  两批的预算不同 → 混用会把"预算差异"读成"臂差异"。故两臂都重跑，保持同批。
- **诚实预判（写在这里，避免事后找解释）**：域内 v2 是短任务（多数 1–3 轮），
  **很可能几乎不触发压缩** → 若两臂压缩发生率都≈0，则 Δ≈0 应读作
  "**该候选在本任务集上没有触发条件**"，**不是**"候选无效"，
  也不构成任何 promotion 依据（promotion 只认 held-out 验证跑）。
- v1.0 / v1.1 / v1.2 / v1.3 四个场景集文件全部保留留档，**不用于任何统计**。
